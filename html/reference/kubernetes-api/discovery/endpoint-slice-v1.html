EndpointSlice

EndpointSlice مجموعه‌ای از endpointهای یک سرویس را نمایش می‌دهد. بیشتر EndpointSliceها توسط کنترل‌کننده EndpointSlice ایجاد می‌شوند تا Podهای انتخاب‌شده توسط آبجکت‌های Service را نمایش دهند. برای یک سرویس مشخص ممکن است چندین آبجکت EndpointSlice وجود داشته باشد که برای ساخت مجموعه کامل endpointها باید با هم ترکیب شوند؛ با فهرست کردن EndpointSliceها در فضای نام سرویس، که برچسب `kubernetes.io/service-name` آن‌ها نام سرویس را در خود دارد، می‌توانید همه sliceهای مربوط به یک سرویس را پیدا کنید.

apiVersion: discovery.k8s.io/v1

import "k8s.io/api/discovery/v1"

EndpointSlice {#EndpointSlice}

EndpointSlice مجموعه‌ای از endpointهای یک سرویس را نمایش می‌دهد. بیشتر EndpointSliceها توسط کنترل‌کننده EndpointSlice ایجاد می‌شوند تا Podهای انتخاب‌شده توسط آبجکت‌های Service را نمایش دهند. برای یک سرویس مشخص ممکن است چندین آبجکت EndpointSlice وجود داشته باشد که برای ساخت مجموعه کامل endpointها باید با هم ترکیب شوند؛ با فهرست کردن EndpointSliceها در فضای نام سرویس، که برچسب kubernetes.io/service-name آن‌ها نام سرویس را در خود دارد، می‌توانید همه sliceهای مربوط به یک سرویس را پیدا کنید.

فیلدتوضیحات
addressType *
string		 addressType نوع آدرس‌های موجود در این EndpointSlice را مشخص می‌کند. همه آدرس‌های این slice باید از یک نوع باشند. این فیلد پس از ایجاد تغییرناپذیر است. در حال حاضر انواع آدرس زیر پشتیبانی می‌شوند: * IPv4: یک آدرس IPv4 را نمایش می‌دهد. * IPv6: یک آدرس IPv6 را نمایش می‌دهد. * FQDN: یک نام دامنه کاملاً مشخص (Fully Qualified Domain Name) را نمایش می‌دهد. (منسوخ‌شده) کنترل‌کننده EndpointSlice فقط sliceهایی با addressType برابر "IPv4" و "IPv6" تولید می‌کند و kube-proxy نیز فقط همین sliceها را پردازش می‌کند. برای نوع "FQDN" هیچ معنایی تعریف نشده است.

مقادیر enum ممکن:
- `"FQDN"` یک FQDN را نمایش می‌دهد.
- `"IPv4"` یک آدرس IPv4 را نمایش می‌دهد.
- `"IPv6"` یک آدرس IPv6 را نمایش می‌دهد.
apiVersion
string		 APIVersion طرح‌واره نسخه‌دار این نمایش از یک آبجکت را تعریف می‌کند. سرورها باید طرح‌واره‌های شناخته‌شده را به آخرین مقدار داخلی تبدیل کنند و می‌توانند مقادیر ناشناخته را رد کنند. اطلاعات بیشتر: https://git.k8s.io/community/contributors/devel/sig-architecture/api-conventions.md#resources
endpoints
Endpoint array		 endpoints فهرستی از endpointهای یکتا در این slice است. هر slice می‌تواند حداکثر ۱۰۰۰ endpoint داشته باشد.
kind
string		 Kind رشته‌ای است که منبع REST مربوط به این آبجکت را مشخص می‌کند. سرورها ممکن است این مقدار را از endpointی که کلاینت درخواست‌ها را به آن ارسال می‌کند استنتاج کنند. قابل به‌روزرسانی نیست. به‌صورت CamelCase است. اطلاعات بیشتر: https://git.k8s.io/community/contributors/devel/sig-architecture/api-conventions.md#types-kinds
metadata
ObjectMeta		 فراداده استاندارد آبجکت.
ports
EndpointPort array		 ports فهرست پورت‌های شبکه‌ای را مشخص می‌کند که هر endpoint در این slice در اختیار می‌گذارد. هر پورت باید نامی یکتا داشته باشد. هر slice می‌تواند حداکثر ۱۰۰ پورت داشته باشد. Serviceها همیشه دست‌کم یک پورت دارند؛ بنابراین EndpointSliceهای تولیدشده توسط کنترل‌کننده EndpointSlice نیز همیشه دست‌کم یک پورت خواهند داشت. EndpointSliceهایی که برای مقاصد دیگر استفاده می‌شوند ممکن است فهرست پورت خالی داشته باشند.

Endpoint {#Endpoint}

Endpoint یک «backend» منطقی واحد را نمایش می‌دهد که یک سرویس را پیاده‌سازی می‌کند.

فیلدتوضیحات
addresses *
string array		 addresses آدرس‌های این endpoint است. برای EndpointSliceهایی با addressType برابر "IPv4" یا "IPv6"، مقادیر آدرس‌های IP به شکل استاندارد (canonical) هستند. نحو و معنای مقادیر دیگر addressType تعریف نشده است. این فیلد باید دست‌کم یک و حداکثر ۱۰۰ آدرس داشته باشد. EndpointSliceهای تولیدشده توسط کنترل‌کننده EndpointSlice همیشه دقیقاً یک آدرس دارند. برای آدرس‌های اضافه بعد از آدرس اول هیچ معنایی تعریف نشده است و kube-proxy آن‌ها را بررسی نمی‌کند.
conditions
EndpointConditions		 conditions اطلاعاتی درباره وضعیت فعلی endpoint در بر دارد.
deprecatedTopology
object		 deprecatedTopology اطلاعات توپولوژی را که بخشی از API نسخه v1beta1 بود در بر دارد. این فیلد منسوخ شده است و هنگام حذف API نسخه v1beta1 (حداکثر زودتر از کوبرنتیز v1.24 نخواهد بود) حذف خواهد شد. اگرچه این فیلد می‌تواند مقدار نگه دارد، از طریق API نسخه v1 قابل نوشتن نیست و هر تلاشی برای نوشتن در آن بی‌صدا نادیده گرفته می‌شود. اطلاعات توپولوژی را به‌جای آن می‌توانید در فیلدهای zone و nodeName پیدا کنید.
hints
EndpointHints		 hints اطلاعاتی در بر دارد که به نحوه مصرف endpoint مربوط می‌شود.
hostname
string		 hostname نام میزبان این endpoint است. مصرف‌کنندگان endpointها می‌توانند از این فیلد برای تمایز endpointها از یکدیگر استفاده کنند (برای مثال در نام‌های DNS). چند endpoint که hostname یکسان دارند باید جایگزین‌پذیر (fungible) در نظر گرفته شوند (برای مثال چند مقدار A در DNS). باید با حروف کوچک باشد و اعتبارسنجی DNS Label (مطابق RFC 1123) را بگذراند.
nodeName
string		 nodeName نام Nodeی را نشان می‌دهد که این endpoint را میزبانی می‌کند. با استفاده از آن می‌توان endpointهای محلیِ یک Node را تشخیص داد.
targetRef
ObjectReference		 targetRef ارجاعی به یک آبجکت کوبرنتیز است که این endpoint را نمایش می‌دهد.
zone
string		 zone نام Zoneای است که این endpoint در آن قرار دارد.

EndpointConditions {#EndpointConditions}

EndpointConditions شرایط فعلی یک endpoint را نمایش می‌دهد.

فیلدتوضیحات
ready
boolean		 ready نشان می‌دهد که این endpoint، به گفته سامانه‌ای که آن را مدیریت می‌کند، آماده دریافت ترافیک است. مقدار nil باید به‌صورت "true" تفسیر شود. به‌طور کلی، یک endpoint در صورتی باید آماده (ready) علامت‌گذاری شود که در حال سرویس‌دهی باشد و در حال خاتمه نباشد؛ البته در برخی موارد می‌توان این رفتار را بازنویسی کرد، مثلاً وقتی Service مرتبط پرچم publishNotReadyAddresses را تنظیم کرده باشد.
serving
boolean		 serving نشان می‌دهد که این endpoint، به گفته سامانه‌ای که آن را مدیریت می‌کند، می‌تواند ترافیک دریافت کند. برای endpointهایی که پشتوانه آن‌ها Pod است، اگر شرط Ready در Pod برابر True باشد، کنترل‌کننده EndpointSlice آن endpoint را در حال سرویس‌دهی (serving) علامت‌گذاری می‌کند. مقدار nil باید به‌صورت "true" تفسیر شود.
terminating
boolean		 terminating نشان می‌دهد که این endpoint در حال خاتمه یافتن است. مقدار nil باید به‌صورت "false" تفسیر شود.

EndpointPort {#EndpointPort}

EndpointPort یک پورت را نمایش می‌دهد که توسط یک EndpointSlice استفاده می‌شود.

فیلدتوضیحات
appProtocol
string		 پروتکل کاربردی (application protocol) این پورت. این مقدار به‌عنوان راهنما برای پیاده‌سازی‌ها استفاده می‌شود تا برای پروتکل‌هایی که می‌شناسند رفتار غنی‌تری ارائه دهند. این فیلد از نحو استاندارد برچسب‌های کوبرنتیز پیروی می‌کند. مقادیر معتبر عبارت‌اند از: * نام‌های پروتکل بدون پیشوند - رزرو‌شده برای نام‌های استاندارد سرویس IANA (مطابق RFC-6335 و https://www.iana.org/assignments/service-names). * نام‌های پیشوندداری که کوبرنتیز تعریف کرده است: * 'kubernetes.io/h2c' - HTTP/2 با آگاهی قبلی (prior knowledge) روی متن آشکار، همان‌گونه که در https://www.rfc-editor.org/rfc/rfc9113.html#name-starting-http-2-with-prior- توضیح داده شده است * 'kubernetes.io/ws' - WebSocket روی متن آشکار، همان‌گونه که در https://www.rfc-editor.org/rfc/rfc6455 توضیح داده شده است * 'kubernetes.io/wss' - WebSocket روی TLS، همان‌گونه که در https://www.rfc-editor.org/rfc/rfc6455 توضیح داده شده است * پروتکل‌های دیگر باید از نام‌های پیشوندداری استفاده کنند که پیاده‌سازی تعریف می‌کند، مانند mycompany.com/my-custom-protocol.
name
string		 name نام این پورت را نشان می‌دهد. همه پورت‌های یک EndpointSlice باید نامی یکتا داشته باشند. اگر EndpointSlice از یک سرویس کوبرنتیز مشتق شده باشد، این فیلد با Service.ports[].name متناظر است. نام باید یا رشته خالی باشد یا اعتبارسنجی DNS_LABEL را بگذراند: * طول آن نباید بیش از ۶۳ نویسه باشد. * باید از نویسه‌های الفبایی-عددی با حروف کوچک یا '-' تشکیل شده باشد. * باید با یک نویسه الفبایی-عددی شروع و با یک نویسه الفبایی-عددی تمام شود. مقدار پیش‌فرض رشته خالی است.
port
integer		 port شماره پورت endpoint را نشان می‌دهد. اگر EndpointSlice از یک سرویس کوبرنتیز مشتق شده باشد، این مقدار باید برابر پورت هدف (target port) سرویس تنظیم شود. EndpointSliceهایی که برای مقاصد دیگر استفاده می‌شوند ممکن است پورت nil داشته باشند.
protocol
string		 protocol پروتکل IP این پورت را نشان می‌دهد. باید UDP، TCP یا SCTP باشد. مقدار پیش‌فرض TCP است.

مقادیر enum ممکن:
- `"SCTP"` پروتکل SCTP است.
- `"TCP"` پروتکل TCP است.
- `"UDP"` پروتکل UDP است.

resourceVersion string resourceVersion محدودیتی برای نسخه‌های منبعی تعیین می‌کند که درخواست می‌تواند از آن‌ها پاسخ داده شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است
resourceVersionMatch string resourceVersionMatch تعیین می‌کند که resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. به‌شدت توصیه می‌شود resourceVersionMatch برای فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، تعیین شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است
sendInitialEvents boolean `sendInitialEvents=true` را می‌توان همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های مجموعه را تولید می‌کنند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای مربوط به تغییرات (پس از آن RV) در آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینه `sendInitialEvents` تنظیم شده باشد، لازم است گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به‌معنای «داده‌ای دست‌کم به‌روز مانند `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای همگام شده باشد که دست‌کم به تازگی مقدار ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه شروع پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر منطقی OR) برای تعیین یک یا چند بازه هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشه object استفاده می‌کند (برای مثال "object.metadata.uid") و از قالب fieldSelector ("metadata.uid") استفاده نمی‌کند. مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های literal در CEL هستند که درون تک‌نقل‌قول قرار می‌گیرند و پیشوند '0x' دارند. آن‌ها کران پایین شامل‌شونده و کران بالای شامل‌نشونده را بر فضای هش 64 بیتی FNV-1a تعیین می‌کنند. بازه کامل [0x0, 0x10000000000000000) است و کران بالای شامل‌نشونده برابر 2^64 است. مثال‌ها: تقسیم به 2 shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به 4 shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز دارد feature gate با نام ShardedListAndWatch فعال شود.
timeoutSeconds integer مهلت زمانی برای فراخوانی list/watch. این مقدار مدت فراخوانی را بدون توجه به هرگونه فعالیت یا عدم فعالیت محدود می‌کند.

allowWatchBookmarks boolean allowWatchBookmarks رویدادهای watch با نوع "BOOKMARK" را درخواست می‌کند. سرورهایی که bookmark را پیاده‌سازی نکرده‌اند ممکن است این پرچم را نادیده بگیرند و ارسال bookmarkها به صلاحدید سرور است. کلاینت‌ها نباید فرض کنند که bookmarkها در بازه زمانی مشخصی بازگردانده می‌شوند و نباید انتظار داشته باشند که سرور در طول یک نشست حتماً رویداد BOOKMARK ارسال کند. اگر درخواست از نوع watch نباشد، این فیلد نادیده گرفته می‌شود.
continue string هنگام دریافت نتایج بیشتر از سرور، باید گزینه continue تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند مقدار continue حاصل از نتیجه یک کوئری قبلی را با پارامترهای کوئری یکسان (به‌جز مقدار خود continue) استفاده کنند و سرور ممکن است مقدار continue ناشناخته را رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به‌دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به‌دلیل تغییر پیکربندی در سرور، سرور با خطای 410 ResourceExpired و یک توکن continue پاسخ می‌دهد. اگر کلاینت به فهرستی سازگار نیاز دارد، باید فهرست‌گیری را بدون فیلد continue از ابتدا آغاز کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری را با توکن دریافتی همراه با خطای 410 ارسال کند؛ سرور با فهرستی که از کلید بعدی شروع می‌شود، اما از جدیدترین snapshot گرفته شده است، پاسخ می‌دهد. این فهرست با نتایج قبلی ناسازگار است: آبجکت‌هایی که پس از اولین درخواست فهرست ایجاد، اصلاح یا حذف شده‌اند، تا زمانی که کلیدشان بعد از «کلید بعدی» باشد، در پاسخ گنجانده می‌شوند. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند watch را از آخرین مقدار resourceVersion بازگردانده‌شده توسط سرور آغاز کنند، بدون آنکه تغییری را از دست بدهند.
fieldSelector string انتخابگری (selector) برای محدود کردن فهرست آبجکت‌های بازگردانده‌شده بر اساس فیلدهایشان. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
labelSelector string انتخابگری برای محدود کردن فهرست آبجکت‌های بازگردانده‌شده بر اساس برچسب‌هایشان. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
limit integer limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی فهرست بازمی‌گرداند. اگر موارد بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان کوئری اولیه برای دریافت مجموعه بعدی نتایج به کار برد. تنظیم limit ممکن است تعداد کمتری از موارد درخواست‌شده (حتی صفر مورد) را بازگرداند، در صورتی که همه آبجکت‌های درخواست‌شده فیلتر شوند؛ بنابراین کلاینت‌ها باید برای تشخیص وجود نتایج بیشتر فقط به وجود فیلد continue تکیه کنند. سرورها می‌توانند آرگومان limit را پشتیبانی نکنند و در این حالت همه نتایج موجود را بازمی‌گردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند که آبجکت‌های بازگردانده‌شده هنگام استفاده از continue با آبجکت‌های یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور اولین درخواست ایجاد، اصلاح یا حذف شده است، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. این ویژگی گاهی snapshot سازگار نامیده می‌شود و تضمین می‌کند کلاینتی که برای دریافت بخش‌های کوچک‌تر از یک نتیجه بسیار بزرگ از limit استفاده می‌کند، همه آبجکت‌های ممکن را مشاهده کند. اگر آبجکت‌ها در طول فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت که در زمان محاسبه اولین نتیجه فهرست وجود داشته است بازگردانده می‌شود.
resourceVersion string resourceVersion محدودیتی را تعیین می‌کند که درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض: تنظیم‌نشده

continue string هنگام دریافت نتایج بیشتر از سرور، باید گزینه continue تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند از مقدار continue حاصل از نتیجه یک پرس‌وجوی قبلی با پارامترهای یکسان (به‌جز مقدار خود continue) استفاده کنند و سرور ممکن است مقداری را که نمی‌شناسد رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به دلیل تغییر پیکربندی سرور، سرور همراه با یک continue token خطای 410 ResourceExpired برمی‌گرداند. اگر کلاینت به فهرست سازگار نیاز دارد، باید فهرست‌گیری را بدون فیلد continue از ابتدا شروع کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری با توکن دریافت‌شده همراه خطای 410 ارسال کند؛ سرور فهرستی را از کلید بعدی به بعد، اما از جدیدترین snapshot برمی‌گرداند که با نتایج فهرست قبلی ناسازگار است: آبجکت‌هایی که پس از نخستین درخواست فهرست ایجاد، تغییر یا حذف شده‌اند، تا زمانی که کلیدشان بعد از «کلید بعدی» باشد، در پاسخ گنجانده می‌شوند. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند watch را از آخرین مقدار resourceVersion که سرور برگردانده است آغاز کنند، بدون اینکه هیچ تغییری را از دست بدهند.
fieldSelector string انتخابگری (selector) برای محدود کردن فهرست آبجکت‌های برگردانده‌شده بر اساس فیلدهایشان. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
labelSelector string انتخابگری برای محدود کردن فهرست آبجکت‌های برگردانده‌شده بر اساس برچسب‌هایشان. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
limit integer limit حداکثر تعداد پاسخ‌هایی است که در یک فراخوانی فهرست برگردانده می‌شود. اگر مورد بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان پرس‌وجوی اولیه برای دریافت مجموعه بعدی نتایج به کار برد. در صورتی که همه آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است کمتر از تعداد درخواستی (حتی صفر مورد) برگرداند و کلاینت‌ها برای تشخیص وجود نتایج بیشتر باید فقط به وجود فیلد continue تکیه کنند. سرورها می‌توانند آرگومان limit را پشتیبانی نکنند و در این صورت همه نتایج موجود را برمی‌گردانند. اگر limit مشخص شده و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند که آبجکت‌های برگردانده‌شده هنگام استفاده از continue با آبجکت‌های یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور درخواست اول ایجاد، تغییر یا حذف شده باشد، در درخواست‌های بعدیِ ادامه‌دار گنجانده نمی‌شود. به این ویژگی گاهی snapshot سازگار گفته می‌شود و تضمین می‌کند کلاینتی که برای دریافت بخش‌های کوچک‌تر از یک نتیجه بسیار بزرگ از limit استفاده می‌کند، همه آبجکت‌های ممکن را می‌بیند. اگر آبجکت‌ها در طول فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت برگردانده می‌شود که در زمان محاسبه نخستین نتیجه فهرست وجود داشته است.
pretty string اگر مقدار 'true' باشد، خروجی به‌صورت خوانا (pretty print) چاپ می‌شود. مقدار پیش‌فرض 'false' است، مگر اینکه user-agent نشان دهد درخواست از یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) ارسال شده است.
resourceVersion string resourceVersion محدودیتی روی نسخه‌های منبعی تعیین می‌کند که درخواست می‌تواند از آن‌ها پاسخ داده شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده (unset) است.
resourceVersionMatch string resourceVersionMatch تعیین می‌کند که resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. به‌شدت توصیه می‌شود در فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده (unset) است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را ارائه کند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به‌طور معمول ادامه می‌یابد و رویدادهای مربوط به تغییرات (پس از آن RV) در آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینه `sendInitialEvents` تنظیم شده باشد، باید گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این شرح است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به این معنا تفسیر می‌شود: «داده‌ای دست‌کم به‌روز به‌اندازه `resourceVersion` ارائه‌شده»، و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای همگام شده باشد که دست‌کم به‌اندازه مقدار ارائه‌شده در ListOptions تازه است. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه شروع پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا تنظیم‌نشده باشد، خطای Invalid برگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های برگردانده‌شده را با یک عبارت shard selector مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() به‌همراه || (عملگر OR منطقی) برای مشخص کردن یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشه object استفاده می‌کند (مانند "object.metadata.uid") و نه قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده فعلی: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های لفظی CEL داخل تک‌نقل‌قول با پیشوند '0x' هستند و کران پایین (شامل) و کران بالای (غیرشامل) بازه را روی فضای hash ‏FNV-1a ۶۴ بیتی تعریف می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') شارد 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') شارد 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') شارد 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') شارد 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز به فعال‌سازی feature gate با نام ShardedListAndWatch دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را محدود می‌کند، صرف‌نظر از هر فعالیت یا عدم فعالیتی.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف برمی‌گرداند. resourceVersion را مشخص کنید.

- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به‌دلایل سازگاری با نسخه‌های قبلی) true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های برگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر OR منطقی) برای تعیین یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو object-rooted به سبک CEL پیروی می‌کند (مثلاً "object.metadata.uid") و از قالب fieldSelector (یعنی "metadata.uid") پیروی نمی‌کند. مسیرهای پشتیبانی‌شده فعلی: - object.metadata.uid - object.metadata.namespace hexStart و hexEnd رشته‌های لفظی CEL درون تک‌نقل‌قول با پیشوند '0x' هستند که کران پایین (شامل‌شونده) و کران بالا (شامل‌نشونده) را در فضای hash ۶۴ بیتی FNV-1a مشخص می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که کران بالای آن، به‌صورت شامل‌نشونده، برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و برای استفاده از آن باید feature gate با نام ShardedListAndWatch فعال شود.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را، فارغ از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.

limit integer limit حداکثر تعداد پاسخ‌هایی است که برای یک فراخوانی فهرست بازگردانده می‌شود. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان پرس‌وجوی اولیه برای دریافت مجموعه بعدی نتایج به کار برد. تنظیم limit ممکن است تعداد آیتم‌های کمتری از مقدار درخواستی (حتی صفر آیتم) بازگرداند، در حالتی که همه آبجکت‌های درخواستی فیلتر شوند؛ بنابراین کلاینت‌ها باید فقط از وجود فیلد continue برای تشخیص اینکه نتایج بیشتری در دسترس است یا نه استفاده کنند. سرورها می‌توانند از آرگومان limit پشتیبانی نکنند و در این صورت همه نتایج موجود را بازمی‌گردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با صدور یک فراخوانی فهرست واحد و بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور درخواست اول ایجاد، ویرایش یا حذف شده باشد، در درخواست‌های بعدیِ ادامه‌دار نمی‌آید. به این ویژگی گاهی snapshot سازگار گفته می‌شود و تضمین می‌کند کلاینتی که برای دریافت تکه‌های کوچک‌تر از یک نتیجه بسیار بزرگ از limit استفاده می‌کند، همه آبجکت‌های ممکن را می‌بیند. اگر آبجکت‌ها در حین فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبه نخستین نتیجه فهرست وجود داشته است.
pretty string اگر مقدار 'true' باشد، خروجی به‌صورت خوانا (pretty print) نمایش داده می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent نشان دهد درخواست از یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) ارسال شده است.
resourceVersion string resourceVersion محدودیتی روی نسخه‌های منبعی که یک درخواست می‌تواند از آن‌ها پاسخ داده شود اعمال می‌کند. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
resourceVersionMatch string resourceVersionMatch تعیین می‌کند resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. اکیداً توصیه می‌شود برای فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های موجود در مجموعه را تولید می‌کنند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به روال معمول ادامه می‌یابد و رویدادهای مربوط به تغییرات (پس از RV) در آبجکت‌های تحت نظر ارسال می‌شوند. وقتی گزینه `sendInitialEvents` تنظیم شود، لازم است گزینه `resourceVersionMatch` نیز تنظیم شده باشد. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به معنای «داده‌هایی دست‌کم به‌روز به اندازه `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ی همگام شده باشد که دست‌کم به تازگی مقدار ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌صورت «خواندن سازگار» (consistent read) تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ای که پردازش درخواست آغاز شده است همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد true است (به دلایل سازگاری با نسخه‌های قبلی) و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر OR منطقی) برای تعیین یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشه object استفاده می‌کند (مثلاً "object.metadata.uid") و قالب fieldSelector ("metadata.uid") را به کار نمی‌برد. مسیرهایی که در حال حاضر پشتیبانی می‌شوند: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های لیترال CEL داخل single-quote با پیشوند '0x' هستند و به ترتیب کران پایین شامل‌شونده و کران بالای مستثنا را در فضای hash ‏FNV-1a ۶۴ بیتی تعیین می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که در آن کران بالای مستثنا برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و فعال‌سازی feature gate با نام ShardedListAndWatch را لازم دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. resourceVersion را مشخص کنید.
