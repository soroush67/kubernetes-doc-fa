IngressSpec {#IngressSpec}

IngressSpec، Ingress مورد نظر کاربر را توصیف می‌کند.

FieldDescription
defaultBackend
IngressBackend		 defaultBackend همان backendی است که باید درخواست‌هایی را که با هیچ قاعده‌ای مطابقت ندارند پردازش کند. اگر Rules مشخص نشده باشد، باید DefaultBackend مشخص شود. اگر DefaultBackend تنظیم نشده باشد، نحوه پردازش درخواست‌هایی که با هیچ‌یک از قواعد مطابقت ندارند بر عهده کنترل‌کننده Ingress خواهد بود.
ingressClassName
string		 ingressClassName نام یک منبع IngressClass در کلاستر است. پیاده‌سازی‌های کنترل‌کننده Ingress از این فیلد استفاده می‌کنند تا از طریق یک اتصال غیرمستقیم (کنترل‌کننده <- IngressClass <- منبع Ingress) تشخیص دهند که آیا باید به این منبع Ingress سرویس بدهند یا خیر. اگرچه حاشیه‌نویسی (annotation) با نام `kubernetes.io/ingress.class` (یک نام ثابت ساده) هرگز به‌طور رسمی تعریف نشد، کنترل‌کننده‌های Ingress به‌طور گسترده از آن پشتیبانی می‌کردند تا میان کنترل‌کننده Ingress و منابع Ingress یک اتصال مستقیم برقرار کنند. منابع Ingress که تازه ایجاد می‌شوند باید ترجیحاً از این فیلد استفاده کنند. با این حال، هرچند این annotation رسمی‌اً منسوخ شده است، به‌دلیل سازگاری با نسخه‌های قبلی، کنترل‌کننده‌های Ingress همچنان باید در صورت وجود آن را رعایت کنند.
rules
IngressRule array		 rules فهرستی از قواعد میزبان است که برای پیکربندی Ingress استفاده می‌شود. اگر مشخص نشده باشد یا هیچ قاعده‌ای مطابقت نداشته باشد، همه ترافیک به backend پیش‌فرض ارسال می‌شود.
tls
IngressTLS array		 tls پیکربندی TLS را نشان می‌دهد. در حال حاضر Ingress فقط از یک پورت TLS یعنی 443 پشتیبانی می‌کند. اگر چند عضو این فهرست میزبان‌های متفاوتی را مشخص کنند، در صورتی که کنترل‌کننده Ingress مسئول این Ingress از SNI پشتیبانی کند، این اعضا بر اساس نام میزبانی که از طریق افزونه SNI در TLS مشخص می‌شود، روی همان پورت چندگانه‌سازی (multiplex) خواهند شد.

HTTPIngressPath {#HTTPIngressPath}

HTTPIngressPath یک مسیر را به یک backend مرتبط می‌کند. نشانی‌های ورودی که با مسیر مطابقت دارند به backend هدایت می‌شوند.

FieldDescription
backend *
IngressBackend		 backend، endpoint سرویس ارجاع‌شده‌ای را تعریف می‌کند که ترافیک به آن هدایت می‌شود.
path
string		 path با مسیر یک درخواست ورودی مقایسه می‌شود. در حال حاضر این مسیر می‌تواند شامل نویسه‌هایی باشد که در بخش متعارف «path» از یک URL طبق RFC 3986 مجاز نیستند. مسیرها باید با «/» آغاز شوند و هنگام استفاده از PathType با مقدار «Exact» یا «Prefix» باید حتماً وجود داشته باشند.
pathType *
string		 pathType نحوه تفسیر تطابق مسیر را تعیین می‌کند. PathType می‌تواند یکی از مقادیر زیر باشد: * Exact: مسیر URL را دقیقاً مطابقت می‌دهد. * Prefix: بر اساس پیشوند مسیر URL که با «/» تقسیم شده است مطابقت می‌دهد. مطابقت به‌صورت عنصر به عنصر روی مسیر انجام می‌شود. منظور از عنصر مسیر، فهرست برچسب‌های موجود در مسیر است که با جداکننده «/» تقسیم شده‌اند. یک درخواست برای مسیر p زمانی مطابقت دارد که p پیشوندی عنصر به عنصر از مسیر درخواست باشد. توجه کنید که اگر آخرین عنصر مسیر زیررشته‌ای از آخرین عنصر مسیر درخواست باشد، مطابقت وجود ندارد (برای مثال /foo/bar با /foo/bar/baz مطابقت دارد، اما با /foo/barbaz مطابقت ندارد). * ImplementationSpecific: تفسیر تطابق مسیر بر عهده IngressClass است. پیاده‌سازی‌ها می‌توانند این مقدار را یک PathType جداگانه در نظر بگیرند یا آن را مانند انواع مسیر Prefix یا Exact رفتار کنند. پیاده‌سازی‌ها موظفند از همه انواع مسیر پشتیبانی کنند.

مقادیر ممکن enum:
- `"Exact"` مسیر URL را دقیقاً و با حساسیت به بزرگی و کوچکی حروف مطابقت می‌دهد.
- `"ImplementationSpecific"` تطابق بر عهده IngressClass است. پیاده‌سازی‌ها می‌توانند این مقدار را یک PathType جداگانه در نظر بگیرند یا آن را مانند انواع مسیر Prefix یا Exact رفتار کنند.
- `"Prefix"` بر اساس پیشوند مسیر URL که با «/» تقسیم شده است مطابقت می‌دهد. مطابقت با حساسیت به بزرگی و کوچکی حروف و به‌صورت عنصر به عنصر روی مسیر انجام می‌شود. منظور از عنصر مسیر، فهرست برچسب‌های موجود در مسیر است که با جداکننده «/» تقسیم شده‌اند. یک درخواست برای مسیر p زمانی مطابقت دارد که p پیشوندی عنصر به عنصر از مسیر درخواست باشد. توجه کنید که اگر آخرین عنصر مسیر زیررشته‌ای از آخرین عنصر مسیر درخواست باشد، مطابقت وجود ندارد (برای مثال /foo/bar با /foo/bar/baz مطابقت دارد، اما با /foo/barbaz مطابقت ندارد). اگر در مشخصات یک Ingress چند مسیر مطابق وجود داشته باشد، طولانی‌ترین مسیر مطابق اولویت دارد. مثال‌ها: - /foo/bar با درخواست‌های /foo/barbaz مطابقت ندارد - /foo/bar با درخواست‌های /foo/bar و /foo/bar/baz مطابقت دارد - /foo و /foo/ هر دو با درخواست‌های /foo و /foo/ مطابقت دارند. اگر هر دو مسیر در مشخصات یک Ingress وجود داشته باشند، طولانی‌ترین مسیر مطابق (/foo/) اولویت دارد.

IngressRule {#IngressRule}

IngressRule قواعدی را نشان می‌دهد که مسیرهای زیر یک میزبان مشخص را به سرویس‌های backend مربوط نگاشت می‌کنند. درخواست‌های ورودی ابتدا از نظر تطابق میزبان ارزیابی می‌شوند و سپس به backend مرتبط با IngressRuleValue مطابق هدایت می‌شوند.

FieldDescription
host
string		 host نام دامنه کاملاً معتبر (fully qualified) یک میزبان شبکه است، همان‌طور که در RFC 3986 تعریف شده است. به انحراف‌های زیر نسبت به بخش «host» از URI که در RFC 3986 تعریف شده است توجه کنید: 1. نشانی‌های IP مجاز نیستند. در حال حاضر یک IngressRuleValue فقط می‌تواند برای IP موجود در Spec مربوط به Ingress والد اعمال شود. 2. جداکننده `:` رعایت نمی‌شود، زیرا پورت‌ها مجاز نیستند. در حال حاضر پورت یک Ingress به‌طور ضمنی برای http برابر :80 و برای https برابر :443 است. هر دوی این مقادیر ممکن است در آینده تغییر کنند. درخواست‌های ورودی پیش از IngressRuleValue با host مقایسه می‌شوند. اگر host مشخص نشده باشد، Ingress همه ترافیک را بر اساس IngressRuleValue مشخص‌شده مسیریابی می‌کند. host می‌تواند «دقیق» (precise) باشد، یعنی نام دامنه یک میزبان شبکه بدون نقطه پایانی (مانند "foo.bar.com")، یا «wildcard» باشد، یعنی نام دامنه‌ای که با یک برچسب wildcard منفرد پیشوند گرفته است (مانند "*.foo.com"). نویسه wildcard یعنی '\*' باید به‌تنهایی به‌عنوان اولین برچسب DNS ظاهر شود و فقط با یک برچسب مطابقت دارد. نمی‌توان یک برچسب wildcard را به‌تنهایی داشت (مثلاً Host == "*"). درخواست‌ها با فیلد Host به روش زیر مطابقت داده می‌شوند: 1. اگر host دقیق باشد، درخواست در صورتی با این قاعده مطابقت دارد که هدر host در http با Host برابر باشد. 2. اگر host از نوع wildcard باشد، درخواست در صورتی با این قاعده مطابقت دارد که هدر host در http با پسوند قاعده wildcard (پس از حذف اولین برچسب) برابر باشد.
http
HTTPIngressRuleValue		 http یک IngressRuleValue از نوع HTTP است که شامل فهرستی از انتخابگرهای (selector) http است.

limit integer limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی فهرست برمی‌گرداند. اگر مورد بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان کوئری اولیه برای دریافت مجموعه بعدی نتایج به کار برد. تنظیم limit ممکن است در صورتی که همه آبجکت‌های درخواست‌شده فیلتر شوند، تعداد کمتری از موارد درخواست‌شده (حتی صفر مورد) برگرداند؛ بنابراین کلاینت‌ها برای تشخیص وجود نتایج بیشتر باید فقط به حضور فیلد continue تکیه کنند. سرورها ممکن است آرگومان limit را پشتیبانی نکنند و همه نتایج موجود را برگردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند که آبجکت‌های بازگردانده‌شده هنگام استفاده از continue با آبجکت‌های یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور اولین درخواست ایجاد، تغییر یا حذف شده باشد، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. این رفتار گاهی «snapshot سازگار» نامیده می‌شود و تضمین می‌کند کلاینتی که برای دریافت تکه‌های کوچک‌تر از یک نتیجه بسیار بزرگ از limit استفاده می‌کند، همه آبجکت‌های ممکن را می‌بیند. اگر آبجکت‌ها در حین فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت که در زمان محاسبه اولین نتیجه فهرست وجود داشته است برگردانده می‌شود.
orphanDependents boolean منسوخ‌شده: لطفاً از PropagationPolicy استفاده کنید؛ این فیلد در نسخه 1.7 منسوخ خواهد شد. مشخص می‌کند که آبجکت‌های وابسته به حال خود رها شوند (orphan) یا خیر. اگر true/false باشد، finalizer با نام "orphan" به فهرست finalizerهای آبجکت اضافه یا از آن حذف می‌شود. فقط یکی از این فیلد یا PropagationPolicy را می‌توان تنظیم کرد، نه هر دو را.
propagationPolicy string مشخص می‌کند که آیا و چگونه garbage collection انجام شود. فقط یکی از این فیلد یا OrphanDependents را می‌توان تنظیم کرد، نه هر دو را. سیاست پیش‌فرض بر اساس finalizerهای موجود در metadata.finalizers و سیاست پیش‌فرض مختص منبع تعیین می‌شود. مقادیر قابل قبول عبارت‌اند از: 'Orphan' - وابسته‌ها را رها کن؛ 'Background' - به garbage collector اجازه بده وابسته‌ها را در پس‌زمینه حذف کند؛ 'Foreground' - یک سیاست آبشاری که همه وابسته‌ها را در پیش‌زمینه حذف می‌کند.

sendInitialEvents boolean `sendInitialEvents=true` را می‌توان همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را ارائه دهد. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای watch مربوط به تغییرات (پس از RV) آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینه `sendInitialEvents` تنظیم شده باشد، لازم است گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این صورت است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به معنای «داده‌ای که دست‌کم به‌اندازه `resourceVersion` ارائه‌شده جدید باشد» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا یک `resourceVersion` به‌روز مانند مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این به معنای «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه شروع پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به‌دلایل سازگاری با نسخه‌های قبلی)، مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر OR منطقی) برای تعیین یک یا چند بازه هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشه object استفاده می‌کند (مثلاً "object.metadata.uid") و قالب fieldSelector ("metadata.uid") را به کار نمی‌برد. مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace hexStart و hexEnd رشته‌های literal در CEL هستند که داخل تک‌نقل‌قول قرار می‌گیرند و با پیشوند '0x' شروع می‌شوند. این دو، کران پایین شامل‌شونده و کران بالای شامل‌نشونده را بر فضای هش FNV-1a شصت‌وچهار بیتی تعیین می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که کران بالای شامل‌نشونده آن برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز دارد که feature gate با نام ShardedListAndWatch فعال شود.

sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های موجود در مجموعه را تولید کند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) به‌صورت `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق روال معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات آبجکت‌های تحت نظر (پس از RV) را ارسال می‌کند. وقتی گزینه `sendInitialEvents` تنظیم شده باشد، لازم است گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به این معنا تفسیر می‌شود: «داده‌ای که دست‌کم به تازگی `resourceVersion` ارائه‌شده باشد»، و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا یک `resourceVersion` به‌روزتر یا هم‌اندازه با مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ای که پردازش درخواست آغاز شده است همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی)، مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت shard selector مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر OR منطقی) برای تعیین یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشه object استفاده می‌کنند (مانند "object.metadata.uid") و از قالب fieldSelector (یعنی "metadata.uid") پیروی نمی‌کنند. مسیرهایی که در حال حاضر پشتیبانی می‌شوند: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های literal در CEL هستند که درون تک‌کوتیشن قرار می‌گیرند و پیشوند '0x' دارند؛ این دو، کران پایین (شامل) و کران بالا (غیرشامل) را در فضای hash ‏64 بیتی FNV-1a تعریف می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که کران بالای غیرشامل آن برابر 2^64 است. نمونه‌ها: تقسیم به دو shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به چهار shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و برای استفاده از آن باید feature gate با نام ShardedListAndWatch فعال شود.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را محدود می‌کند، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت.

allowWatchBookmarks boolean allowWatchBookmarks رویدادهای watch از نوع "BOOKMARK" را درخواست می‌کند. سرورهایی که bookmark را پیاده‌سازی نکرده‌اند می‌توانند این پرچم را نادیده بگیرند و ارسال bookmarkها به صلاحدید سرور است. کلاینت‌ها نباید فرض کنند که bookmarkها در بازه‌ای مشخص بازگردانده می‌شوند و همچنین نباید فرض کنند که سرور در طول یک نشست حتماً رویدادی از نوع BOOKMARK ارسال می‌کند. اگر درخواست از نوع watch نباشد، این فیلد نادیده گرفته می‌شود.
continue string هنگام دریافت نتایج بیشتر از سرور باید گزینه continue تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند مقدار continue را از نتیجهٔ یک پرس‌وجوی قبلی با پارامترهای یکسان (به‌جز مقدار خود continue) به کار ببرند و سرور ممکن است مقدار continue ناشناخته را رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به دلیل تغییر پیکربندی در سرور، سرور همراه با یک continue token با خطای 410 ResourceExpired پاسخ می‌دهد. اگر کلاینت به فهرستی سازگار نیاز دارد، باید فهرست‌گیری را بدون فیلد continue از ابتدا آغاز کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری با token دریافت‌شده همراه با خطای 410 ارسال کند؛ سرور با فهرستی پاسخ می‌دهد که از کلید بعدی شروع می‌شود، اما از جدیدترین snapshot گرفته شده است و با نتایج فهرست قبلی ناسازگار است. آبجکت‌هایی که پس از اولین درخواست فهرست ایجاد، ویرایش یا حذف شده‌اند، تا زمانی که کلیدشان پس از «کلید بعدی» باشد، در پاسخ گنجانده می‌شوند. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند watch را از آخرین مقدار resourceVersion بازگردانده‌شده توسط سرور آغاز کنند و هیچ تغییری را از دست ندهند.
fieldSelector string انتخابگری برای محدود کردن فهرست آبجکت‌های بازگردانده‌شده بر اساس فیلدهایشان. مقدار پیش‌فرض همه‌چیز را شامل می‌شود.
labelSelector string انتخابگری برای محدود کردن فهرست آبجکت‌های بازگردانده‌شده بر اساس برچسب‌هایشان. مقدار پیش‌فرض همه‌چیز را شامل می‌شود.
limit integer limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی فهرست بازمی‌گرداند. اگر موارد بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده‌های فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان پرس‌وجوی اولیه برای دریافت مجموعهٔ بعدی نتایج به کار برد. اگر همهٔ آبجکت‌های درخواست‌شده فیلتر شوند، تعیین limit ممکن است تعداد کمتری از موارد درخواستی (حتی صفر مورد) را بازگرداند و کلاینت‌ها برای تشخیص وجود نتایج بیشتر باید فقط به حضور فیلد continue تکیه کنند. سرورها می‌توانند آرگومان limit را پشتیبانی نکنند و در این صورت همهٔ نتایج موجود را بازمی‌گردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجهٔ دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند که آبجکت‌های بازگردانده‌شده هنگام استفاده از continue با آبجکت‌های یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور اولین درخواست ایجاد، ویرایش یا حذف شده باشد در درخواست‌های ادامهٔ بعدی گنجانده نمی‌شود. این وضعیت گاهی snapshot سازگار نامیده می‌شود و تضمین می‌کند کلاینتی که برای دریافت بخش‌های کوچک‌تر از یک نتیجهٔ بسیار بزرگ از limit استفاده می‌کند، همهٔ آبجکت‌های ممکن را مشاهده می‌کند. اگر آبجکت‌ها در طول فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبهٔ اولین نتیجهٔ فهرست وجود داشته است.
pretty string اگر مقدار 'true' باشد، خروجی به‌صورت خوانا (pretty printed) نمایش داده می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) را نشان دهد.
resourceVersion string resourceVersion محدودیتی تعیین می‌کند که یک درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
resourceVersionMatch string resourceVersionMatch تعیین می‌کند resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. به‌شدت توصیه می‌شود در فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
sendInitialEvents boolean `sendInitialEvents=true` را می‌توان همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های مجموعه را تولید می‌کنند. پس از ارسال همهٔ این رویدادها، یک رویداد "Bookmark" مصنوعی ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعهٔ آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای مربوط به تغییرات (پس از RV) آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینهٔ `sendInitialEvents` تنظیم شود، لازم است گزینهٔ `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این شرح است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به‌معنای «داده‌ای دست‌کم به‌روز بودن `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای همگام شده باشد که دست‌کم به تازگی مقدار ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت «خواندن سازگار» (consistent read) تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظهٔ شروع پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی)، مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با یک عبارت shard selector مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (عملگر منطقی OR) برای تعیین یک یا چند بازهٔ hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشهٔ object استفاده می‌کنند (برای نمونه "object.metadata.uid") و نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های literal در CEL و داخل تک‌کوتیشن با پیشوند '0x' هستند و کران پایین شمول‌پذیر (inclusive) و کران بالای شمول‌ناپذیر (exclusive) را در فضای hash ۶۴ بیتی FNV-1a تعیین می‌کنند. بازهٔ کامل [0x0, 0x10000000000000000) است که در آن کران بالای شمول‌ناپذیر برابر 2^64 است. نمونه‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و به فعال بودن feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را بدون توجه به فعالیت یا عدم فعالیت محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. resourceVersion را مشخص کنید.

force boolean Force درخواست‌های Apply را «اجباری» می‌کند؛ یعنی کاربر فیلدهای دارای تعارضی را که متعلق به دیگران است دوباره در اختیار می‌گیرد. پرچم Force برای درخواست‌های patch غیر از apply باید تنظیم نشده باشد.
