FlowSchema

FlowSchema طرح‌واره (schema) یک گروه از جریان‌ها را تعریف می‌کند. توجه داشته باشید که هر جریان (flow) از مجموعه‌ای از درخواست‌های API ورودی با ویژگی‌های مشابه تشکیل می‌شود و با یک جفت رشته مشخص می‌گردد: نام FlowSchema و یک «شناسه‌ی تمایز جریان» (flow distinguisher).

NonResourcePolicyRule {#NonResourcePolicyRule}

NonResourcePolicyRule گزاره‌ای (predicate) است که درخواست‌های غیرمنبعی را بر اساس فعل (verb) و URL غیرمنبعی هدف مطابقت می‌دهد. یک NonResourcePolicyRule با یک درخواست مطابقت دارد اگر و فقط اگر هر دو شرط برقرار باشند: (الف) دست‌کم یکی از اعضای verbs با درخواست مطابقت داشته باشد و (ب) دست‌کم یکی از اعضای nonResourceURLs با درخواست مطابقت داشته باشد.

FieldDescription
nonResourceURLs *
string array		 `nonResourceURLs` مجموعه‌ای از پیشوندهای URL است که کاربر باید به آن‌ها دسترسی داشته باشد و نمی‌تواند خالی باشد. برای مثال: - "/healthz" معتبر است - "/hea*" نامعتبر است - "/hea" معتبر است اما با هیچ چیزی مطابقت ندارد - "/hea/*" نیز با هیچ چیزی مطابقت ندارد - "/healthz/*" با همه‌ی بررسی‌های سلامت هر مؤلفه مطابقت دارد. "*" با همه‌ی URLهای غیرمنبعی مطابقت دارد. اگر وجود داشته باشد، باید تنها مدخل باشد. این فیلد الزامی است.
verbs *
string array		 `verbs` فهرستی از فعل‌های مطابق است و نمی‌تواند خالی باشد. "*" با همه‌ی فعل‌ها مطابقت دارد. اگر وجود داشته باشد، باید تنها مدخل باشد. این فیلد الزامی است.

PolicyRulesWithSubjects {#PolicyRulesWithSubjects}

PolicyRulesWithSubjects آزمونی را تجویز می‌کند که بر درخواستی به یک apiserver اعمال می‌شود. این آزمون سه مورد را در نظر می‌گیرد: subject ارسال‌کننده‌ی درخواست، فعل درخواست‌شده و منبعی که عملیات روی آن انجام می‌شود. این PolicyRulesWithSubjects با یک درخواست مطابقت دارد اگر و فقط اگر هر دو شرط برقرار باشند: (الف) دست‌کم یکی از اعضای subjects با درخواست مطابقت داشته باشد و (ب) دست‌کم یکی از اعضای resourceRules یا nonResourceRules با درخواست مطابقت داشته باشد.

FieldDescription
nonResourceRules
NonResourcePolicyRule array		 `nonResourceRules` فهرستی از NonResourcePolicyRuleها است که درخواست‌های مطابق را بر اساس فعل و URL غیرمنبعی هدف مشخص می‌کنند.
resourceRules
ResourcePolicyRule array		 `resourceRules` یک slice از ResourcePolicyRuleها است که درخواست‌های مطابق را بر اساس فعل و منبع هدف مشخص می‌کنند. دست‌کم یکی از `resourceRules` و `nonResourceRules` باید غیرخالی باشد.
subjects *
Subject array		 subjects فهرست کاربران عادی، serviceaccountها یا گروه‌هایی است که این قاعده به آن‌ها مربوط می‌شود. این slice باید دست‌کم یک عضو داشته باشد. اگر slice هم گروه کاربری system:authenticated و هم system:unauthenticated را شامل شود، با همه‌ی درخواست‌ها مطابقت خواهد داشت. این فیلد الزامی است.

ResourcePolicyRule {#ResourcePolicyRule}

ResourcePolicyRule گزاره‌ای است که برخی درخواست‌های منبعی را با بررسی فعل درخواست و منبع هدف مطابقت می‌دهد. یک ResourcePolicyRule با یک درخواست منبعی مطابقت دارد اگر و فقط اگر: (الف) دست‌کم یکی از اعضای verbs با درخواست مطابقت داشته باشد، (ب) دست‌کم یکی از اعضای apiGroups با درخواست مطابقت داشته باشد، (ج) دست‌کم یکی از اعضای resources با درخواست مطابقت داشته باشد، و (د) یا (د۱) درخواست فضای نام مشخص نکرده باشد (یعنی Namespace=="") و clusterScope برابر true باشد، یا (د۲) درخواست یک فضای نام مشخص کرده باشد و دست‌کم یکی از اعضای namespaces با فضای نام درخواست مطابقت داشته باشد.

FieldDescription
apiGroups *
string array		 `apiGroups` فهرستی از گروه‌های API مطابق است و نمی‌تواند خالی باشد. "*" با همه‌ی گروه‌های API مطابقت دارد و اگر وجود داشته باشد، باید تنها مدخل باشد. این فیلد الزامی است.
clusterScope
boolean		 `clusterScope` مشخص می‌کند آیا با درخواست‌هایی که فضای نام مشخص نمی‌کنند مطابقت داده شود یا نه (این حالت یا به این دلیل رخ می‌دهد که منبع فضای نام ندارد، یا به این دلیل که درخواست همه‌ی فضاهای نام را هدف قرار داده است). اگر این فیلد حذف شود یا false باشد، فیلد `namespaces` باید فهرستی غیرخالی داشته باشد.
namespaces
string array		 `namespaces` فهرستی از فضاهای نام هدف است که مطابقت را محدود می‌کند. درخواستی که یک فضای نام هدف مشخص می‌کند، فقط در صورتی مطابقت دارد که (الف) این فهرست شامل آن فضای نام هدف باشد یا (ب) این فهرست شامل "*" باشد. توجه داشته باشید که "*" با هر فضای نام مشخص‌شده مطابقت دارد، اما با درخواستی که فضای نام را _مشخص نمی‌کند_ مطابقت ندارد (برای آن حالت به فیلد `clusterScope` مراجعه کنید). این فهرست فقط در صورتی می‌تواند خالی باشد که `clusterScope` برابر true باشد.
resources *
string array		 `resources` فهرستی از منابع مطابق است (یعنی با حروف کوچک و به‌صورت جمع) که در صورت نیاز می‌تواند زیرمنبع (subresource) نیز داشته باشد. برای مثال: [ "services", "nodes/status" ]. این فهرست نمی‌تواند خالی باشد. "*" با همه‌ی منابع مطابقت دارد و اگر وجود داشته باشد، باید تنها مدخل باشد. این فیلد الزامی است.
verbs *
string array		 `verbs` فهرستی از فعل‌های مطابق است و نمی‌تواند خالی باشد. "*" با همه‌ی فعل‌ها مطابقت دارد و اگر وجود داشته باشد، باید تنها مدخل باشد. این فیلد الزامی است.

resourceVersion string resourceVersion محدودیتی را برای نسخه‌های منبعی تعیین می‌کند که یک درخواست می‌تواند از روی آن‌ها پاسخ داده شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
resourceVersionMatch string resourceVersionMatch تعیین می‌کند resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. به‌شدت توصیه می‌شود برای فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های موجود در مجموعه را تولید کند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) آبجکت‌های تحت نظارت را ارسال می‌کند. هنگامی که گزینه `sendInitialEvents` تنظیم شود، لازم است گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به‌معنای «داده‌هایی دست‌کم به‌روز مانند `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای دست‌کم به‌تازگی مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌معنای «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه شروع پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) مقدار پیش‌فرض true است، و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگشتی را با استفاده از یک عبارت shard selector مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() به‌همراه || (OR منطقی) برای تعیین یک یا چند بازه هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو مبتنی بر ریشه آبجکت به سبک CEL (مثلاً "object.metadata.uid") استفاده می‌کند، نه قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده فعلی: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های literal تک‌نقل‌قولی CEL با پیشوند '0x' هستند و به‌ترتیب کران پایین (شامل) و کران بالا (غیرشامل) را در فضای هش 64 بیتی FNV-1a تعریف می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که کران بالای غیرشامل آن برابر 2^64 است. مثال‌ها: تقسیم به 2 shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به 4 shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز به فعال‌سازی feature gate با نام ShardedListAndWatch دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را، بدون توجه به فعالیت یا عدم فعالیت، محدود می‌کند.

continue string هنگام دریافت نتایج بیشتر از سرور باید گزینه‌ی continue تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند از مقدار continue حاصل از نتیجه‌ی یک کوئری قبلی با پارامترهای کوئری یکسان (به‌جز مقدار خود continue) استفاده کنند و سرور ممکن است مقداری از continue را که نمی‌شناسد رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به دلیل تغییر پیکربندی در سرور، سرور همراه با یک توکن continue با خطای 410 ResourceExpired پاسخ می‌دهد. اگر کلاینت به یک فهرست سازگار نیاز دارد، باید فهرست‌گیری را بدون فیلد continue از نو آغاز کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری با توکن دریافتی همراه با خطای 410 ارسال کند؛ سرور با فهرستی پاسخ می‌دهد که از کلید بعدی شروع می‌شود، اما از جدیدترین snapshot گرفته شده است و با نتایج فهرست قبلی ناسازگار است: آبجکت‌هایی که پس از اولین درخواست فهرست ایجاد، تغییر یا حذف شده‌اند، تا زمانی که کلیدشان پس از «کلید بعدی» باشد، در پاسخ گنجانده می‌شوند. این فیلد در زمانی که watch برابر true باشد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند یک watch را از آخرین مقدار resourceVersion بازگردانده‌شده توسط سرور آغاز کنند و هیچ تغییری را از دست ندهند.

continue string گزینه continue باید هنگام دریافت نتایج بیشتر از سرور تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند مقدار continue حاصل از نتیجه یک پرس‌وجوی قبلی را با پارامترهای پرس‌وجوی یکسان (به‌جز مقدار continue) استفاده کنند و سرور می‌تواند مقداری از continue را که نمی‌شناسد رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به دلیل تغییر پیکربندی در سرور، سرور با خطای 410 ResourceExpired و همراه با یک توکن continue پاسخ می‌دهد. اگر کلاینت به یک فهرست سازگار نیاز دارد، باید فهرست‌کردن را بدون فیلد continue از ابتدا آغاز کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری را با توکن دریافت‌شده همراه با خطای 410 ارسال کند؛ در این حالت سرور با فهرستی پاسخ می‌دهد که از کلید بعدی شروع می‌شود، اما از جدیدترین snapshot گرفته شده است و با نتایج فهرست قبلی ناسازگار است؛ آبجکت‌هایی که پس از درخواست اول فهرست ایجاد، تغییر یا حذف شده‌اند، تا زمانی که کلیدهایشان پس از «کلید بعدی» باشد، در پاسخ گنجانده می‌شوند. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند یک watch را از آخرین مقدار resourceVersion بازگردانده‌شده توسط سرور آغاز کنند و هیچ تغییری را از دست ندهند.
fieldSelector string یک انتخابگر (selector) برای محدودکردن فهرست آبجکت‌های بازگردانده‌شده بر اساس فیلدهای آن‌ها. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
labelSelector string یک انتخابگر برای محدودکردن فهرست آبجکت‌های بازگردانده‌شده بر اساس برچسب‌های آن‌ها. مقدار پیش‌فرض همه آبجکت‌ها را شامل می‌شود.
limit integer limit حداکثر تعداد پاسخ‌هایی است که در یک فراخوانی فهرست بازگردانده می‌شود. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراپیوند (metadata) فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان پرس‌وجوی اولیه برای دریافت مجموعه بعدی نتایج به کار برد. در صورتی که همه آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است کمتر از تعداد درخواست‌شده آیتم (حتی صفر آیتم) بازگرداند و کلاینت‌ها برای تشخیص وجود نتایج بیشتر فقط باید به وجود فیلد continue تکیه کنند. سرورها می‌توانند آرگومان limit را پشتیبانی نکنند و در این حالت همه نتایج موجود را بازمی‌گردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه دیگری وجود ندارد. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند که آبجکت‌های بازگردانده‌شده هنگام استفاده از continue با آبجکت‌های یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور درخواست اول ایجاد، تغییر یا حذف شده باشد در درخواست‌های بعدیِ ادامه‌دار گنجانده نمی‌شود. این رفتار گاهی «snapshot سازگار» نامیده می‌شود و تضمین می‌کند کلاینتی که برای دریافت بخش‌های کوچک‌تر از یک نتیجه بسیار بزرگ از limit استفاده می‌کند، همه آبجکت‌های ممکن را می‌بیند. اگر آبجکت‌ها در حین فهرست‌کردن بخش‌به‌بخش به‌روزرسانی شوند، نسخه‌ای از آبجکت که در زمان محاسبه نتیجه اول فهرست وجود داشته است بازگردانده می‌شود.
pretty string اگر 'true' باشد، خروجی به‌صورت خوانا (pretty print) نمایش داده می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent نشان دهد که درخواست از یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) ارسال شده است.
resourceVersion string resourceVersion محدودیتی تعیین می‌کند که یک درخواست از چه نسخه‌های منبعی می‌تواند پاسخ داده شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
resourceVersionMatch string resourceVersionMatch مشخص می‌کند resourceVersion چگونه در فراخوانی‌های فهرست اعمال شود. به‌شدت توصیه می‌شود برای فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض تنظیم‌نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های موجود در مجموعه را تولید می‌کنند. پس از ارسال همه این رویدادها، یک رویداد "Bookmark" مصنوعی ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق روال معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینه `sendInitialEvents` تنظیم شده باشد، گزینه `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به معنای «داده‌ای که دست‌کم به‌اندازه `resourceVersion` ارائه‌شده جدید باشد» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای همگام شده باشد که دست‌کم به‌اندازه مقدار ارائه‌شده در ListOptions تازه است. اگر `resourceVersion` تنظیم نشده باشد، این حالت «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ای که پردازش درخواست آغاز شده است همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) مقدار پیش‌فرض true است و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() به‌همراه || (عملگر OR منطقی) برای مشخص‌کردن یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشه object استفاده می‌کند (مثلاً "object.metadata.uid") و نه از قالب fieldSelector (یعنی "metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های literal در CEL هستند که درون تک‌نقل‌قول قرار می‌گیرند، پیشوند '0x' دارند و کران پایین (شامل) و کران بالا (غیرشامل) را در فضای hash ‏64 بیتی FNV-1a تعریف می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز به فعال‌سازی feature gate با نام ShardedListAndWatch دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. resourceVersion را مشخص کنید.

- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد true است (به‌دلایل سازگاری با نسخه‌های قبلی) و در غیر این صورت false است.
shardSelector string shardSelector فهرست آبجکت‌های برگردانده‌شده را با یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() به‌همراه || (عملگر OR منطقی) برای مشخص کردن یک یا چند بازه hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو شیءمحور CEL (مثلاً "object.metadata.uid") استفاده می‌کنند، نه قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده فعلی: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های لفظی CEL داخل تک‌نقل‌قول و با پیشوند '0x' هستند و به‌ترتیب کران پایین (شامل) و کران بالا (غیرشامل) را در فضای hash ۶۴ بیتی FNV-1a تعیین می‌کنند. بازه کامل [0x0, 0x10000000000000000) است که کران بالای غیرشامل آن برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این فیلد آلفا است و نیاز به فعال‌سازی feature gate با نام ShardedListAndWatch دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را بدون توجه به وجود یا نبود هرگونه فعالیت محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف برمی‌گرداند. resourceVersion را مشخص کنید.

force boolean Force درخواست‌های Apply را «اجباری» می‌کند. این یعنی کاربر مالکیت فیلدهای دارای تعارض را که متعلق به دیگران است دوباره به دست می‌آورد. برای درخواست‌های patch غیر از apply، پرچم force باید تنظیم نشده باشد.
