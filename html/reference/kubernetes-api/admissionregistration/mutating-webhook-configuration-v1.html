MutatingWebhook {#MutatingWebhook}

آبجکت MutatingWebhook یک وب‌هوک پذیرش و منابع و عملیاتی را که این وب‌هوک بر آن‌ها اعمال می‌شود توصیف می‌کند.

فیلدتوضیحات
admissionReviewVersions *
string array		 فیلد admissionReviewVersions فهرستی مرتب از نسخه‌های ترجیحی `AdmissionReview` است که وب‌هوک انتظار دارد. سرور API تلاش می‌کند نخستین نسخه‌ای از این فهرست را که پشتیبانی می‌کند به کار ببرد. اگر سرور API از هیچ‌یک از نسخه‌های مشخص‌شده در این فهرست پشتیبانی نکند، اعتبارسنجی این آبجکت ناموفق خواهد بود. اگر یک پیکربندی وب‌هوکِ ذخیره‌شده نسخه‌های مجاز را مشخص کند اما هیچ نسخه‌ای را که برای سرور API شناخته‌شده است در بر نگیرد، فراخوانی‌های وب‌هوک ناموفق خواهند بود و تابع سیاست شکست (failure policy) قرار می‌گیرند.
clientConfig *
WebhookClientConfig		 فیلد clientConfig نحوهٔ ارتباط با هوک را تعریف می‌کند. الزامی است.
failurePolicy
string		 فیلد failurePolicy تعیین می‌کند خطاهای ناشناخته‌ای که از نقطهٔ پایانی پذیرش دریافت می‌شوند چگونه مدیریت شوند؛ مقادیر مجاز Ignore یا Fail هستند. مقدار پیش‌فرض Fail است.

مقادیر ممکن enum:
- مقدار `"Fail"` به این معناست که بروز خطا در فراخوانی وب‌هوک باعث شکست پذیرش می‌شود.
- مقدار `"Ignore"` به این معناست که خطای فراخوانی وب‌هوک نادیده گرفته می‌شود.
matchConditions
MatchCondition array
راهبرد patch: ادغام بر اساس کلید name		 فیلد matchConditions فهرستی از شرط‌هایی است که برای ارسال یک درخواست به این وب‌هوک باید برقرار باشند. شرط‌های تطبیق، درخواست‌هایی را فیلتر می‌کنند که پیش‌تر با rules، namespaceSelector و objectSelector تطبیق یافته‌اند. فهرست خالیِ matchConditions با همهٔ درخواست‌ها تطبیق دارد. حداکثر ۶۴ شرط تطبیق مجاز است. منطق دقیق تطبیق (به ترتیب) چنین است: ۱. اگر حتی یکی از شرط‌های matchCondition به FALSE ارزیابی شود، از وب‌هوک صرف‌نظر می‌شود. ۲. اگر همهٔ شرط‌های matchCondition به TRUE ارزیابی شوند، وب‌هوک فراخوانی می‌شود. ۳. اگر ارزیابی یکی از شرط‌ها به خطا منجر شود (اما هیچ‌کدام FALSE نباشد): - اگر failurePolicy=Fail باشد، درخواست رد می‌شود - اگر failurePolicy=Ignore باشد، خطا نادیده گرفته می‌شود و از وب‌هوک صرف‌نظر می‌شود
matchPolicy
string		 فیلد matchPolicy تعیین می‌کند فهرست "rules" چگونه برای تطبیق درخواست‌های ورودی به کار رود. مقادیر مجاز "Exact" یا "Equivalent" هستند. - مقدار Exact: درخواست فقط زمانی تطبیق می‌یابد که دقیقاً با یکی از قوانین مشخص‌شده منطبق باشد. برای نمونه، اگر Deploymentها را بتوان از طریق apps/v1، apps/v1beta1 و extensions/v1beta1 تغییر داد، اما "rules" فقط شامل `apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"]` باشد، درخواستی که به apps/v1beta1 یا extensions/v1beta1 ارسال شود به وب‌هوک فرستاده نمی‌شود. - مقدار Equivalent: درخواست زمانی تطبیق می‌یابد که منبعی فهرست‌شده در rules را تغییر دهد، حتی اگر این کار از طریق گروه یا نسخهٔ دیگری از API انجام شود. برای نمونه، اگر Deploymentها را بتوان از طریق apps/v1، apps/v1beta1 و extensions/v1beta1 تغییر داد و "rules" فقط شامل `apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"]` باشد، درخواستی که به apps/v1beta1 یا extensions/v1beta1 ارسال شود به apps/v1 تبدیل و به وب‌هوک فرستاده می‌شود. مقدار پیش‌فرض "Equivalent" است.

مقادیر ممکن enum:
- مقدار `"Equivalent"` به این معناست که اگر درخواست‌ها منبعی فهرست‌شده در rules را از طریق گروه یا نسخهٔ دیگری از API تغییر دهند، باید به وب‌هوک فرستاده شوند.
- مقدار `"Exact"` به این معناست که درخواست‌ها فقط در صورتی باید به وب‌هوک فرستاده شوند که دقیقاً با یکی از قوانین مشخص‌شده منطبق باشند.
name *
string		 فیلد name نام وب‌هوک پذیرش است. نام باید کاملاً مشخص (fully qualified) باشد؛ برای نمونه imagepolicy.kubernetes.io که در آن "imagepolicy" نام وب‌هوک و kubernetes.io نام سازمان است. الزامی است.
namespaceSelector
LabelSelector		 فیلد namespaceSelector بر اساس اینکه فضای نام (namespace) آبجکت با انتخابگر (selector) تطبیق دارد یا نه، تعیین می‌کند که وب‌هوک روی آن آبجکت اجرا شود یا خیر. اگر خود آبجکت یک فضای نام باشد، تطبیق روی object.metadata.labels انجام می‌شود. اگر آبجکت منبع دیگری با دامنهٔ کلاستر باشد، هرگز از وب‌هوک صرف‌نظر نمی‌شود. برای نمونه، برای اجرای وب‌هوک روی هر آبجکتی که فضای نام آن با "runlevel" برابر "0" یا "1" مرتبط نیست، انتخابگر را به این صورت تنظیم می‌کنید: "namespaceSelector": { "matchExpressions": [ { "key": "runlevel", "operator": "NotIn", "values": [ "0", "1" ] } ] } اگر در عوض بخواهید وب‌هوک فقط روی آبجکت‌هایی اجرا شود که فضای نام آن‌ها با "environment" برابر "prod" یا "staging" مرتبط است، انتخابگر را به این صورت تنظیم می‌کنید: "namespaceSelector": { "matchExpressions": [ { "key": "environment", "operator": "In", "values": [ "prod", "staging" ] } ] } برای مشاهدهٔ نمونه‌های بیشتر از انتخابگرهای برچسب به https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/ مراجعه کنید. مقدار پیش‌فرض، یک LabelSelector خالی است که با همه چیز تطبیق دارد.
objectSelector
LabelSelector		 فیلد objectSelector بر اساس اینکه آبجکت برچسب‌های منطبق دارد یا نه، تعیین می‌کند که وب‌هوک اجرا شود یا خیر. این انتخابگر هم روی oldObject و هم روی newObject که قرار است به وب‌هوک ارسال شوند ارزیابی می‌شود و اگر هر یک از این دو آبجکت با انتخابگر تطبیق داشته باشد، منطبق در نظر گرفته می‌شود. آبجکت null (یعنی oldObject در حالت ایجاد یا newObject در حالت حذف) یا آبجکتی که نمی‌تواند برچسب داشته باشد (مانند آبجکت DeploymentRollback یا PodProxyOptions) منطبق در نظر گرفته نمی‌شود. از انتخابگر آبجکت فقط زمانی استفاده کنید که استفاده از وب‌هوک اختیاری (opt-in) باشد، زیرا کاربران نهایی می‌توانند با تنظیم برچسب‌ها از وب‌هوک پذیرش عبور کنند. مقدار پیش‌فرض، یک LabelSelector خالی است که با همه چیز تطبیق دارد.
reinvocationPolicy
string		 فیلد reinvocationPolicy نشان می‌دهد که آیا این وب‌هوک باید در جریان یک ارزیابی پذیرش واحد چند بار فراخوانی شود یا نه. مقادیر مجاز "Never" و "IfNeeded" هستند. مقدار Never: وب‌هوک در یک ارزیابی پذیرش واحد بیش از یک بار فراخوانی نمی‌شود. مقدار IfNeeded: اگر آبجکتِ در حال پذیرش پس از نخستین فراخوانی وب‌هوک به‌وسیلهٔ افزونه‌های پذیرش دیگر تغییر کند، وب‌هوک دست‌کم یک بار دیگر در جریان ارزیابی پذیرش فراخوانی می‌شود. وب‌هوک‌هایی که این گزینه را مشخص می‌کنند *باید* idempotent باشند و بتوانند آبجکت‌هایی را که پیش‌تر پذیرفته‌اند پردازش کنند. نکته: * تضمینی وجود ندارد که تعداد فراخوانی‌های اضافی دقیقاً یک بار باشد. * اگر فراخوانی‌های اضافی به تغییرات بیشتری در آبجکت منجر شوند، تضمینی برای فراخوانی دوبارهٔ وب‌هوک‌ها وجود ندارد. * ممکن است ترتیب وب‌هوک‌هایی که از این گزینه استفاده می‌کنند تغییر کند تا تعداد فراخوانی‌های اضافی به حداقل برسد. * برای اعتبارسنجی آبجکت پس از آنکه اطمینان حاصل شد همهٔ تغییرات کامل شده‌اند، به جای این گزینه از یک وب‌هوک پذیرشِ اعتبارسنج (validating admission webhook) استفاده کنید. مقدار پیش‌فرض "Never" است.

مقادیر ممکن enum:
- مقدار `"IfNeeded"` نشان می‌دهد که اگر آبجکتِ در حال پذیرش پس از نخستین فراخوانی تغییر به‌وسیلهٔ افزونه‌های پذیرش دیگر تغییر کند، تغییر ممکن است دست‌کم یک بار دیگر در جریان ارزیابی پذیرش فراخوانی شود.
- مقدار `"Never"` نشان می‌دهد که تغییر نباید در یک ارزیابی پذیرش واحد بیش از یک بار فراخوانی شود.
rules
RuleWithOperations array		 فیلد rules توصیف می‌کند که وب‌هوک به کدام عملیات روی کدام منابع یا زیرمنابع توجه دارد. وب‌هوک به عملیاتی توجه می‌کند که با _هر یک_ از قوانین (Rule) تطبیق داشته باشد. با این حال، برای جلوگیری از اینکه ValidatingAdmissionWebhooks و MutatingAdmissionWebhooks کلاستر را در وضعیتی قرار دهند که بدون غیرفعال‌کردن کامل افزونه قابل بازیابی نباشد، این وب‌هوک‌ها هرگز برای درخواست‌های پذیرشِ مربوط به آبجکت‌های ValidatingWebhookConfiguration و MutatingWebhookConfiguration فراخوانی نمی‌شوند.
sideEffects *
string		 فیلد sideEffects مشخص می‌کند که آیا این وب‌هوک اثر جانبی دارد یا نه. مقادیر قابل قبول None و NoneOnDryRun هستند (وب‌هوک‌هایی که از طریق v1beta1 ایجاد شده‌اند می‌توانند Some یا Unknown را نیز مشخص کنند). وب‌هوک‌هایی که اثر جانبی دارند *باید* یک سازوکار تطبیق‌دهی (reconciliation) پیاده‌سازی کنند، زیرا ممکن است درخواست در مرحله‌ای بعدی از زنجیرهٔ پذیرش رد شود و در نتیجه لازم باشد اثرهای جانبی بازگردانده شوند. درخواست‌هایی که ویژگی dryRun دارند، اگر با وب‌هوکی با sideEffects == Unknown یا Some تطبیق یابند، به‌طور خودکار رد می‌شوند.

مقادیر ممکن enum:
- مقدار `"None"` به این معناست که فراخوانی وب‌هوک هیچ اثر جانبی ندارد.
- مقدار `"NoneOnDryRun"` به این معناست که فراخوانی وب‌هوک ممکن است اثر جانبی داشته باشد، اما اگر درخواستِ در حال بررسی ویژگی dry-run را داشته باشد، اثرهای جانبی سرکوب می‌شوند.
- مقدار `"Some"` به این معناست که فراخوانی وب‌هوک ممکن است اثر جانبی داشته باشد. اگر درخواستی با ویژگی dry-run باعث فراخوانی این وب‌هوک شود، آن درخواست به جای آن ناموفق خواهد بود.
- مقدار `"Unknown"` به این معناست که هیچ اطلاعاتی دربارهٔ اثرهای جانبی فراخوانی وب‌هوک در دست نیست. اگر درخواستی با ویژگی dry-run باعث فراخوانی این وب‌هوک شود، آن درخواست به جای آن ناموفق خواهد بود.
timeoutSeconds
integer		 فیلد timeoutSeconds مهلت زمانی این وب‌هوک را مشخص می‌کند. پس از سپری‌شدن این مهلت، بسته به سیاست شکست، فراخوانی وب‌هوک نادیده گرفته می‌شود یا فراخوانی API ناموفق خواهد بود. مقدار مهلت باید بین ۱ تا ۳۰ ثانیه باشد. مقدار پیش‌فرض ۱۰ ثانیه است.

limit integer فیلد limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی list برمی‌گرداند. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده‌ی فهرست روی مقداری تنظیم می‌کند که می‌توان آن را همراه با همان کوئری اولیه برای دریافت مجموعه‌ی بعدی نتایج به کار برد. اگر همه‌ی آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است تعدادی کمتر از آیتم‌های درخواست‌شده (تا صفر آیتم) برگرداند؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص اینکه نتایج بیشتری در دسترس است یا نه استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و همه‌ی نتایج موجود را برگردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه‌ی دیگری در دسترس نیست. وقتی watch برابر true باشد، این فیلد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجه‌ی یک فراخوانی list واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از ارسال نخستین درخواست ایجاد، تغییر یا حذف شده است، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. به این ویژگی گاهی snapshot سازگار گفته می‌شود و تضمین می‌کند کلاینتی که از limit برای دریافت بخش‌های کوچک‌تری از یک نتیجه‌ی بسیار بزرگ استفاده می‌کند، همه‌ی آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در طول یک فهرست‌گیری بخش‌بندی‌شده به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبه‌ی نخستین نتیجه‌ی فهرست وجود داشته است.
orphanDependents boolean منسوخ‌شده: لطفاً از PropagationPolicy استفاده کنید؛ این فیلد در نسخه‌ی 1.7 منسوخ خواهد شد. تعیین می‌کند که آیا آبجکت‌های وابسته باید یتیم (orphan) شوند یا نه. اگر true/false باشد، finalizer «orphan» به فهرست finalizerهای آبجکت افزوده/از آن حذف می‌شود. می‌توان یا این فیلد یا PropagationPolicy را تنظیم کرد، اما نه هر دو را.
propagationPolicy string تعیین می‌کند که آیا جمع‌آوری زباله (garbage collection) انجام شود و چگونه. می‌توان یا این فیلد یا OrphanDependents را تنظیم کرد، اما نه هر دو را. سیاست پیش‌فرض بر اساس finalizer موجود در metadata.finalizers و سیاست پیش‌فرض مختص منبع تعیین می‌شود. مقادیر قابل قبول عبارت‌اند از: 'Orphan' - وابسته‌ها را یتیم می‌کند؛ 'Background' - به garbage collector اجازه می‌دهد وابسته‌ها را در پس‌زمینه حذف کند؛ 'Foreground' - سیاستی آبشاری که همه‌ی وابسته‌ها را در پیش‌زمینه حذف می‌کند.
resourceVersion string فیلد resourceVersion محدودیتی تعیین می‌کند که درخواست را می‌توان از کدام نسخه‌های منبع پاسخ داد. برای جزئیات، https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions را ببینید. مقدار پیش‌فرض: تنظیم‌نشده
resourceVersionMatch string فیلد resourceVersionMatch تعیین می‌کند که resourceVersion چگونه روی فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های list که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات، https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions را ببینید. مقدار پیش‌فرض: تنظیم‌نشده
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همه‌ی این رویدادها، یک رویداد مصنوعی «Bookmark» ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه‌ی آبجکت‌ها را گزارش می‌دهد و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق روال عادی ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینه‌ی `sendInitialEvents` تنظیم شده باشد، لازم است گزینه‌ی `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این صورت است:
- مقدار `resourceVersionMatch` = NotOlderThan به معنای «داده‌ای دست‌کم به تازگی `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت تا `resourceVersion`ای همگام شده باشد که دست‌کم به تازگی مقدار ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت به معنای «خواندن سازگار» (consistent read) تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ی آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شود یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد، مقدار پیش‌فرض true است (به دلایل سازگاری با نسخه‌های قبلی) و در غیر این صورت false است.
shardSelector string فیلد shardSelector فهرست آبجکت‌های بازگردانده‌شده را با یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. در این قالب، تابع shardRange() همراه با || (یای منطقی) برای مشخص کردن یک یا چند بازه‌ی هش به کار می‌رود: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو ریشه‌دار در object به سبک CEL استفاده می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر عبارت‌اند از: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون نقل‌قول تکی با پیشوند '0x' هستند و کران پایین (شامل) و کران بالای (غیرشامل) را روی فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازه‌ی کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی (timeout) برای فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.

sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این صورت، جریان watch با رویدادهای مصنوعی آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همه‌ی این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه‌ی آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به روال معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینه‌ی `sendInitialEvents` تنظیم شده باشد، گزینه‌ی `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به شرح زیر است:
- اگر `resourceVersionMatch` = NotOlderThan باشد، به‌صورت «داده‌هایی دست‌کم به جدیدیِ `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت تا یک `resourceVersion` دست‌کم به تازگیِ مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، به‌صورت «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ی آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. اگر `resourceVersion=""` یا `resourceVersion="0"` باشد، مقدار پیش‌فرض true است (به دلایل سازگاری با نسخه‌های قبلی) و در غیر این صورت false است.
shardSelector string پارامتر shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. در این قالب، تابع shardRange() همراه با || (OR منطقی) برای مشخص کردن یک یا چند بازه‌ی هش به کار می‌رود: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشه‌ی object پیروی می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های لفظی CEL درون نقل‌قول تکی با پیشوند '0x' هستند و کران پایین (شامل) و کران بالا (غیرشامل) را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازه‌ی کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و برای استفاده از آن باید feature gate با نام ShardedListAndWatch را فعال کنید.
timeoutSeconds integer مهلت زمانی برای فراخوانی list/watch. این مقدار، مدت فراخوانی را صرف‌نظر از وجود یا نبود فعالیت محدود می‌کند.

limit integer فیلد limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی list بازمی‌گرداند. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در فراداده‌ی فهرست با مقداری پر می‌کند که می‌توان از آن همراه با همان کوئری اولیه برای دریافت مجموعه‌ی بعدی نتایج استفاده کرد. اگر همه‌ی آبجکت‌های درخواست‌شده فیلتر شوند، تعیین limit ممکن است به بازگرداندن تعدادی کمتر از آیتم‌های درخواست‌شده (حتی صفر آیتم) منجر شود؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص در دسترس بودن نتایج بیشتر استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و همه‌ی نتایج موجود را بازگردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه‌ی دیگری در دسترس نیست. وقتی watch برابر true باشد، از این فیلد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجه‌ی یک فراخوانی list واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور نخستین درخواست ایجاد، تغییر یا حذف شده است، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. به این حالت گاهی snapshot سازگار (consistent snapshot) گفته می‌شود، و تضمین می‌کند کلاینتی که از limit برای دریافت بخش‌های کوچک‌تر یک نتیجه‌ی بسیار بزرگ استفاده می‌کند، همه‌ی آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در حین دریافت بخش‌بخش فهرست به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبه‌ی نخستین نتیجه‌ی فهرست وجود داشته است.
pretty string اگر مقدار آن 'true' باشد، خروجی به‌صورت خوانا و قالب‌بندی‌شده چاپ می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent نشان دهد درخواست از یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) ارسال شده است.
resourceVersion string فیلد resourceVersion محدودیتی تعیین می‌کند که درخواست را می‌توان از کدام نسخه‌های منبع پاسخ داد. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
resourceVersionMatch string فیلد resourceVersionMatch تعیین می‌کند که resourceVersion چگونه روی فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های list که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این صورت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همه‌ی این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه‌ی آبجکت‌ها را گزارش می‌دهد و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به روال معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینه‌ی `sendInitialEvents` تنظیم شده باشد، گزینه‌ی `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به این صورت است:
- مقدار `resourceVersionMatch` = NotOlderThan به‌صورت «داده‌ای دست‌کم به تازگی `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت تا یک `resourceVersion` دست‌کم به تازگی مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌صورت «خواندن سازگار» (consistent read) تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ی آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) true و در غیر این صورت false است.
shardSelector string فیلد shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. این قالب از تابع shardRange() همراه با || (OR منطقی) برای مشخص کردن یک یا چند بازه‌ی هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشه‌ی object استفاده می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهایی که در حال حاضر پشتیبانی می‌شوند: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون نقل‌قول تکی و با پیشوند '0x' هستند که کران پایینِ شامل و کران بالای غیرشامل را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازه‌ی کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی (timeout) برای فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از وجود یا نبود فعالیت، محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. مقدار resourceVersion را مشخص کنید.
