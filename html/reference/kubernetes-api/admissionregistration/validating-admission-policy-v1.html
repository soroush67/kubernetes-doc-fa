فیلدتوضیحات
auditAnnotations
AuditAnnotation array		 فیلد auditAnnotations شامل عبارت‌های CEL است که برای تولید حاشیه‌نویسی‌های ممیزی (audit annotations) در رویداد ممیزی درخواست API به کار می‌روند. فیلدهای validations و auditAnnotations نمی‌توانند هر دو خالی باشند؛ وجود دست‌کم یکی از آن‌ها الزامی است.
failurePolicy
string		 فیلد failurePolicy نحوهٔ رسیدگی به خطاها را در سیاست پذیرش تعریف می‌کند. خطاها ممکن است ناشی از خطاهای تجزیهٔ عبارت CEL، خطاهای بررسی نوع، خطاهای زمان اجرا، و تعریف‌ها یا اتصال‌های (bindings) نامعتبر یا نادرست پیکربندی‌شدهٔ سیاست باشند. یک سیاست زمانی نامعتبر است که spec.paramKind به یک Kind ناموجود اشاره کند. یک اتصال زمانی نامعتبر است که spec.paramRef.name به منبعی ناموجود اشاره کند. فیلد failurePolicy تعیین نمی‌کند که با اعتبارسنجی‌هایی که حاصل ارزیابی‌شان false است چگونه رفتار شود. وقتی failurePolicy روی Fail تنظیم شده باشد، فیلد validationActions در ValidatingAdmissionPolicyBinding نحوهٔ اعمال خطاها را تعیین می‌کند. مقادیر مجاز Ignore یا Fail هستند. مقدار پیش‌فرض Fail است.

مقادیر ممکن enum:
- مقدار `"Fail"` به این معناست که خطا در فراخوانی وب‌هوک (webhook) باعث شکست پذیرش می‌شود.
- مقدار `"Ignore"` به این معناست که خطا در فراخوانی وب‌هوک نادیده گرفته می‌شود.
matchConditions
MatchCondition array
راهبرد وصله (patch strategy): ادغام بر اساس کلید name		 فیلد matchConditions فهرستی از شرط‌هایی است که برای اعتبارسنجی یک درخواست باید برقرار باشند. شرط‌های تطبیق، درخواست‌هایی را پالایش می‌کنند که پیش‌تر با rules، namespaceSelector و objectSelector تطبیق یافته‌اند. فهرست خالی matchConditions با همهٔ درخواست‌ها تطبیق می‌یابد. حداکثر ۶۴ شرط تطبیق مجاز است. اگر آبجکت پارامتری ارائه شده باشد، می‌توان مانند عبارت‌های اعتبارسنجی، از طریق دستگیرهٔ `params` به آن دسترسی داشت. منطق دقیق تطبیق به ترتیب زیر است: ۱. اگر حاصل ارزیابی هر یک از matchConditionها FALSE باشد، از سیاست صرف‌نظر می‌شود. ۲. اگر حاصل ارزیابی همهٔ matchConditionها TRUE باشد، سیاست ارزیابی می‌شود. ۳. اگر ارزیابی هر یک از matchConditionها به خطا منجر شود (ولی حاصل هیچ‌کدام FALSE نباشد): - اگر failurePolicy=Fail باشد، درخواست رد می‌شود - اگر failurePolicy=Ignore باشد، از سیاست صرف‌نظر می‌شود
matchConstraints
MatchResources		 فیلد matchConstraints مشخص می‌کند که این سیاست برای اعتبارسنجی چه منابعی طراحی شده است. آبجکت AdmissionPolicy تنها زمانی به یک درخواست رسیدگی می‌کند که آن درخواست با _همهٔ_ قیدها (Constraints) تطبیق داشته باشد. با این حال، برای جلوگیری از قرار گرفتن کلاسترها در وضعیتی ناپایدار که نتوان آن را از طریق API بازیابی کرد، ValidatingAdmissionPolicy نمی‌تواند با ValidatingAdmissionPolicy و ValidatingAdmissionPolicyBinding تطبیق یابد. این فیلد الزامی است.
paramKind
ParamKind		 فیلد paramKind نوع منابعی را مشخص می‌کند که برای پارامتری‌کردن این سیاست به کار می‌روند. اگر این فیلد وجود نداشته باشد، این سیاست پارامتری ندارد و متغیر param در CEL در اختیار عبارت‌های اعتبارسنجی قرار نمی‌گیرد. اگر ParamKind به نوعی ناموجود اشاره کند، تعریف این سیاست نادرست پیکربندی شده است و FailurePolicy اعمال می‌شود. اگر paramKind مشخص شده باشد ولی paramRef در ValidatingAdmissionPolicyBinding تنظیم نشده باشد، مقدار متغیر params برابر null خواهد بود.
validations
Validation array		 فیلد validations شامل عبارت‌های CEL است که برای اعمال اعتبارسنجی به کار می‌روند. فیلدهای Validations و AuditAnnotations نمی‌توانند هر دو خالی باشند؛ وجود دست‌کم یکی از آن‌ها الزامی است.
variables
Variable array
راهبرد وصله: ادغام بر اساس کلید name		 فیلد variables شامل تعریف متغیرهایی است که می‌توان در ترکیب سایر عبارت‌ها از آن‌ها استفاده کرد. هر متغیر به‌صورت یک عبارت CEL نام‌دار تعریف می‌شود. متغیرهایی که در اینجا تعریف می‌شوند، در سایر عبارت‌های سیاست زیر `variables` در دسترس خواهند بود، به‌جز در MatchConditions؛ زیرا MatchConditions پیش از بقیهٔ سیاست ارزیابی می‌شوند. عبارت یک متغیر می‌تواند به متغیرهایی که پیش‌تر در فهرست تعریف شده‌اند ارجاع دهد، اما نه به متغیرهای بعدی. بنابراین متغیرها باید به ترتیب نخستین ظهورشان مرتب شده باشند و وابستگی چرخه‌ای نداشته باشند.

AuditAnnotation {#AuditAnnotation}

نوع AuditAnnotation توصیف می‌کند که چگونه برای یک درخواست API حاشیه‌نویسی ممیزی تولید شود.

فیلدتوضیحات
key *
string		 فیلد key کلید حاشیه‌نویسی ممیزی را مشخص می‌کند. کلیدهای حاشیه‌نویسی ممیزی یک ValidatingAdmissionPolicy باید یکتا باشند. کلید باید یک نام واجد شرایط (qualified name) به شکل ([A-Za-z0-9][-A-Za-z0-9_.]*) با طول حداکثر ۶۳ بایت باشد. این کلید با نام منبع ValidatingAdmissionPolicy ترکیب می‌شود تا یک کلید حاشیه‌نویسی ممیزی به شکل "{ValidatingAdmissionPolicy name}/{key}" ساخته شود. اگر یک وب‌هوک پذیرش (admission webhook) از همان نام منبع این ValidatingAdmissionPolicy و همان کلید حاشیه‌نویسی ممیزی استفاده کند، کلیدهای حاشیه‌نویسی یکسان خواهند بود. در این حالت، نخستین حاشیه‌نویسی‌ای که با این کلید نوشته شود در رویداد ممیزی گنجانده می‌شود و همهٔ حاشیه‌نویسی‌های بعدی با همان کلید کنار گذاشته می‌شوند. این فیلد الزامی است.
valueExpression *
string		 فیلد valueExpression عبارتی را نشان می‌دهد که CEL آن را برای تولید مقدار حاشیه‌نویسی ممیزی ارزیابی می‌کند. حاصل ارزیابی این عبارت باید یک رشته یا مقدار null باشد. اگر حاصل ارزیابی یک رشته باشد، حاشیه‌نویسی ممیزی با همان مقدار رشته‌ای گنجانده می‌شود. اگر حاصل ارزیابی null یا رشتهٔ خالی باشد، حاشیه‌نویسی ممیزی حذف می‌شود. طول valueExpression نمی‌تواند بیش از 5kb باشد. اگر طول نتیجهٔ valueExpression بیش از 10kb باشد، به 10kb کوتاه می‌شود. اگر چند منبع ValidatingAdmissionPolicyBinding با یک درخواست API تطبیق داشته باشند، valueExpression برای هر اتصال جداگانه ارزیابی می‌شود. همهٔ مقادیر یکتایی که valueExpressionها تولید می‌کنند، در قالب فهرستی جداشده با ویرگول به هم پیوسته می‌شوند. این فیلد الزامی است.

Validation {#Validation}

نوع Validation عبارتی از CEL را مشخص می‌کند که برای انجام اعتبارسنجی به کار می‌رود.

فیلدتوضیحات
expression *
string		 فیلد expression عبارتی را نشان می‌دهد که CEL آن را ارزیابی می‌کند. مرجع: https://github.com/google/cel-spec عبارت‌های CEL به محتوای درخواست/پاسخ API دسترسی دارند. این محتوا در قالب متغیرهای CEL سازمان‌دهی شده است و چند متغیر کاربردی دیگر نیز در دسترس است: - 'object' - آبجکتِ درخواست ورودی. مقدار آن برای درخواست‌های DELETE برابر null است. - 'oldObject' - آبجکت موجود. مقدار آن برای درخواست‌های CREATE برابر null است. - 'request' - ویژگی‌های درخواست API ([مرجع](/pkg/apis/admission/types.go#AdmissionRequest)). - 'params' - منبع پارامتری که اتصال سیاست (policy binding) در حال ارزیابی به آن ارجاع می‌دهد. این متغیر فقط زمانی مقدار می‌گیرد که سیاست دارای ParamKind باشد. - 'namespaceObject' - آبجکت فضای نام (namespace) که آبجکت ورودی به آن تعلق دارد. مقدار آن برای منابعی که در سطح کلاستر تعریف می‌شوند برابر null است. - 'variables' - نگاشتی از متغیرهای ترکیبی که نام هر متغیر را به مقدار آن نگاشت می‌کند؛ این مقدار به‌صورت تنبل (lazy) ارزیابی می‌شود. برای مثال، به متغیری با نام 'foo' می‌توان از طریق 'variables.foo' دسترسی داشت. - 'authorizer' - یک Authorizer در CEL. با آن می‌توان بررسی‌های مجوزدهی را برای هویت اصلی (کاربر یا حساب سرویس) درخواست انجام داد. برای اطلاعات بیشتر به https://pkg.go.dev/k8s.io/apiserver/pkg/cel/library#Authz مراجعه کنید. - 'authorizer.requestResource' - یک ResourceCheck در CEL که از 'authorizer' ساخته شده و با منبع درخواست پیکربندی شده است. فیلدهای `apiVersion`، `kind`، `metadata.name` و `metadata.generateName` همیشه از ریشهٔ آبجکت در دسترس هستند. هیچ ویژگی دیگری از metadata در دسترس نیست. فقط نام ویژگی‌هایی به شکل `[a-zA-Z_.-/][a-zA-Z0-9_.-/]*` در دسترس هستند. هنگام دسترسی به نام ویژگی‌های در دسترس در عبارت، این نام‌ها طبق قواعد زیر escape می‌شوند: - '__' به '__underscores__' تبدیل می‌شود - '.' به '__dot__' تبدیل می‌شود - '-' به '__dash__' تبدیل می‌شود - '/' به '__slash__' تبدیل می‌شود - نام ویژگی‌هایی که دقیقاً با یکی از کلیدواژه‌های رزروشده (RESERVED) در CEL یکسان باشند، به '__{keyword}__' تبدیل می‌شوند. این کلیدواژه‌ها عبارت‌اند از: "true", "false", "null", "in", "as", "break", "const", "continue", "else", "for", "function", "if", "import", "let", "loop", "package", "namespace", "return". مثال‌ها: - عبارتی که به ویژگی‌ای با نام "namespace" دسترسی دارد: {"Expression": "object.__namespace__ > 0"} - عبارتی که به ویژگی‌ای با نام "x-prop" دسترسی دارد: {"Expression": "object.x__dash__prop > 0"} - عبارتی که به ویژگی‌ای با نام "redact__d" دسترسی دارد: {"Expression": "object.redact__underscores__d > 0"} در آرایه‌هایی که نوع فهرستشان 'set' یا 'map' است، مقایسهٔ برابری ترتیب عناصر را نادیده می‌گیرد؛ یعنی [1, 2] == [2, 1]. الحاق آرایه‌هایی که x-kubernetes-list-type دارند از معناشناسی همان نوع فهرست پیروی می‌کند: - 'set': عبارت `X + Y` اجتماعی را انجام می‌دهد که در آن جایگاه همهٔ عناصر `X` در آرایه حفظ می‌شود و عناصر غیرمشترکِ `Y` با حفظ ترتیب جزئی خود به انتهای آرایه افزوده می‌شوند. - 'map': عبارت `X + Y` ادغامی را انجام می‌دهد که در آن جایگاه همهٔ کلیدهای `X` در آرایه حفظ می‌شود، اما هرگاه مجموعهٔ کلیدهای `X` و `Y` اشتراک داشته باشند، مقادیر با مقادیر `Y` بازنویسی می‌شوند. عناصری از `Y` که کلیدهای غیرمشترک دارند، با حفظ ترتیب جزئی خود به انتهای آرایه افزوده می‌شوند. الزامی.
message
string		 فیلد message پیامی را نشان می‌دهد که هنگام شکست اعتبارسنجی نمایش داده می‌شود. اگر Expression شامل شکست خط باشد، تعیین message الزامی است. پیام نباید شامل شکست خط باشد. اگر این فیلد تنظیم نشود، پیام "failed rule: {Rule}" خواهد بود. برای مثال: "must be a URL with the host matching spec.host". اگر Expression شامل شکست خط باشد، تعیین message الزامی است. پیام نباید شامل شکست خط باشد. اگر این فیلد تنظیم نشود، پیام "failed Expression: {Expression}" خواهد بود.
messageExpression
string		 فیلد messageExpression یک عبارت CEL تعریف می‌کند که حاصل ارزیابی آن، پیام شکست اعتبارسنجی است و هنگام شکست این قاعده برگردانده می‌شود. از آنجا که messageExpression به‌عنوان پیام شکست به کار می‌رود، حاصل ارزیابی آن باید یک رشته باشد. اگر برای یک اعتبارسنجی هم message و هم messageExpression تعیین شده باشد، هنگام شکست اعتبارسنجی از messageExpression استفاده می‌شود. اگر messageExpression به خطای زمان اجرا منجر شود، این خطا ثبت می‌شود و پیام شکست اعتبارسنجی طوری تولید می‌شود که گویی فیلد messageExpression تنظیم نشده است. اگر حاصل ارزیابی messageExpression رشته‌ای خالی، رشته‌ای فقط شامل فاصله یا رشته‌ای شامل شکست خط باشد، پیام شکست اعتبارسنجی باز هم طوری تولید می‌شود که گویی فیلد messageExpression تنظیم نشده است و این واقعیت که messageExpression رشته‌ای خالی، رشته‌ای فقط شامل فاصله یا رشته‌ای شامل شکست خط تولید کرده است نیز ثبت می‌شود. عبارت messageExpression به همهٔ متغیرهایی که `expression` به آن‌ها دسترسی دارد دسترسی دارد، به جز 'authorizer' و 'authorizer.requestResource'. مثال: "object.x must be less than max ("+string(params.max)+")"
reason
string		 فیلد reason توضیحی ماشین‌خوان از علت شکست این اعتبارسنجی ارائه می‌دهد. اگر این نخستین اعتبارسنجیِ فهرست باشد که شکست می‌خورد، این علت همراه با کد پاسخ HTTP متناظر با آن در پاسخ HTTP به کلاینت به کار می‌رود. علت‌هایی که در حال حاضر پشتیبانی می‌شوند عبارت‌اند از: "Unauthorized"، "Forbidden"، "Invalid"، "RequestEntityTooLarge". اگر این فیلد تنظیم نشود، StatusReasonInvalid در پاسخ به کلاینت به کار می‌رود.

limit integer فیلد limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی فهرست بازمی‌گرداند. اگر موارد بیشتری وجود داشته باشد، سرور فیلد `continue` را در متادیتای فهرست با مقداری تنظیم می‌کند که می‌توان از آن همراه با همان کوئری اولیه برای دریافت مجموعهٔ بعدی نتایج استفاده کرد. اگر همهٔ آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است تعدادی کمتر از تعداد درخواستی (حتی صفر مورد) بازگرداند؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص در دسترس بودن نتایج بیشتر استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و همهٔ نتایج موجود را بازگردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجهٔ دیگری در دسترس نیست. این فیلد زمانی که watch برابر true باشد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجهٔ یک فراخوانی فهرست واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور نخستین درخواست ایجاد، تغییر یا حذف شده باشد، در درخواست‌های ادامهٔ بعدی گنجانده نمی‌شود. به این وضعیت گاهی اسنپ‌شات سازگار (consistent snapshot) گفته می‌شود و تضمین می‌کند کلاینتی که از limit برای دریافت بخش‌های کوچک‌تری از یک نتیجهٔ بسیار بزرگ استفاده می‌کند، همهٔ آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در طول یک فهرست‌گیری بخش‌بندی‌شده به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبهٔ نخستین نتیجهٔ فهرست وجود داشته است.
orphanDependents boolean منسوخ‌شده: لطفاً از PropagationPolicy استفاده کنید؛ این فیلد در نسخهٔ 1.7 منسوخ خواهد شد. این فیلد مشخص می‌کند که آیا آبجکت‌های وابسته باید یتیم شوند یا نه. اگر مقدار آن true/false باشد، finalizer «orphan» به فهرست finalizerهای آبجکت افزوده/از آن حذف می‌شود. می‌توان یا این فیلد یا PropagationPolicy را تنظیم کرد، اما نه هر دو را.
propagationPolicy string مشخص می‌کند که آیا و چگونه جمع‌آوری زباله انجام شود. می‌توان یا این فیلد یا OrphanDependents را تنظیم کرد، اما نه هر دو را. سیاست پیش‌فرض بر اساس مجموعهٔ finalizerهای موجود در metadata.finalizers و سیاست پیش‌فرضِ مختص منبع تعیین می‌شود. مقادیر قابل‌قبول عبارت‌اند از: 'Orphan' - وابسته‌ها را یتیم می‌کند؛ 'Background' - به garbage collector اجازه می‌دهد وابسته‌ها را در پس‌زمینه حذف کند؛ 'Foreground' - سیاستی آبشاری که همهٔ وابسته‌ها را در پیش‌زمینه حذف می‌کند.
resourceVersion string فیلد resourceVersion محدودیتی تعیین می‌کند که درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض: تنظیم‌نشده
resourceVersionMatch string فیلد resourceVersionMatch تعیین می‌کند که resourceVersion چگونه بر فراخوانی‌های فهرست اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های فهرستی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض: تنظیم‌نشده
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همهٔ این رویدادها، یک رویداد مصنوعی «Bookmark» ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعهٔ آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینهٔ `sendInitialEvents` تنظیم شده باشد، لازم است گزینهٔ `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این صورت است:
- اگر `resourceVersionMatch` برابر NotOlderThan باشد، به‌صورت «داده‌هایی دست‌کم به تازگیِ `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ی همگام شده باشد که دست‌کم به تازگیِ مقدار ارائه‌شده در ListOptions باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌صورت «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظهٔ آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا اصلاً تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) برابر true و در غیر این صورت false است.
shardSelector string فیلد shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر شارد مبتنی بر CEL محدود می‌کند. این قالب از تابع shardRange() همراه با || (OR منطقی) برای مشخص کردن یک یا چند بازهٔ هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو ریشه‌دار در object به سبک CEL استفاده می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهایی که در حال حاضر پشتیبانی می‌شوند: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون نقل‌قول تکی و با پیشوند '0x' هستند و کران پایینِ شامل و کران بالای غیرشامل را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازهٔ کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') شارد 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') شارد 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') شارد 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') شارد 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی (timeout) برای فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.

limit integer فیلد limit حداکثر تعداد پاسخ‌هایی است که یک فراخوانی list بازمی‌گرداند. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در متادیتای فهرست به مقداری تنظیم می‌کند که می‌توان آن را همراه با همان کوئری اولیه برای دریافت مجموعه‌ی بعدی نتایج استفاده کرد. اگر همه‌ی آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است تعدادی کمتر از آیتم‌های درخواست‌شده (حتی صفر آیتم) بازگرداند؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص در دسترس بودن نتایج بیشتر استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و در این صورت همه‌ی نتایج موجود را بازمی‌گردانند. اگر limit مشخص شده و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجه‌ی دیگری در دسترس نیست. وقتی watch برابر true باشد، این فیلد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجه‌ی صدور یک فراخوانی list واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور نخستین درخواست ایجاد، تغییر یا حذف شده باشد، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. گاهی به این ویژگی «اسنپ‌شات سازگار» (consistent snapshot) گفته می‌شود و تضمین می‌کند کلاینتی که از limit برای دریافت یک نتیجه‌ی بسیار بزرگ در تکه‌های کوچک‌تر استفاده می‌کند، همه‌ی آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در حین فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبه‌ی نخستین نتیجه‌ی فهرست وجود داشته است.
resourceVersion string فیلد resourceVersion محدودیتی تعیین می‌کند که مشخص می‌کند درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
resourceVersionMatch string فیلد resourceVersionMatch تعیین می‌کند که resourceVersion چگونه بر فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های list که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
sendInitialEvents boolean گزینه‌ی `sendInitialEvents=true` را می‌توان همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همه‌ی این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این بوکمارک، ResourceVersion (RV) متناظر با مجموعه‌ی آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق روال عادی ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینه‌ی `sendInitialEvents` تنظیم شده باشد، لازم است گزینه‌ی `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به این صورت است:
- اگر `resourceVersionMatch` = NotOlderThan باشد، به معنای «داده‌ای دست‌کم به تازگیِ `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد بوکمارک زمانی ارسال می‌شود که وضعیت تا یک `resourceVersion` دست‌کم به تازگیِ مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» تفسیر می‌شود و رویداد بوکمارک زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ی آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا اصلاً تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) true و در غیر این صورت false است.
shardSelector string فیلد shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر شارد مبتنی بر CEL محدود می‌کند. این قالب از تابع shardRange() همراه با || (OR منطقی) برای مشخص کردن یک یا چند بازه‌ی هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشه‌ی object استفاده می‌کنند (برای مثال "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهایی که در حال حاضر پشتیبانی می‌شوند: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون نقل‌قول تکی و با پیشوند '0x' هستند که کران پایینِ شامل و کران بالای غیرشامل را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازه‌ی کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ شارد: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ شارد: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی (timeout) برای فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. مقدار resourceVersion را مشخص کنید.

- حالت `resourceVersionMatch` = NotOlderThan به معنای «داده‌ای دست‌کم به تازگیِ `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت تا یک `resourceVersion` دست‌کم به تازگیِ مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به معنای «خواندن سازگار» (consistent read) تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه آغاز پردازش درخواست همگام شده باشد.

fieldValidation string پارامتر fieldValidation به سرور اعلام می‌کند که با آبجکت‌های موجود در درخواست (POST/PUT/PATCH) که فیلدهای ناشناخته یا تکراری دارند چگونه رفتار کند. مقادیر معتبر عبارت‌اند از: - Ignore: هر فیلد ناشناخته‌ای که بی‌صدا از آبجکت حذف می‌شود نادیده گرفته می‌شود و از میان فیلدهای تکراری، همه به‌جز آخرین فیلدی که رمزگشا با آن روبه‌رو می‌شود نادیده گرفته می‌شوند. این رفتار پیش‌فرض پیش از نسخه v1.23 است. - Warn: برای هر فیلد ناشناخته‌ای که از آبجکت حذف می‌شود و برای هر فیلد تکراری که با آن روبه‌رو می‌شود، یک هشدار از طریق سرآیند استاندارد هشدار در پاسخ ارسال می‌شود. اگر خطای دیگری وجود نداشته باشد، درخواست همچنان موفق خواهد بود و از میان فیلدهای تکراری فقط آخرین آن‌ها ذخیره می‌شود. این رفتار پیش‌فرض در نسخه v1.23 به بعد است. - Strict: اگر هر فیلد ناشناخته‌ای از آبجکت حذف شود یا هر فیلد تکراری وجود داشته باشد، درخواست با خطای BadRequest ناموفق می‌شود. خطای برگردانده‌شده از سرور شامل همه فیلدهای ناشناخته و تکراری یافت‌شده است.
