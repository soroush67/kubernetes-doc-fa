آبجکت ValidatingWebhook یک وب‌هوک پذیرش و منابع و عملیات‌هایی را که این وب‌هوک بر آن‌ها اعمال می‌شود توصیف می‌کند.

فیلدتوضیحات
admissionReviewVersions *
string array		 فیلد admissionReviewVersions فهرستی مرتب از نسخه‌های ترجیحی `AdmissionReview` است که وب‌هوک انتظار دارد. سرور API تلاش می‌کند نخستین نسخه‌ای از این فهرست را که پشتیبانی می‌کند به کار ببرد. اگر سرور API از هیچ‌یک از نسخه‌های مشخص‌شده در این فهرست پشتیبانی نکند، اعتبارسنجی این آبجکت ناموفق خواهد بود. اگر یک پیکربندی وب‌هوکِ ذخیره‌شده نسخه‌های مجاز را مشخص کند و هیچ‌یک از نسخه‌های شناخته‌شده برای سرور API را در بر نگیرد، فراخوانی‌های این وب‌هوک با شکست مواجه می‌شوند و تابع سیاست خطا (failure policy) خواهند بود.

string		 فیلد failurePolicy تعیین می‌کند خطاهای ناشناخته‌ای که از endpoint پذیرش بازگردانده می‌شوند چگونه مدیریت شوند؛ مقادیر مجاز Ignore و Fail هستند. مقدار پیش‌فرض Fail است.

مقادیر ممکن enum:
- مقدار `"Fail"` یعنی بروز خطا در فراخوانی وب‌هوک باعث شکست پذیرش می‌شود.
- مقدار `"Ignore"` یعنی خطای فراخوانی وب‌هوک نادیده گرفته می‌شود.
matchConditions
MatchCondition array
راهبرد patch: ادغام (merge) بر اساس کلید name		 فیلد matchConditions فهرستی از شرط‌هایی است که برای ارسال یک درخواست به این وب‌هوک باید برقرار باشند. شرط‌های تطبیق، درخواست‌هایی را فیلتر می‌کنند که پیش‌تر با rules، namespaceSelector و objectSelector تطبیق داده شده‌اند. فهرست خالی matchConditions با همه‌ی درخواست‌ها تطبیق پیدا می‌کند. حداکثر ۶۴ شرط تطبیق مجاز است. منطق دقیق تطبیق (به ترتیب) چنین است: ۱. اگر ارزیابی «هر یک» از matchConditionها FALSE باشد، از وب‌هوک صرف‌نظر می‌شود. ۲. اگر ارزیابی «همه‌ی» matchConditionها TRUE باشد، وب‌هوک فراخوانی می‌شود. ۳. اگر ارزیابی یکی از matchConditionها به خطا بینجامد (اما هیچ‌کدام FALSE نباشد): - اگر failurePolicy=Fail باشد، درخواست رد می‌شود - اگر failurePolicy=Ignore باشد، خطا نادیده گرفته می‌شود و از وب‌هوک صرف‌نظر می‌شود
matchPolicy
string		 فیلد matchPolicy تعیین می‌کند فهرست "rules" چگونه برای تطبیق درخواست‌های ورودی به کار رود. مقادیر مجاز "Exact" و "Equivalent" هستند. - Exact: درخواست فقط در صورتی تطبیق داده می‌شود که دقیقاً با یکی از قواعد مشخص‌شده منطبق باشد. برای مثال، اگر deploymentها از طریق apps/v1، apps/v1beta1 و extensions/v1beta1 قابل تغییر باشند، اما "rules" فقط شامل `apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"]` باشد، درخواستی که به apps/v1beta1 یا extensions/v1beta1 ارسال شود به وب‌هوک فرستاده نمی‌شود. - Equivalent: درخواست در صورتی تطبیق داده می‌شود که منبعی را که در rules فهرست شده است تغییر دهد، حتی اگر این کار از طریق گروه یا نسخه‌ی دیگری از API انجام شود. برای مثال، اگر deploymentها از طریق apps/v1، apps/v1beta1 و extensions/v1beta1 قابل تغییر باشند و "rules" فقط شامل `apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"]` باشد، درخواستی که به apps/v1beta1 یا extensions/v1beta1 ارسال شود به apps/v1 تبدیل و سپس به وب‌هوک فرستاده می‌شود. مقدار پیش‌فرض "Equivalent" است.

مقادیر ممکن enum:
- مقدار `"Equivalent"` یعنی اگر درخواست‌ها منبعی را که در rules فهرست شده است از طریق گروه یا نسخه‌ی دیگری از API تغییر دهند، باید به وب‌هوک فرستاده شوند.
- مقدار `"Exact"` یعنی درخواست‌ها فقط در صورتی باید به وب‌هوک فرستاده شوند که دقیقاً با یک قاعده‌ی مشخص منطبق باشند.
name *
string		 فیلد name نام وب‌هوک پذیرش است. این نام باید کاملاً واجد شرایط (fully qualified) باشد؛ برای مثال imagepolicy.kubernetes.io که در آن "imagepolicy" نام وب‌هوک و kubernetes.io نام سازمان است. این فیلد الزامی است.
namespaceSelector
LabelSelector		 فیلد namespaceSelector بر اساس اینکه فضای نام (namespace) یک آبجکت با انتخابگر (selector) تطبیق دارد یا نه، تعیین می‌کند که وب‌هوک روی آن آبجکت اجرا شود یا خیر. اگر خود آبجکت یک فضای نام باشد، تطبیق روی object.metadata.labels انجام می‌شود. اگر آبجکت منبع دیگری با دامنه‌ی کلاستر باشد، هرگز از وب‌هوک صرف‌نظر نمی‌شود. برای مثال، برای اجرای وب‌هوک روی هر آبجکتی که فضای نام آن به "runlevel" با مقدار "0" یا "1" مرتبط نیست، انتخابگر را به این صورت تنظیم می‌کنید: "namespaceSelector": { "matchExpressions": [ { "key": "runlevel", "operator": "NotIn", "values": [ "0", "1" ] } ] } اما اگر بخواهید وب‌هوک فقط روی آبجکت‌هایی اجرا شود که فضای نامشان به "environment" با مقدار "prod" یا "staging" مرتبط است، انتخابگر را به این صورت تنظیم می‌کنید: "namespaceSelector": { "matchExpressions": [ { "key": "environment", "operator": "In", "values": [ "prod", "staging" ] } ] } برای مشاهده‌ی نمونه‌های بیشتری از انتخابگرهای برچسب، به https://kubernetes.io/docs/concepts/overview/working-with-objects/labels مراجعه کنید. مقدار پیش‌فرض، یک LabelSelector خالی است که با همه چیز تطبیق پیدا می‌کند.
objectSelector
LabelSelector		 فیلد objectSelector بر اساس اینکه آبجکت برچسب‌های منطبق دارد یا نه، تعیین می‌کند که وب‌هوک اجرا شود یا خیر. این فیلد هم روی oldObject و هم روی newObject که قرار است به وب‌هوک ارسال شوند ارزیابی می‌شود و اگر هر یک از این دو آبجکت با انتخابگر منطبق باشد، تطبیق برقرار تلقی می‌شود. آبجکت null (یعنی oldObject در عملیات ایجاد یا newObject در عملیات حذف) یا آبجکتی که نمی‌تواند برچسب داشته باشد (مانند آبجکت DeploymentRollback یا PodProxyOptions) منطبق در نظر گرفته نمی‌شود. از انتخابگر آبجکت فقط زمانی استفاده کنید که وب‌هوک اختیاری (opt-in) باشد، زیرا کاربران نهایی می‌توانند با تنظیم برچسب‌ها از وب‌هوک پذیرش عبور کنند. مقدار پیش‌فرض، یک LabelSelector خالی است که با همه چیز تطبیق پیدا می‌کند.
rules
RuleWithOperations array		 فیلد rules مشخص می‌کند که وب‌هوک به کدام عملیات‌ها روی کدام منابع یا زیرمنابع اهمیت می‌دهد. وب‌هوک به عملیاتی اهمیت می‌دهد که با _هر یک_ از قواعد (Rule) منطبق باشد. با این حال، برای جلوگیری از اینکه ValidatingAdmissionWebhookها و MutatingAdmissionWebhookها کلاستر را در وضعیتی قرار دهند که بازیابی از آن بدون غیرفعال‌سازی کامل افزونه ممکن نباشد، این وب‌هوک‌ها هرگز برای درخواست‌های پذیرشِ مربوط به آبجکت‌های ValidatingWebhookConfiguration و MutatingWebhookConfiguration فراخوانی نمی‌شوند.
sideEffects *
string		 فیلد sideEffects مشخص می‌کند که آیا این وب‌هوک اثر جانبی دارد یا نه. مقادیر قابل قبول None و NoneOnDryRun هستند (وب‌هوک‌هایی که از طریق v1beta1 ایجاد شده‌اند ممکن است Some یا Unknown را نیز مشخص کنند). وب‌هوک‌هایی که اثر جانبی دارند «باید» یک سازوکار همسان‌سازی (reconciliation) پیاده‌سازی کنند، زیرا ممکن است درخواست در مرحله‌ای بعدی از زنجیره‌ی پذیرش رد شود و در نتیجه لازم باشد اثرات جانبی آن بازگردانده شوند. درخواست‌هایی که ویژگی dryRun دارند، اگر با وب‌هوکی با sideEffects == Unknown یا Some منطبق شوند، به‌طور خودکار رد می‌شوند.

مقادیر ممکن enum:
- مقدار `"None"` یعنی فراخوانی وب‌هوک هیچ اثر جانبی ندارد.
- مقدار `"NoneOnDryRun"` یعنی فراخوانی وب‌هوک ممکن است اثر جانبی داشته باشد، اما اگر درخواستِ در حال بررسی ویژگی dry-run داشته باشد، اثرات جانبی سرکوب می‌شوند.
- مقدار `"Some"` یعنی فراخوانی وب‌هوک ممکن است اثر جانبی داشته باشد. اگر درخواستی با ویژگی dry-run موجب فراخوانی این وب‌هوک شود، آن درخواست در عوض با شکست مواجه می‌شود.
- مقدار `"Unknown"` یعنی هیچ اطلاعاتی درباره‌ی اثرات جانبی فراخوانی وب‌هوک در دست نیست. اگر درخواستی با ویژگی dry-run موجب فراخوانی این وب‌هوک شود، آن درخواست در عوض با شکست مواجه می‌شود.
timeoutSeconds
integer		 فیلد timeoutSeconds مهلت زمانی (timeout) این وب‌هوک را مشخص می‌کند. پس از سپری شدن این مهلت، بسته به سیاست خطا، فراخوانی وب‌هوک نادیده گرفته می‌شود یا فراخوانی API با شکست مواجه می‌شود. مقدار مهلت زمانی باید بین ۱ تا ۳۰ ثانیه باشد. مقدار پیش‌فرض ۱۰ ثانیه است.

limit integer فیلد limit حداکثر تعداد پاسخ‌هایی را تعیین می‌کند که یک فراخوانی list بازمی‌گرداند. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در متادیتای فهرست روی مقداری تنظیم می‌کند که می‌توان از آن همراه با همان کوئری اولیه برای بازیابی دستهٔ بعدی نتایج استفاده کرد. اگر همهٔ آبجکت‌های درخواست‌شده فیلتر شوند، تنظیم limit ممکن است به بازگشت آیتم‌هایی کمتر از تعداد درخواست‌شده (حتی صفر آیتم) منجر شود؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص در دسترس بودن نتایج بیشتر استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و همهٔ نتایج موجود را برگردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجهٔ دیگری وجود ندارد. وقتی watch برابر true باشد، از این فیلد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجهٔ یک فراخوانی list واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور نخستین درخواست ایجاد، تغییر یا حذف شده باشد، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. گاهی به این ویژگی تصویر لحظه‌ای سازگار (consistent snapshot) گفته می‌شود و تضمین می‌کند کلاینتی که از limit برای دریافت بخش‌های کوچک‌تر یک نتیجهٔ بسیار بزرگ استفاده می‌کند، همهٔ آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در حین فهرست‌گیری بخش‌بخش به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبهٔ نخستین نتیجهٔ فهرست وجود داشته است.
orphanDependents boolean منسوخ‌شده: لطفاً از PropagationPolicy استفاده کنید؛ این فیلد در نسخهٔ 1.7 منسوخ خواهد شد. تعیین می‌کند که آیا آبجکت‌های وابسته باید یتیم (orphan) شوند یا خیر. اگر true/false باشد، finalizer با نام «orphan» به فهرست finalizerهای آبجکت افزوده/از آن حذف می‌شود. می‌توان یا این فیلد یا PropagationPolicy را تنظیم کرد، اما نه هر دو را.
propagationPolicy string تعیین می‌کند که آیا و چگونه جمع‌آوری زباله (garbage collection) انجام شود. می‌توان یا این فیلد یا OrphanDependents را تنظیم کرد، اما نه هر دو را. سیاست پیش‌فرض بر اساس finalizerهای موجود در metadata.finalizers و سیاست پیش‌فرض مختص منبع تعیین می‌شود. مقادیر قابل قبول عبارت‌اند از: 'Orphan' - وابسته‌ها را یتیم می‌کند؛ 'Background' - به جمع‌آورندهٔ زباله اجازه می‌دهد وابسته‌ها را در پس‌زمینه حذف کند؛ 'Foreground' - یک سیاست آبشاری که همهٔ وابسته‌ها را در پیش‌زمینه حذف می‌کند.
resourceVersion string فیلد resourceVersion محدودیتی را تعیین می‌کند که مشخص می‌کند درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض، تنظیم‌نشده است
resourceVersionMatch string فیلد resourceVersionMatch تعیین می‌کند که resourceVersion چگونه بر فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود برای فراخوانی‌های listی که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. مقدار پیش‌فرض، تنظیم‌نشده است
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همهٔ این رویدادها، یک رویداد مصنوعی «Bookmark» ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعهٔ آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق روال عادی ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینهٔ `sendInitialEvents` تنظیم شده باشد، گزینهٔ `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به این صورت است:
- مقدار `resourceVersionMatch` = NotOlderThan به‌صورت «داده‌ای دست‌کم به تازگی `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ی همگام شده باشد که دست‌کم به تازگی مقدار ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظهٔ آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده باشد یا تنظیم نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) true و در غیر این صورت false است.
shardSelector string فیلد shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر شارد مبتنی بر CEL محدود می‌کند. در این قالب، تابع shardRange() همراه با || (OR منطقی) برای مشخص کردن یک یا چند بازهٔ هش به کار می‌رود: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشهٔ object استفاده می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون نقل‌قول تکی با پیشوند '0x' هستند و کران پایین (شامل) و کران بالا (غیرشامل) را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازهٔ کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') شارد 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ شارد: شارد 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') شارد 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') شارد 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') شارد 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی برای فراخوانی list/watch. این مقدار مدت فراخوانی را، صرف‌نظر از وجود یا نبود فعالیت، محدود می‌کند.

allowWatchBookmarks boolean پارامتر allowWatchBookmarks رویدادهای watch از نوع "BOOKMARK" را درخواست می‌کند. سرورهایی که bookmark را پیاده‌سازی نکرده‌اند ممکن است این پرچم را نادیده بگیرند و ارسال bookmarkها به صلاحدید سرور انجام می‌شود. کلاینت‌ها نباید فرض کنند که bookmarkها در فاصله‌ی زمانی مشخصی بازگردانده می‌شوند و همچنین نمی‌توانند فرض کنند که سرور در طول یک نشست حتماً رویداد BOOKMARK ارسال می‌کند. اگر درخواست از نوع watch نباشد، این فیلد نادیده گرفته می‌شود.
continue string گزینه‌ی continue باید هنگام دریافت نتایج بیشتر از سرور تنظیم شود. از آنجا که این مقدار را سرور تعیین می‌کند، کلاینت‌ها فقط می‌توانند از مقدار continue حاصل از نتیجه‌ی یک پرس‌وجوی قبلی با پارامترهای پرس‌وجوی یکسان (به‌جز مقدار continue) استفاده کنند و سرور ممکن است مقدار continue ناشناخته را رد کند. اگر مقدار continue مشخص‌شده دیگر معتبر نباشد، چه به دلیل انقضا (معمولاً پنج تا پانزده دقیقه) و چه به دلیل تغییر پیکربندی در سرور، سرور با خطای 410 ResourceExpired همراه با یک توکن continue پاسخ می‌دهد. اگر کلاینت به فهرستی سازگار (consistent) نیاز دارد، باید فهرست‌گیری را بدون فیلد continue از نو آغاز کند. در غیر این صورت، کلاینت می‌تواند درخواست فهرست دیگری را با توکن دریافت‌شده همراه خطای 410 ارسال کند؛ در این حالت سرور فهرستی را برمی‌گرداند که از کلید بعدی آغاز می‌شود، اما بر اساس آخرین snapshot تهیه شده و با نتایج فهرست قبلی سازگار نیست: آبجکت‌هایی که پس از نخستین درخواست فهرست ایجاد، تغییر یا حذف شده‌اند، تا زمانی که کلیدشان پس از «کلید بعدی» (next key) باشد، در پاسخ گنجانده می‌شوند. وقتی watch برابر true باشد، این فیلد پشتیبانی نمی‌شود. کلاینت‌ها می‌توانند watch را از آخرین مقدار resourceVersion بازگردانده‌شده از سوی سرور آغاز کنند و هیچ تغییری را از دست ندهند.
fieldSelector string انتخابگری (selector) است که فهرست آبجکت‌های بازگردانده‌شده را بر اساس فیلدهایشان محدود می‌کند. به‌طور پیش‌فرض همه‌ی آبجکت‌ها بازگردانده می‌شوند.
labelSelector string انتخابگری است که فهرست آبجکت‌های بازگردانده‌شده را بر اساس برچسب‌هایشان محدود می‌کند. به‌طور پیش‌فرض همه‌ی آبجکت‌ها بازگردانده می‌شوند.

resourceVersion string پارامتر resourceVersion محدودیتی بر نسخه‌های منبعی که درخواست می‌تواند از آن‌ها پاسخ داده شود اعمال می‌کند. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
resourceVersionMatch string پارامتر resourceVersionMatch تعیین می‌کند که resourceVersion چگونه روی فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های list که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بازسازی کند. پس از ارسال همه‌ی این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه‌ی آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به روال عادی ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظارت را ارسال می‌کند. وقتی گزینه‌ی `sendInitialEvents` تنظیم شده باشد، لازم است گزینه‌ی `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به شرح زیر است:

limit integer پارامتر limit بیشینهٔ تعداد پاسخ‌هایی است که یک فراخوانی list برمی‌گرداند. اگر آیتم‌های بیشتری وجود داشته باشد، سرور فیلد `continue` را در فرادادهٔ فهرست با مقداری تنظیم می‌کند که می‌توان آن را همراه با همان پرس‌وجوی اولیه برای بازیابی مجموعهٔ بعدی نتایج به کار برد. اگر همهٔ آبجکت‌های درخواستی فیلتر شوند، تعیین limit ممکن است تعدادی کمتر از آیتم‌های درخواستی (حتی صفر آیتم) برگرداند؛ بنابراین کلاینت‌ها فقط باید از وجود فیلد continue برای تشخیص در دسترس بودن نتایج بیشتر استفاده کنند. سرورها ممکن است از آرگومان limit پشتیبانی نکنند و در این صورت همهٔ نتایج موجود را برمی‌گردانند. اگر limit مشخص شده باشد و فیلد continue خالی باشد، کلاینت‌ها می‌توانند فرض کنند که نتیجهٔ دیگری در دسترس نیست. وقتی watch برابر true باشد، این فیلد پشتیبانی نمی‌شود. سرور تضمین می‌کند آبجکت‌هایی که هنگام استفاده از continue بازگردانده می‌شوند، با نتیجهٔ یک فراخوانی list واحد بدون limit یکسان باشند؛ یعنی هیچ آبجکتی که پس از صدور نخستین درخواست ایجاد، ویرایش یا حذف شده باشد، در درخواست‌های ادامه‌دار بعدی گنجانده نمی‌شود. گاهی به این ویژگی snapshot سازگار گفته می‌شود و تضمین می‌کند کلاینتی که با استفاده از limit یک نتیجهٔ بسیار بزرگ را در تکه‌های کوچک‌تر دریافت می‌کند، همهٔ آبجکت‌های ممکن را ببیند. اگر آبجکت‌ها در طول یک فهرست‌گیری تکه‌تکه به‌روزرسانی شوند، نسخه‌ای از آبجکت بازگردانده می‌شود که در زمان محاسبهٔ نخستین نتیجهٔ فهرست وجود داشته است.
pretty string اگر مقدار آن 'true' باشد، خروجی به‌صورت قالب‌بندی‌شده و خوانا چاپ می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent نشان‌دهندهٔ یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) باشد.
resourceVersion string پارامتر resourceVersion محدودیتی تعیین می‌کند که درخواست از کدام نسخه‌های منبع می‌تواند پاسخ داده شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم‌نشده است.
resourceVersionMatch string پارامتر resourceVersionMatch تعیین می‌کند که resourceVersion چگونه بر فراخوانی‌های list اعمال شود. اکیداً توصیه می‌شود در فراخوانی‌های list که resourceVersion در آن‌ها تنظیم شده است، resourceVersionMatch نیز تنظیم شود. برای جزئیات بیشتر به https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions مراجعه کنید. به‌طور پیش‌فرض تنظیم‌نشده است.
sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی آغاز می‌شود تا وضعیت فعلی آبجکت‌های مجموعه را بسازد. پس از ارسال همهٔ این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark نسخهٔ منبع (ResourceVersion یا RV) متناظر با مجموعهٔ آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch به روال عادی ادامه می‌یابد و رویدادهای watch متناظر با تغییرات (پس از RV) در آبجکت‌های تحت نظر را ارسال می‌کند. وقتی گزینهٔ `sendInitialEvents` تنظیم شده باشد، گزینهٔ `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به این صورت است:
- مقدار NotOlderThan برای `resourceVersionMatch` به معنای «داده‌ای دست‌کم به تازگی `resourceVersion` ارائه‌شده» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ی همگام شده باشد که دست‌کم به تازگی نسخهٔ ارائه‌شده در ListOptions است. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» تفسیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظهٔ آغاز پردازش درخواست همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا تنظیم‌نشده باشد، خطای Invalid بازگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد (به دلایل سازگاری با نسخه‌های قبلی) برابر true و در غیر این صورت برابر false است.
shardSelector string پارامتر shardSelector فهرست آبجکت‌های بازگردانده‌شده را با استفاده از یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. این قالب از تابع shardRange() به همراه || (یای منطقی) برای تعیین یک یا چند بازهٔ هش استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیرهای فیلد از نحو CEL با ریشهٔ object استفاده می‌کنند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd لیترال‌های رشته‌ای CEL درون تک‌نقل‌قول با پیشوند '0x' هستند که کران پایین شامل و کران بالای غیرشامل را در فضای هش ۶۴ بیتی FNV-1a تعریف می‌کنند. بازهٔ کامل [0x0, 0x10000000000000000) است که در آن کران بالای غیرشامل برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و به فعال‌سازی feature gate با نام ShardedListAndWatch نیاز دارد.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این پارامتر مدت‌زمان فراخوانی را، صرف‌نظر از وجود یا نبود فعالیت، محدود می‌کند.
watch boolean تغییرات منابع توصیف‌شده را زیر نظر می‌گیرد و آن‌ها را به‌صورت جریانی از اعلان‌های افزودن، به‌روزرسانی و حذف بازمی‌گرداند. مقدار resourceVersion را مشخص کنید.
