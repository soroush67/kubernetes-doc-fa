DeviceTaint {#DeviceTaint}

دستگاهی که این taint به آن متصل شده است، روی هر claim که این taint را تحمل (tolerate) نکند و از طریق claim روی Podهایی که از آن استفاده می‌کنند، «اثر» (effect) مشخص‌شده را دارد.

فیلدتوضیحات
effect *
string		 اثر taint روی claimهایی که taint را تحمل نمی‌کنند و از طریق این claimها روی Podهایی که از آن‌ها استفاده می‌کنند. اثرهای معتبر None، NoSchedule و NoExecute هستند. PreferNoSchedule که برای نودها استفاده می‌شود در اینجا معتبر نیست. ممکن است در آینده اثرهای بیشتری اضافه شوند. مصرف‌کنندگان باید اثرهای ناشناخته را مانند None در نظر بگیرند.

مقادیر enum ممکن:
- `"NoExecute"` هر Pod در حال اجرایی را که taint دستگاه را تحمل نمی‌کند اخراج می‌کند.
- `"NoSchedule"` اجازه نمی‌دهد Podهای جدیدی که از دستگاه دارای taint استفاده می‌کنند زمان‌بندی شوند، مگر اینکه taint را تحمل کنند؛ اما اجازه می‌دهد همه‌ی Podهایی که بدون عبور از زمان‌بند به Kubelet ارسال شده‌اند شروع به کار کنند و همه‌ی Podهای در حال اجرا به اجرای خود ادامه دهند.
- `"None"` بدون اثر است و taint صرفاً جنبه‌ی اطلاعاتی دارد.
key *
string		 کلید taint که باید روی دستگاه اعمال شود. باید یک نام برچسب (label) معتبر باشد.
timeAdded
Time		 TimeAdded زمانی را نشان می‌دهد که taint اضافه شده یا (فقط در DeviceTaintRule) اثر آن تغییر کرده است. در صورت تنظیم نشدن، هنگام ایجاد یا به‌روزرسانی به‌طور خودکار اضافه می‌شود. علاوه بر این، در یک DeviceTaintRule، مقداری که هنگام به‌روزرسانی ارائه شود، در صورتی که با مقدار قبلی یکسان باشد و اثر جدید متفاوت باشد، با زمان فعلی جایگزین می‌شود. تغییر کلید و/یا مقدار با حفظ اثر امکان‌پذیر است و برچسب زمانی را به‌روزرسانی نمی‌کند، زیرا اخراجی که از آن استفاده می‌کند یا پیش‌تر آغاز شده است (NoExecute) یا هنوز آغاز نشده است (NoEffect، NoSchedule).
value
string		 مقدار taint که با کلید taint متناظر است. باید یک مقدار برچسب (label) معتبر باشد.

DeviceTaintSelector {#DeviceTaintSelector}

DeviceTaintSelector مشخص می‌کند یک DeviceTaintRule برای کدام دستگاه یا دستگاه‌ها اعمال می‌شود. انتخابگر خالی با همه‌ی دستگاه‌ها مطابقت دارد. اگر انتخابگری وجود نداشته باشد، با هیچ دستگاهی مطابقت صورت نمی‌گیرد.

فیلدتوضیحات

pool
string		 اگر pool تنظیم شده باشد، فقط دستگاه‌هایی که در آن pool قرار دارند انتخاب می‌شوند. تنظیم نام درایور نیز می‌تواند برای جلوگیری از ابهام، زمانی که درایورهای مختلف از نام pool یکسانی استفاده می‌کنند، مفید باشد؛ اما الزامی نیست، زیرا انتخاب poolها از درایورهای مختلف نیز ممکن است مفید باشد، برای مثال وقتی درایورهایی با دستگاه‌های محلی نود، نام نود را به‌عنوان نام pool خود به کار می‌برند.

shardSelector string shardSelector فهرست آبجکت‌های بازگردانده‌شده را با یک عبارت انتخابگر shard مبتنی بر CEL محدود می‌کند. قالب آن از تابع shardRange() همراه با || (OR منطقی) برای تعیین یک یا چند بازهٔ hash استفاده می‌کند: shardRange(object.metadata.uid, '0x0', '0x8000000000000000') shardRange(object.metadata.uid, '0x0', '0x8000000000000000') || shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') مسیر فیلدها از نحو CEL با ریشهٔ object استفاده می‌کند (مثلاً "object.metadata.uid")، نه از قالب fieldSelector ("metadata.uid"). مسیرهای پشتیبانی‌شده در حال حاضر: - object.metadata.uid - object.metadata.namespace مقادیر hexStart و hexEnd رشته‌های لیترال CEL درون تک‌نقل‌قول با پیشوند '0x' هستند و کران پایین شامل‌شونده و کران بالای شامل‌نشونده را روی فضای hash نوع FNV-1a ۶۴ بیتی تعریف می‌کنند. بازهٔ کامل [0x0, 0x10000000000000000) است که در آن کران بالای شامل‌نشونده برابر 2^64 است. مثال‌ها: تقسیم به ۲ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x8000000000000000') shard 1: shardRange(object.metadata.uid, '0x8000000000000000', '0x10000000000000000') تقسیم به ۴ shard: shard 0: shardRange(object.metadata.uid, '0x0000000000000000', '0x4000000000000000') shard 1: shardRange(object.metadata.uid, '0x4000000000000000', '0x8000000000000000') shard 2: shardRange(object.metadata.uid, '0x8000000000000000', '0xc000000000000000') shard 3: shardRange(object.metadata.uid, '0xc000000000000000', '0x10000000000000000') این یک فیلد آلفا است و نیاز دارد feature gate با نام ShardedListAndWatch فعال شود.
timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت فراخوانی را بدون توجه به هرگونه فعالیت یا عدم فعالیت محدود می‌کند.

sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های مجموعه را تولید می‌کنند. پس از ارسال همه این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعه آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی (annotation) `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch طبق معمول ادامه می‌یابد و رویدادهای مربوط به تغییرات (پس از RV) آبجکت‌های تحت نظر را ارسال می‌کند. هنگامی که گزینه `sendInitialEvents` تنظیم شده باشد، لازم است گزینه `resourceVersionMatch` نیز تنظیم شود. معنای درخواست watch به شرح زیر است:
- مقدار `resourceVersionMatch` برابر NotOlderThan به این معنا تعبیر می‌شود: «داده‌هایی دست‌کم به‌روز به اندازه `resourceVersion` ارائه‌شده»، و رویداد bookmark زمانی ارسال می‌شود که وضعیت با `resourceVersion`ای دست‌کم به‌تازگی مقدار ارائه‌شده در ListOptions همگام شده باشد. اگر `resourceVersion` تنظیم نشده باشد، این حالت به‌عنوان «خواندن سازگار» (consistent read) تعبیر می‌شود و رویداد bookmark زمانی ارسال می‌شود که وضعیت دست‌کم تا لحظه‌ای که پردازش درخواست آغاز شده است همگام شده باشد.
- اگر `resourceVersionMatch` روی هر مقدار دیگری تنظیم شده یا تنظیم نشده باشد، خطای Invalid برگردانده می‌شود. مقدار پیش‌فرض در صورتی که `resourceVersion=""` یا `resourceVersion="0"` باشد true است (به دلایل سازگاری با نسخه‌های قبلی) و در غیر این صورت false است.

timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت‌زمان فراخوانی را بدون توجه به وجود یا نبود فعالیت محدود می‌کند.

sendInitialEvents boolean می‌توان `sendInitialEvents=true` را همراه با `watch=true` تنظیم کرد. در این حالت، جریان watch با رویدادهای مصنوعی (synthetic) آغاز می‌شود که وضعیت فعلی آبجکت‌های مجموعه را تولید می‌کنند. پس از ارسال همهٔ این رویدادها، یک رویداد مصنوعی "Bookmark" ارسال می‌شود. این bookmark مقدار ResourceVersion (RV) متناظر با مجموعهٔ آبجکت‌ها را گزارش می‌کند و با حاشیه‌نویسی `"k8s.io/initial-events-end": "true"` علامت‌گذاری می‌شود. پس از آن، جریان watch مطابق معمول ادامه می‌یابد و رویدادهای watch مربوط به تغییرات آبجکت‌های تحت نظر (پس از RV) را ارسال می‌کند. هنگامی که گزینهٔ `sendInitialEvents` تنظیم شده باشد، گزینهٔ `resourceVersionMatch` نیز باید تنظیم شود. معنای درخواست watch به شرح زیر است:

timeoutSeconds integer مهلت زمانی فراخوانی list/watch. این مقدار مدت‌زمان فراخوانی را، فارغ از هرگونه فعالیت یا عدم فعالیت، محدود می‌کند.

پارامترهای پرس‌وجو

نامنوعتوضیحات
pretty string اگر مقدار 'true' باشد، خروجی به‌صورت خوانا (pretty printed) نمایش داده می‌شود. مقدار پیش‌فرض 'false' است، مگر آنکه user-agent یک مرورگر یا ابزار HTTP خط فرمان (curl و wget) باشد.
dryRun string وجود این پارامتر نشان می‌دهد که تغییرات نباید ماندگار شوند. دستور dryRun نامعتبر یا ناشناخته به پاسخ خطا می‌انجامد و پردازش درخواست در همان نقطه متوقف می‌شود. مقادیر معتبر: - All: همه مراحل dry run پردازش می‌شوند
fieldManager string fieldManager نامی است که به عامل یا نهادی که این تغییرات را اعمال می‌کند مرتبط است. طول این مقدار باید کمتر از ۱۲۸ نویسه یا برابر با آن باشد و فقط شامل نویسه‌های قابل چاپ باشد، مطابق تعریف https://golang.org/pkg/unicode/#IsPrint. این فیلد برای درخواست‌های apply (از نوع application/apply-patch) الزامی است، اما برای انواع patch غیر از apply (JsonPatch، MergePatch، StrategicMergePatch) اختیاری است.
fieldValidation string fieldValidation به سرور دستور می‌دهد با آبجکت‌های موجود در درخواست (POST/PUT/PATCH) که فیلدهای ناشناخته یا تکراری دارند چگونه رفتار کند. مقادیر معتبر: - Ignore: فیلدهای ناشناخته را نادیده می‌گیرد و بی‌سروصدا از آبجکت حذف می‌کند و از میان فیلدهای تکراری فقط آخرین فیلدی را که رمزگشا (decoder) با آن مواجه می‌شود در نظر می‌گیرد. این رفتار پیش‌فرض پیش از نسخه v1.23 است. - Warn: برای هر فیلد ناشناخته‌ای که از آبجکت حذف می‌شود و برای هر فیلد تکراری که با آن مواجه می‌شود، از طریق هدر استاندارد پاسخ هشدار (warning) ارسال می‌کند. اگر خطای دیگری وجود نداشته باشد، درخواست همچنان موفق می‌شود و از میان فیلدهای تکراری فقط آخرین فیلد ماندگار می‌شود. این رفتار پیش‌فرض در نسخه v1.23 و بالاتر است. - Strict: اگر قرار باشد هر فیلد ناشناخته‌ای از آبجکت حذف شود یا فیلد تکراری وجود داشته باشد، درخواست با خطای BadRequest رد می‌شود. خطای بازگردانده‌شده از سرور شامل همه فیلدهای ناشناخته و تکراری مشاهده‌شده خواهد بود.
force boolean Force درخواست‌های Apply را «اجباری» می‌کند. به این معنا که کاربر فیلدهای دارای تعارض را که متعلق به دیگران است دوباره تصاحب می‌کند. برای درخواست‌های patch غیر از apply، پرچم force باید تنظیم نشده باشد.
