kube-proxy

خلاصه

پراکسی شبکه کوبرنتیز روی هر نود اجرا می‌شود. این پراکسی Serviceهای تعریف‌شده در API کوبرنتیز را روی هر نود بازتاب می‌دهد و می‌تواند ارسال ساده جریان‌های TCP، UDP و SCTP را انجام دهد یا ارسال TCP، UDP و SCTP را به‌صورت round robin میان مجموعه‌ای از بک‌اندها انجام دهد. IPهای کلاستر و پورت‌های Service در حال حاضر از طریق متغیرهای محیطی سازگار با Docker-links پیدا می‌شوند که پورت‌های بازشده توسط پراکسی Service را مشخص می‌کنند. یک افزونه (addon) اختیاری نیز وجود دارد که DNS کلاستر را برای این IPهای کلاستر فراهم می‌کند. کاربر باید با استفاده از API سرور API (apiserver) یک Service ایجاد کند تا پراکسی را پیکربندی کند.

kube-proxy [flags]

گزینه‌ها

--add_dir_header

در صورت true بودن، مسیر دایرکتوری فایل به سرایند (header) پیام‌های لاگ اضافه می‌شود.
--alsologtostderr

لاگ‌ها علاوه بر فایل‌ها، در خروجی خطای استاندارد نیز نوشته می‌شوند (در صورت true بودن -logtostderr بی‌تأثیر است).
--alsologtostderrthreshold int

در صورتی که -alsologtostderr برابر true باشد، لاگ‌هایی که سطح آن‌ها برابر با این آستانه یا بالاتر از آن باشد به stderr ارسال می‌شوند (در صورت true بودن -logtostderr بی‌تأثیر است).
--bind-address string     Default: 0.0.0.0

برداشت kube-proxy از IP اصلی نود خود را بازنویسی می‌کند. توجه کنید که این نام یک یادگار تاریخی است و kube-proxy در واقع هیچ سوکتی را به این IP متصل (bind) نمی‌کند. در صورتی که فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--bind-address-hard-fail

در صورت true بودن، kube-proxy شکست در اتصال به یک پورت را خطای مهلک تلقی می‌کند و خارج می‌شود.
--cleanup

در صورت true بودن، قوانین iptables و ipvs پاک‌سازی می‌شوند و برنامه خارج می‌شود.
--cluster-cidr string

محدوده CIDR پادهای کلاستر. (برای کلاسترهای dual-stack می‌تواند یک جفت محدوده CIDR dual-stack جداشده با کاما باشد.) وقتی --detect-local-mode روی ClusterCIDR تنظیم شده باشد، kube-proxy ترافیکی را محلی در نظر می‌گیرد که IP مبدأ آن در این محدوده باشد. (در غیر این صورت استفاده نمی‌شود.) در صورتی که فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--config string

مسیر فایل پیکربندی.
--config-sync-period duration     Default: 15m0s

تناوب به‌روزرسانی پیکربندی دریافتی از apiserver. باید بزرگ‌تر از 0 باشد.
--conntrack-max-per-core int32     Default: 32768

بیشترین تعداد اتصال‌های NAT که به‌ازای هر هسته CPU ردیابی می‌شود (مقدار 0 محدودیت را بدون تغییر باقی می‌گذارد و conntrack-min را نادیده می‌گیرد).
--conntrack-min int32     Default: 131072

کمترین تعداد ورودی‌های conntrack که صرف‌نظر از conntrack-max-per-core تخصیص داده می‌شود (برای بدون تغییر ماندن محدودیت، conntrack-max-per-core=0 را تنظیم کنید).
--conntrack-tcp-be-liberal

با تنظیم nf_conntrack_tcp_be_liberal روی 1، حالت آسان‌گیرانه (liberal) برای ردیابی بسته‌های TCP فعال می‌شود.
--conntrack-tcp-timeout-close-wait duration     Default: 1h0m0s

مهلت NAT برای اتصال‌های TCP در وضعیت CLOSE_WAIT
--conntrack-tcp-timeout-established duration     Default: 24h0m0s

مهلت بیکاری برای اتصال‌های TCP برقرارشده (مقدار 0 بدون تغییر باقی می‌گذارد)
--conntrack-udp-timeout duration

مهلت بیکاری برای اتصال‌های UDP از نوع UNREPLIED (مقدار 0 بدون تغییر باقی می‌گذارد)
--conntrack-udp-timeout-stream duration

مهلت بیکاری برای اتصال‌های UDP از نوع ASSURED (مقدار 0 بدون تغییر باقی می‌گذارد)
--detect-local-mode LocalMode

حالتی که برای تشخیص ترافیک محلی استفاده می‌شود. در صورتی که فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.

-h, --help

راهنمای kube-proxy
--hostname-override string

در صورت غیرخالی بودن، به‌عنوان نام Node‌ای که kube-proxy روی آن اجرا می‌شود استفاده می‌گردد. در صورت تنظیم نشدن، فرض می‌شود نام نود با نام میزبان (hostname) آن یکسان است.
--init-only

در صورت true بودن، هر گام راه‌اندازی اولیه‌ای که باید با دسترسی کامل root انجام شود اجرا می‌شود و سپس برنامه خارج می‌شود. پس از این کار، می‌توانید kube-proxy را دوباره و تنها با قابلیت (capability) CAP_NET_ADMIN اجرا کنید.
--iptables-localhost-nodeports     Default: true

در صورت false بودن، kube-proxy رفتار قدیمی (legacy) مجاز بودن دسترسی به سرویس‌های NodePort از طریق localhost را غیرفعال می‌کند. (فقط در حالت iptables و برای IPv4 اعمال می‌شود؛ NodePortهای localhost در سایر حالت‌های پروکسی یا با IPv6 هرگز مجاز نیستند.)
--iptables-masquerade-bit int32     Default: 14

در صورت استفاده از حالت پروکسی iptables یا ipvs، بیتی از فضای fwmark که بسته‌های نیازمند SNAT با آن علامت‌گذاری می‌شوند. باید در بازه [0, 31] باشد.
--iptables-min-sync-period duration     Default: 1s

کمترین فاصله زمانی میان همگام‌سازی‌های مجدد قوانین iptables (برای مثال '5s'، '1m'، '2h22m'). مقدار 0 به این معناست که هر تغییر در Service یا EndpointSlice بلافاصله به یک همگام‌سازی مجدد iptables منجر می‌شود.
--iptables-sync-period duration     Default: 30s

فاصله زمانی (برای مثال '5s'، '1m'، '2h22m') که نشان می‌دهد عملیات مختلف همگام‌سازی مجدد و پاک‌سازی هر چند وقت یک بار انجام می‌شوند. باید بزرگ‌تر از 0 باشد.
--ipvs-exclude-cidrs strings

فهرستی از CIDRها، جداشده با کاما، که ipvs proxier هنگام پاک‌سازی قوانین IPVS نباید به آن‌ها دست بزند.
--ipvs-min-sync-period duration     Default: 1s

کمترین فاصله زمانی میان همگام‌سازی‌های مجدد قوانین IPVS (برای مثال '5s'، '1m'، '2h22m'). مقدار 0 به این معناست که هر تغییر در Service یا EndpointSlice بلافاصله به یک همگام‌سازی مجدد IPVS منجر می‌شود.
--ipvs-scheduler string

نوع زمان‌بند ipvs در زمانی که حالت پروکسی ipvs است
--ipvs-strict-arp

با تنظیم arp_ignore روی 1 و arp_announce روی 2، ARP سخت‌گیرانه (strict ARP) فعال می‌شود.
--ipvs-sync-period duration     Default: 30s

بازه‌ای زمانی (مثلاً '5s'، '1m'، '2h22m') که مشخص می‌کند عملیات مختلف همگام‌سازی مجدد و پاک‌سازی هر چند وقت یک‌بار انجام شوند. مقدار آن باید بزرگ‌تر از 0 باشد.
--ipvs-tcp-timeout duration

مهلت زمانی برای اتصال‌های TCP بیکار در IPVS؛ مقدار 0 مقدار فعلی را بدون تغییر نگه می‌دارد. (مثلاً '5s'، '1m'، '2h22m').
--ipvs-tcpfin-timeout duration

مهلت زمانی برای اتصال‌های TCP در IPVS پس از دریافت بسته FIN؛ مقدار 0 مقدار فعلی را بدون تغییر نگه می‌دارد. (مثلاً '5s'، '1m'، '2h22m').
--ipvs-udp-timeout duration

مهلت زمانی برای بسته‌های UDP در IPVS؛ مقدار 0 مقدار فعلی را بدون تغییر نگه می‌دارد. (مثلاً '5s'، '1m'، '2h22m').
--kube-api-burst int32     Default: 10

مقدار burst که هنگام ارتباط با apiserver کوبرنتیز استفاده می‌شود.
--kube-api-content-type string     Default: "application/vnd.kubernetes.protobuf"

نوع محتوای درخواست‌هایی که به apiserver ارسال می‌شوند.
--kube-api-qps float     Default: 5

مقدار QPS که هنگام ارتباط با apiserver کوبرنتیز استفاده می‌شود.
--kubeconfig string

مسیر فایل kubeconfig حاوی اطلاعات احراز هویت و مجوزدهی (نشانی master را می‌توان با پرچم master بازنویسی کرد).
--legacy_stderr_threshold_behavior     Default: true

اگر true باشد، در حالتی که logtostderr=true است، stderrthreshold نادیده گرفته می‌شود (رفتار قدیمی). اگر false باشد، stderrthreshold حتی زمانی که logtostderr=true است نیز اعمال می‌شود.
--log-flush-frequency duration     Default: 5s

حداکثر تعداد ثانیه‌های بین دو بار تخلیه (flush) لاگ‌ها
--log-text-info-buffer-size quantity

[آلفا] در قالب متنی با جریان‌های خروجی جداشده، پیام‌های اطلاعاتی را می‌توان برای مدتی بافر کرد تا کارایی افزایش یابد. مقدار پیش‌فرض صفر بایت است که بافر کردن را غیرفعال می‌کند. اندازه را می‌توان به‌صورت تعداد بایت (512)، مضرب‌هایی از 1000 (1K)، مضرب‌هایی از 1024 (2Ki) یا توان‌های آن‌ها (3M، 4G، 5Mi، 6Gi) مشخص کرد. برای استفاده از این گزینه، feature gate با نام LoggingAlphaOptions را فعال کنید.
--log-text-split-stream

[آلفا] در قالب متنی، پیام‌های خطا را در stderr و پیام‌های اطلاعاتی را در stdout می‌نویسد. به‌طور پیش‌فرض یک جریان واحد در stdout نوشته می‌شود. برای استفاده از این گزینه، feature gate با نام LoggingAlphaOptions را فعال کنید.
--log_backtrace_at <a string in the form 'file:N'>     Default: :0

هنگامی که لاگ‌گذاری به خط file:N برسد، یک stack trace تولید می‌شود
--log_dir string

اگر خالی نباشد، فایل‌های لاگ در این دایرکتوری نوشته می‌شوند (در صورت logtostderr=true بی‌اثر است)
--log_file string

اگر خالی نباشد، از این فایل لاگ استفاده می‌شود (در صورت logtostderr=true بی‌اثر است)
--log_file_max_size uint     Default: 1800

حداکثر اندازه‌ای را که یک فایل لاگ می‌تواند به آن برسد تعیین می‌کند (در صورت logtostderr=true بی‌اثر است). واحد آن مگابایت است. اگر مقدار 0 باشد، حداکثر اندازه فایل نامحدود است.
--logging-format string     Default: "text"

قالب لاگ را تعیین می‌کند. قالب‌های مجاز: "text".
--logtostderr     Default: true

لاگ‌ها به‌جای فایل‌ها در خروجی خطای استاندارد نوشته می‌شوند
--masquerade-all

برای تمام ترافیکی که از طریق IPهای کلاستر Service ارسال می‌شود، SNAT انجام می‌دهد. ممکن است در برخی افزونه‌های CNI لازم باشد. فقط در لینوکس پشتیبانی می‌شود.
--master string

نشانی سرور API کوبرنتیز (هر مقدار موجود در kubeconfig را بازنویسی می‌کند)
--metrics-bind-address ipport     Default: 127.0.0.1:10249

نشانی IP و پورتی که سرور متریک‌ها روی آن سرویس‌دهی می‌کند؛ مقدار پیش‌فرض "127.0.0.1:10249" است. (برای اتصال به همه اینترفیس‌ها، آن را روی "0.0.0.0:10249" / "[::]:10249" تنظیم کنید.) اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--nodeport-addresses strings

فهرستی از محدوده‌های CIDR و/یا کلیدواژه‌هایی که به محدوده‌های CIDR گسترش می‌یابند. سرویس‌های NodePort فقط روی IPهای نودی که در این فهرست قرار می‌گیرند در دسترس هستند. کلیدواژه‌های پشتیبانی‌شده: 'primary' (نشانی‌های IPv4 و/یا IPv6 اصلی آبجکت Node)، 'localhost' (127.0.0.0/8 و ::1/128) و 'all' (0.0.0.0/0 و ::/0). هر ترکیبی از کلیدواژه‌ها و CIDRهای معتبر را می‌توان در فهرست قرار داد. سرویس‌دهی NodePortها روی IPهای loopback فقط در حالت iptables پشتیبانی می‌شود (فقط IPv4، به --iptables-localhost-nodeports مراجعه کنید)، و فقط برای TCP در حالت nftables، زمانی که feature gate با نام KubeProxyNFTablesLocalhostNodePorts فعال باشد و فهرست به‌صراحت loopback را شامل شود (مثلاً 'localhost'). اگر تنظیم نشود، مقدار پیش‌فرض در حالت‌های iptables و ipvs برابر 'all' و در حالت nftables برابر 'primary' است. اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--one_output

اگر true باشد، لاگ‌ها فقط در سطح شدت اصلی خود نوشته می‌شوند (به‌جای نوشته شدن در هر سطح شدت پایین‌تر نیز؛ در صورت logtostderr=true بی‌اثر است)
--oom-score-adj int32     Default: -999

مقدار oom-score-adj برای فرایند kube-proxy. مقادیر باید در بازه [-1000, 1000] باشند. اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--pod-bridge-interface string

نام یک اینترفیس bridge. زمانی که --detect-local-mode روی BridgeInterface تنظیم شده باشد، kube-proxy ترافیکی را که از این bridge سرچشمه بگیرد محلی در نظر می‌گیرد.
--pod-interface-name-prefix string

پیشوند نام اینترفیس. زمانی که --detect-local-mode روی InterfaceNamePrefix تنظیم شده باشد، kube-proxy ترافیکی را که از هر اینترفیسی با نامی که با این پیشوند آغاز می‌شود سرچشمه بگیرد محلی در نظر می‌گیرد.
--profiling

اگر true باشد، پروفایل‌گیری از طریق رابط وب روی handler با مسیر /debug/pprof فعال می‌شود. اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--proxy-mode ProxyMode

حالت پراکسی مورد استفاده: در لینوکس می‌تواند 'iptables' (پیش‌فرض)، 'ipvs' یا 'nftables' باشد. در ویندوز تنها مقدار پشتیبانی‌شده 'kernelspace' است. اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--show-hidden-metrics-for-version string

نسخه قبلی که می‌خواهید متریک‌های پنهان‌شده آن نمایش داده شوند. فقط نسخه فرعی (minor) قبلی معنا دارد و مقادیر دیگر پذیرفته نمی‌شوند. قالب آن <major>.<minor> است، مثلاً: '1.16'. هدف از این قالب آن است که اگر انتشار بعدی متریک‌های بیشتری را پنهان کرد، فرصت داشته باشید متوجه شوید و هنگام حذف دائمی آن‌ها در انتشار پس از آن غافلگیر نشوید. اگر فایل پیکربندی با --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--skip_headers

اگر true باشد، از افزودن پیشوند سرصفحه (header) به پیام‌های لاگ خودداری می‌شود
--skip_log_headers

اگر true باشد، هنگام باز کردن فایل‌های لاگ از نوشتن سرصفحه‌ها خودداری می‌شود (در صورت logtostderr=true بی‌اثر است)
--stderrthreshold int     Default: 2

لاگ‌هایی که در این آستانه یا بالاتر از آن باشند، هنگام نوشتن همزمان در فایل‌ها و stderr به stderr ارسال می‌شوند (در صورت logtostderr=true یا alsologtostderr=true بی‌اثر است، مگر آنکه legacy_stderr_threshold_behavior=false باشد)
-v, --v int

عددی برای سطح جزئیات (verbosity) لاگ
--version version[=true]

--version و --version=raw اطلاعات نسخه را چاپ کرده و خارج می‌شوند؛ --version=vX.Y.Z... نسخه گزارش‌شده را تنظیم می‌کند
--vmodule pattern=N,...

فهرستی جداشده با کاما از تنظیمات pattern=N برای لاگ‌گذاری فیلترشده بر اساس فایل (فقط برای قالب لاگ متنی کار می‌کند)
--write-config-to string

اگر تنظیم شود، مقادیر پیش‌فرض پیکربندی را در این فایل می‌نویسد و خارج می‌شود.
