kube-scheduler

خلاصه

زمان‌بند کوبرنتیز یک فرایند control plane است که Podها را به نودها اختصاص می‌دهد. زمان‌بند بر اساس محدودیت‌ها و منابع در دسترس مشخص می‌کند که کدام نودها برای قرار گرفتن هر Pod موجود در صف زمان‌بندی معتبر هستند. سپس زمان‌بند هر نود معتبر را رتبه‌بندی می‌کند و Pod را به نود مناسب متصل (bind) می‌کند. در یک کلاستر می‌توان از چند زمان‌بند مختلف استفاده کرد؛ kube-scheduler پیاده‌سازی مرجع است. برای اطلاعات بیشتر درباره زمان‌بندی و مؤلفه kube-scheduler به زمان‌بندی مراجعه کنید.

kube-scheduler [flags]

گزینه‌ها

--allow-metric-labels stringToString     Default: []

نگاشتی از برچسب متریک (metric label) به فهرست مقادیر مجاز آن برچسب. قالب کلید به صورت <MetricName>,<LabelName> است. قالب مقدار به صورت <allowed_value>,<allowed_value>... است؛ برای مثال: metric1,label1='v1,v2,v3', metric1,label2='v1,v2,v3' metric2,label1='v1,v2,v3'.
--allow-metric-labels-manifest string

مسیر فایل مانیفستی که نگاشت فهرست مجاز را در بر دارد. قالب این فایل مشابه قالب پرچم --allow-metric-labels است، یعنی:
allowListMapping:
"metric1,label1": "value11,value12"
"metric2,label2": ""
توجه کنید که پرچم --allow-metric-labels بر فایل مانیفست اولویت دارد و آن را بازنویسی می‌کند.
--authentication-kubeconfig string

فایل kubeconfig که به سرور «core» کوبرنتیز اشاره می‌کند و دسترسی کافی برای ایجاد tokenreviews.authentication.k8s.io را دارد. این گزینه اختیاری است. اگر خالی باشد، همه درخواست‌های توکن ناشناس در نظر گرفته می‌شوند و هیچ CA کلاینتی در کلاستر جست‌وجو نمی‌شود.
--authentication-skip-lookup

اگر false باشد، از authentication-kubeconfig برای جست‌وجوی پیکربندی احراز هویت مفقود در کلاستر استفاده می‌شود.
--authentication-token-webhook-cache-ttl duration     Default: 10s

مدت زمان نگهداری پاسخ‌های احراز‌کننده هویت توکن مبتنی بر webhook در حافظه نهان.
--authentication-tolerate-lookup-failure     Default: true

اگر true باشد، شکست در جست‌وجوی پیکربندی احراز هویت مفقود از کلاستر، خطای مهلک تلقی نمی‌شود. توجه کنید که این امر می‌تواند به احراز هویتی منجر شود که همه درخواست‌ها را ناشناس در نظر می‌گیرد.
--authorization-always-allow-paths strings     Default: "/healthz,/readyz,/livez"

فهرستی از مسیرهای HTTP که در هنگام اعطای مجوز نادیده گرفته می‌شوند؛ یعنی این مسیرها بدون تماس با سرور «core» کوبرنتیز مجاز شمرده می‌شوند.
--authorization-kubeconfig string

فایل kubeconfig که به سرور «core» کوبرنتیز اشاره می‌کند و دسترسی کافی برای ایجاد subjectaccessreviews.authorization.k8s.io را دارد. این گزینه اختیاری است. اگر خالی باشد، همه درخواست‌هایی که از اعطای مجوز مستثنا نشده‌اند ممنوع می‌شوند.
--authorization-webhook-cache-authorized-ttl duration     Default: 10s

مدت زمان نگهداری پاسخ‌های «مجاز» از مجوزدهنده webhook در حافظه نهان.
--authorization-webhook-cache-unauthorized-ttl duration     Default: 10s

مدت زمان نگهداری پاسخ‌های «غیرمجاز» از مجوزدهنده webhook در حافظه نهان.
--bind-address string     Default: 0.0.0.0

نشانی IP که برای پورت --secure-port روی آن گوش داده می‌شود. رابط‌های مرتبط باید برای سایر بخش‌های کلاستر و همچنین برای کلاینت‌های CLI/وب در دسترس باشند. اگر خالی یا یک نشانی نامشخص (0.0.0.0 یا ::) باشد، همه رابط‌ها و خانواده‌های نشانی IP استفاده می‌شوند.
--cert-dir string

دایرکتوری‌ای که گواهی‌های TLS در آن قرار دارند. اگر --tls-cert-file و --tls-private-key-file مشخص شده باشند، این پرچم نادیده گرفته می‌شود.
--client-ca-file string

اگر تنظیم شود، هر درخواستی که گواهی کلاینتی ارائه کند که توسط یکی از مراجع موجود در client-ca-file امضا شده باشد، با هویتی متناظر با CommonName گواهی کلاینت احراز هویت می‌شود.
--config string

مسیر فایل پیکربندی.
--contention-profiling     Default: true

منسوخ‌شده: در صورت فعال بودن پروفایل‌گیری، block profiling را فعال می‌کند. اگر فایل پیکربندی در --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--disable-http2-serving

اگر true باشد، سرویس‌دهی HTTP2 غیرفعال می‌شود [پیش‌فرض=false]
--disabled-metrics strings

این پرچم راهی اضطراری برای متریک‌های پرمشکل فراهم می‌کند. برای غیرفعال کردن یک متریک باید نام کاملاً مشخص (fully qualified) آن را وارد کنید. توجه: اولویت غیرفعال کردن متریک‌ها از نمایش متریک‌های پنهان بالاتر است.
--emulated-version strings

نسخه‌هایی که اجزای مختلف قابلیت‌های خود (APIها، ویژگی‌ها و ...) را بر اساس آن شبیه‌سازی می‌کنند.
در صورت تنظیم، جزء مورد نظر به‌جای نسخه باینری زیرین، رفتار این نسخه را شبیه‌سازی می‌کند.
قالب نسخه فقط می‌تواند major.minor باشد، برای مثال: '--emulated-version=wardle=1.2,kube=1.31'.
گزینه‌ها: kube=1.34..1.37(پیش‌فرض:1.37)
اگر جزء مشخص نشود، به‌طور پیش‌فرض "kube" در نظر گرفته می‌شود
--feature-gates colonSeparatedMultimapStringString

-h, --help

راهنمای kube-scheduler
--http2-max-streams-per-connection int

حداکثر تعداد stream‌هایی که سرور در یک اتصال HTTP/2 به کلاینت‌ها اجازه می‌دهد. مقدار صفر به معنای استفاده از مقدار پیش‌فرض golang است.
--kube-api-burst int32     Default: 100

منسوخ‌شده: مقدار burst برای ارتباط با kube-apiserver کوبرنتیز. اگر فایل پیکربندی در --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--kube-api-content-type string     Default: "application/vnd.kubernetes.protobuf"

منسوخ‌شده: نوع محتوای (content type) درخواست‌های ارسالی به apiserver. اگر فایل پیکربندی در --config مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--kube-api-qps float     Default: 50

منسوخ‌شده: نرخ QPS مورد استفاده هنگام ارتباط با kube-apiserver کوبرنتیز. اگر در --config یک فایل پیکربندی مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--kubeconfig string

منسوخ‌شده: مسیر فایل kubeconfig که اطلاعات احراز هویت و مکان master را در بر دارد. اگر در --config یک فایل پیکربندی مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--leader-elect     Default: true

یک کلاینت انتخاب رهبر (leader election) را راه‌اندازی می‌کند و پیش از اجرای حلقه اصلی، رهبری را به دست می‌گیرد. هنگام اجرای مؤلفه‌های replicated برای دستیابی به دسترس‌پذیری بالا، این گزینه را فعال کنید.
--leader-elect-lease-duration duration     Default: 15s

مدت زمانی که نامزدهای غیررهبر پس از مشاهده تمدید رهبری صبر می‌کنند تا برای به دست گرفتن رهبری یک جایگاه رهبری که اشغال شده اما تمدید نشده است اقدام کنند. این مقدار در عمل بیشترین مدتی است که یک رهبر می‌تواند متوقف باشد تا نامزد دیگری جایگزین آن شود. این گزینه فقط در صورت فعال بودن انتخاب رهبر کاربرد دارد.
--leader-elect-renew-deadline duration     Default: 10s

فاصله زمانی میان تلاش‌های رهبر فعلی برای تمدید جایگاه رهبری پیش از آنکه از رهبری دست بکشد. این مقدار باید کمتر از مدت lease باشد. این گزینه فقط در صورت فعال بودن انتخاب رهبر کاربرد دارد.
--leader-elect-resource-lock string     Default: "leases"

نوع آبجکت منبعی که هنگام انتخاب رهبر برای قفل کردن استفاده می‌شود. گزینه‌های پشتیبانی‌شده: 'leases'.
--leader-elect-resource-name string     Default: "kube-scheduler"

نام آبجکت منبعی که هنگام انتخاب رهبر برای قفل کردن استفاده می‌شود.
--leader-elect-resource-namespace string     Default: "kube-system"

فضای نام (namespace) آبجکت منبعی که هنگام انتخاب رهبر برای قفل کردن استفاده می‌شود.
--leader-elect-retry-period duration     Default: 2s

مدت زمانی که کلاینت‌ها باید میان تلاش‌های خود برای به دست آوردن و تمدید رهبری صبر کنند. این گزینه فقط در صورت فعال بودن انتخاب رهبر کاربرد دارد.
--log-flush-frequency duration     Default: 5s

بیشترین تعداد ثانیه میان دو بار flush شدن لاگ‌ها
--log-text-info-buffer-size quantity

[آلفا] در قالب متنی با جریان‌های خروجی جداشده، پیام‌های اطلاعاتی را می‌توان برای مدتی بافر کرد تا کارایی افزایش یابد. مقدار پیش‌فرض صفر بایت، بافر کردن را غیرفعال می‌کند. اندازه را می‌توان به‌صورت تعداد بایت (512)، مضرب‌های 1000 (1K)، مضرب‌های 1024 (2Ki) یا توان‌های آن‌ها (3M، 4G، 5Mi، 6Gi) مشخص کرد. برای استفاده از این گزینه، feature gate با نام LoggingAlphaOptions را فعال کنید.
--log-text-split-stream

[آلفا] در قالب متنی، پیام‌های خطا را در stderr و پیام‌های اطلاعاتی را در stdout می‌نویسد. رفتار پیش‌فرض، نوشتن یک جریان واحد در stdout است. برای استفاده از این گزینه، feature gate با نام LoggingAlphaOptions را فعال کنید.
--logging-format string     Default: "text"

قالب لاگ را تعیین می‌کند. قالب‌های مجاز: "text".
--master string

نشانی API server کوبرنتیز (هر مقداری را که در kubeconfig وجود دارد بازنویسی می‌کند)
--min-compatibility-version strings

کمترین نسخه مؤلفه‌های control plane که سرور باید با آن سازگار باشد.
باید کمتر از emulated-version یا برابر با آن باشد. قالب نسخه فقط می‌تواند major.minor باشد، برای مثال: '--min-compatibility-version=wardle=1.2,kube=1.31'.
گزینه‌ها: kube=1.34..1.37(پیش‌فرض:1.36)
اگر مؤلفه مشخص نشود، مقدار پیش‌فرض "kube" است
--permit-address-sharing

اگر true باشد، هنگام bind کردن پورت از SO_REUSEADDR استفاده می‌شود. این کار امکان bind همزمان به IPهای wildcard مانند 0.0.0.0 و IPهای مشخص را فراهم می‌کند و از انتظار برای آزاد شدن سوکت‌های در وضعیت TIME_WAIT توسط هسته جلوگیری می‌کند. [پیش‌فرض=false]
--permit-port-sharing

اگر true باشد، هنگام bind کردن پورت از SO_REUSEPORT استفاده می‌شود که به بیش از یک نمونه اجازه می‌دهد روی همان نشانی و پورت bind شوند. [پیش‌فرض=false]
--pod-max-in-unschedulable-pods-duration duration     Default: 5m0s

منسوخ‌شده: بیشترین مدتی که یک Pod می‌تواند در unschedulablePods بماند. اگر یک Pod بیش از این مقدار در unschedulablePods بماند، از unschedulablePods به backoffQ یا activeQ منتقل می‌شود. این پرچم منسوخ شده است و در نسخه‌ای در آینده حذف خواهد شد.
--profiling     Default: true

منسوخ‌شده: فعال‌سازی profiling از طریق رابط وب در host:port/debug/pprof/. اگر در --config یک فایل پیکربندی مشخص شده باشد، این پارامتر نادیده گرفته می‌شود.
--requestheader-allowed-names strings

فهرست common nameهای گواهی کلاینت که اجازه دارند نام‌های کاربری را در هدرهای مشخص‌شده با --requestheader-username-headers ارائه کنند. اگر خالی باشد، هر گواهی کلاینتی که توسط مراجع موجود در --requestheader-client-ca-file اعتبارسنجی شود مجاز است.
--requestheader-client-ca-file string

بسته گواهی ریشه که پیش از اعتماد به نام‌های کاربری موجود در هدرهای مشخص‌شده با --requestheader-username-headers، برای تأیید گواهی‌های کلاینت در درخواست‌های ورودی استفاده می‌شود. هشدار: به‌طور کلی به این موضوع که احراز مجوز (authorization) برای درخواست‌های ورودی از قبل انجام شده است، تکیه نکنید.
--requestheader-extra-headers-prefix strings     Default: "x-remote-extra-"

فهرست پیشوندهای هدر درخواست که باید بررسی شوند. مقدار X-Remote-Extra- پیشنهاد می‌شود.
--requestheader-group-headers strings     Default: "x-remote-group"

فهرست هدرهای درخواست که برای گروه‌ها بررسی می‌شوند. مقدار X-Remote-Group پیشنهاد می‌شود.
--requestheader-uid-headers strings

فهرست هدرهای درخواست که برای UIDها بررسی می‌شوند. مقدار X-Remote-Uid پیشنهاد می‌شود. نیازمند فعال بودن قابلیت RemoteRequestHeaderUID است.
--requestheader-username-headers strings     Default: "x-remote-user"

فهرست هدرهای درخواست که برای نام‌های کاربری بررسی می‌شوند. مقدار X-Remote-User رایج است.
--secure-port int     Default: 10259

پورتی که HTTPS همراه با احراز هویت و احراز مجوز روی آن سرویس‌دهی می‌شود. اگر 0 باشد، HTTPS اصلاً سرویس‌دهی نمی‌شود.
--show-hidden-metrics-for-version string

نسخه قبلی که می‌خواهید معیارهای (metrics) پنهان آن نمایش داده شود. فقط نسخه minor قبلی معنادار است و مقادیر دیگر مجاز نخواهند بود. قالب آن <major>.<minor> است، برای مثال: '1.16'. هدف از این قالب آن است که اگر نسخه بعدی معیارهای بیشتری را پنهان کرد، فرصت داشته باشید متوجه شوید و هنگام حذف دائمی آن‌ها در نسخه پس از آن غافلگیر نشوید.
--tls-cert-file string

فایلی که گواهی x509 پیش‌فرض برای HTTPS را در بر دارد. (گواهی CA، در صورت وجود، پس از گواهی سرور به آن الحاق می‌شود). اگر سرویس‌دهی HTTPS فعال باشد و --tls-cert-file و --tls-private-key-file ارائه نشده باشند، یک گواهی و کلید خودامضا برای نشانی عمومی تولید می‌شود و در دایرکتوری مشخص‌شده با --cert-dir ذخیره می‌گردد.
--tls-cipher-suites strings

فهرست مجموعه‌های رمز (cipher suite) سرور، جداشده با ویرگول. اگر مشخص نشود، از cipher suiteهای پیش‌فرض Go استفاده می‌شود.
مقادیر ترجیحی: TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256.
مقادیر ناامن: TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, TLS_ECDHE_RSA_WITH_3DES_EDE_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_RSA_WITH_RC4_128_SHA, TLS_RSA_WITH_3DES_EDE_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA256, TLS_RSA_WITH_AES_128_GCM_SHA256, TLS_RSA_WITH_AES_256_CBC_SHA, TLS_RSA_WITH_AES_256_GCM_SHA384, TLS_RSA_WITH_RC4_128_SHA.
--tls-curve-preferences int32Slice     Default: []

فهرست مقادیر عددی CurveID در crypto/tls زبان Go، جداشده با ویرگول، به‌عنوان سازوکارهای مجاز تبادل کلید برای سرور. مقادیر پشتیبانی‌شده به نسخه Go مورد استفاده بستگی دارد. برای مقادیر پشتیبانی‌شده در هر نسخه Go به https://pkg.go.dev/crypto/tls#CurveID مراجعه کنید. ترتیب فهرست نادیده گرفته می‌شود و سازوکارهای تبادل کلید توسط Go از این فهرست و با استفاده از یک ترتیب ترجیحی داخلی انتخاب می‌شوند. اگر مشخص نشود، از curveهای پیش‌فرض Go استفاده می‌شود.
--tls-min-version string

کمترین نسخه TLS پشتیبانی‌شده. مقادیر ممکن: VersionTLS10, VersionTLS11, VersionTLS12, VersionTLS13
--tls-private-key-file string

فایلی که کلید خصوصی x509 پیش‌فرض متناظر با --tls-cert-file را در بر دارد.
--tls-sni-cert-key string

یک جفت مسیر فایل گواهی x509 و کلید خصوصی که در صورت تمایل می‌تواند با فهرستی از الگوهای دامنه (domain patterns) ادامه یابد؛ این الگوها نام‌های دامنه کاملاً معتبر (fully qualified) هستند و ممکن است بخش‌های wildcard پیشوندی داشته باشند. الگوهای دامنه نشانی‌های IP را نیز مجاز می‌دانند، اما IPها فقط زمانی باید استفاده شوند که apiserver به نشانی IP درخواستی کلاینت دسترسی داشته باشد. اگر هیچ الگوی دامنه‌ای ارائه نشود، نام‌های موجود در گواهی استخراج می‌شوند. تطابق‌های بدون wildcard بر تطابق‌های wildcard برتری دارند و الگوهای دامنه صریح بر نام‌های استخراج‌شده برتری دارند. برای چند جفت کلید/گواهی، --tls-sni-cert-key را چند بار استفاده کنید. نمونه‌ها: "example.crt,example.key" یا "foo.crt,foo.key:*.foo.com,foo.com".
