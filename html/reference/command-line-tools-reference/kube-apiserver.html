kube-apiserver

خلاصه

سرور API کوبرنتیز داده‌های آبجکت‌های API را که شامل Podها، Serviceها، replicationcontrollerها و موارد دیگر است، اعتبارسنجی و پیکربندی می‌کند. سرور API عملیات REST را سرویس‌دهی می‌کند و رابط کاربری (frontend) وضعیت مشترک کلاستر را فراهم می‌آورد که تمام اجزای دیگر از طریق آن با یکدیگر تعامل دارند.

kube-apiserver [flags]

گزینه‌ها

--admission-control strings

فرایند Admission به دو مرحله تقسیم می‌شود. در مرحله اول فقط افزونه‌های admission از نوع mutating اجرا می‌شوند و در مرحله دوم فقط افزونه‌های admission از نوع validating اجرا می‌شوند. نام‌های فهرست زیر ممکن است نشان‌دهنده یک افزونه validating، یک افزونه mutating یا هر دو باشند. ترتیبی که افزونه‌ها به این فلگ داده می‌شوند اهمیتی ندارد. فهرستی که با کاما جدا شده است از: AlwaysAdmit, AlwaysDeny, AlwaysPullImages, CertificateApproval, CertificateSigning, CertificateSubjectRestriction, ClusterTrustBundleAttest, DefaultIngressClass, DefaultStorageClass, DefaultTolerationSeconds, DenyServiceExternalIPs, EventRateLimit, ExtendedResourceToleration, ImagePolicyWebhook, LimitPodHardAntiAffinityTopology, LimitRanger, MutatingAdmissionPolicy, MutatingAdmissionWebhook, NamespaceAutoProvision, NamespaceExists, NamespaceLifecycle, NodeDeclaredFeatureValidator, NodeRestriction, OwnerReferencesPermissionEnforcement, PersistentVolumeClaimResize, PodGroupProtection, PodNodeSelector, PodResizeValidator, PodSecurity, PodTolerationRestriction, PodTopologyLabels, Priority, ResourceQuota, RuntimeClass, ServiceAccount, StorageObjectInUseProtection, TaintNodesByCondition, ValidatingAdmissionPolicy, ValidatingAdmissionWebhook. (منسوخ‌شده: به‌جای آن از --enable-admission-plugins یا --disable-admission-plugins استفاده کنید. در نسخه‌ای در آینده حذف خواهد شد.)
--admission-control-config-file string

فایل حاوی پیکربندی admission control.
--advertise-address string

آدرس IP که apiserver از طریق آن به اعضای کلاستر اعلام می‌شود. این آدرس باید برای سایر اجزای کلاستر قابل دسترسی باشد. اگر خالی باشد، از --bind-address استفاده می‌شود. اگر --bind-address نیز مشخص نشده باشد، از اینترفیس پیش‌فرض میزبان استفاده می‌شود.
--aggregator-reject-forwarding-redirect     Default: true

Aggregator پاسخ‌های ریدایرکتِ هدایت‌شده را به کلاینت برنمی‌گرداند و آن‌ها را رد می‌کند.
--allow-metric-labels stringToString     Default: []

نگاشتی از برچسب متریک (metric-label) به فهرست مقادیر مجاز آن برچسب. قالب کلید به‌صورت <MetricName>,<LabelName> است. قالب مقدار به‌صورت <allowed_value>,<allowed_value>... است؛ برای مثال metric1,label1='v1,v2,v3', metric1,label2='v1,v2,v3' metric2,label1='v1,v2,v3'.
--allow-metric-labels-manifest string

مسیر فایل مانیفستی که نگاشت فهرست مجاز را در بر دارد. قالب فایل مانند فلگ --allow-metric-labels است، یعنی:
allowListMapping:
"metric1,label1": "value11,value12"
"metric2,label2": ""
توجه داشته باشید که فلگ --allow-metric-labels بر فایل مانیفست اولویت دارد و آن را بازنویسی می‌کند.
--allow-privileged

اگر true باشد، کانتینرهای privileged مجاز هستند. [پیش‌فرض=false]
--anonymous-auth     Default: true

درخواست‌های ناشناس (anonymous) را به پورت امن API server فعال می‌کند. درخواست‌هایی که توسط روش احراز هویت دیگری رد نشوند، به‌عنوان درخواست ناشناس در نظر گرفته می‌شوند. درخواست‌های ناشناس نام کاربری system:anonymous و نام گروه system:unauthenticated دارند.
--api-audiences strings

شناسه‌های API. احراز‌کننده هویت توکن service account بررسی می‌کند که توکن‌های استفاده‌شده در برابر API دست‌کم به یکی از این audienceها مقید (bound) باشند. اگر فلگ --service-account-issuer پیکربندی شده باشد و این فلگ پیکربندی نشده باشد، مقدار پیش‌فرض این فیلد فهرستی تک‌عضوی حاوی URL صادرکننده (issuer) است.
--audit-log-batch-buffer-size int     Default: 10000

اندازه بافر برای نگهداری رویدادها پیش از دسته‌بندی و نوشتن. فقط در حالت batch استفاده می‌شود.
--audit-log-batch-max-size int     Default: 1

بیشینه اندازه یک دسته (batch). فقط در حالت batch استفاده می‌شود.
--audit-log-batch-max-wait duration

مدت زمان انتظار پیش از نوشتن اجباری دسته‌ای که به بیشینه اندازه نرسیده است. فقط در حالت batch استفاده می‌شود.
--audit-log-batch-throttle-burst int

بیشینه تعداد درخواست‌هایی که هم‌زمان ارسال می‌شوند، در صورتی که ThrottleQPS پیش‌تر مورد استفاده قرار نگرفته باشد. فقط در حالت batch استفاده می‌شود.
--audit-log-batch-throttle-enable

مشخص می‌کند که آیا محدودسازی نرخ (throttling) دسته‌ها فعال است یا خیر. فقط در حالت batch استفاده می‌شود.
--audit-log-batch-throttle-qps float

بیشینه میانگین تعداد دسته‌ها در هر ثانیه. فقط در حالت batch استفاده می‌شود.
--audit-log-compress

اگر تنظیم شود، فایل‌های لاگِ چرخش‌یافته (rotated) با gzip فشرده می‌شوند.
--audit-log-format string     Default: "json"

قالب ذخیره‌سازی رویدادهای audit. مقدار "legacy" نشان‌دهنده قالب متنی تک‌خطی برای هر رویداد است. مقدار "json" نشان‌دهنده قالب ساختاریافته json است. قالب‌های شناخته‌شده legacy و json هستند.
--audit-log-maxage int     Default: 366

بیشینه تعداد روزی که فایل‌های قدیمی لاگ audit بر اساس زمان‌سنجی (timestamp) کدگذاری‌شده در نام فایل نگهداری می‌شوند. مقدار 0 به این معناست که فایل‌های قدیمی لاگ audit بر اساس سن حذف نمی‌شوند.
--audit-log-maxbackup int     Default: 100

بیشینه تعداد فایل‌های قدیمی لاگ audit که نگهداری می‌شوند. مقدار 0 به این معناست که محدودیتی برای تعداد فایل‌ها وجود ندارد.
--audit-log-maxsize int     Default: 100

بیشینه اندازه فایل لاگ audit بر حسب مگابایت پیش از آنکه چرخش (rotate) داده شود. مقدار 0 چرخش را غیرفعال می‌کند (توصیه نمی‌شود).
--audit-log-mode string     Default: "blocking"

راهبرد ارسال رویدادهای audit. حالت Blocking به این معناست که ارسال رویدادها پاسخ‌های سرور را مسدود می‌کند. حالت Batch باعث می‌شود backend رویدادها را بافر کند و به‌صورت ناهمگام بنویسد. حالت‌های شناخته‌شده batch و blocking و blocking-strict هستند.
--audit-log-path string

اگر تنظیم شود، تمام درخواست‌هایی که به apiserver می‌رسند در این فایل ثبت می‌شوند. مقدار '-' به معنای خروجی استاندارد (standard out) است.
--audit-log-truncate-enabled

مشخص می‌کند که آیا کوتاه‌سازی (truncating) رویداد و دسته فعال است یا خیر.
--audit-log-truncate-max-batch-size int     Default: 10485760

بیشینه اندازه دسته‌ای که به backend زیرین ارسال می‌شود. اندازه واقعی سریال‌شده می‌تواند چند صد بایت بیشتر باشد. اگر یک دسته از این حد فراتر رود، به چند دسته با اندازه کوچک‌تر تقسیم می‌شود.
--audit-log-truncate-max-event-size int     Default: 102400

بیشینه اندازه رویداد audit که به backend زیرین ارسال می‌شود. اگر اندازه یک رویداد از این عدد بیشتر باشد، ابتدا درخواست و پاسخ حذف می‌شوند و اگر این کار اندازه را به‌اندازه کافی کاهش ندهد، رویداد دور انداخته می‌شود.
--audit-log-version string     Default: "audit.k8s.io/v1"

گروه و نسخه API که برای سریال‌سازی رویدادهای audit نوشته‌شده در لاگ استفاده می‌شود.
--audit-policy-file string

مسیر فایلی که پیکربندی سیاست audit را تعریف می‌کند.
--audit-webhook-batch-buffer-size int     Default: 10000

اندازه بافر برای نگهداری رویدادها پیش از دسته‌بندی و نوشتن. فقط در حالت batch استفاده می‌شود.
--audit-webhook-batch-max-size int     Default: 400

بیشینه اندازه یک دسته (batch). فقط در حالت batch استفاده می‌شود.
--audit-webhook-batch-max-wait duration     Default: 30s

مدت زمان انتظار پیش از نوشتن اجباری دسته‌ای که به بیشینه اندازه نرسیده است. فقط در حالت batch استفاده می‌شود.
--audit-webhook-batch-throttle-burst int     Default: 15

بیشینه تعداد درخواست‌هایی که هم‌زمان ارسال می‌شوند، در صورتی که ThrottleQPS پیش‌تر مورد استفاده قرار نگرفته باشد. فقط در حالت batch استفاده می‌شود.
--audit-webhook-batch-throttle-enable     Default: true

مشخص می‌کند که آیا محدودسازی نرخ (throttling) دسته‌ها فعال است یا خیر. فقط در حالت batch استفاده می‌شود.
--audit-webhook-batch-throttle-qps float     Default: 10

بیشینه میانگین تعداد دسته‌ها در هر ثانیه. فقط در حالت batch استفاده می‌شود.
--audit-webhook-config-file string

مسیر فایلی با قالب kubeconfig که پیکربندی webhook مربوط به audit را تعریف می‌کند.
--audit-webhook-initial-backoff duration     Default: 10s

مدت زمان انتظار پیش از تلاش مجدد برای نخستین درخواست ناموفق.
--audit-webhook-mode string     Default: "batch"

راهبرد ارسال رویدادهای audit. حالت Blocking به این معناست که ارسال رویدادها پاسخ‌های سرور را مسدود می‌کند. حالت Batch باعث می‌شود backend رویدادها را بافر کند و به‌صورت ناهمگام بنویسد. حالت‌های شناخته‌شده batch و blocking و blocking-strict هستند.
--audit-webhook-truncate-enabled

مشخص می‌کند که آیا کوتاه‌سازی (truncating) رویداد و دسته فعال است یا خیر.
--audit-webhook-truncate-max-batch-size int     Default: 10485760

بیشینه اندازه دسته‌ای که به backend زیرین ارسال می‌شود. اندازه واقعی سریال‌شده می‌تواند چند صد بایت بیشتر باشد. اگر یک دسته از این حد فراتر رود، به چند دسته با اندازه کوچک‌تر تقسیم می‌شود.

--audit-webhook-version string     Default: "audit.k8s.io/v1"

گروه و نسخه API که برای سریال‌سازی رویدادهای audit نوشته‌شده در webhook استفاده می‌شود.
--authentication-config string

فایل حاوی پیکربندی احراز هویت (Authentication Configuration) برای پیکربندی احراز‌کننده هویت JWT Token یا احراز‌کننده هویت ناشناس (anonymous). اگر فایل، احراز‌کننده JWT Token را پیکربندی کند، این فلگ با فلگ‌های --oidc-* هم‌زمان قابل استفاده نیست. اگر فایل، احراز‌کننده Anonymous را پیکربندی کند، این فلگ با --anonymous-auth هم‌زمان قابل استفاده نیست.
--authentication-token-webhook-cache-ttl duration     Default: 2m0s

مدت زمان نگهداری پاسخ‌های webhook احراز‌کننده هویت توکن در حافظه نهان (cache).
--authentication-token-webhook-config-file string

فایل حاوی پیکربندی webhook برای احراز هویت توکن با قالب kubeconfig. API server برای تعیین احراز هویت bearer tokenها از سرویس راه دور پرس‌وجو می‌کند.
--authentication-token-webhook-version string     Default: "v1beta1"

نسخه API مربوط به TokenReview در authentication.k8s.io که به webhook ارسال می‌شود و از آن انتظار می‌رود.
--authorization-config string

فایل حاوی پیکربندی مجوزدهی (Authorization Configuration) برای پیکربندی زنجیره authorizerها. این فلگ با سایر فلگ‌های --authorization-mode و --authorization-webhook-* هم‌زمان قابل استفاده نیست.
--authorization-mode strings

فهرست مرتب‌شده‌ای از افزونه‌ها برای انجام مجوزدهی روی پورت امن. اگر --authorization-config استفاده نشود، مقدار پیش‌فرض AlwaysAllow است. فهرستی که با کاما جدا شده است از: AlwaysAllow,AlwaysDeny,ABAC,Webhook,RBAC,Node.
--authorization-policy-file string

فایل حاوی سیاست مجوزدهی با قالب json خط‌به‌خط که همراه با --authorization-mode=ABAC روی پورت امن استفاده می‌شود.
--authorization-webhook-cache-authorized-ttl duration     Default: 5m0s

مدت زمان نگهداری پاسخ‌های 'authorized' از webhook مجوزدهنده (authorizer) در حافظه نهان (cache).
--authorization-webhook-cache-unauthorized-ttl duration     Default: 30s

مدت زمان نگهداری پاسخ‌های 'unauthorized' از webhook مجوزدهنده (authorizer) در حافظه نهان (cache).
--authorization-webhook-config-file string

فایل حاوی پیکربندی webhook با قالب kubeconfig که همراه با --authorization-mode=Webhook استفاده می‌شود. API server برای تعیین دسترسی روی پورت امن API server از سرویس راه دور پرس‌وجو می‌کند.
--authorization-webhook-version string     Default: "v1beta1"

نسخهٔ API مربوط به SubjectAccessReview از گروه authorization.k8s.io که باید به webhook ارسال شود و از آن انتظار می‌رود.
--bind-address string     Default: 0.0.0.0

آدرس IP که برای گوش دادن روی پورت --secure-port استفاده می‌شود. اینترفیس‌های مرتبط باید برای بقیهٔ کلاستر و برای کلاینت‌های CLI/وب در دسترس باشند. اگر خالی باشد یا یک آدرس نامشخص (0.0.0.0 یا ::) باشد، همهٔ اینترفیس‌ها و خانواده‌های آدرس IP استفاده خواهند شد.
--cert-dir string     Default: "/var/run/kubernetes"

دایرکتوری که گواهی‌های TLS در آن قرار دارند. اگر --tls-cert-file و --tls-private-key-file تعیین شده باشند، این فلگ نادیده گرفته می‌شود.
--client-ca-file string

در صورت تنظیم، هر درخواستی که گواهی کلاینتی را ارائه کند که توسط یکی از مراجع موجود در client-ca-file امضا شده باشد، با هویتی متناظر با CommonName آن گواهی کلاینت احراز هویت می‌شود.
--contention-profiling

در صورتی که profiling فعال باشد، block profiling را فعال می‌کند.
--coordinated-leadership-lease-duration duration     Default: 15s

مدت زمان lease مورد استفاده برای انتخاب رهبر هماهنگ‌شده (Coordinated Leader Election).
--coordinated-leadership-renew-deadline duration     Default: 10s

مهلت تمدید lease در انتخاب رهبر هماهنگ‌شده.
--coordinated-leadership-retry-period duration     Default: 2s

فاصلهٔ زمانی تلاش مجدد برای تمدید lease در انتخاب رهبر هماهنگ‌شده.
--cors-allowed-origins strings

فهرست originهای مجاز برای CORS که با ویرگول از هم جدا شده‌اند. یک origin مجاز می‌تواند یک عبارت باقاعده (regular expression) باشد تا تطبیق زیردامنه‌ها را پشتیبانی کند. اگر این فهرست خالی باشد، CORS فعال نخواهد شد. لطفاً اطمینان حاصل کنید که هر عبارت کل نام میزبان را تطبیق می‌دهد؛ برای این کار، ابتدای آن را با '^' یا با گنجاندن پیشوند '//' و انتهای آن را با '$' یا با گنجاندن پسوند جداکنندهٔ پورت ':' مقید کنید. نمونه‌هایی از عبارت‌های معتبر عبارت‌اند از '//example.com(:|$)' و '^https://example.com(:|$)'
--debug-socket-path string

برای profiling از یک سوکت دامنهٔ یونیکس محافظت‌نشده (بدون authn/authz) با مسیر داده‌شده استفاده می‌کند.
--default-not-ready-toleration-seconds int     Default: 300

مقدار tolerationSeconds را برای toleration مربوط به notReady:NoExecute مشخص می‌کند که به‌طور پیش‌فرض به هر Pod که قبلاً چنین toleration ای نداشته باشد افزوده می‌شود.
--default-unreachable-toleration-seconds int     Default: 300

مقدار tolerationSeconds را برای toleration مربوط به unreachable:NoExecute مشخص می‌کند که به‌طور پیش‌فرض به هر Pod که قبلاً چنین toleration ای نداشته باشد افزوده می‌شود.
--delete-collection-workers int     Default: 1

شناسه صادرکننده توکن service account. صادرکننده این شناسه را در claim با نام "iss" توکن‌های صادرشده درج می‌کند. این مقدار یک رشته یا URI است. اگر این گزینه بر اساس مشخصات OpenID Discovery 1.0 یک URI معتبر نباشد، قابلیت ServiceAccountIssuerDiscovery حتی در صورتی که feature gate آن روی true تنظیم شده باشد، غیرفعال باقی می‌ماند. به‌شدت توصیه می‌شود که این مقدار با مشخصات OpenID مطابقت داشته باشد: https://openid.net/specs/openid-connect-discovery-1_0.html. در عمل، این به آن معناست که service-account-issuer باید یک URL از نوع https باشد. همچنین به‌شدت توصیه می‌شود که این URL قادر باشد اسناد OpenID discovery را در آدرس {service-account-issuer}/.well-known/openid-configuration ارائه دهد. وقتی این فلگ چندین بار مشخص شود، اولین مقدار برای تولید توکن‌ها استفاده می‌شود و همه مقادیر برای تعیین اینکه کدام صادرکنندگان پذیرفته شوند به کار می‌روند.

URI مربوط به JSON Web Key Set را در سند discovery که در مسیر /.well-known/openid-configuration ارائه می‌شود، بازنویسی می‌کند. این فلگ زمانی مفید است که سند discovery و مجموعه کلیدها از طریق URLی غیر از آدرس خارجی API server (که به‌صورت خودکار شناسایی می‌شود یا با external-hostname بازنویسی شده است) به relying partyها ارائه شوند.
--service-account-key-file strings

فایلی حاوی کلیدهای خصوصی یا عمومی RSA یا ECDSA از نوع x509 با کدگذاری PEM که برای تأیید توکن‌های ServiceAccount استفاده می‌شود. فایل مشخص‌شده می‌تواند شامل چندین کلید باشد و این فلگ را می‌توان چندین بار با فایل‌های متفاوت مشخص کرد. اگر مشخص نشود، از --tls-private-key-file استفاده می‌شود. هنگامی که --service-account-signing-key-file ارائه شده باشد، باید این فلگ نیز مشخص شود.
--service-account-lookup     Default: true

اگر true باشد، در چارچوب احراز هویت، وجود توکن‌های ServiceAccount در etcd اعتبارسنجی می‌شود.
--service-account-max-token-expiration duration

حداکثر مدت اعتبار توکنی که توسط صادرکننده توکن service account ایجاد می‌شود. اگر یک TokenRequest که در غیر این صورت معتبر است، مدت اعتباری بیشتر از این مقدار درخواست کند، توکن با مدت اعتبار برابر با همین مقدار صادر خواهد شد.
--service-account-signing-endpoint string

مسیر سوکتی که یک امضاکننده JWT خارجی روی آن گوش می‌دهد. این فلگ با --service-account-signing-key-file و --service-account-key-file ناسازگار است و نمی‌توان آن‌ها را هم‌زمان به کار برد. نیازمند فعال‌سازی feature gate با نام ExternalServiceAccountTokenSigner است.
--service-account-signing-key-file string

مسیر فایلی که شامل کلید خصوصی فعلی صادرکننده توکن service account است. صادرکننده توکن‌های ID صادرشده را با این کلید خصوصی امضا می‌کند.
--service-cluster-ip-range string

محدوده IP با نمادگذاری CIDR که از آن IPهای کلاستری Serviceها تخصیص داده می‌شود. این محدوده نباید با هیچ‌یک از محدوده‌های IP تخصیص‌یافته به نودها یا Podها هم‌پوشانی داشته باشد. حداکثر دو CIDR دوپشته‌ای (dual-stack) مجاز است.
--service-node-port-range <a string in the form 'N1-N2'>     Default: 30000-32767

محدوده‌ای از پورت‌ها که برای Serviceهای با قابلیت دسترسی NodePort رزرو می‌شود. این محدوده نباید با محدوده پورت‌های موقت (ephemeral) روی نودها هم‌پوشانی داشته باشد. مثال: '30000-32767'. هر دو سر محدوده شامل می‌شوند.
--show-hidden-metrics-for-version string

نسخه قبلی که می‌خواهید معیارهای پنهان‌شده آن نمایش داده شود. فقط نسخه فرعی (minor) قبلی معنا دارد و مقادیر دیگر پذیرفته نمی‌شوند. قالب آن <major>.<minor> است، برای مثال: '1.16'. هدف از این قالب آن است که اگر انتشار بعدی معیارهای بیشتری را پنهان کند، فرصت داشته باشید متوجه آن شوید و با حذف دائمی آن‌ها در انتشار پس از آن غافلگیر نشوید.
--shutdown-delay-duration duration

مدت زمان تأخیر در خاتمه‌دادن. در این مدت، سرور همچنان درخواست‌ها را به‌طور عادی پاسخ می‌دهد. endpointهای /healthz و /livez موفقیت را برمی‌گردانند، اما /readyz بلافاصله شکست را برمی‌گرداند. خاتمه مطلوب (graceful termination) پس از سپری‌شدن این تأخیر آغاز می‌شود. از این گزینه می‌توان برای این استفاده کرد که load balancer ارسال ترافیک به این سرور را متوقف کند.
--shutdown-send-retry-after

اگر true باشد، سرور HTTP تا زمانی که همه درخواست‌های در حال پردازشِ غیرطولانی‌مدت تخلیه شوند به گوش دادن ادامه می‌دهد؛ در این بازه، همه درخواست‌های ورودی با کد وضعیت 429 و هدر پاسخ 'Retry-After' رد می‌شوند و علاوه بر آن، هدر پاسخ 'Connection: close' تنظیم می‌شود تا اتصال TCP در زمان بیکاری قطع شود.
--shutdown-watch-termination-grace-period duration

این گزینه در صورت تنظیم، بیشترین مدت مهلتی را مشخص می‌کند که apiserver در بازه خاموش‌شدن مطلوب سرور منتظر می‌ماند تا درخواست‌های watch فعال تخلیه شوند.
--storage-backend string

بک‌اند ذخیره‌سازی برای پایداری داده‌ها. گزینه‌ها: 'etcd3' (پیش‌فرض).
--storage-initialization-timeout duration     Default: 1m0s

حداکثر مدت انتظار برای راه‌اندازی اولیه ذخیره‌سازی پیش از اعلام آماده‌بودن apiserver. مقدار پیش‌فرض 1m است.
--storage-media-type string     Default: "application/vnd.kubernetes.protobuf"

نوع رسانه‌ای (media type) که برای ذخیره آبجکت‌ها در ذخیره‌سازی استفاده می‌شود. برخی منابع یا بک‌اندهای ذخیره‌سازی ممکن است فقط از یک نوع رسانه خاص پشتیبانی کنند و این تنظیم را نادیده بگیرند. انواع رسانه پشتیبانی‌شده: [application/json, application/yaml, application/vnd.kubernetes.protobuf]
--strict-transport-security-directives strings

فهرست دستورهای (directives) HSTS که با کاما از هم جدا می‌شوند. اگر این فهرست خالی باشد، دستورهای HSTS اضافه نخواهند شد. مثال: 'max-age=31536000,includeSubDomains,preload'
--tls-cert-file string

فایلی حاوی گواهی x509 پیش‌فرض برای HTTPS. (گواهی CA، در صورت وجود، پس از گواهی سرور به آن الحاق می‌شود). اگر ارائه HTTPS فعال باشد و --tls-cert-file و --tls-private-key-file ارائه نشده باشند، یک گواهی و کلید خودامضا برای آدرس عمومی تولید و در دایرکتوری مشخص‌شده با --cert-dir ذخیره می‌شود.
--tls-cipher-suites strings

فهرست مجموعه‌رمزهای (cipher suites) سرور که با کاما از هم جدا می‌شوند. اگر حذف شود، از مجموعه‌رمزهای پیش‌فرض Go استفاده می‌شود.
مقادیر ترجیحی: TLS_AES_128_GCM_SHA256, TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256, TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_ECDSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256, TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305, TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256.
مقادیر ناامن: TLS_ECDHE_ECDSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, TLS_ECDHE_RSA_WITH_3DES_EDE_CBC_SHA, TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256, TLS_ECDHE_RSA_WITH_RC4_128_SHA, TLS_RSA_WITH_3DES_EDE_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA, TLS_RSA_WITH_AES_128_CBC_SHA256, TLS_RSA_WITH_AES_128_GCM_SHA256, TLS_RSA_WITH_AES_256_CBC_SHA, TLS_RSA_WITH_AES_256_GCM_SHA384, TLS_RSA_WITH_RC4_128_SHA.
--tls-curve-preferences int32Slice     Default: []

فهرستی از مقادیر عددی CurveID در crypto/tls زبان Go که با کاما از هم جدا شده‌اند و به‌عنوان سازوکارهای مجاز تبادل کلید برای سرور به کار می‌روند. مقادیر پشتیبانی‌شده به نسخه Go مورد استفاده بستگی دارد. برای مشاهده مقادیر پشتیبانی‌شده در هر نسخه Go به https://pkg.go.dev/crypto/tls#CurveID مراجعه کنید. ترتیب فهرست نادیده گرفته می‌شود و سازوکارهای تبادل کلید توسط Go از این فهرست و بر اساس یک ترتیب ترجیحی داخلی انتخاب می‌شوند. اگر حذف شود، از منحنی‌های پیش‌فرض Go استفاده می‌شود.
--tls-min-version string

حداقل نسخه TLS پشتیبانی‌شده. مقادیر ممکن: VersionTLS10, VersionTLS11, VersionTLS12, VersionTLS13
--tls-private-key-file string

فایلی حاوی کلید خصوصی x509 پیش‌فرض که با --tls-cert-file مطابقت دارد.
--tls-sni-cert-key string

یک جفت مسیر فایل گواهی x509 و کلید خصوصی که می‌تواند در انتها فهرستی از الگوهای دامنه (domain patterns) داشته باشد؛ این الگوها نام‌های دامنه کاملاً معتبر (fully qualified) هستند و ممکن است بخش‌های wildcard در ابتدای آن‌ها آمده باشد. الگوهای دامنه آدرس‌های IP را نیز مجاز می‌دانند، اما IPها فقط در صورتی باید استفاده شوند که apiserver به آدرس IP درخواست‌شده توسط کلاینت دسترسی داشته باشد. اگر هیچ الگوی دامنه‌ای ارائه نشود، نام‌های موجود در گواهی استخراج می‌شوند. تطابق‌های بدون wildcard بر تطابق‌های wildcard اولویت دارند و الگوهای دامنه صریح بر نام‌های استخراج‌شده اولویت دارند. برای چند جفت کلید/گواهی، فلگ --tls-sni-cert-key را چندین بار به کار ببرید. مثال‌ها: "example.crt,example.key" یا "foo.crt,foo.key:*.foo.com,foo.com".
--token-auth-file string

در صورت تنظیم، فایلی که برای ایمن‌سازی پورت امن API server از طریق احراز هویت مبتنی بر توکن استفاده می‌شود.
--tracing-config-file string

فایل پیکربندی ردیابی (tracing) مربوط به apiserver.
-v, --v int

عددی برای تعیین سطح جزئیات لاگ
--version version[=true]

--version و --version=raw اطلاعات نسخه را چاپ کرده و خارج می‌شوند؛ --version=vX.Y.Z... نسخه گزارش‌شده را تنظیم می‌کند
--vmodule pattern=N,...

فهرستی از تنظیمات pattern=N که با کاما از هم جدا می‌شوند، برای ثبت لاگ با فیلتر بر اساس فایل (فقط در قالب لاگ متنی کار می‌کند)
--watch-cache     Default: true

فعال‌سازی کش watch در apiserver
--watch-cache-sizes strings

تنظیمات اندازه کش watch برای برخی منابع (Podها، نودها و غیره) که با کاما از هم جدا می‌شوند. قالب هر تنظیم: resource[.group]#size است، که در آن resource حالت جمع با حروف کوچک (بدون نسخه) است، group برای منابع apiVersion v1 (API هسته قدیمی) حذف می‌شود و برای بقیه درج می‌شود، و size یک عدد است. این گزینه فقط برای منابعی معنا دارد که در apiserver تعبیه شده‌اند، نه منابعی که با CRDها تعریف شده‌اند یا از سرورهای خارجی تجمیع (aggregate) شده‌اند، و تنها در صورتی بررسی می‌شود که watch-cache فعال باشد. تنها مقدار معنادار برای size در اینجا صفر است که به معنای غیرفعال‌کردن کش watch برای منبع مربوطه است؛ همه مقادیر غیرصفر معادل هستند و به معنای غیرفعال‌نکردن کش watch برای آن منبع می‌باشند
