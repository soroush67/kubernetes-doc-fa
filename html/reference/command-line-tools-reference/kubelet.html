kubelet

خلاصه

kubelet عامل اصلی «نود» (node agent) است که روی هر نود اجرا می‌شود. این مؤلفه می‌تواند نود را با یکی از روش‌های زیر در apiserver ثبت کند: با استفاده از نام میزبان (hostname)؛ با استفاده از یک پرچم (flag) که نام میزبان را بازنویسی می‌کند؛ یا با استفاده از منطق مخصوص یک ارائه‌دهنده ابری (cloud provider).

kubelet بر اساس PodSpec کار می‌کند. PodSpec یک آبجکت YAML یا JSON است که یک pod را توصیف می‌کند. kubelet مجموعه‌ای از PodSpecها را که از طریق سازوکارهای گوناگون (عمدتاً از طریق apiserver) در اختیارش قرار می‌گیرد دریافت می‌کند و اطمینان می‌دهد که کانتینرهای توصیف‌شده در این PodSpecها در حال اجرا و سالم باشند. kubelet کانتینرهایی را که توسط کوبرنتیز ایجاد نشده‌اند مدیریت نمی‌کند.

علاوه بر PodSpec دریافتی از apiserver، دو روش دیگر نیز برای ارائه مانیفست کانتینر به kubelet وجود دارد.

فایل: مسیری که به‌صورت یک پرچم در خط فرمان داده می‌شود. فایل‌های موجود در این مسیر به‌طور دوره‌ای برای یافتن به‌روزرسانی‌ها پایش می‌شوند. بازه پایش به‌طور پیش‌فرض ۲۰ ثانیه است و از طریق یک پرچم قابل پیکربندی است.

نقطه پایانی HTTP (HTTP endpoint): نقطه پایانی HTTP که به‌صورت یک پارامتر در خط فرمان داده می‌شود. این نقطه پایانی هر ۲۰ ثانیه بررسی می‌شود (این بازه نیز با یک پرچم قابل پیکربندی است).

kubelet [flags]

گزینه‌ها

--address string     Default: 0.0.0.0

آدرس IP که Kubelet روی آن سرویس‌دهی می‌کند (برای گوش دادن روی تمام اینترفیس‌ها و خانواده‌های آدرس IP مقدار '0.0.0.0' یا '::' را تنظیم کنید) (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--allowed-unsafe-sysctls strings

فهرست مجاز، جداشده با کاما، از sysctlهای ناایمن یا الگوهای sysctl ناایمن (که به * ختم می‌شوند). استفاده از این موارد با مسئولیت خودتان است. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--anonymous-auth     Default: true

درخواست‌های ناشناس به سرور Kubelet را فعال می‌کند. درخواست‌هایی که توسط روش احراز هویت دیگری رد نشوند، به‌عنوان درخواست ناشناس در نظر گرفته می‌شوند. درخواست‌های ناشناس دارای نام کاربری system:anonymous و نام گروه system:unauthenticated هستند. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--authentication-token-webhook

برای تعیین احراز هویت توکن‌های bearer از TokenReview API استفاده می‌کند. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--authentication-token-webhook-cache-ttl duration     Default: 2m0s

مدت زمان نگهداری پاسخ‌های احراز‌کننده توکن webhook در حافظه نهان. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--authorization-mode string     Default: "AlwaysAllow"

حالت مجوزدهی برای سرور Kubelet. گزینه‌های معتبر AlwaysAllow یا Webhook هستند. حالت Webhook برای تعیین مجوزدهی از SubjectAccessReview API استفاده می‌کند. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)

مدت زمان نگهداری پاسخ‌های «مجاز» (authorized) از مجوزدهنده webhook در حافظه نهان. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--authorization-webhook-cache-unauthorized-ttl duration     Default: 30s

مدت زمان نگهداری پاسخ‌های «غیرمجاز» (unauthorized) از مجوزدهنده webhook در حافظه نهان. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--bootstrap-kubeconfig string

مسیر یک فایل kubeconfig که برای دریافت گواهی کلاینت برای kubelet استفاده می‌شود. اگر فایل مشخص‌شده با --kubeconfig وجود نداشته باشد، از bootstrap kubeconfig برای درخواست گواهی کلاینت از API server استفاده می‌شود. در صورت موفقیت، یک فایل kubeconfig که به گواهی کلاینت و کلید تولیدشده ارجاع می‌دهد در مسیر مشخص‌شده با --kubeconfig نوشته می‌شود. فایل گواهی کلاینت و کلید در دایرکتوری مشخص‌شده با --cert-dir ذخیره خواهد شد.
--cert-dir string     Default: "/var/lib/kubelet/pki"

دایرکتوری که گواهی‌های TLS در آن قرار دارند. اگر --tls-cert-file و --tls-private-key-file ارائه شده باشند، این پرچم نادیده گرفته می‌شود.
--cgroup-driver string     Default: "cgroupfs"

درایوری که kubelet برای مدیریت cgroupها روی میزبان از آن استفاده می‌کند. مقادیر ممکن: 'cgroupfs'، 'systemd' (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--cgroup-root string

cgroup ریشه اختیاری برای استفاده توسط podها. این مورد توسط container runtime و در حد امکان (best effort) مدیریت می‌شود. مقدار پیش‌فرض: '' که به معنای استفاده از مقدار پیش‌فرض container runtime است. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--cgroups-per-qos     Default: true

ایجاد سلسله‌مراتب cgroup مربوط به QoS را فعال می‌کند؛ در صورت true بودن، cgroupهای سطح بالای QoS و cgroupهای podها ایجاد می‌شوند. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--client-ca-file string

در صورت تنظیم، هر درخواستی که گواهی کلاینتی ارائه کند که توسط یکی از مراجع موجود در client-ca-file امضا شده باشد، با هویتی متناظر با CommonName گواهی کلاینت احراز هویت می‌شود. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--cloud-provider string

ارائه‌دهنده سرویس‌های ابری. برای اجرا بدون ارائه‌دهنده ابری، آن را روی رشته خالی تنظیم کنید. برای اجرا با یک ارائه‌دهنده ابری خارجی، آن را روی 'external' تنظیم کنید.
--cluster-dns strings

فهرست آدرس‌های IP سرورهای DNS، جداشده با کاما. این مقدار برای سرور DNS کانتینرها در Podهایی با "dnsPolicy=ClusterFirst" استفاده می‌شود. توجه: تمام سرورهای DNS موجود در این فهرست باید مجموعه رکوردهای یکسانی را ارائه کنند، در غیر این صورت ممکن است تفکیک نام در داخل کلاستر به‌درستی کار نکند. هیچ تضمینی وجود ندارد که برای تفکیک نام با کدام سرور DNS ارتباط برقرار شود. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--cluster-domain string

دامنه این کلاستر. در صورت تنظیم، kubelet تمام کانتینرها را طوری پیکربندی می‌کند که علاوه بر دامنه‌های جست‌وجوی میزبان، این دامنه را نیز جست‌وجو کنند. (منسوخ‌شده: این پارامتر باید از طریق فایل پیکربندی که با پرچم --config مربوط به Kubelet مشخص می‌شود تنظیم شود. برای اطلاعات بیشتر به https://kubernetes.io/docs/tasks/administer-cluster/kubelet-config-file/ مراجعه کنید.)
--config string

Kubelet پیکربندی اولیه خود را از این فایل بارگذاری می‌کند. مسیر می‌تواند مطلق یا نسبی باشد؛ مسیرهای نسبی از دایرکتوری کاری فعلی Kubelet شروع می‌شوند. برای استفاده از مقادیر پیش‌فرض داخلی پیکربندی، این پرچم را حذف کنید. پرچم‌های خط فرمان، پیکربندی این فایل را بازنویسی می‌کنند.
--config-dir string

مسیر دایرکتوری حاوی فایل‌های پیکربندی drop-in که تنظیمات مقادیر پیش‌فرض و فایل --config را بازنویسی می‌کنند. مسیر می‌تواند مطلق یا نسبی باشد؛ مسیرهای نسبی از دایرکتوری کاری فعلی Kubelet شروع می‌شوند. فایل‌های drop-in باید پسوند '.conf' داشته باشند (مثلاً '99-kubelet-address.conf') و به ترتیب واژه‌نامه‌ای (lexical) پردازش می‌شوند. فقط فایل‌های '.conf' بارگذاری می‌شوند و سایر فایل‌ها نادیده گرفته می‌شوند. تمام فایل‌های .conf موجود در دایرکتوری و زیردایرکتوری‌های آن به ترتیب واژه‌نامه‌ای پردازش می‌شوند.
