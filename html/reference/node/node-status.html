وضعیت نود

وضعیت یک نود در کوبرنتیز جنبه‌ای حیاتی از مدیریت کلاستر کوبرنتیز است. در این مقاله، مبانی پایش و نگهداری وضعیت نود را برای اطمینان از سلامت و پایداری کلاستر بررسی می‌کنیم.

فیلدهای وضعیت نود

وضعیت هر Node شامل اطلاعات زیر است:

  • آدرس‌ها
  • شرایط
  • ظرفیت و مقدار تخصیص‌پذیر
  • اطلاعات
  • ویژگی‌های اعلام‌شده

برای مشاهده وضعیت یک Node و جزئیات دیگر آن می‌توانید از kubectl استفاده کنید:

kubectl describe node <insert-node-name-here>

هر بخش از این خروجی در ادامه توضیح داده شده است.

آدرس‌ها

کاربرد این فیلدها بسته به ارائه‌دهنده ابری یا پیکربندی سرور فیزیکی (bare metal) شما متفاوت است.

  • فیلد HostName: نام میزبان، همان‌گونه که هسته نود گزارش می‌کند. می‌توان این مقدار را با پارامتر --hostname-override در kubelet بازنویسی کرد.
  • فیلد ExternalIP: معمولاً آدرس IP نود است که از خارج کلاستر قابل مسیریابی و در دسترس است.
  • فیلد InternalIP: معمولاً آدرس IP نود است که فقط در داخل کلاستر قابل مسیریابی است.

شرایط {#condition}

فیلد conditions وضعیت همه نودهای Running را توصیف می‌کند. نمونه‌هایی از این شرایط عبارت‌اند از:

شرط نود توضیح
Ready اگر نود سالم و آماده پذیرش Podها باشد، مقدار آن True است؛ اگر نود سالم نباشد و Podها را نپذیرد، False است؛ و اگر کنترل‌کننده نود در بازه node-monitor-grace-period اخیر (به‌طور پیش‌فرض ۵۰ ثانیه) پیامی از نود دریافت نکرده باشد، Unknown است
DiskPressure اگر روی فضای دیسک فشار وجود داشته باشد، یعنی ظرفیت دیسک کم باشد، مقدار آن True و در غیر این صورت False است
MemoryPressure اگر روی حافظه نود فشار وجود داشته باشد، یعنی حافظه نود کم باشد، مقدار آن True و در غیر این صورت False است
PIDPressure اگر روی پردازه‌ها فشار وجود داشته باشد، یعنی تعداد پردازه‌های روی نود بیش از حد باشد، مقدار آن True و در غیر این صورت False است
NetworkUnavailable اگر شبکه نود به‌درستی پیکربندی نشده باشد، مقدار آن True و در غیر این صورت False است
توجه:

اگر با ابزارهای خط فرمان جزئیات یک Node از نوع cordon‌شده را چاپ کنید، بخش Condition شامل SchedulingDisabled خواهد بود. با این حال، SchedulingDisabled در API کوبرنتیز یک Condition نیست؛ بلکه نودهای cordon‌شده در spec خود با مقدار Unschedulable علامت‌گذاری می‌شوند.

در API کوبرنتیز، شرایط نود به‌عنوان بخشی از .status منبع Node نمایش داده می‌شود. برای مثال، ساختار JSON زیر یک نود سالم را توصیف می‌کند:

"conditions": [
  {
    "type": "Ready",
    "status": "True",
    "reason": "KubeletReady",
    "message": "kubelet is posting ready status",
    "lastHeartbeatTime": "2019-06-05T18:38:35Z",
    "lastTransitionTime": "2019-06-05T11:41:27Z"
  }
]

هنگامی که روی نودها مشکلی رخ می‌دهد، control plane کوبرنتیز به‌طور خودکار taintهایی متناسب با شرایط اثرگذار بر نود ایجاد می‌کند. برای نمونه، ممکن است status شرط Ready بیش از مقدار NodeMonitorGracePeriod در kube-controller-manager، که به‌طور پیش‌فرض ۵۰ ثانیه است، روی Unknown یا False بماند. در این حالت، برای وضعیت Unknown یک taint با نام node.kubernetes.io/unreachable و برای وضعیت False یک taint با نام node.kubernetes.io/not-ready به Node افزوده می‌شود.

این taintها بر Podهای در انتظار اثر می‌گذارند، زیرا زمان‌بند هنگام تخصیص Pod به Node، taintهای آن را در نظر می‌گیرد. ممکن است Podهای موجودی که روی نود زمان‌بندی شده‌اند، بر اثر اعمال taintهای NoExecute بیرون رانده شوند. همچنین Podها می‌توانند تحمل‌پذیری‌هایی (toleration) داشته باشند که به آن‌ها امکان می‌دهد با وجود taint مشخصی روی یک Node، روی آن زمان‌بندی شوند و به اجرا ادامه دهند.

برای جزئیات بیشتر، بیرون‌راندن مبتنی بر taint و اعمال taint بر نودها بر اساس شرایط را ببینید.

ظرفیت و مقدار تخصیص‌پذیر {#capacity}

این بخش منابع موجود روی نود را توصیف می‌کند: CPU، حافظه و حداکثر تعداد Podهایی که می‌توان روی نود زمان‌بندی کرد.

فیلدهای بلوک capacity مقدار کل منابع یک Node را نشان می‌دهند. بلوک allocatable مقدار منابعی از Node را نشان می‌دهد که Podهای عادی می‌توانند مصرف کنند.

هنگام یادگیری شیوه رزرو منابع محاسباتی روی یک Node، می‌توانید درباره ظرفیت و منابع تخصیص‌پذیر بیشتر بخوانید.

اطلاعات

این بخش اطلاعات کلی نود را توصیف می‌کند؛ مانند نسخه هسته، نسخه کوبرنتیز (نسخه kubelet و kube-proxy)، جزئیات محیط اجرای کانتینر و سیستم‌عاملی که نود از آن استفاده می‌کند. مؤلفه kubelet این اطلاعات را از نود جمع‌آوری می‌کند و در API کوبرنتیز منتشر می‌سازد.

ویژگی‌های اعلام‌شده {#declaredfeatures}

وضعیت ویژگی: Kubernetes [] ()

این فیلد ویژگی‌های مشخصی از کوبرنتیز را فهرست می‌کند که در حال حاضر از طریق feature gateها در kubelet نود فعال هستند. مؤلفه kubelet این ویژگی‌ها را به‌صورت فهرستی از رشته‌ها در فیلد .status.declaredFeatures آبجکت Node گزارش می‌کند.

این فیلد برای ویژگی‌های جدیدتری در نظر گرفته شده است که در حال توسعه فعال هستند. ویژگی‌هایی که به مرحله نهایی رسیده‌اند و دیگر به feature gate نیاز ندارند، جزو قابلیت‌های پایه به شمار می‌روند و در این فیلد اعلام نمی‌شوند. این فیلد فعال بودن ویژگی‌های کوبرنتیز را نشان می‌دهد، نه قابلیت‌های سیستم‌عامل یا هسته زیربنایی نود را.

برای جزئیات بیشتر، ویژگی‌های اعلام‌شده نود را ببینید.

ضربان‌های حیات

ضربان‌های حیات (heartbeat) که نودهای کوبرنتیز ارسال می‌کنند، به کلاستر کمک می‌کنند در دسترس بودن هر نود را تشخیص دهد و هنگام شناسایی خرابی، اقدام مناسب را انجام دهد.

نودها دو نوع ضربان حیات دارند:

  • به‌روزرسانی‌های .status یک Node
  • آبجکت‌های Lease در فضای نام (namespace) kube-node-lease. هر Node یک آبجکت Lease مرتبط دارد.

در مقایسه با به‌روزرسانی‌های .status یک Node، منبع Lease سبک است. استفاده از Leaseها برای ضربان حیات، تأثیر این به‌روزرسانی‌ها را بر کارایی کلاسترهای بزرگ کاهش می‌دهد.

مسئولیت ایجاد و به‌روزرسانی .status نودها و نیز به‌روزرسانی Leaseهای مرتبط با آن‌ها بر عهده kubelet است.

  • مؤلفه kubelet هنگام تغییر وضعیت، یا در صورت انجام نشدن به‌روزرسانی در یک بازه پیکربندی‌شده، .status نود را به‌روزرسانی می‌کند. بازه پیش‌فرض به‌روزرسانی .status نودها ۵ دقیقه است که بسیار طولانی‌تر از مهلت پیش‌فرض ۴۰ ثانیه‌ای برای نودهای غیرقابل دسترس است.
  • مؤلفه kubelet آبجکت Lease خود را ایجاد می‌کند و سپس آن را هر ۱۰ ثانیه (بازه پیش‌فرض به‌روزرسانی) به‌روزرسانی می‌کند. به‌روزرسانی‌های Lease مستقل از به‌روزرسانی‌های .status نود انجام می‌شوند. اگر به‌روزرسانی Lease با شکست مواجه شود، kubelet با عقب‌نشینی نمایی (exponential backoff) دوباره تلاش می‌کند؛ این عقب‌نشینی از ۲۰۰ میلی‌ثانیه آغاز می‌شود و حداکثر به ۷ ثانیه می‌رسد.
