کتابخانه‌های کلاینت با پشتیبانی رسمی

برای فراخوانی API کوبرنتیز از یک زبان برنامه‌نویسی می‌توانید از کتابخانه‌های کلاینت استفاده کنید. کتابخانه‌های کلاینت با پشتیبانی رسمی عبارت‌اند از:

  • کتابخانه کلاینت Go برای کوبرنتیز
  • کتابخانه کلاینت Python برای کوبرنتیز
  • کتابخانه کلاینت Java برای کوبرنتیز
  • کتابخانه کلاینت JavaScript برای کوبرنتیز
  • کتابخانه کلاینت C# برای کوبرنتیز
  • کتابخانه کلاینت Haskell برای کوبرنتیز

CLI

  • kubectl - ابزار اصلی خط فرمان برای اجرای دستورات و مدیریت کلاسترهای کوبرنتیز.
    • JSONPath - راهنمای نحو برای استفاده از عبارات JSONPath در kubectl.
  • kubeadm - ابزار خط فرمان برای راه‌اندازی آسان یک کلاستر امن کوبرنتیز.

مؤلفه‌ها

  • kubelet - عامل اصلی که روی هر نود اجرا می‌شود. kubelet مجموعه‌ای از PodSpecها را دریافت می‌کند و اطمینان می‌دهد کانتینرهای توصیف‌شده در آن‌ها در حال اجرا و سالم هستند.

  • kube-apiserver - یک REST API که داده‌های آبجکت‌های API مانند Podها، Serviceها و replication controllerها را اعتبارسنجی و پیکربندی می‌کند.

  • kube-controller-manager - دیمنی که حلقه‌های کنترلی اصلی همراه با کوبرنتیز را در خود جای داده است.

  • kube-proxy - می‌تواند هدایت ساده جریان TCP/UDP یا هدایت round-robin ترافیک TCP/UDP را میان مجموعه‌ای از بک‌اندها انجام دهد.

  • kube-scheduler - زمان‌بندی که دسترس‌پذیری، کارایی و ظرفیت را مدیریت می‌کند.

    • سیاست‌های زمان‌بند
    • پروفایل‌های زمان‌بند

  • فهرست پورت‌ها و پروتکل‌ها که باید روی نودهای control plane و worker باز باشند

کدگذاری‌ها

ابزارهایی مانند kubectl می‌توانند با قالب‌ها / کدگذاری‌های مختلف کار کنند. این موارد عبارت‌اند از:

  • CBOR، که روی شبکه استفاده می‌شود اما به‌عنوان قالب خروجی kubectl در دسترس نیست
    • بخش کدگذاری CBOR برای منابع را ببینید
  • JSON، که به‌عنوان قالب خروجی kubectl در دسترس است و در لایهٔ HTTP نیز استفاده می‌شود
  • KYAML، گویشی از YAML مختص کوبرنتیز
    • KYAML در اصل یک قالب خروجی است؛ در هر جایی که می‌توانید KYAML را به کوبرنتیز بدهید، می‌توانید هر ورودی معتبر YAML دیگری را نیز ارائه کنید
  • YAML، که به‌عنوان قالب خروجی kubectl در دسترس است و در لایهٔ HTTP نیز استفاده می‌شود

کوبرنتیز همچنین یک کدگذاری protobuf اختصاصی دارد که فقط در پیام‌های HTTP استفاده می‌شود.

ابزار kubectl از برخی قالب‌های خروجی دیگر مانند custom columns پشتیبانی می‌کند؛ بخش قالب‌های خروجی را در مرجع kubectl ببینید.
