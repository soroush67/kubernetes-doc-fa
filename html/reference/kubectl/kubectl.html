kubectl

خلاصه

(تعریف واژه‌نامه: kubectl)

اطلاعات بیشتر را در ابزار خط فرمان (kubectl) بیابید.

kubectl [flags]

گزینه‌ها

--add-dir-header
اگر true باشد، دایرکتوری فایل به سرآیند پیام‌های لاگ اضافه می‌شود
--alsologtostderr
لاگ‌ها علاوه بر فایل‌ها در خروجی خطای استاندارد نیز نوشته می‌شوند
--as string
نام کاربری که عملیات با جعل هویت (impersonation) آن انجام می‌شود
--as-group stringArray
گروهی که عملیات با جعل هویت آن انجام می‌شود؛ برای مشخص کردن چند گروه می‌توان این فلگ را تکرار کرد.
--azure-container-registry-config string
مسیر فایلی که اطلاعات پیکربندی رجیستری کانتینر Azure را در خود دارد.
--cache-dir string     پیش‌فرض: "$HOME/.kube/cache"

--client-key string
مسیر فایل کلید کلاینت برای TLS

--cloud-provider-gce-lb-src-cidrs cidrs     پیش‌فرض: 130.211.0.0/22,209.85.152.0/22,209.85.204.0/22,35.191.0.0/16
محدوده‌های CIDR که در فایروال GCE برای پراکسی ترافیک متعادل‌کنندهٔ بار لایهٔ ۴ (L4 LB) و بررسی‌های سلامت باز شده‌اند

--default-unreachable-toleration-seconds int     پیش‌فرض: 300
مقدار tolerationSeconds را برای toleration مربوط به unreachable:NoExecute مشخص می‌کند؛ این toleration به‌طور پیش‌فرض به هر پادی که از قبل چنین tolerationای نداشته باشد اضافه می‌شود.
-h, --help

--kubeconfig string

--log-backtrace-at traceLocation     پیش‌فرض: :0

--log-file string
اگر خالی نباشد، از این فایل لاگ استفاده می‌شود
--log-file-max-size uint     پیش‌فرض: 1800
حداکثر اندازه‌ای را که یک فایل لاگ می‌تواند به آن برسد تعیین می‌کند. واحد آن مگابایت است. اگر مقدار آن 0 باشد، حداکثر اندازهٔ فایل نامحدود است.
--log-flush-frequency duration     پیش‌فرض: 5s
حداکثر فاصلهٔ زمانی بر حسب ثانیه میان دو بار تخلیهٔ (flush) لاگ‌ها
--logtostderr     پیش‌فرض: true
لاگ‌ها به‌جای فایل‌ها در خروجی خطای استاندارد نوشته می‌شوند
--match-server-version
الزام می‌کند که نسخهٔ سرور با نسخهٔ کلاینت یکسان باشد
-n, --namespace string
در صورت تعیین، دامنهٔ فضای نام (namespace) این درخواست CLI را مشخص می‌کند
--one-output
اگر true باشد، لاگ‌ها فقط در سطح شدت اصلی خودشان نوشته می‌شوند (به‌جای اینکه در همهٔ سطوح شدت پایین‌تر نیز نوشته شوند)
--password string
گذرواژه برای احراز هویت پایه (basic authentication) در سرور API
--profile string     پیش‌فرض: "none"
نام پروفایلی که باید ثبت شود. یکی از مقادیر (none|cpu|heap|goroutine|threadcreate|block|mutex)
--profile-output string     پیش‌فرض: "profile.pprof"
نام فایلی که پروفایل در آن نوشته می‌شود
--request-timeout string     پیش‌فرض: "0"
مدت زمانی که پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور باید منتظر ماند. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (مثلاً 1s، 2m، 3h). مقدار صفر به این معناست که درخواست‌ها هیچ‌گاه به مهلت زمانی نمی‌رسند.
-s, --server string
نشانی و پورت سرور API کوبرنتیز
--skip-headers
اگر true باشد، پیشوندهای سرآیند در پیام‌های لاگ نوشته نمی‌شوند
--skip-log-headers
اگر true باشد، هنگام باز کردن فایل‌های لاگ سرآیندی نوشته نمی‌شود
--stderrthreshold severity     پیش‌فرض: 2
لاگ‌هایی که در این آستانه یا بالاتر از آن باشند به stderr فرستاده می‌شوند
--tls-server-name string
نام سروری که برای اعتبارسنجی گواهی سرور به کار می‌رود. اگر تعیین نشود، از نام میزبانی استفاده می‌شود که برای برقراری ارتباط با سرور به کار رفته است
--token string
توکن حامل (Bearer) برای احراز هویت در سرور API
--user string
نام کاربری از kubeconfig که باید استفاده شود
--username string
نام کاربری برای احراز هویت پایه در سرور API
-v, --v Level
عدد سطح جزئیات (verbosity) لاگ
--version version[=true]
اطلاعات نسخه را چاپ می‌کند و خارج می‌شود
--vmodule moduleSpec
فهرستی از تنظیمات pattern=N، جداشده با کاما، برای لاگ‌گیری فیلترشده بر اساس فایل
--warnings-as-errors
هشدارهای دریافت‌شده از سرور را خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود

متغیرهای محیطی

KUBECONFIG
مسیر فایل پیکربندی kubectl ("kubeconfig"). پیش‌فرض: "$HOME/.kube/config"
KUBECTL_EXPLAIN_OPENAPIV3
تعیین می‌کند که فراخوانی‌های `kubectl explain` از منبع دادهٔ جدید و در دسترس OpenAPIv3 استفاده کنند یا نه. از کوبرنتیز 1.24 به بعد، OpenAPIV3 به‌طور پیش‌فرض فعال است.
KUBECTL_ENABLE_CMD_SHADOW
اگر روی true تنظیم شود، در صورتی که زیرفرمانی وجود نداشته باشد، می‌توان از افزونه‌های خارجی به‌عنوان زیرفرمانِ فرمان‌های داخلی استفاده کرد. در مرحلهٔ آلفا، این قابلیت فقط برای فرمان create قابل استفاده است (برای نمونه kubectl create networkpolicy).
KUBECTL_PORT_FORWARD_WEBSOCKETS
اگر روی true تنظیم شود، فرمان kubectl port-forward تلاش می‌کند جریان داده را با پروتکل websockets منتقل کند. اگر ارتقا به websockets ناموفق باشد، فرمان‌ها به استفاده از پروتکل فعلی SPDY بازمی‌گردند.
KUBECTL_REMOTE_COMMAND_WEBSOCKETS
اگر روی true تنظیم شود، فرمان‌های kubectl exec، cp و attach تلاش می‌کنند جریان داده را با پروتکل websockets منتقل کنند. اگر ارتقا به websockets ناموفق باشد، فرمان‌ها به استفاده از پروتکل فعلی SPDY بازمی‌گردند.
KUBECTL_KUBERC
اگر روی true تنظیم شود، فایل kuberc برای تعریف ترجیحات مختص هر کاربر در نظر گرفته می‌شود.

همچنین ببینید

  • kubectl annotate - به‌روزرسانی حاشیه‌نویسی‌های (annotation) یک منبع
  • kubectl api-resources - چاپ منابع API پشتیبانی‌شده روی سرور
  • kubectl api-versions - چاپ نسخه‌های API پشتیبانی‌شده روی سرور، به شکل "group/version"
  • kubectl apply - اعمال یک پیکربندی بر یک منبع با استفاده از نام فایل یا stdin
  • kubectl attach - اتصال به یک کانتینر در حال اجرا
  • kubectl auth - بررسی مجوزدهی
  • kubectl autoscale - مقیاس‌دهی خودکار یک Deployment، ReplicaSet یا ReplicationController
  • kubectl certificate - تغییر منابع گواهی.
  • kubectl cluster-info - نمایش اطلاعات کلاستر
  • kubectl completion - تولید کد تکمیل خودکار پوسته برای پوستهٔ مشخص‌شده (bash یا zsh)
  • kubectl config - تغییر فایل‌های kubeconfig
  • kubectl cordon - علامت‌گذاری نود به‌عنوان غیرقابل زمان‌بندی
  • kubectl cp - کپی فایل‌ها و دایرکتوری‌ها به کانتینرها و از آن‌ها.
  • kubectl create - ایجاد یک منبع از فایل یا از stdin.
  • kubectl debug - ایجاد نشست‌های اشکال‌زدایی برای عیب‌یابی بارهای کاری و نودها
  • kubectl delete - حذف منابع بر اساس نام فایل‌ها، stdin، منابع و نام‌ها، یا منابع و انتخابگر (selector) برچسب
  • kubectl describe - نمایش جزئیات یک منبع مشخص یا گروهی از منابع
  • kubectl diff - مقایسهٔ نسخهٔ فعلی با نسخه‌ای که اعمال خواهد شد
  • kubectl drain - تخلیهٔ نود برای آماده‌سازی جهت نگهداری
  • kubectl edit - ویرایش یک منبع روی سرور
  • kubectl events - فهرست کردن رویدادها
  • kubectl exec - اجرای یک فرمان در یک کانتینر
  • kubectl explain - مستندات منابع
  • kubectl expose - گرفتن یک replication controller، service، deployment یا pod و ارائهٔ آن به‌صورت یک Service جدید کوبرنتیز
  • kubectl get - نمایش یک یا چند منبع
  • kubectl kustomize - ساخت یک هدف kustomization از یک دایرکتوری یا یک URL راه دور.
  • kubectl label - به‌روزرسانی برچسب‌های یک منبع
  • kubectl logs - چاپ لاگ‌های یک کانتینر در یک پاد
  • kubectl options - چاپ فهرست فلگ‌هایی که همهٔ فرمان‌ها به ارث می‌برند
  • kubectl patch - به‌روزرسانی فیلد(های) یک منبع
  • kubectl plugin - ابزارهایی برای تعامل با افزونه‌ها فراهم می‌کند.
  • kubectl port-forward - هدایت یک یا چند پورت محلی به یک پاد
  • kubectl proxy - اجرای یک پراکسی به سرور API کوبرنتیز
  • kubectl replace - جایگزینی یک منبع با استفاده از نام فایل یا stdin
  • kubectl rollout - مدیریت انتشار (rollout) یک منبع
  • kubectl run - اجرای یک ایمیج مشخص روی کلاستر
  • kubectl scale - تعیین اندازهٔ جدید برای یک Deployment، ReplicaSet یا Replication Controller
  • kubectl set - تنظیم ویژگی‌های مشخص روی آبجکت‌ها
  • kubectl taint - به‌روزرسانی taintهای یک یا چند نود
  • kubectl top - نمایش میزان مصرف منابع (CPU/حافظه/ذخیره‌سازی).
  • kubectl uncordon - علامت‌گذاری نود به‌عنوان قابل زمان‌بندی
  • kubectl version - چاپ اطلاعات نسخهٔ کلاینت و سرور
  • kubectl wait - آزمایشی: انتظار برای برقراری یک وضعیت مشخص روی یک یا چند منبع.
