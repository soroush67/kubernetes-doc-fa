kubectl برای کاربران Docker

می‌توانید از ابزار خط فرمان کوبرنتیز، یعنی kubectl، برای تعامل با API Server استفاده کنید. اگر با ابزار خط فرمان Docker آشنا باشید، استفاده از kubectl ساده است. با این حال، میان دستورهای Docker و دستورهای kubectl چند تفاوت وجود دارد. در بخش‌های زیر یک زیردستور Docker نشان داده می‌شود و دستور معادل آن در kubectl شرح داده می‌شود.

docker run

برای اجرای یک Deployment از nginx و در دسترس قرار دادن آن، به kubectl create deployment مراجعه کنید.

docker:

docker run -d --restart=always -e DOMAIN=cluster --name nginx-app -p 80:80 nginx

55c103fa129692154a7652490236fee9be47d70a8dd562281ae7d2f9a339a6db

docker ps

CONTAINER ID        IMAGE               COMMAND                  CREATED             STATUS              PORTS                NAMES
55c103fa1296        nginx               "nginx -g 'daemon of…"   9 seconds ago       Up 9 seconds        0.0.0.0:80->80/tcp   nginx-app

kubectl:

# start the pod running nginx
kubectl create deployment --image=nginx nginx-app

deployment.apps/nginx-app created

# add env to nginx-app
kubectl set env deployment/nginx-app  DOMAIN=cluster

deployment.apps/nginx-app env updated
توجه:

دستورهای kubectl نوع و نام منبعی را که ایجاد یا تغییر داده‌اند چاپ می‌کنند و می‌توان از آن‌ها در دستورهای بعدی استفاده کرد. پس از ایجاد یک Deployment می‌توانید یک Service جدید را در دسترس قرار دهید.

# expose a port through with a service
kubectl expose deployment nginx-app --port=80 --name=nginx-http

service "nginx-http" exposed

با استفاده از kubectl می‌توانید یک Deployment ایجاد کنید تا اطمینان حاصل شود که N پاد nginx را اجرا می‌کنند؛ در اینجا N تعداد replicaهایی است که در spec مشخص شده است و مقدار پیش‌فرض آن 1 است. همچنین می‌توانید یک service با یک انتخابگر (selector) ایجاد کنید که با برچسب‌های پادها مطابقت داشته باشد. برای اطلاعات بیشتر، به استفاده از Service برای دسترسی به یک برنامه در کلاستر مراجعه کنید.

به‌طور پیش‌فرض، ایمیج‌ها در پس‌زمینه اجرا می‌شوند، مشابه docker run -d .... برای اجرای آن‌ها در پیش‌زمینه، از kubectl run برای ایجاد پاد استفاده کنید:

kubectl run [-i] [--tty] --attach <name> --image=<image>

برخلاف docker run ...، اگر --attach را مشخص کنید، stdin، stdout و stderr متصل می‌شوند. نمی‌توانید کنترل کنید که کدام جریان‌ها متصل شوند (docker -a ...). برای جدا شدن از کانتینر، می‌توانید دنباله escape یعنی Ctrl+P و سپس Ctrl+Q را وارد کنید.

docker attach

برای اتصال به فرایندی که از قبل در یک کانتینر در حال اجراست، به kubectl attach مراجعه کنید.

docker:

docker ps

CONTAINER ID        IMAGE               COMMAND                  CREATED             STATUS              PORTS                NAMES
55c103fa1296        nginx               "nginx -g 'daemon of…"   5 minutes ago       Up 5 minutes        0.0.0.0:80->80/tcp   nginx-app

docker attach 55c103fa1296
...

kubectl:

kubectl get pods

NAME              READY     STATUS    RESTARTS   AGE
nginx-app-5jyvm   1/1       Running   0          10m

kubectl attach -it nginx-app-5jyvm
...

برای جدا شدن از کانتینر، می‌توانید دنباله escape یعنی Ctrl+P و سپس Ctrl+Q را وارد کنید.

docker exec

برای اجرای یک دستور در یک کانتینر، به kubectl exec مراجعه کنید.

docker:

docker ps

CONTAINER ID        IMAGE               COMMAND                  CREATED             STATUS              PORTS                NAMES
55c103fa1296        nginx               "nginx -g 'daemon of…"   6 minutes ago       Up 6 minutes        0.0.0.0:80->80/tcp   nginx-app

docker exec 55c103fa1296 cat /etc/hostname

55c103fa1296

kubectl:

kubectl get po

NAME              READY     STATUS    RESTARTS   AGE
nginx-app-5jyvm   1/1       Running   0          10m

kubectl exec nginx-app-5jyvm -- cat /etc/hostname

nginx-app-5jyvm

برای استفاده از دستورهای تعاملی:

docker:

docker exec -ti 55c103fa1296 /bin/sh
# exit

kubectl:

kubectl exec -ti nginx-app-5jyvm -- /bin/sh
# exit

برای اطلاعات بیشتر، به دریافت یک شل در کانتینر در حال اجرا مراجعه کنید.

docker logs

برای دنبال کردن stdout/stderr یک فرایند در حال اجرا، به kubectl logs مراجعه کنید.

docker:

docker logs -f a9e

192.168.9.1 - - [14/Jul/2015:01:04:02 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.35.0" "-"
192.168.9.1 - - [14/Jul/2015:01:04:03 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.35.0" "-"

kubectl:

kubectl logs -f nginx-app-zibvs

10.240.63.110 - - [14/Jul/2015:01:09:01 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.26.0" "-"
10.240.63.110 - - [14/Jul/2015:01:09:02 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.26.0" "-"

میان پادها و کانتینرها تفاوت اندکی وجود دارد؛ به‌طور پیش‌فرض، پادها در صورت خروج فرایندهایشان خاتمه نمی‌یابند. در عوض، پادها فرایند را دوباره راه‌اندازی می‌کنند. این رفتار مشابه گزینه --restart=always در docker run است، با یک تفاوت عمده: در docker، خروجی هر بار اجرای فرایند به خروجی قبلی افزوده می‌شود، اما در کوبرنتیز هر بار اجرا جداگانه است. برای مشاهده خروجی اجرای قبلی در کوبرنتیز، به این صورت عمل کنید:

kubectl logs --previous nginx-app-zibvs

10.240.63.110 - - [14/Jul/2015:01:09:01 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.26.0" "-"
10.240.63.110 - - [14/Jul/2015:01:09:02 +0000] "GET / HTTP/1.1" 200 612 "-" "curl/7.26.0" "-"

برای اطلاعات بیشتر، به معماری ثبت لاگ مراجعه کنید.

docker stop and docker rm

برای متوقف کردن و حذف یک فرایند در حال اجرا، به kubectl delete مراجعه کنید.

docker:

docker ps

CONTAINER ID        IMAGE               COMMAND                CREATED             STATUS              PORTS                         NAMES
a9ec34d98787        nginx               "nginx -g 'daemon of"  22 hours ago        Up 22 hours         0.0.0.0:80->80/tcp, 443/tcp   nginx-app

docker stop a9ec34d98787

a9ec34d98787

docker rm a9ec34d98787

a9ec34d98787

kubectl:

kubectl get deployment nginx-app

NAME         READY   UP-TO-DATE   AVAILABLE   AGE
nginx-app    1/1     1            1           2m

kubectl get po -l app=nginx-app

NAME                         READY     STATUS    RESTARTS   AGE
nginx-app-2883164633-aklf7   1/1       Running   0          2m

kubectl delete deployment nginx-app

deployment "nginx-app" deleted

kubectl get po -l app=nginx-app
# Return nothing
توجه:

هنگام استفاده از kubectl، پاد را مستقیماً حذف نمی‌کنید. ابتدا باید Deployment مالک آن پاد را حذف کنید. اگر پاد را مستقیماً حذف کنید، Deployment آن را دوباره ایجاد می‌کند.

docker login

در kubectl معادل مستقیمی برای docker login وجود ندارد. اگر می‌خواهید کوبرنتیز را با یک رجیستری خصوصی به کار ببرید، به استفاده از رجیستری خصوصی مراجعه کنید.
