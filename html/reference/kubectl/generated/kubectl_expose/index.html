kubectl expose

یک ReplicationController، Service، Deployment یا Pod را بگیرید و آن را به‌صورت یک Service جدید کوبرنتیز در معرض دسترسی قرار دهید

خلاصه

یک منبع را به‌صورت یک Service جدید کوبرنتیز در معرض دسترسی قرار می‌دهد.

این دستور یک Deployment، Service، ReplicaSet، ReplicationController یا Pod را با نامش پیدا می‌کند و انتخابگر (selector) آن منبع را به‌عنوان انتخابگر یک Service جدید روی پورت مشخص‌شده به کار می‌برد. یک Deployment یا ReplicaSet تنها زمانی به‌صورت Service در معرض دسترسی قرار می‌گیرد که انتخابگر آن به انتخابگری قابل تبدیل باشد که Service از آن پشتیبانی می‌کند؛ یعنی زمانی که انتخابگر فقط شامل مؤلفه matchLabels باشد. توجه کنید که اگر با --port هیچ پورتی مشخص نشود و منبعِ در معرض دسترسی چند پورت داشته باشد، Service جدید از همه آن پورت‌ها دوباره استفاده می‌کند. همچنین اگر هیچ برچسبی مشخص نشود، Service جدید از برچسب‌های منبعی که در معرض دسترسی قرار می‌دهد استفاده می‌کند.

منابع ممکن عبارت‌اند از (بدون حساسیت به بزرگی و کوچکی حروف):

pod (po), service (svc), replicationcontroller (rc), deployment (deploy), replicaset (rs)

kubectl expose (-f FILENAME | TYPE NAME) [--port=port] [--protocol=TCP|UDP|SCTP] [--target-port=number-or-name] [--name=name] [--external-ip=external-ip-of-service] [--type=type]

مثال‌ها

  # Create a service for a replicated nginx, which serves on port 80 and connects to the containers on port 8000
  kubectl expose rc nginx --port=80 --target-port=8000
  
  # Create a service for a replication controller identified by type and name specified in "nginx-controller.yaml", which serves on port 80 and connects to the containers on port 8000
  kubectl expose -f nginx-controller.yaml --port=80 --target-port=8000
  
  # Create a service for a pod valid-pod, which serves on port 444 with the name "frontend"
  kubectl expose pod valid-pod --port=444 --name=frontend
  
  # Create a second service based on the above service, exposing the container port 8443 as port 443 with the name "nginx-https"
  kubectl expose service nginx --port=443 --target-port=8443 --name=nginx-https
  
  # Create a service for a replicated streaming application on port 4100 balancing UDP traffic and named 'video-stream'.
  kubectl expose rc streamer --port=4100 --protocol=UDP --name=video-stream
  
  # Create a service for a replicated nginx using replica set, which serves on port 80 and connects to the containers on port 8000
  kubectl expose rs nginx --port=80 --target-port=8000
  
  # Create a service for an nginx deployment, which serves on port 80 and connects to the containers on port 8000
  kubectl expose deployment nginx --port=80 --target-port=8000

گزینه‌ها

--allow-missing-template-keys     پیش‌فرض: true

اگر true باشد، هر خطایی در قالب‌ها که ناشی از نبودِ یک فیلد یا کلید map در قالب باشد نادیده گرفته می‌شود. این گزینه فقط برای قالب‌های خروجی golang و jsonpath اعمال می‌شود.
--cluster-ip string

نشانی ClusterIP که باید به Service اختصاص یابد. برای تخصیص خودکار آن را خالی بگذارید، یا برای ایجاد یک Service بدون سر (headless) مقدار آن را 'None' قرار دهید.
--dry-run string[="unchanged"]     پیش‌فرض: "none"

مقدار آن باید یکی از "none"، "server" یا "client" باشد. در راهبرد client، فقط آبجکتی که قرار است ارسال شود چاپ می‌شود، بدون آنکه واقعاً ارسال شود. در راهبرد server، درخواست سمت سرور ارسال می‌شود، بدون آنکه منبع ذخیره شود.
--external-ip string

نشانی IP خارجی اضافی (که کوبرنتیز آن را مدیریت نمی‌کند) که Service باید آن را بپذیرد. اگر این IP به یک نود مسیریابی شود، علاوه بر IP تولیدشده برای Service، از طریق این IP نیز می‌توان به Service دسترسی داشت.
--field-manager string     پیش‌فرض: "kubectl-expose"

نام مدیری که برای ردیابی مالکیت فیلدها استفاده می‌شود.
-f, --filename strings

نام فایل، دایرکتوری یا URL فایل‌هایی که منبع موردنظر برای در معرض دسترسی قرار دادن یک Service را مشخص می‌کنند
-h, --help

راهنمای expose
-k, --kustomize string

دایرکتوری kustomization را پردازش می‌کند. این فلگ را نمی‌توان همراه با -f یا -R استفاده کرد.
-l, --labels string

برچسب‌هایی که روی Service ایجادشده با این فراخوانی اعمال می‌شوند.
--load-balancer-ip string

نشانی IP که باید به LoadBalancer اختصاص یابد. اگر خالی باشد، یک IP موقت ایجاد و استفاده می‌شود (وابسته به ارائه‌دهنده ابر).
--name string

نام آبجکتی که تازه ایجاد می‌شود.
-o, --output string

قالب خروجی. یکی از این مقادیر: (json, yaml, kyaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).
--override-type string     پیش‌فرض: "merge"

روشی که برای بازنویسی آبجکت تولیدشده استفاده می‌شود: json، merge یا strategic.
--overrides string

یک بازنویسی JSON درون‌خطی برای آبجکت تولیدشده. اگر این مقدار خالی نباشد، برای بازنویسی آبجکت تولیدشده به کار می‌رود. لازم است آبجکت یک فیلد apiVersion معتبر داشته باشد.
--port string

پورتی که Service باید روی آن سرویس دهد. اگر مشخص نشود، از منبعی که در معرض دسترسی قرار می‌گیرد کپی می‌شود
--protocol string

پروتکل شبکه برای Service‌ای که ایجاد می‌شود. مقدار پیش‌فرض 'TCP' است.
-R, --recursive

دایرکتوری استفاده‌شده در -f, --filename را به‌صورت بازگشتی پردازش می‌کند. این گزینه زمانی مفید است که بخواهید مانیفست‌های مرتبطی را که در یک دایرکتوری سازمان‌دهی شده‌اند مدیریت کنید.
--save-config

اگر true باشد، پیکربندی آبجکت فعلی در حاشیه‌نویسی (annotation) آن ذخیره می‌شود. در غیر این صورت، حاشیه‌نویسی بدون تغییر می‌ماند. این فلگ زمانی مفید است که بخواهید در آینده دستور kubectl apply را روی این آبجکت اجرا کنید.
--selector string

یک انتخابگر برچسب برای استفاده در این Service. فقط الزامات انتخابگرِ مبتنی بر برابری پشتیبانی می‌شوند. اگر خالی باشد (حالت پیش‌فرض)، انتخابگر از منبعی که در معرض دسترسی قرار می‌گیرد استنتاج می‌شود.
--session-affinity string

اگر خالی نباشد، وابستگی نشست (session affinity) برای Service روی این مقدار تنظیم می‌شود؛ مقادیر مجاز: 'None'، 'ClientIP'
--show-managed-fields

اگر true باشد، هنگام چاپ آبجکت‌ها در قالب JSON یا YAML، فیلد managedFields حفظ می‌شود.
--target-port string

نام یا شماره پورتی روی کانتینر که Service باید ترافیک را به آن هدایت کند. این گزینه اختیاری است.
--template string

رشته قالب یا مسیر فایل قالب که هنگام استفاده از -o=go-template یا -o=go-template-file به کار می‌رود. قالب‌ها از نوع قالب‌های golang هستند [http://golang.org/pkg/text/template/#pkg-overview].
--type string

نوع این Service: ClusterIP، NodePort، LoadBalancer یا ExternalName. مقدار پیش‌فرض 'ClusterIP' است.

گزینه‌های ارث‌بری شده از والد

--as string

نام کاربری‌ای که عملیات با جعل هویت آن انجام می‌شود. این کاربر می‌تواند یک کاربر عادی یا یک حساب سرویس (service account) در یک فضای نام (namespace) باشد.
--as-group strings

گروهی که عملیات با جعل هویت آن انجام می‌شود. برای مشخص‌کردن چند گروه می‌توانید این فلگ را تکرار کنید.
--as-uid string

شناسهٔ UID که عملیات با جعل هویت آن انجام می‌شود.
--as-user-extra strings

اطلاعات تکمیلی کاربر که عملیات با جعل هویت آن انجام می‌شود. برای مشخص‌کردن چند مقدار برای یک کلید می‌توانید این فلگ را تکرار کنید.
--cache-dir string     Default: "$HOME/.kube/cache"

دایرکتوری پیش‌فرض کش
--certificate-authority string

مسیر فایل گواهی مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستری از kubeconfig که باید استفاده شود
--context string

نام context از kubeconfig که باید استفاده شود
--disable-compression

اگر true باشد، فشرده‌سازی پاسخ برای همهٔ درخواست‌های ارسالی به سرور غیرفعال می‌شود
--insecure-skip-tls-verify

اگر true باشد، اعتبار گواهی سرور بررسی نمی‌شود. با این کار اتصال‌های HTTPS شما ناامن می‌شوند
--kubeconfig string

مسیر فایل kubeconfig که برای درخواست‌های CLI استفاده می‌شود.
--kuberc string

مسیر فایل kuberc که برای ترجیحات استفاده می‌شود. می‌توان این قابلیت را با export کردن feature gate به‌صورت KUBECTL_KUBERC=false یا خاموش‌کردن قابلیت با KUBERC=off غیرفعال کرد.
--match-server-version

الزام به یکسان بودن نسخهٔ سرور با نسخهٔ کلاینت
-n, --namespace string

در صورت تعیین، دامنهٔ فضای نام برای این درخواست CLI
--password string

گذرواژه برای احراز هویت پایه (basic authentication) در API server
--profile string     Default: "none"

نام پروفایلی که باید ثبت شود. یکی از مقادیر (none|cpu|heap|goroutine|threadcreate|block|mutex|trace)
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی برای درخواست‌های ارسالی به API server
--request-timeout string     Default: "0"

مدت زمان انتظار پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (مثلاً 1s، 2m، 3h). مقدار صفر به این معناست که درخواست‌ها هیچ‌گاه منقضی نمی‌شوند.
-s, --server string

نشانی و پورت API server کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

نوشتن‌ها در درایور ذخیره‌سازی به این مدت در بافر نگه داشته می‌شوند و سپس در قالب یک تراکنش واحد در بک‌اندهای غیرحافظه‌ای ثبت می‌شوند
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

میزبان و پورت پایگاه داده (host:port)
--storage-driver-password string     Default: "root"

گذرواژهٔ پایگاه داده
--storage-driver-secure

استفاده از اتصال امن با پایگاه داده
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور استفاده می‌شود. اگر تعیین نشود، نام میزبانی که برای برقراری ارتباط با سرور به کار رفته است استفاده می‌شود
--token string

توکن Bearer برای احراز هویت در API server
--user string

نام کاربری از kubeconfig که باید استفاده شود
--username string

نام کاربری برای احراز هویت پایه در API server
--version version[=true]

گزینه‌های --version و --version=raw اطلاعات نسخه را چاپ می‌کنند و از برنامه خارج می‌شوند؛ گزینهٔ --version=vX.Y.Z... نسخهٔ گزارش‌شده را تنظیم می‌کند
--warnings-as-errors

هشدارهای دریافتی از سرور را خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود
