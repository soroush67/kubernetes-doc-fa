kubectl get

نمایش یک یا چند منبع

خلاصه

یک یا چند منبع را نمایش می‌دهد.

این دستور جدولی از مهم‌ترین اطلاعات منابع مشخص‌شده را چاپ می‌کند. می‌توانید فهرست را با یک انتخابگر برچسب (label selector) و فلگ ‎--selector فیلتر کنید. اگر نوع منبع موردنظر وابسته به فضای نام (namespace) باشد و هیچ فضای نامی مشخص نکنید، فقط نتایج موجود در فضای نام جاری را خواهید دید.

اگر خروجی را 'template' تعیین کنید و یک قالب Go را به‌عنوان مقدار فلگ ‎--template بدهید، می‌توانید ویژگی‌های منابع دریافت‌شده را فیلتر کنید.

برای دیدن فهرست کامل منابع پشتیبانی‌شده، از دستور "kubectl api-resources" استفاده کنید.

kubectl get [(-o|--output=)json|yaml|kyaml|name|go-template|go-template-file|template|templatefile|jsonpath|jsonpath-as-json|jsonpath-file|custom-columns|custom-columns-file|wide] (TYPE[.VERSION][.GROUP] [NAME | -l label] | TYPE[.VERSION][.GROUP]/NAME ...) [flags]

مثال‌ها

  # List all pods in ps output format
  kubectl get pods
  
  # List all pods in ps output format with more information (such as node name)
  kubectl get pods -o wide
  
  # List a single replication controller with specified NAME in ps output format
  kubectl get replicationcontroller web
  
  # List deployments in JSON output format, in the "v1" version of the "apps" API group
  kubectl get deployments.v1.apps -o json
  
  # List a single pod in JSON output format
  kubectl get -o json pod web-pod-13je7
  
  # List a pod identified by type and name specified in "pod.yaml" in JSON output format
  kubectl get -f pod.yaml -o json
  
  # List resources from a directory with kustomization.yaml - e.g. dir/kustomization.yaml
  kubectl get -k dir/
  
  # Return only the phase value of the specified pod
  kubectl get -o template pod/web-pod-13je7 --template={{.status.phase}}
  
  # List resource information in custom columns
  kubectl get pod test-pod -o custom-columns=CONTAINER:.spec.containers[0].name,IMAGE:.spec.containers[0].image
  
  # List all replication controllers and services together in ps output format
  kubectl get rc,services
  
  # List one or more resources by their type and names
  kubectl get rc/web service/frontend pods/web-pod-13je7
  
  # List the 'status' subresource for a single pod
  kubectl get pod web-pod-13je7 --subresource status
  
  # List all deployments in namespace 'backend'
  kubectl get deployments.apps --namespace backend
  
  # List all pods existing in all namespaces
  kubectl get pods --all-namespaces

گزینه‌ها

-A, --all-namespaces

در صورت وجود، آبجکت‌های درخواست‌شده را در همهٔ فضاهای نام فهرست می‌کند. فضای نام موجود در context جاری نادیده گرفته می‌شود، حتی اگر با ‎--namespace مشخص شده باشد.
--allow-missing-template-keys     Default: true

اگر true باشد، هنگامی که یک فیلد یا کلید map در قالب وجود نداشته باشد، از هرگونه خطا در قالب‌ها چشم‌پوشی می‌شود. این گزینه فقط برای قالب‌های خروجی golang و jsonpath اعمال می‌شود.
--chunk-size int     Default: 500

فهرست‌های بزرگ را به‌جای ارسال یکجا، در چند بخش برمی‌گرداند. برای غیرفعال‌کردن این قابلیت، مقدار 0 را بدهید.
--field-selector string

انتخابگر (پرس‌وجوی فیلد) برای فیلترکردن؛ از عملگرهای '=' و '==' و '!=' پشتیبانی می‌کند (برای نمونه ‎--field-selector key1=value1,key2=value2). سرور برای هر نوع، فقط تعداد محدودی از پرس‌وجوهای فیلد را پشتیبانی می‌کند.
-f, --filename strings

نام فایل، دایرکتوری یا URL فایل‌هایی که منبع موردنظر برای دریافت از سرور را مشخص می‌کنند.
-h, --help

راهنمای دستور get
--ignore-not-found

اگر روی true تنظیم شود، خطای NotFound را برای آبجکت‌های مشخصی که وجود ندارند سرکوب می‌کند. استفاده از این فلگ همراه با دستورهایی که مجموعه‌ای از منابع را پرس‌وجو می‌کنند، در صورت پیدا نشدن هیچ منبعی، اثری ندارد.
-k, --kustomize string

دایرکتوری kustomization را پردازش می‌کند. این فلگ را نمی‌توان همراه با ‎-f یا ‎-R استفاده کرد.
-L, --label-columns strings

فهرستی از برچسب‌ها را که با ویرگول از هم جدا شده‌اند می‌پذیرد تا به‌صورت ستون نمایش داده شوند. نام‌ها به بزرگی و کوچکی حروف حساس هستند. همچنین می‌توانید این فلگ را چند بار به کار ببرید، مانند ‎-L label1 -L label2...
--no-headers

هنگام استفاده از قالب خروجی پیش‌فرض یا custom-column، سرستون‌ها را چاپ نمی‌کند (به‌طور پیش‌فرض سرستون‌ها چاپ می‌شوند).
-o, --output string

قالب خروجی. یکی از این موارد: (json, yaml, kyaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file, custom-columns, custom-columns-file, wide). برای اطلاعات بیشتر، ستون‌های سفارشی [https://kubernetes.io/docs/reference/kubectl/#custom-columns]، قالب golang [http://golang.org/pkg/text/template/#pkg-overview] و قالب jsonpath [https://kubernetes.io/docs/reference/kubectl/jsonpath/] را ببینید.
--output-watch-events

هنگام استفاده از ‎--watch یا ‎--watch-only، آبجکت‌های رویداد watch را در خروجی نمایش می‌دهد. آبجکت‌های موجود به‌صورت رویدادهای اولیهٔ ADDED در خروجی می‌آیند.
--raw string

نشانی URI خامی که باید از سرور درخواست شود. از سازوکار انتقالی استفاده می‌کند که در فایل kubeconfig مشخص شده است.
-R, --recursive

دایرکتوری استفاده‌شده در ‎-f یا ‎--filename را به‌صورت بازگشتی پردازش می‌کند. این گزینه زمانی مفید است که بخواهید مانیفست‌های مرتبطی را که در یک دایرکتوری سازمان‌دهی شده‌اند مدیریت کنید.
-l, --selector string

انتخابگر (پرس‌وجوی برچسب) برای فیلترکردن؛ از عملگرهای '=' و '==' و '!=' و 'in' و 'notin' پشتیبانی می‌کند (برای نمونه ‎-l key1=value1,key2=value2,key3 in (value3)). آبجکت‌های منطبق باید همهٔ محدودیت‌های برچسب مشخص‌شده را برآورده کنند.
--server-print     Default: true

اگر true باشد، سرور خروجی جدولی مناسب را برمی‌گرداند. از APIهای افزونه و CRDها پشتیبانی می‌کند.
--show-kind

در صورت وجود، نوع منبع آبجکت‌های درخواست‌شده را فهرست می‌کند.
--show-labels

هنگام چاپ، همهٔ برچسب‌ها را در ستون آخر نمایش می‌دهد (به‌طور پیش‌فرض ستون برچسب‌ها پنهان است).
--show-managed-fields

اگر true باشد، هنگام چاپ آبجکت‌ها در قالب JSON یا YAML، فیلد managedFields حفظ می‌شود.
--sort-by string

اگر خالی نباشد، انواع فهرستی را بر اساس این مشخصهٔ فیلد مرتب می‌کند. مشخصهٔ فیلد به‌صورت یک عبارت JSONPath بیان می‌شود (برای نمونه '{.metadata.name}'). فیلدی از منبع API که این عبارت JSONPath مشخص می‌کند، باید از نوع عدد صحیح یا رشته باشد.
--subresource string

در صورت تعیین، زیرمنبع (subresource) آبجکت درخواست‌شده را دریافت می‌کند.
--template string

رشتهٔ قالب یا مسیر فایل قالب که هنگام استفاده از ‎-o=go-template یا ‎-o=go-template-file به کار می‌رود. قالب آن، قالب‌های golang است [http://golang.org/pkg/text/template/#pkg-overview].
-w, --watch

پس از فهرست‌کردن یا دریافت آبجکت درخواست‌شده، تغییرات آن را زیر نظر می‌گیرد.
--watch-only

تغییرات آبجکت‌های درخواست‌شده را بدون فهرست‌کردن یا دریافت اولیهٔ آن‌ها زیر نظر می‌گیرد.

گزینه‌های ارث‌بری شده از والد

--as string

نام کاربری‌ای که عملیات با جعل هویت (impersonate) آن انجام می‌شود. این کاربر می‌تواند یک کاربر عادی یا یک حساب سرویس (service account) در یک فضای نام (namespace) باشد.
--as-group strings

گروهی که عملیات با جعل هویت آن انجام می‌شود. برای مشخص کردن چند گروه می‌توان این فلگ را تکرار کرد.
--as-uid string

شناسهٔ UID که عملیات با جعل هویت آن انجام می‌شود.
--as-user-extra strings

اطلاعات اضافی کاربر که عملیات با جعل هویت آن انجام می‌شود. برای مشخص کردن چند مقدار برای یک کلید می‌توان این فلگ را تکرار کرد.
--cache-dir string     Default: "$HOME/.kube/cache"

پوشهٔ پیش‌فرض حافظهٔ نهان (cache)
--certificate-authority string

مسیر فایل گواهی مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستری از kubeconfig که باید استفاده شود
--context string

نام context از kubeconfig که باید استفاده شود
--disable-compression

اگر true باشد، فشرده‌سازی پاسخ برای همهٔ درخواست‌ها به سرور غیرفعال می‌شود
--insecure-skip-tls-verify

اگر true باشد، اعتبار گواهی سرور بررسی نمی‌شود. با این کار اتصال‌های HTTPS شما ناامن می‌شوند
--kubeconfig string

مسیر فایل kubeconfig برای استفاده در درخواست‌های CLI.
--kuberc string

مسیر فایل kuberc برای استفاده در تنظیمات ترجیحی. می‌توان این قابلیت را با export کردن feature gate به‌صورت KUBECTL_KUBERC=false یا خاموش کردن قابلیت با KUBERC=off غیرفعال کرد.
--match-server-version

الزام به یکسان بودن نسخهٔ سرور با نسخهٔ کلاینت
-n, --namespace string

در صورت وجود، دامنهٔ فضای نام برای این درخواست CLI
--password string

گذرواژه برای احراز هویت پایه (basic authentication) در API server
--profile string     Default: "none"

نام پروفایلی که باید ثبت شود. یکی از مقادیر (none|cpu|heap|goroutine|threadcreate|block|mutex|trace)
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی برای استفاده در درخواست‌ها به API server
--request-timeout string     Default: "0"

مدت زمان انتظار پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (مثلاً 1s، 2m، 3h). مقدار صفر یعنی درخواست‌ها هیچ‌گاه به پایان مهلت نمی‌رسند.
-s, --server string

نشانی و درگاه (port) سرور API کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

نوشتن‌ها در درایور ذخیره‌سازی به همین مدت در بافر نگه داشته می‌شوند و سپس در قالب یک تراکنش واحد در پشتیبان‌های غیرحافظه‌ای (non memory backends) ثبت می‌شوند
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

میزبان و درگاه پایگاه داده به‌صورت host:port
--storage-driver-password string     Default: "root"

گذرواژهٔ پایگاه داده
--storage-driver-secure

استفاده از اتصال امن با پایگاه داده
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور استفاده می‌شود. اگر این مقدار ارائه نشود، از نام میزبانی (hostname) که برای برقراری ارتباط با سرور به کار رفته است استفاده می‌شود
--token string

توکن Bearer برای احراز هویت در API server
--user string

نام کاربری از kubeconfig که باید استفاده شود
--username string

نام کاربری برای احراز هویت پایه در API server
--version version[=true]

گزینه‌های --version و --version=raw اطلاعات نسخه را چاپ می‌کنند و خارج می‌شوند؛ گزینهٔ --version=vX.Y.Z... نسخهٔ گزارش‌شده را تنظیم می‌کند
--warnings-as-errors

هشدارهای دریافتی از سرور را خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود
