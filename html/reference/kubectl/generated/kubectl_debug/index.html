kubectl debug

ایجاد نشست‌های اشکال‌زدایی برای عیب‌یابی بارهای کاری و نودها

خلاصه

منابع کلاستر را با استفاده از کانتینرهای اشکال‌زدایی تعاملی اشکال‌زدایی کنید.

دستور 'debug' کارهای رایج اشکال‌زدایی را برای آبجکت‌های کلاستر خودکار می‌کند. این آبجکت‌ها با نوع منبع و نام مشخص می‌شوند. اگر هیچ منبعی مشخص نشود، به‌طور پیش‌فرض از Podها استفاده می‌شود.

کاری که 'debug' انجام می‌دهد به منبع مشخص‌شده بستگی دارد. اقدام‌های پشتیبانی‌شده عبارت‌اند از:

  • بار کاری: ایجاد یک کپی از یک پاد موجود با تغییر برخی از ویژگی‌های آن، برای مثال تغییر برچسب (tag) ایمیج به یک نسخه‌ی جدید.
  • بار کاری: افزودن یک کانتینر موقت (ephemeral) به پادی که در حال اجراست، برای مثال برای افزودن ابزارهای اشکال‌زدایی بدون راه‌اندازی مجدد پاد.
  • نود: ایجاد یک پاد جدید که در فضاهای نام میزبانِ نود اجرا می‌شود و به سامانه‌ی فایل نود دسترسی دارد.

نکته: هنگامی که برای کل Pod هدف یک کاربر غیر root پیکربندی شده باشد، ممکن است برخی از قابلیت‌هایی که پروفایل اشکال‌زدایی اعطا می‌کند کار نکنند.

kubectl debug (POD | TYPE[[.VERSION].GROUP]/NAME) [ -- COMMAND [args...] ]

مثال‌ها

  # Create an interactive debugging session in pod mypod and immediately attach to it.
  kubectl debug mypod -it --image=busybox
  
  # Create an interactive debugging session for the pod in the file pod.yaml and immediately attach to it.
  # (requires the EphemeralContainers feature to be enabled in the cluster)
  kubectl debug -f pod.yaml -it --image=busybox
  
  # Create a debug container named debugger using a custom automated debugging image.
  kubectl debug --image=myproj/debug-tools -c debugger mypod
  
  # Create a copy of mypod adding a debug container and attach to it
  kubectl debug mypod -it --image=busybox --copy-to=my-debugger
  
  # Create a copy of mypod changing the command of mycontainer
  kubectl debug mypod -it --copy-to=my-debugger --container=mycontainer -- sh
  
  # Create a copy of mypod changing all container images to busybox
  kubectl debug mypod --copy-to=my-debugger --set-image=*=busybox
  
  # Create a copy of mypod adding a debug container and changing container images
  kubectl debug mypod -it --copy-to=my-debugger --image=debian --set-image=app=app:debug,sidecar=sidecar:debug
  
  # Create an interactive debugging session on a node and immediately attach to it.
  # The container will run in the host namespaces and the host's filesystem will be mounted at /host
  kubectl debug node/mynode -it --image=busybox

گزینه‌ها

--arguments-only

اگر مشخص شود، هر چیزی که پس از -- بیاید به‌جای Command به‌عنوان Args به کانتینر جدید داده می‌شود.
--attach

اگر true باشد، منتظر می‌ماند تا اجرای کانتینر آغاز شود و سپس، گویی 'kubectl attach ...' فراخوانی شده باشد، به آن متصل می‌شود. مقدار پیش‌فرض false است، مگر اینکه '-i/--stdin' تنظیم شده باشد که در این صورت مقدار پیش‌فرض true است.
-c, --container string

نامی که برای کانتینر اشکال‌زدایی استفاده می‌شود.
--copy-to string

یک کپی از Pod هدف با این نام ایجاد می‌کند.
--custom string

مسیر یک فایل JSON یا YAML حاوی مشخصات بخشی از کانتینر، برای سفارشی‌سازی پروفایل‌های اشکال‌زدایی داخلی.
--env stringToString     Default: []

متغیرهای محیطی که باید در کانتینر تنظیم شوند.
-f, --filename strings

منبعی را که باید اشکال‌زدایی شود مشخص می‌کند
-h, --help

راهنمای debug
--image string

ایمیج کانتینری که برای کانتینر اشکال‌زدایی استفاده می‌شود.
--image-pull-policy string

سیاست دریافت (pull) ایمیج برای کانتینر. اگر خالی بماند، کلاینت این مقدار را مشخص نمی‌کند و سرور مقدار پیش‌فرض را برای آن تعیین می‌کند.
--keep-annotations

اگر true باشد، حاشیه‌نویسی‌های (annotations) اصلی پاد حفظ می‌شوند. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--keep-init-containers     Default: true

کانتینرهای init پاد را اجرا می‌کند. مقدار پیش‌فرض true است. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--keep-labels

اگر true باشد، برچسب‌های اصلی پاد حفظ می‌شوند. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--keep-liveness

اگر true باشد، کاوشگرهای liveness اصلی پاد حفظ می‌شوند. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--keep-readiness

اگر true باشد، کاوشگرهای readiness اصلی پاد حفظ می‌شوند. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--keep-startup

اگر true باشد، کاوشگرهای startup اصلی حفظ می‌شوند. (این فلگ فقط همراه با '--copy-to' کار می‌کند)
--profile string     Default: "general"

گزینه‌ها عبارت‌اند از "general"، "baseline"، "restricted"، "netadmin" یا "sysadmin". مقدار پیش‌فرض "general" است.
-q, --quiet

اگر true باشد، پیام‌های اطلاع‌رسانی نمایش داده نمی‌شوند.
--replace

هنگامی که همراه با '--copy-to' استفاده شود، Pod اصلی را حذف می‌کند.
--same-node

هنگامی که همراه با '--copy-to' استفاده شود، کپی Pod هدف را روی همان نود زمان‌بندی می‌کند.
--set-image stringToString     Default: []

هنگامی که همراه با '--copy-to' استفاده شود، فهرستی از جفت‌های name=image برای تغییر ایمیج‌های کانتینر است؛ مشابه شیوه‌ی کار 'kubectl set image'.
--share-processes     Default: true

هنگامی که همراه با '--copy-to' استفاده شود، اشتراک‌گذاری فضای نام پردازه‌ها را در کپی فعال می‌کند.
-i, --stdin

ورودی استاندارد (stdin) را روی کانتینر(های) پاد باز نگه می‌دارد، حتی اگر چیزی به آن متصل نباشد.
--target string

هنگام استفاده از کانتینر موقت، پردازه‌های کانتینری با این نام را هدف قرار می‌دهد.
-t, --tty

یک TTY به کانتینر اشکال‌زدایی تخصیص می‌دهد.

گزینه‌های ارث‌بری شده از والد

--as string

نام کاربری‌ای که عملیات با جعل هویت (impersonate) آن انجام می‌شود. این کاربر می‌تواند یک کاربر عادی یا یک حساب سرویس (service account) در یک فضای نام باشد.
--as-group strings

گروهی که عملیات با جعل هویت آن انجام می‌شود. برای مشخص کردن چند گروه می‌توان این فلگ را تکرار کرد.
--as-uid string

شناسه‌ی UID که عملیات با جعل هویت آن انجام می‌شود.
--as-user-extra strings

اطلاعات اضافی کاربر که عملیات با جعل هویت آن انجام می‌شود. برای مشخص کردن چند مقدار برای یک کلید می‌توان این فلگ را تکرار کرد.
--cache-dir string     Default: "$HOME/.kube/cache"

دایرکتوری پیش‌فرض حافظه‌ی نهان (cache)
--certificate-authority string

مسیر فایل گواهی مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستری از kubeconfig که باید استفاده شود
--context string

نام زمینه‌ای (context) از kubeconfig که باید استفاده شود
--disable-compression

اگر true باشد، فشرده‌سازی پاسخ برای همه‌ی درخواست‌ها به سرور غیرفعال می‌شود
--insecure-skip-tls-verify

اگر true باشد، اعتبار گواهی سرور بررسی نمی‌شود. با این کار اتصال‌های HTTPS شما ناامن می‌شوند
--kubeconfig string

مسیر فایل kubeconfig که برای درخواست‌های CLI استفاده می‌شود.
--kuberc string

مسیر فایل kuberc که برای ترجیحات استفاده می‌شود. می‌توان این قابلیت را با export کردن feature gate ‏KUBECTL_KUBERC=false یا خاموش کردن قابلیت KUBERC=off غیرفعال کرد.
--match-server-version

الزام می‌کند که نسخه‌ی سرور با نسخه‌ی کلاینت مطابقت داشته باشد
-n, --namespace string

در صورت وجود، دامنه‌ی فضای نام برای این درخواست CLI
--password string

گذرواژه برای احراز هویت پایه در API server
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی برای درخواست‌ها به API server
--request-timeout string     Default: "0"

مدت زمانی که پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور منتظر می‌ماند. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (مثلاً 1s، 2m، 3h). مقدار صفر یعنی درخواست‌ها هیچ‌گاه منقضی نمی‌شوند.
-s, --server string

نشانی و پورت API server کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

نوشتن‌ها در درایور ذخیره‌سازی به مدت این بازه بافر می‌شوند و سپس به‌صورت یک تراکنش واحد در پشتیبان‌های غیرحافظه‌ای ثبت می‌شوند
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

میزبان و پورت پایگاه داده به‌صورت host:port
--storage-driver-password string     Default: "root"

گذرواژه‌ی پایگاه داده
--storage-driver-secure

استفاده از اتصال امن با پایگاه داده
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور استفاده می‌شود. اگر ارائه نشود، از نام میزبانی استفاده می‌شود که برای برقراری ارتباط با سرور به کار رفته است
--token string

توکن Bearer برای احراز هویت در API server
--user string

نام کاربری از kubeconfig که باید استفاده شود

گزینه‌های --version و --version=raw اطلاعات نسخه را چاپ می‌کنند و خارج می‌شوند؛ گزینه‌ی --version=vX.Y.Z... نسخه‌ی گزارش‌شده را تنظیم می‌کند
--warnings-as-errors

هشدارهای دریافتی از سرور را خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود
