kubectl drain

تخلیهٔ نود برای آماده‌سازی آن جهت نگهداری

خلاصه

این فرمان نود را برای آماده‌سازی جهت نگهداری تخلیه (drain) می‌کند.

نود مشخص‌شده غیرقابل‌زمان‌بندی (unschedulable) علامت‌گذاری می‌شود تا Podهای جدید روی آن قرار نگیرند. اگر سرور API از بیرون‌رانی (eviction) پشتیبانی کند، فرمان 'drain' پادها را بیرون می‌راند (https://kubernetes.io/docs/concepts/workloads/pods/disruptions/ eviction https://kubernetes.io/docs/concepts/workloads/pods/disruptions/ ). در غیر این صورت، برای حذف پادها از درخواست معمولی DELETE استفاده می‌کند. فرمان 'drain' همهٔ پادها را به‌جز mirror podها (که از طریق سرور API قابل حذف نیستند) بیرون می‌راند یا حذف می‌کند. اگر پادهایی وجود داشته باشند که توسط daemon set مدیریت می‌شوند، این فرمان بدون ‎--ignore-daemonsets ادامه نمی‌یابد و در هر حال هیچ‌یک از پادهای مدیریت‌شده با daemon set را حذف نمی‌کند، زیرا کنترل‌کنندهٔ daemon set که علامت‌گذاری غیرقابل‌زمان‌بندی را نادیده می‌گیرد، بلافاصله پادهای دیگری را جایگزین آن‌ها می‌کند. اگر پادهایی وجود داشته باشند که نه mirror pod هستند و نه توسط replication controller، replica set، daemon set، stateful set یا job مدیریت می‌شوند، فرمان drain هیچ پادی را حذف نمی‌کند، مگر آنکه از ‎--force استفاده کنید. همچنین با ‎--force، اگر منبع مدیریت‌کنندهٔ یک یا چند پاد وجود نداشته باشد، عملیات حذف ادامه می‌یابد.

فرمان 'drain' منتظر خاتمهٔ آرام (graceful termination) پادها می‌ماند. تا پایان اجرای این فرمان نباید هیچ عملیاتی روی ماشین انجام دهید.

هنگامی که آماده شدید نود را دوباره به چرخهٔ سرویس‌دهی بازگردانید، از kubectl uncordon استفاده کنید تا نود دوباره قابل‌زمان‌بندی شود.

تصویر گردش کار: https://kubernetes.io/images/docs/kubectl_drain.svg Workflowhttps://kubernetes.io/images/docs/kubectl_drain.svg

kubectl drain NODE

مثال‌ها

  # Drain node "foo", even if there are pods not managed by a replication controller, replica set, job, daemon set, or stateful set on it
  kubectl drain foo --force
  
  # As above, but abort if there are pods not managed by a replication controller, replica set, job, daemon set, or stateful set, and use a grace period of 15 minutes
  kubectl drain foo --grace-period=900

گزینه‌ها

--chunk-size int     پیش‌فرض: 500

فهرست‌های بزرگ به‌جای اینکه یکجا برگردانده شوند، در قطعه‌های جداگانه برگردانده می‌شوند. برای غیرفعال‌کردن، مقدار 0 را بدهید.
--delete-emptydir-data

حتی اگر پادهایی از emptyDir (داده‌های محلی که هنگام تخلیهٔ نود حذف می‌شوند) استفاده کنند، عملیات ادامه می‌یابد.
--disable-eviction

فرمان drain را وادار می‌کند حتی در صورت پشتیبانی از بیرون‌رانی، از حذف استفاده کند. با این کار بررسی PodDisruptionBudgetها دور زده می‌شود؛ بنابراین با احتیاط از آن استفاده کنید.
--dry-run string[="unchanged"]     پیش‌فرض: "none"

مقدار آن باید یکی از "none"، "server" یا "client" باشد. در راهبرد client، آبجکتی که قرار است ارسال شود فقط چاپ می‌شود و ارسال نمی‌شود. در راهبرد server، درخواست سمت سرور ارسال می‌شود، بی‌آنکه منبع ذخیره شود.
--force

حتی اگر پادهایی وجود داشته باشند که کنترل‌کننده‌ای برایشان اعلام نشده است، عملیات ادامه می‌یابد.
--grace-period int     پیش‌فرض: -1

مدت زمانی بر حسب ثانیه که به هر پاد برای خاتمهٔ آرام داده می‌شود. اگر منفی باشد، مقدار پیش‌فرض تعیین‌شده در پاد استفاده می‌شود.
-h, --help

راهنمای فرمان drain

پادهای مدیریت‌شده با DaemonSet نادیده گرفته می‌شوند.
--pod-selector string

انتخابگر برچسب برای فیلترکردن پادهای روی نود
-l, --selector string

انتخابگر (پرس‌وجوی برچسب) برای فیلترکردن؛ از عملگرهای '=' و '==' و '!=' و 'in' و 'notin' پشتیبانی می‌کند (برای مثال ‎-l key1=value1,key2=value2,key3 in (value3)). آبجکت‌های منطبق باید همهٔ محدودیت‌های برچسب مشخص‌شده را برآورده کنند.
--skip-wait-for-delete-timeout int

اگر مقدار DeletionTimestamp پاد قدیمی‌تر از N ثانیه باشد، از انتظار برای آن پاد صرف‌نظر می‌شود. برای صرف‌نظر کردن، تعداد ثانیه‌ها باید بزرگ‌تر از 0 باشد.
--timeout duration

مدت زمان انتظار پیش از توقف تلاش؛ مقدار صفر به معنای انتظار نامحدود است.
