kubectl set env

به‌روزرسانی متغیرهای محیطی در یک قالب پاد

خلاصه

این دستور متغیرهای محیطی را در یک قالب پاد (pod template) به‌روزرسانی می‌کند.

این دستور تعریف‌های متغیرهای محیطی را در یک یا چند پاد یا قالب پاد فهرست می‌کند. همچنین تعریف‌های متغیرهای محیطی کانتینر را در یک یا چند قالب پاد (درون replication controllerها یا پیکربندی‌های استقرار) اضافه، به‌روزرسانی یا حذف می‌کند. با این دستور می‌توانید تعریف‌های متغیرهای محیطی همهٔ کانتینرهای پادها یا قالب‌های پاد مشخص‌شده را مشاهده یا تغییر دهید، یا این کار را فقط برای کانتینرهایی انجام دهید که با یک الگوی عام (wildcard) مطابقت دارند.

اگر "--env -" داده شود، متغیرهای محیطی را می‌توان با نحو استاندارد env از STDIN خواند.

منابع ممکن عبارت‌اند از (بدون حساسیت به بزرگی و کوچکی حروف):

    pod (po), replicationcontroller (rc), deployment (deploy), daemonset (ds), statefulset (sts), cronjob (cj), replicaset (rs)

kubectl set env RESOURCE/NAME KEY_1=VAL_1 ... KEY_N=VAL_N

مثال‌ها

  # Update deployment 'registry' with a new environment variable
  kubectl set env deployment/registry STORAGE_DIR=/local
  
  # List the environment variables defined on a deployments 'sample-build'
  kubectl set env deployment/sample-build --list
  
  # List the environment variables defined on all pods
  kubectl set env pods --all --list
  
  # Output modified deployment in YAML, and does not alter the object on the server
  kubectl set env deployment/sample-build STORAGE_DIR=/data -o yaml
  
  # Update all containers in all replication controllers in the project to have ENV=prod
  kubectl set env rc --all ENV=prod
  
  # Import environment from a secret
  kubectl set env --from=secret/mysecret deployment/myapp
  
  # Import environment from a config map with a prefix
  kubectl set env --from=configmap/myconfigmap --prefix=MYSQL_ deployment/myapp
  
  # Import specific keys from a config map
  kubectl set env --keys=my-example-key --from=configmap/myconfigmap deployment/myapp
  
  # Remove the environment variable ENV from container 'c1' in all deployment configs
  kubectl set env deployments --all --containers="c1" ENV-
  
  # Remove the environment variable ENV from a deployment definition on disk and
  # update the deployment config on the server
  kubectl set env -f deploy.json ENV-
  
  # Set some of the local shell environment into a deployment config on the server
  env | grep RAILS_ | kubectl set env -e - deployment/registry

گزینه‌ها

--all

اگر true باشد، همهٔ منابعِ انواع منبع مشخص‌شده در فضای نام انتخاب می‌شوند.
--allow-missing-template-keys     Default: true

اگر true باشد، هنگامی که یک فیلد یا کلید نگاشت (map) در قالب وجود نداشته باشد، از خطاهای قالب صرف‌نظر می‌شود. این گزینه فقط برای قالب‌های خروجی golang و jsonpath اعمال می‌شود.
-c, --containers string     Default: "*"

نام کانتینرهایی از قالب‌های پاد انتخاب‌شده که باید تغییر کنند؛ می‌توان از نویسه‌های عام (wildcard) استفاده کرد.
--dry-run string[="unchanged"]     Default: "none"

مقدار آن باید یکی از "none"، "server" یا "client" باشد. در راهبرد client، فقط آبجکتی که قرار است ارسال شود چاپ می‌شود و ارسالی صورت نمی‌گیرد. در راهبرد server، درخواست سمت سرور ارسال می‌شود، اما منبع ذخیره نمی‌شود.
-e, --env strings

یک جفت کلید-مقدار برای متغیر محیطی‌ای مشخص می‌کند که باید در هر کانتینر تنظیم شود.
--field-manager string     Default: "kubectl-set"

نام مدیری که برای ردیابی مالکیت فیلدها به کار می‌رود.
-f, --filename strings

نام فایل، دایرکتوری یا URL فایل‌های منبعی که متغیرهای محیطی آن باید به‌روزرسانی شوند.
--from string

نام منبعی که متغیرهای محیطی از آن تزریق می‌شوند.
-h, --help

راهنمای env
--keys strings

فهرستی از کلیدها، جداشده با ویرگول، که باید از منبع مشخص‌شده وارد شوند.
-k, --kustomize string

دایرکتوری kustomization را پردازش می‌کند. این پرچم را نمی‌توان همراه با -f یا -R به کار برد.
--list

اگر true باشد، متغیرهای محیطی و هرگونه تغییر در آن‌ها با قالب استاندارد نمایش داده می‌شوند. این پرچم پس از افزوده شدن دستور kubectl view env حذف خواهد شد.
--local

اگر true باشد، دستور set env با api-server ارتباط برقرار نمی‌کند و به‌صورت محلی اجرا می‌شود.
-o, --output string

قالب خروجی، که یکی از این مقادیر است: (json, yaml, kyaml, name, go-template, go-template-file, template, templatefile, jsonpath, jsonpath-as-json, jsonpath-file).
--overwrite     Default: true

اگر true باشد، بازنویسی متغیرهای محیطی مجاز است؛ در غیر این صورت، به‌روزرسانی‌هایی که متغیرهای محیطی موجود را بازنویسی می‌کنند رد می‌شوند.
--prefix string

پیشوندی که به نام متغیرها افزوده می‌شود.
-R, --recursive

دایرکتوری تعیین‌شده در -f, --filename را به‌صورت بازگشتی پردازش می‌کند. این گزینه زمانی مفید است که بخواهید مانیفست‌های مرتبطی را مدیریت کنید که در یک دایرکتوری سازمان‌دهی شده‌اند.
--resolve

اگر true باشد، هنگام فهرست کردن متغیرها، ارجاع‌های secret یا configmap نمایش داده می‌شوند.
-l, --selector string

انتخابگر (selector)، یعنی پرس‌وجوی برچسب، برای فیلتر کردن؛ از '='، '=='، '!='، 'in' و 'notin' پشتیبانی می‌کند (مثلاً -l key1=value1,key2=value2,key3 in (value3)). آبجکت‌های منطبق باید همهٔ محدودیت‌های برچسب مشخص‌شده را برآورده کنند.
--show-managed-fields

اگر true باشد، هنگام چاپ آبجکت‌ها با قالب JSON یا YAML، فیلد managedFields حفظ می‌شود.
--template string

رشتهٔ قالب یا مسیر فایل قالب که هنگام تعیین -o=go-template یا -o=go-template-file به کار می‌رود. قالب‌ها از نوع قالب‌های golang هستند [http://golang.org/pkg/text/template/#pkg-overview].

گزینه‌های ارث‌بری شده از والد

--as string

نام کاربری که این عملیات با جعل هویت (impersonation) آن انجام می‌شود. این کاربر می‌تواند یک کاربر عادی یا یک حساب سرویس (service account) در یک فضای نام باشد.
--as-group strings

گروهی که این عملیات با جعل هویت آن انجام می‌شود؛ برای تعیین چند گروه می‌توان این پرچم را تکرار کرد.
--as-uid string

شناسهٔ UID که این عملیات با جعل هویت آن انجام می‌شود.
--as-user-extra strings

اطلاعات اضافی کاربر که این عملیات با جعل هویت آن انجام می‌شود؛ برای تعیین چند مقدار برای یک کلید می‌توان این پرچم را تکرار کرد.
--cache-dir string     Default: "$HOME/.kube/cache"

دایرکتوری پیش‌فرض حافظهٔ نهان (cache)
--certificate-authority string

مسیر فایل گواهی مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستری از kubeconfig که باید استفاده شود
--context string

نام زمینه (context) از kubeconfig که باید استفاده شود
--disable-compression

اگر true باشد، فشرده‌سازی پاسخ برای همهٔ درخواست‌ها به سرور غیرفعال می‌شود.
--insecure-skip-tls-verify

اگر true باشد، اعتبار گواهی سرور بررسی نمی‌شود. این کار اتصال‌های HTTPS شما را ناامن می‌کند.
--kubeconfig string

مسیر فایل kubeconfig برای استفاده در درخواست‌های CLI.
--kuberc string

مسیر فایل kuberc برای استفاده در تنظیمات ترجیحی. می‌توان این قابلیت را با export کردن feature gate به‌صورت KUBECTL_KUBERC=false یا با خاموش کردن قابلیت به‌صورت KUBERC=off غیرفعال کرد.
--match-server-version

الزام می‌کند که نسخهٔ سرور با نسخهٔ کلاینت مطابقت داشته باشد.
-n, --namespace string

در صورت تعیین، محدودهٔ فضای نام برای این درخواست CLI
--password string

گذرواژه برای احراز هویت پایه (basic authentication) در سرور API
--profile string     Default: "none"

نام پروفایلی که باید ثبت شود؛ یکی از مقادیر (none|cpu|heap|goroutine|threadcreate|block|mutex|trace)
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی برای استفاده در درخواست‌ها به سرور API
--request-timeout string     Default: "0"

مدت زمان انتظار پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (مثلاً 1s، 2m، 3h). مقدار صفر به این معناست که برای درخواست‌ها مهلت زمانی (timeout) در نظر گرفته نمی‌شود.
-s, --server string

نشانی و پورت سرور API کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

عملیات نوشتن در درایور ذخیره‌سازی به مدت این بازه بافر می‌شوند و سپس به‌صورت یک تراکنش واحد در پشتیبان‌های غیرحافظه‌ای (non-memory backends) ثبت می‌شوند.
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

نشانی host:port پایگاه داده
--storage-driver-password string     Default: "root"

گذرواژهٔ پایگاه داده
--storage-driver-secure

استفاده از اتصال امن با پایگاه داده
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور به کار می‌رود. اگر این مقدار ارائه نشود، از نام میزبانی (hostname) استفاده می‌شود که برای ارتباط با سرور به کار رفته است.
--token string

توکن حامل (Bearer token) برای احراز هویت در سرور API
--user string

نام کاربری از kubeconfig که باید استفاده شود
--username string

نام کاربری برای احراز هویت پایه در سرور API
--version version[=true]

گزینه‌های --version و --version=raw اطلاعات نسخه را چاپ می‌کنند و خارج می‌شوند؛ گزینهٔ --version=vX.Y.Z... نسخهٔ گزارش‌شده را تنظیم می‌کند.
--warnings-as-errors

هشدارهای دریافتی از سرور را خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود.
