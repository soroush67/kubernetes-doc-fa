kubectl

kubectl مدیر کلاستر کوبرنتیز را کنترل می‌کند

خلاصه

kubectl مدیر کلاستر کوبرنتیز را کنترل می‌کند.

اطلاعات بیشتر را در این نشانی بیابید: https://kubernetes.io/docs/reference/kubectl/

kubectl [flags]

گزینه‌ها

--as string

نام کاربری که برای انجام عملیات جعل هویت (impersonate) می‌شود. کاربر می‌تواند یک کاربر معمولی یا یک service account در یک فضای نام (namespace) باشد.
--as-group strings

گروهی که برای انجام عملیات جعل هویت می‌شود؛ برای مشخص کردن چند گروه می‌توان این فلگ را چندین بار تکرار کرد.
--as-uid string

UID که برای انجام عملیات جعل هویت می‌شود.
--as-user-extra strings

اطلاعات اضافی کاربر که برای انجام عملیات جعل هویت می‌شود؛ برای مشخص کردن چند مقدار برای یک کلید یکسان می‌توان این فلگ را چندین بار تکرار کرد.
--cache-dir string     Default: "$HOME/.kube/cache"

دایرکتوری پیش‌فرض کش
--certificate-authority string

مسیر فایل گواهی مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستر kubeconfig که باید استفاده شود
--context string

نام context در kubeconfig که باید استفاده شود
--disable-compression

اگر true باشد، فشرده‌سازی پاسخ برای همه درخواست‌ها به سرور غیرفعال می‌شود
-h, --help

راهنمای kubectl
--insecure-skip-tls-verify

اگر true باشد، اعتبار گواهی سرور بررسی نخواهد شد. این کار اتصالات HTTPS شما را ناامن می‌کند
--kubeconfig string

مسیر فایل kubeconfig که برای درخواست‌های CLI استفاده می‌شود.
--kuberc string

مسیر فایل kuberc که برای تنظیمات ترجیحی استفاده می‌شود. این قابلیت را می‌توان با صادرکردن feature gate با مقدار KUBECTL_KUBERC=false یا با خاموش کردن قابلیت از طریق KUBERC=off غیرفعال کرد.
--match-server-version

مطابقت نسخه سرور با نسخه کلاینت را الزامی می‌کند
-n, --namespace string

در صورت وجود، محدوده فضای نام (namespace) را برای این درخواست CLI مشخص می‌کند
--password string

گذرواژه برای احراز هویت پایه (basic authentication) به API server
--profile string     Default: "none"

نام پروفایلی که باید ثبت شود. یکی از (none|cpu|heap|goroutine|threadcreate|block|mutex|trace)
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی که برای درخواست‌ها به API server استفاده می‌شود
--request-timeout string     Default: "0"

مدت زمان انتظار پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور. مقادیر غیرصفر باید شامل یک واحد زمانی متناظر باشند (برای مثال 1s، 2m، 3h). مقدار صفر به معنای عدم اعمال محدودیت زمانی برای درخواست‌هاست.
-s, --server string

نشانی و درگاه (port) سرور API کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

نوشتن‌ها در درایور ذخیره‌سازی به‌مدت این بازه زمانی بافر می‌شوند و به‌صورت یک تراکنش واحد در بک‌اندهای غیرحافظه‌ای ثبت می‌گردند
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

میزبان:درگاه پایگاه داده
--storage-driver-password string     Default: "root"

گذرواژه پایگاه داده
--storage-driver-secure

استفاده از اتصال امن با پایگاه داده
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور استفاده می‌شود. اگر ارائه نشود، از نام میزبانی که برای برقراری ارتباط با سرور استفاده شده است، استفاده می‌شود
--token string

توکن Bearer برای احراز هویت به API server
--user string

نام کاربر kubeconfig که باید استفاده شود
--username string

نام کاربری برای احراز هویت پایه (basic authentication) به API server
--version version[=true]

--version و --version=raw اطلاعات نسخه را چاپ کرده و خارج می‌شوند؛ --version=vX.Y.Z... نسخه گزارش‌شده را تنظیم می‌کند
--warnings-as-errors

هشدارهای دریافتی از سرور را به‌عنوان خطا در نظر می‌گیرد و با کد خروج غیرصفر خارج می‌شود

همچنین ببینید

  • kubectl annotate - به‌روزرسانی حاشیه‌نویسی‌ها (annotations) روی یک منبع
  • kubectl api-resources - چاپ منابع API پشتیبانی‌شده روی سرور
  • kubectl api-versions - چاپ نسخه‌های API پشتیبانی‌شده روی سرور، به‌صورت «group/version»
  • kubectl apply - اعمال یک پیکربندی بر یک منبع بر اساس نام فایل یا stdin
  • kubectl attach - اتصال به یک کانتینر در حال اجرا
  • kubectl auth - بررسی مجوزدهی (authorization)
  • kubectl autoscale - مقیاس‌دهی خودکار یک Deployment، ReplicaSet، StatefulSet یا ReplicationController
  • kubectl certificate - تغییر منابع گواهی
  • kubectl cluster-info - نمایش اطلاعات کلاستر
  • kubectl completion - تولید کد تکمیل خودکار شل برای شل مشخص‌شده (bash، zsh، fish یا powershell)
  • kubectl config - تغییر فایل‌های kubeconfig
  • kubectl cordon - علامت‌گذاری نود به‌عنوان غیرقابل زمان‌بندی
  • kubectl cp - کپی فایل‌ها و دایرکتوری‌ها به کانتینرها و از آن‌ها
  • kubectl create - ایجاد یک منبع از یک فایل یا از stdin
  • kubectl debug - ایجاد نشست‌های اشکال‌زدایی برای عیب‌یابی بارهای کاری و نودها
  • kubectl delete - حذف منابع بر اساس نام فایل، stdin، منابع و نام‌ها، یا منابع و انتخابگر برچسب (label selector)
  • kubectl describe - نمایش جزئیات یک منبع مشخص یا گروهی از منابع
  • kubectl diff - مقایسه نسخه فعال با نسخه‌ای که قرار است اعمال شود
  • kubectl drain - تخلیه نود در آماده‌سازی برای نگهداری
  • kubectl edit - ویرایش یک منبع روی سرور
  • kubectl events - فهرست رویدادها
  • kubectl exec - اجرای یک دستور در یک کانتینر
  • kubectl explain - دریافت مستندات یک منبع
  • kubectl expose - دریافت یک ReplicationController، Service، Deployment یا Pod و در دسترس قرار دادن آن به‌عنوان یک Service جدید کوبرنتیز
  • kubectl get - نمایش یک یا چند منبع
  • kubectl kuberc - مدیریت فایل‌های پیکربندی kuberc
  • kubectl kustomize - ساخت یک هدف kustomization از یک دایرکتوری یا URL
  • kubectl label - به‌روزرسانی برچسب‌ها (labels) روی یک منبع
  • kubectl logs - چاپ لاگ‌های یک کانتینر در یک Pod
  • kubectl options - چاپ فهرست فلگ‌هایی که همه دستورها به ارث می‌برند
  • kubectl patch - به‌روزرسانی فیلدهای یک منبع
  • kubectl plugin - ارائه ابزارهایی برای تعامل با افزونه‌ها (plugins)
  • kubectl port-forward - هدایت یک یا چند درگاه محلی به یک Pod
  • kubectl proxy - اجرای یک پراکسی به API server کوبرنتیز
  • kubectl replace - جایگزینی یک منبع بر اساس نام فایل یا stdin
  • kubectl rollout - مدیریت رول‌اوت (rollout) یک منبع
  • kubectl run - اجرای یک ایمیج مشخص روی کلاستر
  • kubectl scale - تنظیم اندازه جدید برای یک Deployment، ReplicaSet یا ReplicationController
  • kubectl set - تنظیم ویژگی‌های مشخص روی آبجکت‌ها
  • kubectl taint - به‌روزرسانی taintها روی یک یا چند نود
  • kubectl top - نمایش میزان مصرف منابع (CPU/حافظه)
  • kubectl uncordon - علامت‌گذاری نود به‌عنوان قابل زمان‌بندی
  • kubectl version - چاپ اطلاعات نسخه کلاینت و سرور
  • kubectl wait - انتظار برای یک شرط مشخص روی یک یا چند منبع
