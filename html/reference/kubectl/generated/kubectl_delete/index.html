kubectl delete

حذف منابع بر اساس نام فایل‌ها، stdin، منابع و نام‌ها، یا بر اساس منابع و انتخابگر برچسب

خلاصه

این دستور منابع را بر اساس نام فایل‌ها، ورودی استاندارد (stdin)، منابع و نام‌ها، یا بر اساس منابع و انتخابگر (selector) برچسب حذف می‌کند.

هر دو قالب JSON و YAML پذیرفته می‌شوند. فقط یک نوع آرگومان را می‌توان مشخص کرد: نام فایل‌ها، منابع و نام‌ها، یا منابع و انتخابگر برچسب.

برخی منابع، مانند پادها، از حذف مؤدبانه (graceful deletion) پشتیبانی می‌کنند. این منابع یک بازه‌ی زمانی پیش‌فرض پیش از خاتمه‌ی اجباری تعریف می‌کنند (دوره‌ی مهلت یا grace period)، اما می‌توانید این مقدار را با فلگ ‎--grace-period بازنویسی کنید یا با ارسال ‎--now دوره‌ی مهلت را روی ۱ تنظیم کنید. از آنجا که این منابع اغلب نماینده‌ی موجودیت‌هایی در کلاستر هستند، ممکن است حذف آن‌ها بلافاصله تأیید نشود. اگر نودی که میزبان یک پاد است از کار افتاده باشد یا نتواند به سرور API دسترسی پیدا کند، خاتمه ممکن است به‌مراتب بیشتر از دوره‌ی مهلت طول بکشد. برای حذف اجباری یک منبع، باید فلگ ‎--force را مشخص کنید. توجه: تنها بخشی از منابع از حذف مؤدبانه پشتیبانی می‌کنند. در صورت نبود این پشتیبانی، فلگ ‎--grace-period نادیده گرفته می‌شود.

مهم: حذف اجباری پادها منتظر تأیید خاتمه‌ی پردازه‌های پاد نمی‌ماند. در نتیجه ممکن است این پردازه‌ها تا زمانی که نود حذف را تشخیص دهد و حذف مؤدبانه را کامل کند، همچنان در حال اجرا بمانند. اگر پردازه‌های شما از ذخیره‌سازی مشترک استفاده می‌کنند یا با یک API راه دور ارتباط دارند و برای شناسایی خود به نام پاد وابسته‌اند، حذف اجباری آن پادها ممکن است باعث شود چند پردازه با شناسه‌ی یکسان روی ماشین‌های مختلف اجرا شوند که می‌تواند به خرابی یا ناسازگاری داده‌ها بینجامد. پادها را فقط زمانی به‌صورت اجباری حذف کنید که مطمئن باشید پاد خاتمه یافته است، یا برنامه‌ی شما بتواند اجرای هم‌زمان چند نسخه از یک پاد را تحمل کند. همچنین اگر پادها را به‌صورت اجباری حذف کنید، ممکن است زمان‌بند پیش از آنکه نود آن منابع را آزاد کند، پادهای جدیدی روی آن نودها قرار دهد و همین امر باعث اخراج (evict) فوری آن پادها شود.

توجه داشته باشید که دستور delete هیچ بررسی‌ای روی نسخه‌ی منبع انجام نمی‌دهد. بنابراین اگر کسی درست هم‌زمان با ارسال درخواست حذف شما، به‌روزرسانی‌ای برای یک منبع ارسال کند، به‌روزرسانی او همراه با بقیه‌ی منبع از بین می‌رود.

پس از حذف یک CustomResourceDefinition، بی‌اعتبار شدن حافظه‌ی نهان discovery ممکن است تا ۶ ساعت طول بکشد. اگر نمی‌خواهید منتظر بمانید، می‌توانید دستور "kubectl api-resources" را اجرا کنید تا حافظه‌ی نهان discovery تازه‌سازی شود.

kubectl delete ([-f FILENAME] | [-k DIRECTORY] | TYPE [(NAME | -l label | --all)])

مثال‌ها

  # Delete a pod using the type and name specified in pod.json
  kubectl delete -f ./pod.json
  
  # Delete resources from a directory containing kustomization.yaml - e.g. dir/kustomization.yaml
  kubectl delete -k dir
  
  # Delete resources from all files that end with '.json'
  kubectl delete -f '*.json'
  
  # Delete a pod based on the type and name in the JSON passed into stdin
  cat pod.json | kubectl delete -f -
  
  # Delete pods and services with same names "baz" and "foo"
  kubectl delete pod,service baz foo
  
  # Delete pods and services with label name=myLabel
  kubectl delete pods,services -l name=myLabel
  
  # Delete a pod with minimal delay
  kubectl delete pod foo --now
  
  # Force delete a pod on a dead node
  kubectl delete pod foo --force
  
  # Delete all pods
  kubectl delete pods --all
  
  # Delete all pods only if the user confirms the deletion
  kubectl delete pods --all --interactive

گزینه‌ها

--all

همه‌ی منابع از انواع منبع مشخص‌شده را در فضای نام (namespace) حذف می‌کند.
-A, --all-namespaces

در صورت وجود، آبجکت‌های درخواست‌شده را در همه‌ی فضاهای نام فهرست می‌کند. فضای نامِ context جاری نادیده گرفته می‌شود، حتی اگر با ‎--namespace مشخص شده باشد.
--cascade string[="background"]     Default: "background"

مقدار آن باید یکی از "background"، "orphan" یا "foreground" باشد. راهبرد حذف آبشاری را برای وابسته‌ها (برای نمونه، پادهایی که یک ReplicationController ایجاد کرده است) انتخاب می‌کند. مقدار پیش‌فرض background است.
--dry-run string[="unchanged"]     Default: "none"

مقدار آن باید یکی از "none"، "server" یا "client" باشد. در راهبرد client، فقط آبجکتی که قرار است ارسال شود چاپ می‌شود و ارسالی صورت نمی‌گیرد. در راهبرد server، درخواست سمت سرور ارسال می‌شود، بدون آنکه منبع ذخیره شود.
--field-selector string

انتخابگر (پرس‌وجوی فیلد) برای فیلتر کردن که از '='، '==' و '!=' پشتیبانی می‌کند (برای نمونه ‎--field-selector key1=value1,key2=value2). سرور برای هر نوع فقط از تعداد محدودی پرس‌وجوی فیلد پشتیبانی می‌کند.
-f, --filename strings

فایلی که منبعِ مورد نظر برای حذف را در بر دارد.
--force

اگر true باشد، منابع بلافاصله از API حذف می‌شوند و حذف مؤدبانه نادیده گرفته می‌شود. توجه داشته باشید که حذف فوری برخی منابع ممکن است به ناسازگاری یا از دست رفتن داده‌ها بینجامد و به تأیید نیاز دارد.
--grace-period int     Default: -1

مدت زمانی بر حسب ثانیه که به منبع داده می‌شود تا به‌صورت مؤدبانه خاتمه یابد. مقدار منفی نادیده گرفته می‌شود. برای خاموش شدن فوری، آن را روی ۱ تنظیم کنید. فقط زمانی می‌توان آن را روی ۰ تنظیم کرد که ‎--force برابر true باشد (حذف اجباری).
-h, --help

راهنمای دستور delete
--ignore-not-found

خطای "resource not found" را به‌عنوان حذف موفق در نظر می‌گیرد. هنگامی که ‎--all مشخص شده باشد، مقدار پیش‌فرض آن "true" است.
-i, --interactive

اگر true باشد، منبع فقط زمانی حذف می‌شود که کاربر آن را تأیید کند.
-k, --kustomize string

یک دایرکتوری kustomization را پردازش می‌کند. این فلگ را نمی‌توان همراه با ‎-f یا ‎-R استفاده کرد.
--now

اگر true باشد، به منابع برای خاموش شدن فوری سیگنال داده می‌شود (معادل ‎--grace-period=1).
-o, --output string

حالت خروجی. برای خروجی کوتاه‌تر (resource/name) از "-o name" استفاده کنید.
--raw string

نشانی URI خامی که درخواست DELETE به آن روی سرور ارسال می‌شود. از transport مشخص‌شده در فایل kubeconfig استفاده می‌کند.
-R, --recursive

دایرکتوری استفاده‌شده در ‎-f, --filename را به‌صورت بازگشتی پردازش می‌کند. این گزینه زمانی مفید است که بخواهید مانیفست‌های مرتبطی را که در یک دایرکتوری سازمان‌دهی شده‌اند مدیریت کنید.
-l, --selector string

انتخابگر (پرس‌وجوی برچسب) برای فیلتر کردن که از '='، '=='، '!='، 'in' و 'notin' پشتیبانی می‌کند (برای نمونه ‎-l key1=value1,key2=value2,key3 in (value3)). آبجکت‌های منطبق باید همه‌ی قیدهای برچسبِ مشخص‌شده را برآورده کنند.
--timeout duration

مدت زمانی که پیش از صرف‌نظر کردن از حذف منتظر می‌ماند. مقدار صفر به این معناست که مهلت زمانی بر اساس اندازه‌ی آبجکت تعیین شود.
--wait     Default: true

اگر true باشد، پیش از بازگشت منتظر می‌ماند تا منابع از بین بروند. این گزینه منتظر finalizerها نیز می‌ماند.

گزینه‌های ارث‌بری شده از والد

--as string

نام کاربری که این عملیات به جای آن و با هویت آن انجام می‌شود (جعل هویت یا impersonation). این کاربر می‌تواند یک کاربر عادی یا یک حساب سرویس (service account) در یک فضای نام (namespace) باشد.
--as-group strings

گروهی که این عملیات با هویت آن انجام می‌شود. برای مشخص کردن چند گروه، می‌توانید این فلگ را چند بار تکرار کنید.
--as-uid string

شناسهٔ UID که این عملیات با هویت آن انجام می‌شود.
--as-user-extra strings

اطلاعات تکمیلی کاربر که این عملیات با هویت آن‌ها انجام می‌شود. برای مشخص کردن چند مقدار برای یک کلید واحد، می‌توانید این فلگ را چند بار تکرار کنید.
--cache-dir string     Default: "$HOME/.kube/cache"

مسیر پیش‌فرض دایرکتوری کش
--certificate-authority string

مسیر فایل گواهی مربوط به مرجع صدور گواهی (certificate authority)
--client-certificate string

مسیر فایل گواهی کلاینت برای TLS
--client-key string

مسیر فایل کلید کلاینت برای TLS
--cluster string

نام کلاستری از فایل kubeconfig که باید از آن استفاده شود
--context string

نام کانتکستی (context) از فایل kubeconfig که باید از آن استفاده شود
--disable-compression

اگر مقدار آن true باشد، فشرده‌سازی پاسخ برای همهٔ درخواست‌هایی که به سرور ارسال می‌شوند غیرفعال می‌شود.
--insecure-skip-tls-verify

اگر مقدار آن true باشد، اعتبار گواهی سرور بررسی نمی‌شود. در این صورت، اتصال‌های HTTPS شما ناامن خواهند بود.
--kubeconfig string

مسیر فایل kubeconfig که برای درخواست‌های خط فرمان (CLI) استفاده می‌شود.
--kuberc string

مسیر فایل kuberc که برای تنظیم ترجیحات کاربر استفاده می‌شود. می‌توان این قابلیت را با export کردن feature gate به صورت KUBECTL_KUBERC=false یا با خاموش کردن قابلیت به صورت KUBERC=off غیرفعال کرد.
--match-server-version

الزام می‌کند که نسخهٔ سرور با نسخهٔ کلاینت یکسان باشد.
-n, --namespace string

در صورت مشخص شدن، دامنهٔ فضای نام را برای این درخواست خط فرمان تعیین می‌کند.
--password string

گذرواژه برای احراز هویت پایه (basic authentication) در سرور API
--profile string     Default: "none"

نام پروفایلی که باید ثبت شود. مقدار آن یکی از این گزینه‌هاست: (none|cpu|heap|goroutine|threadcreate|block|mutex|trace)
--profile-output string     Default: "profile.pprof"

نام فایلی که پروفایل در آن نوشته می‌شود
--proxy-url string

نشانی URL پراکسی که برای ارسال درخواست‌ها به سرور API استفاده می‌شود
--request-timeout string     Default: "0"

مدت زمانی که پیش از صرف‌نظر کردن از یک درخواست منفرد به سرور، منتظر پاسخ می‌مانیم. مقادیر غیرصفر باید واحد زمانی متناظر داشته باشند (برای نمونه 1s، 2m یا 3h). مقدار صفر به این معناست که برای درخواست‌ها هیچ مهلت زمانی (timeout) در نظر گرفته نمی‌شود.
-s, --server string

نشانی و درگاه (port) سرور API کوبرنتیز
--storage-driver-buffer-duration duration     Default: 1m0s

عملیات نوشتن در درایور ذخیره‌سازی به اندازهٔ این مدت در بافر نگه داشته می‌شوند و سپس در قالب یک تراکنش واحد در بک‌اندهای غیرحافظه‌ای (non-memory) ثبت می‌شوند.
--storage-driver-db string     Default: "cadvisor"

نام پایگاه داده
--storage-driver-host string     Default: "localhost:8086"

میزبان و درگاه پایگاه داده به صورت host:port
--storage-driver-password string     Default: "root"

گذرواژهٔ پایگاه داده
--storage-driver-secure

برای اتصال به پایگاه داده از اتصال امن استفاده می‌شود
--storage-driver-table string     Default: "stats"

نام جدول
--storage-driver-user string     Default: "root"

نام کاربری پایگاه داده
--tls-server-name string

نام سروری که برای اعتبارسنجی گواهی سرور استفاده می‌شود. اگر این مقدار مشخص نشود، از نام میزبانی (hostname) که برای برقراری ارتباط با سرور به کار رفته است استفاده می‌شود.
--token string

توکن حامل (bearer token) برای احراز هویت در سرور API
--user string

نام کاربری از فایل kubeconfig که باید از آن استفاده شود
--username string

نام کاربری برای احراز هویت پایه در سرور API
--version version[=true]

گزینه‌های ‎--version و ‎--version=raw اطلاعات نسخه را چاپ می‌کنند و از برنامه خارج می‌شوند؛ گزینهٔ ‎--version=vX.Y.Z...‎ نسخهٔ گزارش‌شده را تعیین می‌کند.
--warnings-as-errors

هشدارهای دریافت‌شده از سرور را به‌عنوان خطا در نظر می‌گیرد و با کد خروج غیرصفر از برنامه خارج می‌شود.
