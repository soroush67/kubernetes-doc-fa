داده‌های معیارهای نود

سازوکارهای دسترسی به معیارها در سطح نود، حجم (volume)، Pod و کانتینر، آن‌گونه که kubelet آن‌ها را مشاهده می‌کند.

kubelet آمار معیارها را در سطح نود، حجم (volume)، Pod و کانتینر گردآوری می‌کند و این اطلاعات را از طریق Summary API ارائه می‌دهد.

می‌توانید از طریق kube-apiserver یک درخواست پراکسی‌شده به API خلاصه آمار (stats summary) ارسال کنید.

در ادامه نمونه‌ای از یک درخواست Summary API برای نودی با نام minikube آمده است:

kubectl get --raw "/api/v1/nodes/minikube/proxy/stats/summary"

در ادامه همین فراخوانی API با استفاده از curl آمده است:

# You need to run "kubectl proxy" first
# Change 8080 to the port that "kubectl proxy" assigns
curl http://localhost:8080/api/v1/nodes/minikube/proxy/stats/summary
توجه:

از metrics-server نسخه 0.6.x به بعد، metrics-server به‌جای /stats/summary، از endpoint با مسیر /metrics/resource در kubelet پرس‌وجو می‌کند.

منبع Summary metrics API {#summary-api-source}

به‌طور پیش‌فرض، کوبرنتیز داده‌های معیارهای خلاصه نود را با استفاده از cAdvisor تعبیه‌شده‌ای که درون kubelet اجرا می‌شود، دریافت می‌کند. اگر PodAndContainerStatsFromCRI feature gate را در کلاستر خود فعال کنید و از یک container runtime استفاده کنید که دسترسی به آمار را از طریق Container Runtime Interface (CRI) پشتیبانی می‌کند، آنگاه kubelet داده‌های معیارهای سطح Pod و کانتینر را با استفاده از CRI دریافت می‌کند و نه از طریق cAdvisor.

Pressure Stall Information (PSI) {#psi}

وضعیت ویژگی: Kubernetes [] ()

به‌عنوان یک قابلیت پایدار، کوبرنتیز به شما امکان می‌دهد kubelet را طوری پیکربندی کنید که Pressure Stall Information (PSI) هسته لینوکس را برای میزان استفاده از CPU، حافظه و I/O گردآوری کند. این اطلاعات در سطح نود، Pod و کانتینر گردآوری می‌شود. برای مشاهده طرح‌واره (schema) کامل، به Summary API مراجعه کنید. از کوبرنتیز نسخه v1.36 به بعد، KubeletPSI feature gate روی true قفل شده است و نمی‌توان آن را غیرفعال کرد. این اطلاعات همچنین در معیارهای Prometheus ارائه می‌شود.

می‌توانید یاد بگیرید معیارهای PSI را چگونه تفسیر کنید، در درک معیارهای PSI.

الزامات {#requirements}

Pressure Stall Information به موارد زیر نیاز دارد:

  • هسته لینوکس نسخه 4.20 یا بالاتر.
  • cgroup v2

گام‌های بعدی

صفحات وظیفه عیب‌یابی کلاسترها نحوه استفاده از یک خط لوله معیارها (metrics pipeline) را که به این داده‌ها متکی است، شرح می‌دهند.
