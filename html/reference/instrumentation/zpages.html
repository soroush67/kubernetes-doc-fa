z-pages کوبرنتیز

تشخیص‌های زمان اجرا را برای مؤلفه‌های کوبرنتیز فراهم می‌کند و دید روشنی از وضعیت زمان اجرا و فلگ‌های پیکربندی مؤلفه ارائه می‌دهد.

وضعیت ویژگی: Kubernetes v1.36 [beta] (بتا)

مؤلفه‌های اصلی کوبرنتیز می‌توانند مجموعه‌ای از z-endpointها را در دسترس قرار دهند تا کاربران بتوانند راحت‌تر کلاستر و مؤلفه‌های آن را اشکال‌زدایی کنند. این اندپوینت‌ها صرفاً برای بررسی توسط انسان در نظر گرفته شده‌اند تا اطلاعات اشکال‌زدایی بی‌درنگ از یک فایل باینری مؤلفه به دست آید. در کوبرنتیز 1.37 این قابلیت‌ها بتا هستند.

z-pages {#z-pages}

کوبرنتیز v1.37 به شما امکان می‌دهد z-pages را فعال کنید تا در عیب‌یابی مشکلات مؤلفه‌های اصلی control plane کمک بگیرید. این اندپوینت‌های اشکال‌زدایی ویژه، اطلاعات داخلی مربوط به مؤلفه‌های در حال اجرا را ارائه می‌دهند. در کوبرنتیز 1.37، مؤلفه‌ها اندپوینت‌های زیر را (در صورت فعال بودن) ارائه می‌کنند:

  • z-pages
    • statusz
      • statusz (structured)
    • flagz
      • flagz (structured)

statusz {#statusz}

اندپوینت /statusz که با استفاده از feature gate با نام ComponentStatusz فعال می‌شود، اطلاعات سطح بالایی درباره مؤلفه، مانند نسخه کوبرنتیز، نسخه شبیه‌سازی (emulation version)، زمان شروع و موارد دیگر را نمایش می‌دهد.

پاسخ متنی ساده /statusz از API server مشابه نمونه زیر است:

kube-apiserver statusz
Warning: This endpoint is not meant to be machine parseable, has no formatting compatibility guarantees and is for debugging purposes only.

Started: Wed Oct 16 21:03:43 UTC 2024
Up: 0 hr 00 min 16 sec
Go version: go1.23.2
Binary version: 1.32.0-alpha.0.1484&#43;5eeac4f21a491b-dirty
Emulation version: 1.32.0-alpha.0.1484
Paths: /healthz /livez /metrics /readyz /statusz /version

statusz (structured) {#statusz-structured}

وضعیت ویژگی: Kubernetes [] ()

از کوبرنتیز v1.35 به بعد، اندپوینت /statusz در صورتی که با هدر Accept مناسب درخواست شود، قالب پاسخ ساختاریافته و نسخه‌دار را پشتیبانی می‌کند. اگر هدر Accept ارسال نشود، اندپوینت به‌طور پیش‌فرض پاسخ را در قالب متن ساده برمی‌گرداند.

برای درخواست پاسخ ساختاریافته از این مقدار استفاده کنید:

Accept: application/json;v=v1beta1;g=config.k8s.io;as=Statusz
توجه:

اگر application/json را بدون مشخص کردن همه پارامترهای لازم (g، v و as) درخواست کنید، سرور با کد 406 Not Acceptable پاسخ می‌دهد.

نمونه‌ای از پاسخ ساختاریافته:

{
  "kind": "Statusz",
  "apiVersion": "config.k8s.io/v1beta1",
  "metadata": {
    "name": "kube-apiserver"
  },
  "startTime": "2025-10-29T00:30:01Z",
  "uptimeSeconds": 856,
  "goVersion": "go1.23.2",
  "binaryVersion": "1.35.0",
  "emulationVersion": "1.35",
  "paths": [
    "/healthz",
    "/livez",
    "/metrics",
    "/readyz",
    "/statusz",
    "/version"
  ]
}

flagz {#flagz}

اندپوینت /flagz که با استفاده از feature gate با نام ComponentFlagz فعال می‌شود، آرگومان‌های خط فرمانی را که برای راه‌اندازی یک مؤلفه استفاده شده‌اند نمایش می‌دهد.

توجه:

/flagz فلگ‌های خط فرمان و مقادیر پیش‌فرض را گزارش می‌کند. در مؤلفه‌هایی که فایل‌های پیکربندی نیز بارگذاری می‌کنند، مانند kubelet و kube-proxy، پیکربندی مؤثر در حال اجرا ممکن است با /flagz متفاوت باشد؛ برای بررسی پیکربندی ادغام‌شده مؤلفه، در صورت وجود از /configz استفاده کنید.

پاسخ متنی ساده /flagz از API server تقریباً به این شکل است:

kube-apiserver flags
Warning: This endpoint is not meant to be machine parseable, has no formatting compatibility guarantees and is for debugging purposes only.

advertise-address=192.168.8.2
contention-profiling=false
enable-priority-and-fairness=true
profiling=true
authorization-mode=[Node,RBAC]
authorization-webhook-cache-authorized-ttl=5m0s
authorization-webhook-cache-unauthorized-ttl=30s
authorization-webhook-version=v1beta1
default-watch-cache-size=100
