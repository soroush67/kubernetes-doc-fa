ExecCredential {#client-authentication-k8s-io-v1beta1-ExecCredential}

ExecCredential توسط افزونه‌های مبتنی بر exec برای انتقال اطلاعات احراز هویت (credentials) به لایه‌های انتقال HTTP استفاده می‌شود.

فیلدتوضیحات
apiVersion
string		client.authentication.k8s.io/v1beta1
kind
string		ExecCredential
spec [الزامی]
ExecCredentialSpec

Spec شامل اطلاعاتی است که لایه انتقال (transport) به افزونه ارسال می‌کند.
status
ExecCredentialStatus

Status توسط افزونه پر می‌شود و شامل اطلاعات احراز هویتی است که لایه انتقال باید برای برقراری ارتباط با API از آن‌ها استفاده کند.

Cluster {#client-authentication-k8s-io-v1beta1-Cluster}

در این بخش‌ها ظاهر می‌شود:

  • ExecCredentialSpec

Cluster شامل اطلاعاتی است که به یک افزونه exec امکان می‌دهد با کلاستر کوبرنتیزی که احراز هویت نسبت به آن انجام می‌شود ارتباط برقرار کند.

برای اطمینان از اینکه این ساختار (struct) همه چیزهای لازم برای ارتباط با یک کلاستر کوبرنتیز را در بر دارد (دقیقاً مانند ارتباط از طریق kubeconfig)، فیلدهای آن باید با "k8s.io/client-go/tools/clientcmd/api/v1".Cluster هم‌خوان باشد، به‌استثنای CertificateAuthority، زیرا داده‌های CA همیشه به‌صورت بایت به افزونه ارسال می‌شوند.

فیلدتوضیحات
server [الزامی]
string

Server آدرس کلاستر کوبرنتیز است (https://hostname:port).
tls-server-name
string

TLSServerName برای SNI به سرور ارسال می‌شود و در کلاینت برای بررسی گواهی‌های سرور استفاده می‌شود. اگر ServerName خالی باشد، از نام میزبانی که برای ارتباط با سرور به کار رفته است استفاده می‌شود.
insecure-skip-tls-verify
bool

InsecureSkipTLSVerify بررسی اعتبار گواهی سرور را نادیده می‌گیرد. این کار اتصالات HTTPS شما را ناامن می‌کند.
certificate-authority-data
[]byte

CAData شامل گواهی‌های مرجع صدور گواهی (certificate authority) با کدگذاری PEM است. اگر خالی باشد، باید از ریشه‌های سیستم (system roots) استفاده شود.
proxy-url
string

ProxyURL نشانی URL پروکسی‌ای است که برای تمام درخواست‌ها به این کلاستر استفاده می‌شود.
disable-compression
bool

DisableCompression به کلاینت اجازه می‌دهد برای تمام درخواست‌ها به سرور، از فشرده‌سازی پاسخ صرف‌نظر کند. این کار هنگامی که پهنای باند شبکه بین کلاینت و سرور فراوان است، با صرفه‌جویی در زمان فشرده‌سازی (سمت سرور) و بازکردن فشرده‌سازی (سمت کلاینت)، برای سرعت‌بخشیدن به درخواست‌ها (به‌ویژه درخواست‌های list) مفید است: https://github.com/kubernetes/kubernetes/issues/112296.
config
k8s.io/apimachinery/pkg/runtime.RawExtension

Config شامل داده‌های پیکربندی اضافی است که مختص افزونه exec و مرتبط با کلاستری است که احراز هویت نسبت به آن انجام می‌شود.

این داده از فیلد extensions[client.authentication.k8s.io/exec] در آبجکت Cluster مربوط به clientcmd گرفته می‌شود:

clusters:

  • name: my-cluster cluster: ... extensions:
    • name: client.authentication.k8s.io/exec # reserved extension name for per cluster exec config extension: audience: 06e3fbd18de8 # arbitrary config

در برخی محیط‌ها، پیکربندی کاربر ممکن است در بسیاری از کلاسترها دقیقاً یکسان باشد (یعنی همین افزونه exec را فراخوانی کند)، به‌جز برخی جزئیات که مختص هر کلاستر است، مانند audience. این فیلد امکان می‌دهد پیکربندی مختص هر کلاستر مستقیماً همراه با اطلاعات کلاستر مشخص شود. استفاده از این فیلد برای ذخیره داده‌های محرمانه توصیه نمی‌شود، زیرا یکی از مزایای اصلی افزونه‌های exec این است که لازم نیست هیچ راز (secret)ی مستقیماً در kubeconfig ذخیره شود.

ExecCredentialSpec {#client-authentication-k8s-io-v1beta1-ExecCredentialSpec}

در این بخش‌ها ظاهر می‌شود:

  • ExecCredential

ExecCredentialSpec شامل اطلاعات مختص درخواست و زمان اجرا است که توسط لایه انتقال (transport) ارائه می‌شود.

فیلدتوضیحات
cluster
Cluster

Cluster شامل اطلاعاتی است که به یک افزونه exec امکان می‌دهد با کلاستر کوبرنتیزی که احراز هویت نسبت به آن انجام می‌شود ارتباط برقرار کند. توجه داشته باشید که Cluster فقط زمانی غیر nil است که provideClusterInfo در پیکربندی ارائه‌دهنده exec روی true تنظیم شده باشد (یعنی ExecConfig.ProvideClusterInfo).
interactive [الزامی]
bool

Interactive مشخص می‌کند که آیا stdin به این افزونه exec ارسال شده است یا خیر.

ExecCredentialStatus {#client-authentication-k8s-io-v1beta1-ExecCredentialStatus}

در این بخش‌ها ظاهر می‌شود:

  • ExecCredential

ExecCredentialStatus شامل اطلاعات احراز هویتی است که لایه انتقال باید از آن‌ها استفاده کند.

Token و ClientKeyData فیلدهای حساسی هستند. این داده‌ها باید فقط به‌صورت درون‌حافظه‌ای (in-memory) میان کلاینت و فرایند افزونه exec منتقل شوند. خود افزونه exec نیز دست‌کم باید از طریق مجوزهای فایل محافظت شود.

فیلدتوضیحات
expirationTimestamp
meta/v1.Time

ExpirationTimestamp زمانی را مشخص می‌کند که اعتبار اطلاعات احراز هویت ارائه‌شده به پایان می‌رسد.
token [الزامی]
string

Token یک bearer token است که کلاینت برای احراز هویت درخواست‌ها از آن استفاده می‌کند.
clientCertificateData [الزامی]
string

گواهی‌های TLS کلاینت با کدگذاری PEM (شامل گواهی‌های میانی، در صورت وجود).
clientKeyData [الزامی]
string

کلید خصوصی با کدگذاری PEM برای گواهی بالا.
