AdmissionRequest {#admission-k8s-io-v1-AdmissionRequest}

نمایش داده‌شده در:

  • AdmissionReview

AdmissionRequest مقدار admission.Attributes را برای درخواست پذیرش توصیف می‌کند.

فیلدتوضیحات
uid
k8s.io/apimachinery/pkg/types.UID

uid شناسه‌ای برای هر درخواست/پاسخ مجزا است. این شناسه امکان تمایز نمونه‌های درخواستی را فراهم می‌کند که در غیر این صورت یکسان هستند (درخواست‌های موازی، درخواست‌هایی که درخواست‌های قبلی آن‌ها چیزی را تغییر نداده‌اند و غیره). UID برای ردیابی رفت‌وبرگشت (درخواست/پاسخ) میان KAS و WebHook در نظر گرفته شده است، نه درخواست کاربر. این شناسه برای تطبیق ورودی‌های لاگ میان webhook و apiserver، چه برای ممیزی (auditing) و چه برای اشکال‌زدایی، مناسب است.
kind
meta/v1.GroupVersionKind

kind نوع کاملاً مشخص‌شده (fully-qualified) آبجکتی است که ارسال می‌شود (برای مثال v1.Pod یا autoscaling.v1.Scale)
resource
meta/v1.GroupVersionResource

resource منبع کاملاً مشخص‌شده‌ای است که درخواست شده است (برای مثال v1.pods)
subResource
string

subResource زیرمنبعی است که درخواست شده است، در صورت وجود (برای مثال "status" یا "scale")
requestKind
meta/v1.GroupVersionKind

requestKind نوع کاملاً مشخص‌شده درخواست اولیه API است (برای مثال v1.Pod یا autoscaling.v1.Scale). اگر این مقدار مشخص شده باشد و با مقدار موجود در "kind" تفاوت داشته باشد، تطبیق و تبدیل معادل انجام شده است.

برای مثال، اگر Deploymentها را بتوان از طریق apps/v1 و apps/v1beta1 تغییر داد، و یک webhook قاعده‌ای با مقدار apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"] و matchPolicy: Equivalent ثبت کرده باشد، یک درخواست API به Deploymentهای apps/v1beta1 تبدیل می‌شود و به webhook ارسال می‌گردد با kind: {group:"apps", version:"v1", kind:"Deployment"} (مطابق قاعده‌ای که webhook برای آن ثبت شده است)، و requestKind: {group:"apps", version:"v1beta1", kind:"Deployment"} (که نشان‌دهنده نوع درخواست اولیه API است).

برای جزئیات بیشتر، مستندات فیلد "matchPolicy" را در نوع پیکربندی webhook ببینید.
requestResource
meta/v1.GroupVersionResource

requestResource منبع کاملاً مشخص‌شده درخواست اولیه API است (برای مثال v1.pods). اگر این مقدار مشخص شده باشد و با مقدار موجود در "resource" تفاوت داشته باشد، تطبیق و تبدیل معادل انجام شده است.

برای مثال، اگر Deploymentها را بتوان از طریق apps/v1 و apps/v1beta1 تغییر داد، و یک webhook قاعده‌ای با مقدار apiGroups:["apps"], apiVersions:["v1"], resources: ["deployments"] و matchPolicy: Equivalent ثبت کرده باشد، یک درخواست API به Deploymentهای apps/v1beta1 تبدیل می‌شود و به webhook ارسال می‌گردد با resource: {group:"apps", version:"v1", resource:"deployments"} (مطابق منبعی که webhook برای آن ثبت شده است)، و requestResource: {group:"apps", version:"v1beta1", resource:"deployments"} (که نشان‌دهنده منبع درخواست اولیه API است).

مستندات فیلد "matchPolicy" را در نوع پیکربندی webhook ببینید.
requestSubResource
string

requestSubResource نام زیرمنبع درخواست اولیه API است، در صورت وجود (برای مثال "status" یا "scale"). اگر این مقدار مشخص شده باشد و با مقدار موجود در "subResource" تفاوت داشته باشد، تطبیق و تبدیل معادل انجام شده است. مستندات فیلد "matchPolicy" را در نوع پیکربندی webhook ببینید.
name
string

name نام آبجکت است، همان‌گونه که در درخواست ارائه شده است. در عملیات CREATE، کلاینت می‌تواند name را حذف کند و تولید نام را به سرور واگذار کند. در این صورت، این فیلد حاوی یک رشته خالی خواهد بود.
namespace
string

namespace فضای نامی (namespace) است که با درخواست مرتبط است (در صورت وجود).
operation
Operation

operation عملیاتی است که در حال انجام است. این عملیات ممکن است با عملیات درخواست‌شده متفاوت باشد. برای مثال، یک patch می‌تواند به عملیات CREATE یا UPDATE منجر شود.
userInfo
authentication/v1.UserInfo

userInfo اطلاعاتی درباره کاربر درخواست‌دهنده است
object
k8s.io/apimachinery/pkg/runtime.RawExtension

object آبجکتی است که در درخواست ورودی قرار دارد.
oldObject
k8s.io/apimachinery/pkg/runtime.RawExtension

oldObject آبجکت موجود است. فقط برای درخواست‌های DELETE و UPDATE مقداردهی می‌شود.
dryRun
bool

dryRun نشان می‌دهد که تغییرات برای این درخواست قطعاً پایدار (persist) نخواهند شد. مقدار پیش‌فرض آن false است.
options
k8s.io/apimachinery/pkg/runtime.RawExtension

options ساختار گزینه‌های عملیاتی است که در حال انجام است. برای مثال meta.k8s.io/v1.DeleteOptions یا meta.k8s.io/v1.CreateOptions. این مقدار ممکن است با گزینه‌هایی که فراخواننده ارائه کرده است متفاوت باشد. برای مثال، در یک درخواست patch عملیات انجام‌شده ممکن است CREATE باشد؛ در این صورت Options از نوع meta.k8s.io/v1.CreateOptions خواهد بود، حتی اگر فراخواننده meta.k8s.io/v1.PatchOptions را ارائه کرده باشد.

AdmissionResponse {#admission-k8s-io-v1-AdmissionResponse}

نمایش داده‌شده در:

  • AdmissionReview

AdmissionResponse یک پاسخ پذیرش را توصیف می‌کند.

فیلدتوضیحات
uid
k8s.io/apimachinery/pkg/types.UID

uid شناسه‌ای برای هر درخواست/پاسخ مجزا است. این مقدار باید از AdmissionRequest متناظر کپی شود.
allowed
bool

allowed نشان می‌دهد که درخواست پذیرش مجاز شمرده شده است یا خیر.
status
meta/v1.Status

status نتیجه‌ای است که جزئیات اضافی درباره دلیل رد شدن یک درخواست پذیرش را در بر دارد. اگر مقدار "Allowed" برابر "true" باشد، این فیلد به هیچ وجه بررسی نمی‌شود.
patch
[]byte

patch بدنه وصله (patch) است. در حال حاضر فقط "JSONPatch" پشتیبانی می‌شود که RFC 6902 را پیاده‌سازی می‌کند.
patchType
PatchType

patchType نوع Patch است. در حال حاضر فقط "JSONPatch" مجاز است.
auditAnnotations
map[string]string

auditAnnotations یک نگاشت کلید-مقدار بدون ساختار است که توسط admission controller راه دور تنظیم می‌شود (برای مثال error=image-blacklisted). admission controllerهای MutatingAdmissionWebhook و ValidatingAdmissionWebhook کلیدها را با نام admission webhook پیشوندگذاری می‌کنند (برای مثال imagepolicy.example.com/error=image-blacklisted). AuditAnnotations توسط admission webhook ارائه می‌شود تا زمینه اضافی را به لاگ ممیزی این درخواست بیفزاید.
warnings
[]string

warnings فهرستی از پیام‌های هشدار است که به کلاینت API درخواست‌دهنده بازگردانده می‌شود. پیام‌های هشدار مشکلی را توصیف می‌کنند که کلاینتِ ارسال‌کننده درخواست API باید آن را اصلاح کند یا از آن آگاه باشد. در صورت امکان، هشدارها را به ۱۲۰ نویسه محدود کنید. هشدارهای بیش از ۲۵۶ نویسه و تعداد زیاد هشدارها ممکن است کوتاه (truncate) شوند.
