TracingConfiguration {#TracingConfiguration}

ظاهر می‌شود در:

  • KubeletConfiguration

  • TracingConfiguration

TracingConfiguration پیکربندی نسخه‌بندی‌شده‌ای را برای کلاینت‌های ردیابی (tracing) OpenTelemetry فراهم می‌کند.

فیلدتوضیحات
endpoint
string

نقطه پایانی (endpoint) کالکتوری که این مؤلفه ردیابی‌ها را به آن گزارش می‌دهد. اتصال ناامن است و در حال حاضر از TLS پشتیبانی نمی‌کند. توصیه می‌شود این مقدار تنظیم نشود و endpoint همان مقدار پیش‌فرض otlp grpc، یعنی localhost:4317، باشد.
samplingRatePerMillion
int32

SamplingRatePerMillion تعداد نمونه‌هایی است که به ازای هر یک میلیون span جمع‌آوری می‌شود. توصیه می‌شود این مقدار تنظیم نشود. اگر تنظیم نشود، نمونه‌بردار (sampler) از نرخ نمونه‌برداری span والد خود پیروی می‌کند و در غیر این صورت هرگز نمونه‌برداری نمی‌کند.

AuthenticationConfiguration {#apiserver-k8s-io-v1alpha1-AuthenticationConfiguration}

AuthenticationConfiguration پیکربندی نسخه‌بندی‌شده‌ای را برای احراز هویت فراهم می‌کند.

فیلدتوضیحات

string		AuthenticationConfiguration
jwt [الزامی]
[]JWTAuthenticator

jwt فهرستی از احراز‌هویت‌کننده‌ها (authenticator) است که کاربران کوبرنتیز را با استفاده از توکن‌های سازگار با JWT احراز هویت می‌کنند. احراز‌هویت‌کننده تلاش می‌کند یک توکن ID خام را تجزیه کند و بررسی کند که توسط issuer پیکربندی‌شده امضا شده باشد. کلید عمومی لازم برای تأیید امضا با استفاده از OIDC discovery از نقطه پایانی عمومی issuer کشف می‌شود. برای هر توکن ورودی، هر احراز‌هویت‌کننده JWT به ترتیبی که در این فهرست مشخص شده است آزموده می‌شود. توجه داشته باشید که سایر احراز‌هویت‌کننده‌ها ممکن است پیش از احراز‌هویت‌کننده‌های JWT یا پس از آن‌ها اجرا شوند. جایگاه دقیق احراز‌هویت‌کننده‌های JWT نسبت به سایر احراز‌هویت‌کننده‌ها نه تعریف شده است و نه در نسخه‌های مختلف پایدار است. از آنجا که هر احراز‌هویت‌کننده JWT باید نشانی issuer یکتایی داشته باشد، حداکثر یک احراز‌هویت‌کننده JWT تلاش می‌کند توکن را به‌صورت رمزنگاشتی اعتبارسنجی کند.

حداقل بار (payload) معتبر JWT باید شامل claimهای زیر باشد: { "iss": "https://issuer.example.com", "aud": ["audience"], "exp": 1234567890, "": "username" }

در صورت وجود، نباید --anonymous-auth تنظیم شده باشد

ClaimMappings {#apiserver-k8s-io-v1alpha1-ClaimMappings}

ظاهر می‌شود در:

  • JWTAuthenticator

ClaimMappings پیکربندی نگاشت claim را فراهم می‌کند

فیلدتوضیحات
username [الزامی]
PrefixedClaimOrExpression

username یک گزینه برای ویژگی نام کاربری را نشان می‌دهد. مقدار claim باید یک رشته منفرد باشد. معادل فلگ‌های --oidc-username-claim و --oidc-username-prefix است. اگر username.expression تنظیم شده باشد، عبارت باید یک مقدار رشته‌ای تولید کند. اگر username.expression از 'claims.email' استفاده کند، آنگاه 'claims.email_verified' باید در username.expression یا extra[].valueExpression یا claimValidationRules[].expression استفاده شود. نمونه‌ای از عبارت قاعده اعتبارسنجی claim که با اعتبارسنجی خودکارِ اعمال‌شده هنگام تنظیم username.claim روی 'email' مطابقت دارد، عبارت 'claims.?email_verified.orValue(true) == true' است. با مقایسه صریح مقدار با true، اجازه می‌دهیم type-checking ببیند که نتیجه یک مقدار بولی خواهد بود، و اطمینان حاصل می‌کنیم که claim غیربولی email_verified در زمان اجرا شناسایی شود.

در رویکرد مبتنی بر فلگ، فلگ‌های --oidc-username-claim و --oidc-username-prefix اختیاری هستند. اگر --oidc-username-claim تنظیم نشده باشد، مقدار پیش‌فرض "sub" است. در پیکربندی احراز هویت، برای claim یا prefix مقدار پیش‌فرضی وجود ندارد. claim و prefix باید به‌صراحت تنظیم شوند. برای claim، اگر در رویکرد قدیمی مبتنی بر فلگ، --oidc-username-claim تنظیم نشده بود، در پیکربندی احراز هویت username.claim="sub" را تنظیم کنید. برای prefix: (1) --oidc-username-prefix="-": هیچ پیشوندی به نام کاربری افزوده نمی‌شد. برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="" را تنظیم کنید (2) --oidc-username-prefix="" و --oidc-username-claim != "email": پیشوند "<value of --oidc-issuer-url>#" بود. برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="#" را تنظیم کنید (3) --oidc-username-prefix="": برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="" را تنظیم کنید
groups
PrefixedClaimOrExpression

groups یک گزینه برای ویژگی گروه‌ها را نشان می‌دهد. مقدار claim باید یک رشته یا آرایه‌ای از رشته‌ها باشد. اگر groups.claim تنظیم شده باشد، prefix باید مشخص شود (و می‌تواند رشته خالی باشد). اگر groups.expression تنظیم شده باشد، عبارت باید یک مقدار رشته‌ای یا آرایه‌ای از رشته‌ها تولید کند. مقادیر ""، [] و null به‌منزله نبود نگاشت گروه در نظر گرفته می‌شوند.
uid
ClaimOrExpression

uid یک گزینه برای ویژگی uid را نشان می‌دهد. claim باید یک claim رشته‌ای منفرد باشد. اگر uid.expression تنظیم شده باشد، عبارت باید یک مقدار رشته‌ای تولید کند.
extra
[]ExtraMapping

extra یک گزینه برای ویژگی extra را نشان می‌دهد. expression باید یک مقدار رشته‌ای یا آرایه‌ای از رشته‌ها تولید کند. اگر مقدار خالی باشد، نگاشت extra وجود نخواهد داشت.

کلید/مقدار extra با مقدار ثابت (hard-coded)

  • key: "foo" valueExpression: "'bar'" این به یک ویژگی extra با مقدار foo: ["bar"] منجر می‌شود

کلید ثابت، با مقداری که از روی مقدار claim کپی می‌شود

  • key: "foo" valueExpression: "claims.some_claim" این به یک ویژگی extra با مقدار foo: [value of some_claim] منجر می‌شود

کلید ثابت، با مقداری که از مقدار claim استخراج می‌شود

  • key: "admin" valueExpression: '(has(claims.is_admin) && claims.is_admin) ? "true":""' این به نتایج زیر منجر می‌شود:
  • اگر claim با نام is_admin وجود داشته باشد و true باشد، ویژگی extra با مقدار admin: ["true"]
  • اگر claim با نام is_admin وجود داشته باشد و false باشد یا اصلاً وجود نداشته باشد، هیچ ویژگی extra افزوده نخواهد شد

ClaimOrExpression {#apiserver-k8s-io-v1alpha1-ClaimOrExpression}

ظاهر می‌شود در:

  • ClaimMappings

ClaimOrExpression پیکربندی یک claim یا عبارت واحد را فراهم می‌کند.

فیلدتوضیحات
claim
string

claim همان claim در JWT است که باید استفاده شود. یا claim یا expression باید تنظیم شود. با expression ناسازگار (mutually exclusive) است.
expression
string

expression عبارتی را نشان می‌دهد که توسط CEL ارزیابی خواهد شد.

عبارت‌های CEL به محتوای claimهای توکن دسترسی دارند که در قالب یک متغیر CEL سازماندهی شده‌اند:

  • 'claims' نگاشتی (map) از نام claimها به مقادیر claimهاست. برای مثال، متغیری به نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تودرتو را می‌توان با نمادگذاری نقطه‌ای، مثلاً 'claims.foo.bar'، در دسترس قرار داد.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

با claim ناسازگار (mutually exclusive) است.

فیلدتوضیحات
claim

requiredValue
string

requiredValue مقدار یک claim الزامی است. معادل فلگ --oidc-required-claim است. فقط مقادیر claim از نوع رشته پشتیبانی می‌شوند. اگر claim تنظیم شده باشد و requiredValue تنظیم نشده باشد، claim باید با مقداری برابر با رشته خالی وجود داشته باشد. با expression و message ناسازگار (mutually exclusive) است.
expression
string

expression عبارتی را نشان می‌دهد که توسط CEL ارزیابی خواهد شد. باید یک مقدار بولی تولید کند.

عبارت‌های CEL به محتوای claimهای توکن دسترسی دارند که در قالب یک متغیر CEL سازماندهی شده‌اند:

  • 'claims' نگاشتی (map) از نام claimها به مقادیر claimهاست. برای مثال، متغیری به نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تودرتو را می‌توان با نمادگذاری نقطه‌ای، مثلاً 'claims.foo.bar'، در دسترس قرار داد. برای موفقیت اعتبارسنجی باید true برگرداند.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

با claim و requiredValue ناسازگار (mutually exclusive) است.
message
string

message پیام خطای بازگردانده‌شده را زمانی که expression مقدار false برگرداند سفارشی می‌کند. message یک رشته لفظی (literal) است. با claim و requiredValue ناسازگار (mutually exclusive) است.

ExtraMapping {#apiserver-k8s-io-v1alpha1-ExtraMapping}

ظاهر شده در:

  • ClaimMappings

ExtraMapping پیکربندی یک نگاشت اضافی (extra mapping) واحد را فراهم می‌کند.

فیلدتوضیحات
key [Required]
string

key رشته‌ای است که به‌عنوان کلید ویژگی اضافی (extra attribute) به کار می‌رود. key باید یک مسیر با پیشوند دامنه باشد (برای مثال example.org/foo). تمام نویسه‌های پیش از اولین "/" باید یک زیردامنه معتبر مطابق RFC 1123 باشند. تمام نویسه‌های پس از اولین "/" باید نویسه‌های معتبر مسیر HTTP مطابق RFC 3986 باشند. key باید با حروف کوچک نوشته شود. یکتا بودن آن الزامی است.
valueExpression [Required]
string

valueExpression یک عبارت CEL برای استخراج مقدار ویژگی اضافی است. valueExpression باید یک مقدار رشته‌ای یا آرایه‌ای از رشته‌ها تولید کند. مقادیر ""، [] و null به‌منزله نبودن نگاشت اضافی در نظر گرفته می‌شوند. مقادیر رشته‌ای خالی موجود در یک آرایه رشته‌ای حذف می‌شوند.

عبارت‌های CEL به محتوای claimهای توکن دسترسی دارند که در قالب یک متغیر CEL سازمان‌دهی شده است:

  • 'claims' نگاشتی از نام claimها به مقادیر آن‌هاست. برای مثال، متغیری با نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تودرتو را می‌توان با نمادگذاری نقطه‌ای در دسترس قرار داد، مانند 'claims.foo.bar'.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

Issuer {#apiserver-k8s-io-v1alpha1-Issuer}

ظاهر شده در:

  • JWTAuthenticator

Issuer پیکربندی تنظیمات خاص یک ارائه‌دهنده خارجی را فراهم می‌کند.

فیلدتوضیحات
url [Required]
string

url به نشانی صادرکننده (issuer) با قالب https://url یا https://url/path اشاره می‌کند. این مقدار باید با claim با نام "iss" در JWT ارائه‌شده و با issuer بازگردانده‌شده از discovery مطابقت داشته باشد. مقدار آن همان مقدار پرچم --oidc-issuer-url است. اطلاعات discovery از "{url}/.well-known/openid-configuration" دریافت می‌شود، مگر اینکه با discoveryURL بازنویسی شده باشد. یکتا بودن آن در میان همه JWT authenticatorها الزامی است. توجه داشته باشید که پیکربندی انتخاب خروجی (egress selection) برای این اتصال شبکه استفاده نمی‌شود.
discoveryURL
string

discoveryURL، در صورت تعیین، نشانی مورد استفاده برای دریافت اطلاعات discovery را به‌جای "{url}/.well-known/openid-configuration" بازنویسی می‌کند. مقدار دقیقاً همان‌گونه که مشخص شده استفاده می‌شود، بنابراین در صورت نیاز باید "/.well-known/openid-configuration" در discoveryURL گنجانده شود.

فیلد "issuer" در اطلاعات discovery دریافت‌شده باید با فیلد "issuer.url" در AuthenticationConfiguration مطابقت داشته باشد و برای اعتبارسنجی claim با نام "iss" در JWT ارائه‌شده به کار می‌رود. این گزینه برای سناریوهایی است که در آن‌ها نقاط پایانی well-known و jwks در مکانی متفاوت از issuer میزبانی می‌شوند (مانند میزبانی محلی در کلاستر).

مثال: نشانی discovery که با استفاده از Service کوبرنتیز با نام 'oidc' در فضای نام (namespace) 'oidc-namespace' در دسترس قرار گرفته و اطلاعات discovery در '/.well-known/openid-configuration' موجود است. discoveryURL: "https://oidc.oidc-namespace/.well-known/openid-configuration" certificateAuthority برای تأیید اتصال TLS به کار می‌رود و نام میزبان (hostname) روی گواهی برگ (leaf certificate) باید روی 'oidc.oidc-namespace' تنظیم شده باشد.

curl https://oidc.oidc-namespace/.well-known/openid-configuration (.discoveryURL field) { issuer: "https://oidc.example.com" (.url field) }

discoveryURL باید با url متفاوت باشد. یکتا بودن آن در میان همه JWT authenticatorها الزامی است. توجه داشته باشید که پیکربندی انتخاب خروجی (egress selection) برای این اتصال شبکه استفاده نمی‌شود.
certificateAuthority
string

certificateAuthority شامل گواهی‌های مرجع صدور گواهی (certificate authority) با کدگذاری PEM است که برای اعتبارسنجی اتصال هنگام دریافت اطلاعات discovery استفاده می‌شود. در صورت تنظیم‌نشدن، از تأییدکننده سیستم (system verifier) استفاده می‌شود. مقدار آن همان محتوای فایلی است که پرچم --oidc-ca-file به آن اشاره می‌کند.
audiences [Required]
[]string

audiences مجموعه مخاطبان (audience) قابل‌قبولی است که JWT باید برای آن‌ها صادر شده باشد. حداقل یکی از ورودی‌ها باید با claim با نام "aud" در JWTهای ارائه‌شده مطابقت داشته باشد. مقدار آن همان مقدار پرچم --oidc-client-id است (البته این فیلد از آرایه پشتیبانی می‌کند). باید غیرخالی باشد.
audienceMatchPolicy
AudienceMatchPolicyType

audienceMatchPolicy تعیین می‌کند که فیلد "audiences" چگونه برای تطبیق با claim با نام "aud" در JWT ارائه‌شده به کار رود. مقادیر مجاز عبارت‌اند از:

  1. "MatchAny" زمانی که چند مخاطب (audience) مشخص شده باشد، و
  2. خالی (یا تنظیم‌نشده) یا "MatchAny" زمانی که یک مخاطب (audience) واحد مشخص شده باشد.

  • MatchAny: claim با نام "aud" در JWT ارائه‌شده باید با دست‌کم یکی از ورودی‌های فیلد "audiences" مطابقت داشته باشد. برای مثال، اگر "audiences" برابر ["foo", "bar"] باشد، claim با نام "aud" در JWT ارائه‌شده باید شامل "foo" یا "bar" باشد (و می‌تواند شامل هر دو نیز باشد).

  • "": زمانی که در فیلد "audiences" فقط یک مخاطب (audience) مشخص شده باشد، سیاست تطبیق می‌تواند خالی (یا تنظیم‌نشده) باشد. claim با نام "aud" در JWT ارائه‌شده باید شامل همان مخاطب واحد باشد (و می‌تواند شامل مخاطبان دیگر نیز باشد).

برای اعتبارسنجی دقیق‌تر مخاطبان، از claimValidationRules استفاده کنید. مثال: claimValidationRule[].expression: 'sets.equivalent(claims.aud, ["bar", "foo", "baz"])' برای الزام به تطبیق دقیق.
egressSelectorType
EgressSelectorType

egressSelectorType نشان‌دهنده این است که برای ارسال تمام ترافیک مربوط به این issuer (شامل discovery، JWKS، claimهای توزیع‌شده و غیره) باید از کدام انتخاب خروجی (egress selection) استفاده شود. اگر مشخص نشود، هیچ dialer سفارشی استفاده نمی‌شود. در صورت تعیین، گزینه‌های معتبر "controlplane" و "cluster" هستند. این‌ها با مقادیر متناظر در --egress-selector-config-file مطابقت دارند.

  • controlplane: برای ترافیکی که قرار است به control plane برود.

  • cluster: برای ترافیکی که قرار است به سامانه‌ای برود که توسط کوبرنتیز مدیریت می‌شود.

منطق دقیق تطبیق (به ترتیب) به شرح زیر است:

  1. اگر دست‌کم یک matchCondition به FALSE ارزیابی شود، وب‌هوک نادیده گرفته می‌شود.
  2. اگر همه matchConditionها به TRUE ارزیابی شوند، وب‌هوک فراخوانی می‌شود.
  3. اگر دست‌کم یک matchCondition به خطا ارزیابی شود (اما هیچ‌کدام FALSE نباشند):
    • اگر failurePolicy=Deny باشد، وب‌هوک درخواست را رد می‌کند
    • اگر failurePolicy=NoOpinion باشد، خطا نادیده گرفته می‌شود و وب‌هوک رد می‌شود

WebhookMatchCondition {#apiserver-k8s-io-v1alpha1-WebhookMatchCondition}

ظاهر شده در:

  • WebhookConfiguration
فیلدتوضیحات
expression [Required]
string

expression عبارتی را نشان می‌دهد که توسط CEL ارزیابی خواهد شد و باید نتیجه آن از نوع bool باشد. عبارت‌های CEL به محتویات SubjectAccessReview در نسخه v1 دسترسی دارند. اگر نسخه مشخص‌شده توسط subjectAccessReviewVersion در متغیر request برابر v1beta1 باشد، محتویات پیش از ارزیابی عبارت CEL به نسخه v1 تبدیل می‌شوند.

  • 'resourceAttributes' اطلاعات مربوط به یک درخواست دسترسی به منبع را توصیف می‌کند و برای درخواست‌های غیرمنبعی تنظیم نمی‌شود. برای مثال: has(request.resourceAttributes) && request.resourceAttributes.namespace == 'default'
  • 'nonResourceAttributes' اطلاعات مربوط به یک درخواست دسترسی غیرمنبعی را توصیف می‌کند و برای درخواست‌های منبعی تنظیم نمی‌شود. برای مثال: has(request.nonResourceAttributes) && request.nonResourceAttributes.path == '/healthz'.
  • 'user' کاربری است که باید برای آن آزمون انجام شود. برای مثال: request.user == 'alice'
  • 'groups' گروه‌هایی است که باید برای آن‌ها آزمون انجام شود. برای مثال: ('group1' in request.groups)
  • 'extra' با متد user.Info.GetExtra() از authenticator متناظر است.
  • 'uid' اطلاعات مربوط به کاربر درخواست‌کننده است. برای مثال: request.uid == '1'
