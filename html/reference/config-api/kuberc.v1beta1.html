Preference {#kubectl-config-k8s-io-v1beta1-Preference}

Preference عناصر فایل پیکربندی KubeRC را ذخیره می‌کند.

FieldDescription
apiVersion
string		kubectl.config.k8s.io/v1beta1
kind
string		Preference
defaults [Required]
[]CommandDefaults

defaults امکان تغییر مقادیر پیش‌فرض گزینه‌های دستورها را فراهم می‌کند. این قابلیت به‌ویژه زمانی مفید است که کاربر نمی‌خواهد هر بار گزینه‌ها را به‌صورت صریح تنظیم کند.
aliases [Required]
[]AliasOverride

aliases امکان تعریف نام‌های مستعار (alias) برای دستورهای موجود kubectl را، همراه با مقادیر پیش‌فرض اختیاری برای گزینه‌ها، فراهم می‌کند. اگر نام alias با یک دستور داخلی تداخل داشته باشد، دستور داخلی همیشه اولویت دارد. بازنویسی‌های گزینه‌ها که در بخش defaults تعریف شده‌اند، بر aliasهای مربوط به همان دستور اعمال نمی‌شوند. عبارت kubectl [ALIAS NAME] [USER_OPTIONS] [USER_EXPLICIT_ARGS] به شکل زیر گسترش می‌یابد: kubectl [COMMAND] # دستور داخلی که alias به آن اشاره می‌کند [KUBERC_PREPEND_ARGS] [USER_OPTIONS] [KUBERC_OPTIONS] # سایر گزینه‌هایی که کاربر در [USER_OPTIONS] ارسال نکرده است [USER_EXPLICIT_ARGS] [KUBERC_APPEND_ARGS] برای مثال:

  • name: runx command: run options:
    • name: image default: nginx appendArgs:
    • custom-arg1 برای مثال، اگر کاربر دستور "kubectl runx test-pod" را اجرا کند، این دستور به "kubectl run --image=nginx test-pod -- custom-arg1" گسترش می‌یابد.
  • name: getn command: get options:
    • name: output default: wide prependArgs:
    • node دستور "kubectl getn control-plane-1" به "kubectl get node control-plane-1 --output=wide" گسترش می‌یابد. دستور "kubectl getn control-plane-1 --output=json" به "kubectl get node --output=json control-plane-1" گسترش می‌یابد.
credentialPluginPolicy
CredentialPluginPolicy

credentialPluginPolicy سیاستی را مشخص می‌کند که تعیین می‌کند کدام یک از افزونه‌های اعتبارنامه (credential plugin) در client-go، در صورت وجود، اجازه اجرا دارند. مقدار آن باید یکی از { "", "AllowAll", "DenyAll", "Allowlist" } باشد. اگر سیاست برابر "" باشد، به "AllowAll" بازمی‌گردد (این کار برای حفظ سازگاری با نسخه‌های قبلی لازم است). اگر سیاست DenyAll باشد، هیچ افزونه اعتبارنامه‌ای اجازه اجرا نخواهد داشت. اگر سیاست Allowlist باشد، فقط افزونه‌هایی اجازه اجرا دارند که معیارهای مشخص‌شده در فیلد credentialPluginAllowlist را برآورده کنند.
credentialPluginAllowlist
[]AllowlistEntry

Allowlist فهرستی از ورودی‌های allowlist است. اگر هر یک از آن‌ها مطابقت داشته باشد، فایل اجرایی مورد نظر اجازه اجرا دارد. یعنی نتیجه، OR منطقی همه ورودی‌های allowlist است. اگر سیاست برابر "Allowlist" نباشد، این فهرست نباید ارائه شود.

برای مثال: credentialPluginAllowlist:

  • name: cloud-provider-plugin
  • name: /usr/local/bin/my-plugin در مثال بالا، کاربر به افزونه‌های اعتبارنامه cloud-provider-plugin (که در جایی از PATH یافت می‌شود) و افزونه‌ای که در مسیر صریح /usr/local/bin/my-plugin قرار دارد، اجازه اجرا می‌دهد.

AliasOverride {#kubectl-config-k8s-io-v1beta1-AliasOverride}

Appears in:

  • Preference

AliasOverride تعریف‌های alias را ذخیره می‌کند.

FieldDescription
name [Required]
string

name نام alias است که فقط می‌تواند شامل نویسه‌های الفبایی باشد. اگر نام alias با یک دستور داخلی تداخل داشته باشد، دستور داخلی استفاده می‌شود.
command [Required]
string

command یک دستور یا مجموعه‌ای از دستورها برای اجراست، مانند "set env" یا "create".
prependArgs [Required]
[]string

prependArgs آرگومان‌هایی مانند نام منابع و غیره را ذخیره می‌کند. این آرگومان‌ها پس از نام alias درج می‌شوند.
appendArgs [Required]
[]string

appendArgs آرگومان‌هایی مانند نام منابع و غیره را ذخیره می‌کند. این آرگومان‌ها به انتهای USER_ARGS افزوده می‌شوند.
options [Required]
[]CommandOptionDefault

options برای ذخیره تعریف‌های گزینه‌های alias در نظر گرفته شده است. options فقط مقدار پیش‌فرض گزینه را تغییر می‌دهد و اگر کاربر مقداری را به‌صورت صریح ارسال کند، مقدار صریح استفاده می‌شود.

AllowlistEntry {#kubectl-config-k8s-io-v1beta1-AllowlistEntry}

Appears in:

  • Preference

AllowlistEntry یک ورودی در allowlist است. برای هر مورد allowlist، دست‌کم یک فیلد باید غیرخالی باشد. ساختاری که همه فیلدهای آن خالی باشد خطای پیکربندی نادرست محسوب می‌شود. هر فیلد یک معیار برای اجراست. اگر چند فیلد مشخص شده باشد، معیارهای همه فیلدهای مشخص‌شده باید برآورده شوند. یعنی نتیجه یک ورودی منفرد AND منطقی همه بررسی‌های متناظر با فیلدهای مشخص‌شده در همان ورودی است.

FieldDescription
name [Required]
string

تطبیق نام به این صورت انجام می‌شود که ابتدا مسیر مطلق هر دو مورد، یعنی افزونه و نام موجود در ورودی allowlist، با استفاده از exec.LookPath تعیین می‌شود. این تابع برای هر دو فراخوانی می‌شود و رشته‌های حاصل باید برابر باشند. اگر هر یک از فراخوانی‌های exec.LookPath به خطا منجر شود، بررسی Name شکست‌خورده در نظر گرفته می‌شود.

منسوخ‌شده: به‌جای آن از Command استفاده کنید.
command [Required]
string

تطبیق دستور به این صورت انجام می‌شود که ابتدا مسیر مطلق هر دو مورد، یعنی افزونه و نام موجود در ورودی allowlist، با استفاده از exec.LookPath تعیین می‌شود. این تابع برای هر دو فراخوانی می‌شود و رشته‌های حاصل باید برابر باشند. اگر هر یک از فراخوانی‌های exec.LookPath به خطا منجر شود، بررسی Command شکست‌خورده در نظر گرفته می‌شود.
