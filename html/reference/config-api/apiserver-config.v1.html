TracingConfiguration {#TracingConfiguration}

ظاهر می‌شود در:

  • KubeletConfiguration

  • TracingConfiguration

  • TracingConfiguration

  • TracingConfiguration

TracingConfiguration پیکربندی نسخه‌بندی‌شده را برای کلاینت‌های ردیابی (tracing) OpenTelemetry فراهم می‌کند.

فیلدتوضیحات
endpoint
string

نشانی Endpoint مربوط به collector که این مؤلفه ردیابی‌ها (traces) را به آن گزارش می‌کند. اتصال ناامن است و در حال حاضر از TLS پشتیبانی نمی‌کند. توصیه می‌شود این مقدار تنظیم نشود و endpoint همان مقدار پیش‌فرض otlp grpc، یعنی localhost:4317، باشد.
samplingRatePerMillion
int32

SamplingRatePerMillion تعداد نمونه‌هایی است که به ازای هر یک میلیون span جمع‌آوری می‌شود. توصیه می‌شود این مقدار تنظیم نشود. اگر تنظیم نشده باشد، نمونه‌بردار (sampler) از نرخ نمونه‌برداری span والد خود پیروی می‌کند، و در غیر این صورت هرگز نمونه‌برداری نمی‌کند.

فیلدتوضیحات

jwt [الزامی]
[]JWTAuthenticator

jwt فهرستی از احراز‌هویت‌کننده‌ها (authenticator) برای احراز هویت کاربران کوبرنتیز با استفاده از توکن‌های سازگار با JWT است. احراز‌هویت‌کننده تلاش می‌کند یک ID token خام را تجزیه کند و بررسی کند که توسط issuer پیکربندی‌شده امضا شده است. کلید عمومی لازم برای تأیید امضا با استفاده از OIDC discovery از نقطه پایانی عمومی issuer کشف می‌شود. برای هر توکن ورودی، هر احراز‌هویت‌کننده JWT به همان ترتیبی که در این فهرست مشخص شده است آزموده می‌شود. توجه کنید که سایر احراز‌هویت‌کننده‌ها ممکن است پیش از احراز‌هویت‌کننده‌های JWT یا پس از آن‌ها اجرا شوند. جایگاه دقیق احراز‌هویت‌کننده‌های JWT نسبت به سایر احراز‌هویت‌کننده‌ها نه تعریف شده است و نه در طول نسخه‌ها پایدار می‌ماند. از آنجا که هر احراز‌هویت‌کننده JWT باید نشانی issuer یکتایی داشته باشد، حداکثر یک احراز‌هویت‌کننده JWT تلاش می‌کند توکن را به‌صورت رمزنگاشتی اعتبارسنجی کند.

حداقل بار (payload) معتبر JWT باید شامل claimهای زیر باشد: { "iss": "https://issuer.example.com", "aud": ["audience"], "exp": 1234567890, "": "username" }

EncryptionConfiguration {#apiserver-config-k8s-io-v1-EncryptionConfiguration}

EncryptionConfiguration پیکربندی کامل ارائه‌دهندگان رمزنگاری را نگهداری می‌کند. همچنین امکان استفاده از wildcardها را برای تعیین منابعی که باید رمزنگاری شوند فراهم می‌کند. برای رمزنگاری همه منابع درون یک گروه از '.' و برای رمزنگاری همه منابع از '.' استفاده کنید. '.' را می‌توان برای رمزنگاری همه منابع در گروه core به کار برد. '.' همه منابع را رمزنگاری می‌کند، حتی منابع سفارشی‌ای که پس از راه‌اندازی API server اضافه می‌شوند. استفاده از wildcardهایی که در یک فهرست منابع یا میان چند ورودی هم‌پوشانی دارند مجاز نیست، زیرا بخشی از پیکربندی بی‌اثر خواهد بود. فهرست‌های منابع به ترتیب پردازش می‌شوند و فهرست‌های قبلی تقدم دارند.

مثال:

kind: EncryptionConfiguration
apiVersion: apiserver.config.k8s.io/v1
resources:
- resources:
  - events
  providers:
  - identity: {}  # do not encrypt events even though *.* is specified below
- resources:
  - secrets
  - configmaps
  - pandas.awesome.bears.example
  providers:
  - aescbc:
      keys:
      - name: key1
        secret: c2VjcmV0IGlzIHNlY3VyZQ==
- resources:
  - '*.apps'
  providers:
  - aescbc:
      keys:
      - name: key2
        secret: c2VjcmV0IGlzIHNlY3VyZSwgb3IgaXMgaXQ/Cg==
- resources:
  - '*.*'
  providers:
  - aescbc:
      keys:
      - name: key3
        secret: c2VjcmV0IGlzIHNlY3VyZSwgSSB0aGluaw==

ClaimMappings {#apiserver-config-k8s-io-v1-ClaimMappings}

ظاهر می‌شود در:

  • JWTAuthenticator

ClaimMappings پیکربندی نگاشت claim را فراهم می‌کند

فیلدتوضیحات
username [الزامی]
PrefixedClaimOrExpression

username گزینه‌ای برای ویژگی نام کاربری است. مقدار claim باید یک رشته منفرد باشد. معادل فلگ‌های --oidc-username-claim و --oidc-username-prefix است. اگر username.expression تنظیم شده باشد، عبارت باید یک مقدار رشته‌ای تولید کند. اگر username.expression از 'claims.email' استفاده کند، آنگاه 'claims.email_verified' باید در username.expression یا extra[].valueExpression یا claimValidationRules[].expression به کار رفته باشد. نمونه‌ای از عبارت قاعده اعتبارسنجی claim که با اعتبارسنجی اعمال‌شده به‌صورت خودکار هنگام تنظیم username.claim روی 'email' مطابقت دارد، 'claims.?email_verified.orValue(true) == true' است. با مقایسه صریح مقدار با true، به بررسی نوع (type-checking) اجازه می‌دهیم ببیند نتیجه یک مقدار بولی خواهد بود، و اطمینان حاصل می‌کنیم که claim غیربولی email_verified در زمان اجرا شناسایی می‌شود.

در رویکرد مبتنی بر فلگ، --oidc-username-claim و --oidc-username-prefix اختیاری هستند. اگر --oidc-username-claim تنظیم نشود، مقدار پیش‌فرض "sub" است. در پیکربندی احراز هویت (authentication config) برای claim یا prefix مقدار پیش‌فرضی وجود ندارد. claim و prefix باید به‌صراحت تنظیم شوند. برای claim، اگر --oidc-username-claim در رویکرد قدیمی مبتنی بر فلگ تنظیم نشده بود، در پیکربندی احراز هویت username.claim="sub" را پیکربندی کنید. برای prefix: (۱) --oidc-username-prefix="-"، هیچ پیشوندی به نام کاربری افزوده نمی‌شد. برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="" را تنظیم کنید (۲) --oidc-username-prefix="" و --oidc-username-claim != "email"، پیشوند "<value of --oidc-issuer-url>#" بود. برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="#" را تنظیم کنید (۳) --oidc-username-prefix="". برای رفتار یکسان با استفاده از پیکربندی احراز هویت، username.prefix="" را تنظیم کنید
groups
PrefixedClaimOrExpression

groups گزینه‌ای برای ویژگی گروه‌هاست. مقدار claim باید یک claim از نوع رشته یا آرایه‌ای از رشته‌ها باشد. اگر groups.claim تنظیم شده باشد، prefix باید مشخص شود (و می‌تواند رشته خالی باشد). اگر groups.expression تنظیم شده باشد، عبارت باید یک مقدار رشته یا آرایه‌ای از رشته‌ها تولید کند. مقادیر ""، [] و null به این معنا تلقی می‌شوند که نگاشت گروه وجود ندارد.
uid
ClaimOrExpression

uid گزینه‌ای برای ویژگی uid است. Claim باید یک claim منفرد از نوع رشته باشد. اگر uid.expression تنظیم شده باشد، عبارت باید یک مقدار رشته‌ای تولید کند.
extra
[]ExtraMapping

extra گزینه‌ای برای ویژگی extra است. expression باید یک مقدار رشته یا آرایه‌ای از رشته‌ها تولید کند. اگر مقدار خالی باشد، نگاشت extra وجود نخواهد داشت.

کلید/مقدار extra با مقدار ثابت (hard-coded)

  • key: "foo" valueExpression: "'bar'" این به ویژگی extra زیر منجر می‌شود - foo: ["bar"]

کلید ثابت، مقدار برگرفته از کپی مقدار claim

  • key: "foo" valueExpression: "claims.some_claim" این به ویژگی extra زیر منجر می‌شود - foo: [value of some_claim]

کلید ثابت، مقدار مشتق‌شده از مقدار claim

  • key: "admin" valueExpression: '(has(claims.is_admin) && claims.is_admin) ? "true":""' این به نتایج زیر منجر می‌شود:
  • اگر claim با نام is_admin وجود داشته باشد و true باشد، ویژگی extra - admin: ["true"]
  • اگر claim با نام is_admin وجود داشته باشد و false باشد یا اصلاً وجود نداشته باشد، هیچ ویژگی extra افزوده نخواهد شد

ClaimOrExpression {#apiserver-config-k8s-io-v1-ClaimOrExpression}

ظاهر می‌شود در:

  • ClaimMappings

ClaimOrExpression پیکربندی یک claim یا عبارت واحد را فراهم می‌کند.

فیلدتوضیحات
claim
string

claim همان claim در JWT است که باید به کار رود. باید یکی از claim یا expression تنظیم شود. با expression به‌طور متقابل ناسازگار است (mutually exclusive).
expression
string

expression عبارتی را نشان می‌دهد که توسط CEL ارزیابی می‌شود.

عبارت‌های CEL به محتوای claimهای توکن دسترسی دارند که در قالب یک متغیر CEL سازمان‌دهی شده‌اند:

  • 'claims' نگاشتی از نام claimها به مقادیر claim است. برای مثال، متغیری با نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تودرتو را می‌توان با نشانه‌گذاری نقطه‌ای (dot notation) در دسترس قرار داد، مثلاً 'claims.foo.bar'.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

با claim به‌طور متقابل ناسازگار است (mutually exclusive).

ClaimValidationRule {#apiserver-config-k8s-io-v1-ClaimValidationRule}

نمایش داده شده در:

  • JWTAuthenticator

ClaimValidationRule پیکربندی یک قاعده اعتبارسنجی claim واحد را فراهم می‌کند.

فیلدتوضیحات
claim
string

claim نام یک claim الزامی است. معادل پرچم --oidc-required-claim است. فقط کلیدهای claim از نوع رشته پشتیبانی می‌شوند. با expression و message متقابلاً ناسازگار است (هم‌زمان قابل استفاده نیستند).
requiredValue
string

requiredValue مقدار یک claim الزامی است. معادل پرچم --oidc-required-claim است. فقط مقادیر claim از نوع رشته پشتیبانی می‌شوند. اگر claim تنظیم شده باشد و requiredValue تنظیم نشده باشد، claim باید وجود داشته باشد و مقدار آن رشته خالی باشد. با expression و message متقابلاً ناسازگار است (هم‌زمان قابل استفاده نیستند).
expression
string

expression بیانگر عبارتی است که توسط CEL ارزیابی خواهد شد. باید یک مقدار بولین تولید کند.

عبارات CEL به محتوای claimهای توکن دسترسی دارند که در قالب متغیر CEL سازمان‌دهی شده است:

  • 'claims' نگاشتی از نام claimها به مقادیر claimها است. برای مثال، متغیری با نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تو در تو را می‌توان با نمادگذاری نقطه‌ای در دسترس قرار داد، مانند 'claims.foo.bar'. برای موفقیت اعتبارسنجی، باید مقدار true برگردانده شود.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

با claim و requiredValue متقابلاً ناسازگار است (هم‌زمان قابل استفاده نیستند).
message
string

message پیام خطای برگردانده‌شده را زمانی که expression مقدار false برگرداند، سفارشی می‌کند. message یک رشته لفظی است. با claim و requiredValue متقابلاً ناسازگار است (هم‌زمان قابل استفاده نیستند).

key رشته‌ای است که به‌عنوان کلید ویژگی extra استفاده می‌شود. key باید یک مسیر دارای پیشوند دامنه باشد (مثلاً example.org/foo). تمام نویسه‌های قبل از اولین "/" باید یک زیردامنه معتبر مطابق RFC 1123 باشند. تمام نویسه‌های بعد از اولین "/" باید نویسه‌های معتبر مسیر HTTP مطابق RFC 3986 باشند. key باید با حروف کوچک باشد. باید یکتا باشد.
valueExpression [الزامی]
string

valueExpression یک عبارت CEL برای استخراج مقدار ویژگی extra است. valueExpression باید یک رشته یا آرایه‌ای از رشته‌ها تولید کند. مقادیر ""، [] و null به‌منزله وجود نداشتن نگاشت extra در نظر گرفته می‌شوند. مقادیر رشته خالی موجود در یک آرایه رشته‌ای حذف می‌شوند.

عبارات CEL به محتوای claimهای توکن دسترسی دارند که در قالب متغیر CEL سازمان‌دهی شده است:

  • 'claims' نگاشتی از نام claimها به مقادیر claimها است. برای مثال، متغیری با نام 'sub' را می‌توان با 'claims.sub' در دسترس قرار داد. claimهای تو در تو را می‌توان با نمادگذاری نقطه‌ای در دسترس قرار داد، مانند 'claims.foo.bar'.

مستندات CEL: https://kubernetes.io/docs/reference/using-api/cel/

Issuer {#apiserver-config-k8s-io-v1-Issuer}

نمایش داده شده در:

  • JWTAuthenticator

Issuer پیکربندی تنظیمات خاص یک provider خارجی را فراهم می‌کند.

فیلدتوضیحات
url [الزامی]
string

url به نشانی issuer با قالب https://url یا https://url/path اشاره می‌کند. این مقدار باید با claim «iss» در JWT ارائه‌شده و issuer برگردانده‌شده از discovery مطابقت داشته باشد. مقدار آن با پرچم --oidc-issuer-url یکسان است. اطلاعات discovery از "{url}/.well-known/openid-configuration" دریافت می‌شود، مگر اینکه با discoveryURL بازنویسی شود. باید در میان تمام JWT authenticatorها یکتا باشد. توجه داشته باشید که پیکربندی egress selection برای این اتصال شبکه استفاده نمی‌شود.
discoveryURL
string

discoveryURL، در صورت تعیین، نشانی مورد استفاده برای دریافت اطلاعات discovery را به‌جای "{url}/.well-known/openid-configuration" بازنویسی می‌کند. مقدار دقیقاً همان‌گونه که مشخص شده استفاده می‌شود، بنابراین در صورت نیاز، "/.well-known/openid-configuration" باید در discoveryURL گنجانده شود.

فیلد "issuer" در اطلاعات discovery دریافت‌شده باید با فیلد "issuer.url" در AuthenticationConfiguration مطابقت داشته باشد و برای اعتبارسنجی claim «iss» در JWT ارائه‌شده استفاده می‌شود. این قابلیت برای سناریوهایی است که در آن‌ها endpointهای well-known و jwks در مکانی متفاوت از issuer میزبانی می‌شوند (مانند میزبانی محلی در کلاستر).

مثال: یک discovery url که با استفاده از Service کوبرنتیز با نام 'oidc' در فضای نام 'oidc-namespace' در دسترس قرار گرفته است و اطلاعات discovery در '/.well-known/openid-configuration' موجود است. discoveryURL: "https://oidc.oidc-namespace/.well-known/openid-configuration" certificateAuthority برای تأیید اتصال TLS استفاده می‌شود و نام میزبان روی leaf certificate باید روی 'oidc.oidc-namespace' تنظیم شده باشد.

curl https://oidc.oidc-namespace/.well-known/openid-configuration (.discoveryURL field) { issuer: "https://oidc.example.com" (.url field) }

discoveryURL باید با url متفاوت باشد. باید در میان تمام JWT authenticatorها یکتا باشد. توجه داشته باشید که پیکربندی egress selection برای این اتصال شبکه استفاده نمی‌شود.
certificateAuthority
string

certificateAuthority شامل گواهی‌های مرجع صدور گواهی با کدگذاری PEM است که برای اعتبارسنجی اتصال هنگام دریافت اطلاعات discovery استفاده می‌شود. در صورت تنظیم نشدن، از تأییدکننده سیستم استفاده می‌شود. مقدار آن با محتوای فایلی که پرچم --oidc-ca-file به آن ارجاع می‌دهد یکسان است.
audiences [الزامی]
[]string

audiences مجموعه مخاطبان (audience) قابل‌قبولی است که JWT باید برای آن‌ها صادر شده باشد. دست‌کم یکی از مدخل‌ها باید با claim «aud» در JWTهای ارائه‌شده مطابقت داشته باشد. مقدار آن با پرچم --oidc-client-id یکسان است (هرچند این فیلد از آرایه پشتیبانی می‌کند). باید غیرتهی باشد.
audienceMatchPolicy
AudienceMatchPolicyType

audienceMatchPolicy تعیین می‌کند که فیلد "audiences" چگونه برای تطبیق با claim «aud» در JWT ارائه‌شده استفاده می‌شود. مقادیر مجاز عبارت‌اند از:

  1. "MatchAny" هنگامی که چندین audience مشخص شده باشد و
  2. خالی (یا تنظیم‌نشده) یا "MatchAny" هنگامی که یک audience مشخص شده باشد.

  • MatchAny: claim «aud» در JWT ارائه‌شده باید با دست‌کم یکی از مدخل‌های فیلد "audiences" مطابقت داشته باشد. برای مثال، اگر "audiences" برابر ["foo", "bar"] باشد، claim «aud» در JWT ارائه‌شده باید شامل "foo" یا "bar" باشد (و ممکن است هر دو را شامل شود).

  • "": هنگامی که در فیلد "audiences" فقط یک audience مشخص شده باشد، سیاست تطبیق می‌تواند خالی (یا تنظیم‌نشده) باشد. claim «aud» در JWT ارائه‌شده باید شامل همان audience واحد باشد (و ممکن است شامل موارد دیگر نیز باشد).

برای اعتبارسنجی دقیق‌تر audience، از claimValidationRules استفاده کنید. مثال: claimValidationRule[].expression: 'sets.equivalent(claims.aud, ["bar", "foo", "baz"])' برای الزام تطبیق دقیق.
egressSelectorType
EgressSelectorType

egressSelectorType نشان‌دهنده این است که کدام egress selection باید برای ارسال تمام ترافیک مربوط به این issuer (discovery، JWKS، claimهای توزیع‌شده و غیره) استفاده شود. اگر تعیین نشود، هیچ dialer سفارشی استفاده نمی‌شود. در صورت تعیین، گزینه‌های معتبر "controlplane" و "cluster" هستند. این‌ها با مقادیر متناظر در --egress-selector-config-file مطابقت دارند.

  • controlplane: برای ترافیکی که قرار است به control plane برود.

  • cluster: برای ترافیکی که قرار است به سامانه‌ای برود که توسط کوبرنتیز مدیریت می‌شود.

  • NoOpinion: ادامه به authorizerهای بعدی تا بررسی شود که آیا یکی از آن‌ها درخواست را مجاز می‌کند یا خیر

منطق دقیق تطبیق به ترتیب چنین است:

  1. اگر دست‌کم یکی از matchConditionها به FALSE ارزیابی شود، webhook نادیده گرفته می‌شود.
  2. اگر همه matchConditionها به TRUE ارزیابی شوند، webhook فراخوانی می‌شود.
  3. اگر دست‌کم یکی از matchConditionها به خطا ارزیابی شود (اما هیچ‌کدام FALSE نباشند):
    • اگر failurePolicy=Deny باشد، webhook درخواست را رد می‌کند
    • اگر failurePolicy=NoOpinion باشد، خطا نادیده گرفته می‌شود و webhook نادیده گرفته می‌شود

WebhookConnectionInfo {#apiserver-config-k8s-io-v1-WebhookConnectionInfo}

نمایش داده‌شده در:

  • WebhookConfiguration
فیلدتوضیحات
type [الزامی]
string

نحوه ارتباط webhook با سرور را کنترل می‌کند. مقادیر معتبر:

  • KubeConfigFile: از فایل مشخص‌شده در kubeConfigFile برای یافتن سرور استفاده می‌شود.
  • InClusterConfig: از پیکربندی درون کلاستر (in-cluster) برای فراخوانی API مربوط به SubjectAccessReview که توسط kube-apiserver ارائه می‌شود، استفاده می‌شود. این حالت برای kube-apiserver مجاز نیست.
kubeConfigFile [الزامی]
string

مسیر KubeConfigFile برای اطلاعات اتصال. اگر connectionInfo.Type برابر KubeConfig باشد، الزامی است.

WebhookMatchCondition {#apiserver-config-k8s-io-v1-WebhookMatchCondition}

نمایش داده‌شده در:

  • WebhookConfiguration
فیلدتوضیحات
expression [الزامی]
string

expression بیانگر عبارتی است که توسط CEL ارزیابی خواهد شد و باید به مقدار bool ارزیابی شود. عبارت‌های CEL به محتوای SubjectAccessReview در نسخه v1 دسترسی دارند. اگر نسخه مشخص‌شده توسط subjectAccessReviewVersion در متغیر request برابر v1beta1 باشد، پیش از ارزیابی عبارت CEL، محتوا به نسخه v1 تبدیل می‌شود.

  • 'resourceAttributes' اطلاعات مربوط به یک درخواست دسترسی به منبع را توصیف می‌کند و برای درخواست‌های غیرمنبعی تنظیم نشده است. برای مثال: has(request.resourceAttributes) && request.resourceAttributes.namespace == 'default'
  • 'nonResourceAttributes' اطلاعات مربوط به یک درخواست دسترسی غیرمنبعی را توصیف می‌کند و برای درخواست‌های منبعی تنظیم نشده است. برای مثال: has(request.nonResourceAttributes) && request.nonResourceAttributes.path == '/healthz'.
  • 'user' کاربری است که باید برای آن آزمون انجام شود. برای مثال: request.user == 'alice'
  • 'groups' گروه‌هایی هستند که باید برای آن‌ها آزمون انجام شود. برای مثال: ('group1' in request.groups)
  • 'extra' متناظر با متد user.Info.GetExtra() از authenticator است.
  • 'uid' اطلاعات مربوط به کاربر درخواست‌کننده است. برای مثال: request.uid == '1'

مستندات مربوط به CEL: https://kubernetes.io/docs/reference/using-api/cel/
