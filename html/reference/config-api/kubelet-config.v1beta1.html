CredentialProviderConfig {#kubelet-config-k8s-io-v1beta1-CredentialProviderConfig}

CredentialProviderConfig پیکربندی‌ای است که اطلاعات مربوط به هر ارائه‌دهنده اعتبارنامه از نوع exec را در بر دارد. Kubelet این پیکربندی را از دیسک می‌خواند و هر ارائه‌دهنده را بر اساس آنچه در نوع CredentialProvider مشخص شده است فعال می‌کند.

FieldDescription
apiVersion
string		kubelet.config.k8s.io/v1beta1
kind
string		CredentialProviderConfig
providers [Required]
[]CredentialProvider

providers فهرستی از افزونه‌های ارائه‌دهنده اعتبارنامه است که توسط kubelet فعال می‌شوند. چند ارائه‌دهنده ممکن است با یک ایمیج واحد مطابقت داشته باشند؛ در این صورت اعتبارنامه‌های همه ارائه‌دهندگان به kubelet بازگردانده می‌شود. اگر برای یک ایمیج واحد چند ارائه‌دهنده فراخوانی شوند، نتایج با هم ترکیب می‌شوند. اگر ارائه‌دهندگان کلیدهای احراز هویت هم‌پوشان بازگردانند، مقدار ارائه‌دهنده‌ای که در این فهرست زودتر آمده است ابتدا امتحان می‌شود.

ImagePulledRecord {#kubelet-config-k8s-io-v1beta1-ImagePulledRecord}

ImagePullRecord رکوردی از ایمیجی است که توسط kubelet pull شده است.

اگر در فیلد kubernetesSecrets هیچ رکوردی وجود نداشته باشد و هر دو فیلد nodeWideCredentials و anonymous برابر false باشند، اعتبارنامه‌ها باید در دفعه بعدی که ایمیجِ نمایش‌داده‌شده توسط این رکورد درخواست می‌شود، دوباره بررسی شوند.

FieldDescription
apiVersion
string		kubelet.config.k8s.io/v1beta1
kind
string		ImagePulledRecord
lastUpdatedTime [Required]
meta/v1.Time

LastUpdatedTime زمان آخرین به‌روزرسانی این رکورد است.
imageRef [Required]
string

ImageRef ارجاعی به ایمیجی است که این فایل نمایش می‌دهد و از CRI دریافت شده است. نام فایل، هش SHA-256 این مقدار است. این کار برای پرهیز از وجود نویسه‌های نامناسب برای نام فایل مانند ':' و '/' انجام می‌شود.
credentialMapping [Required]
map[string]ImagePullCredentials

CredentialMapping مقدار image را به مجموعه اعتبارنامه‌هایی نگاشت می‌کند که پیش‌تر با آن‌ها pull شده است. image در اینجا محتوای فیلد image کانتینر یک Pod است که تگ/digest آن حذف شده است.

مثال: کانتینر ایمیج hello-world:latest@sha256:91fb4b041da273d5a3273b6d587d62d518300a6ad268b28628f74997b93171b2 را درخواست می‌کند: "credentialMapping": { "hello-world": { "nodePodsAccessible": true } }

CredentialProvider یک افزونه exec را نشان می‌دهد که kubelet آن را فراخوانی می‌کند. این افزونه تنها زمانی فراخوانی می‌شود که ایمیجی که در حال pull شدن است با ایمیج‌هایی که افزونه مدیریت می‌کند مطابقت داشته باشد (به matchImages مراجعه کنید).

FieldDescription

name نام الزامی ارائه‌دهنده اعتبارنامه (credential provider) است. این نام باید با نام فایل اجرایی ارائه‌دهنده، آن‌گونه که kubelet می‌بیند، مطابقت داشته باشد. فایل اجرایی باید در پوشه bin مربوط به kubelet باشد (که با فلگ --image-credential-provider-bin-dir تنظیم می‌شود). این نام باید در میان همه ارائه‌دهندگان یکتا باشد.
matchImages [Required]
[]string

matchImages فهرستی الزامی از رشته‌هاست که برای تطبیق با ایمیج‌ها به‌کار می‌رود تا مشخص شود آیا این ارائه‌دهنده باید فراخوانی شود یا خیر. اگر یکی از رشته‌ها با ایمیج درخواست‌شده از سوی kubelet مطابقت داشته باشد، افزونه فراخوانی می‌شود و فرصت می‌یابد اعتبارنامه‌ها را ارائه دهد. انتظار می‌رود ایمیج‌ها شامل دامنه رجیستری و مسیر URL باشند.

هر مدخل در matchImages یک الگو است که می‌تواند به‌صورت اختیاری شامل پورت و مسیر باشد. در دامنه می‌توان از glob استفاده کرد، اما در پورت یا مسیر نمی‌توان. globها به‌صورت زیردامنه مانند '.k8s.io' یا 'k8s..io' و دامنه‌های سطح بالا مانند 'k8s.' پشتیبانی می‌شوند. تطبیق زیردامنه‌های جزئی مانند 'app.k8s.io' نیز پشتیبانی می‌شود. هر glob فقط می‌تواند با یک بخش زیردامنه مطابقت داشته باشد، بنابراین *.io با *.k8s.io مطابقت ندارد.

زمانی بین یک ایمیج و یک matchImage تطابق وجود دارد که همه موارد زیر برقرار باشند:

  • هر دو تعداد بخش‌های دامنه یکسانی داشته باشند و هر بخش مطابقت داشته باشد.
  • مسیر URL در imageMatch باید پیشوندی از مسیر URL ایمیج هدف باشد.
  • اگر imageMatch شامل پورت باشد، پورت باید در ایمیج نیز مطابقت داشته باشد.

نمونه مقادیر matchImages:

  • 123456789.dkr.ecr.us-east-1.amazonaws.com
  • *.azurecr.io
  • gcr.io
  • ..registry.io
  • registry.io:8080/path
