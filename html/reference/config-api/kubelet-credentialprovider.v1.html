CredentialProviderRequest {#credentialprovider-kubelet-k8s-io-v1-CredentialProviderRequest}

CredentialProviderRequest شامل ایمیجی است که kubelet برای آن به احراز هویت نیاز دارد. kubelet این آبجکت درخواست را از طریق stdin به افزونه ارسال می‌کند. به‌طور کلی، افزونه‌ها باید ترجیحاً با همان apiVersion‌ای پاسخ دهند که برایشان ارسال شده است.

FieldDescription
apiVersion
string		credentialprovider.kubelet.k8s.io/v1
kind
string		CredentialProviderRequest
image [Required]
string

image همان ایمیج کانتینری است که به‌عنوان بخشی از درخواست افزونه‌ی ارائه‌دهنده‌ی اعتبارنامه (credential provider) در حال pull شدن است. افزونه‌ها می‌توانند به‌صورت اختیاری ایمیج را تجزیه (parse) کنند تا هر اطلاعاتی را که برای دریافت اعتبارنامه‌ها لازم است استخراج نمایند.
serviceAccountToken [Required]
string

serviceAccountToken توکن service account است که به Podی متصل شده که ایمیج برای آن pull می‌شود. این توکن تنها در صورتی به افزونه ارسال می‌شود که فیلد tokenAttributes.serviceAccountTokenAudience در پیکربندی ارائه‌دهنده‌ی اعتبارنامه‌ی kubelet تنظیم شده باشد.
serviceAccountAnnotations [Required]
map[string]string

serviceAccountAnnotations نگاشتی از حاشیه‌نویسی‌ها (annotations) روی service account است که به Podی متصل شده که ایمیج برای آن pull می‌شود. فهرست annotationهای service account که باید به افزونه ارسال شوند، در پیکربندی ارائه‌دهنده‌ی اعتبارنامه‌ی kubelet تعیین می‌شود.

CredentialProviderResponse {#credentialprovider-kubelet-k8s-io-v1-CredentialProviderResponse}

CredentialProviderResponse شامل اعتبارنامه‌هایی است که kubelet باید برای ایمیج مشخص‌شده در درخواست اولیه از آن‌ها استفاده کند. kubelet پاسخ افزونه را از طریق stdout می‌خواند. این پاسخ باید با همان apiVersion مربوط به CredentialProviderRequest تنظیم شود.

FieldDescription
apiVersion
string		credentialprovider.kubelet.k8s.io/v1
kind
string		CredentialProviderResponse
cacheKeyType [Required]
PluginCacheKeyType

cacheKeyType نوع کلید کش را که باید بر اساس ایمیج ارائه‌شده در درخواست استفاده شود مشخص می‌کند. سه مقدار معتبر برای نوع کلید کش وجود دارد: Image، Registry و Global. اگر مقدار نامعتبری مشخص شود، kubelet از پاسخ استفاده نخواهد کرد.
cacheDuration
meta/v1.Duration

cacheDuration مدت زمانی را نشان می‌دهد که اعتبارنامه‌های ارائه‌شده باید کش شوند. kubelet از این فیلد برای تعیین مدت زمان کش درون‌حافظه‌ای اعتبارنامه‌ها در AuthConfig استفاده می‌کند. اگر null باشد، kubelet از defaultCacheDuration مشخص‌شده در CredentialProviderConfig استفاده می‌کند. اگر روی 0 تنظیم شود، kubelet مقدار AuthConfig ارائه‌شده را کش نخواهد کرد.
auth
map[string]AuthConfig

auth نگاشتی است که اطلاعات احراز هویت ارسال‌شده به kubelet را در بر دارد. هر کلید یک رشته‌ی تطبیق ایمیج (match image) است (توضیحات بیشتر در ادامه). مقدار authConfig متناظر باید برای همه‌ی ایمیج‌هایی که با این کلید مطابقت دارند معتبر باشد. اگر برای ایمیج درخواست‌شده نتوان هیچ اعتبارنامه‌ی معتبری برگرداند، افزونه باید این فیلد را روی null تنظیم کند.

هر کلید در این نگاشت الگویی است که می‌تواند به‌صورت اختیاری شامل یک پورت و یک مسیر باشد. در دامنه می‌توان از glob استفاده کرد، اما در پورت یا مسیر نمی‌توان. globها به‌صورت زیردامنه مانند '.k8s.io' یا 'k8s..io' و دامنه‌های سطح بالا مانند 'k8s.' پشتیبانی می‌شوند. تطبیق زیردامنه‌های جزئی مانند 'app.k8s.io' نیز پشتیبانی می‌شود. هر glob فقط می‌تواند با یک بخش زیردامنه مطابقت داشته باشد، بنابراین *.io با *.k8s.io مطابقت ندارد.

kubelet زمانی ایمیج‌ها را با کلید مطابقت می‌دهد که همه‌ی شرایط زیر برقرار باشند:

  • هر دو تعداد بخش‌های دامنه‌ی یکسانی داشته باشند و هر بخش مطابقت کند.
  • مسیر URL مربوط به imageMatch باید پیشوندی از مسیر URL ایمیج هدف باشد.
  • اگر imageMatch شامل پورت باشد، پورت باید در ایمیج نیز مطابقت داشته باشد.

وقتی چندین کلید برگردانده شوند، kubelet همه‌ی کلیدها را به ترتیب معکوس پیمایش می‌کند، به‌طوری که:

  • کلیدهای بلندتر پیش از کلیدهای کوتاه‌تر با همان پیشوند قرار می‌گیرند
  • کلیدهای بدون wildcard پیش از کلیدهای دارای wildcard با همان پیشوند قرار می‌گیرند.

برای هر تطبیق مشخص، kubelet تلاش می‌کند ایمیج را با اعتبارنامه‌های ارائه‌شده pull کند و پس از نخستین pull که با موفقیت احراز هویت شود، متوقف می‌شود.

نمونه‌ی کلیدها:

  • 123456789.dkr.ecr.us-east-1.amazonaws.com
  • *.azurecr.io
  • gcr.io
  • ..registry.io
  • registry.io:8080/path

AuthConfig {#credentialprovider-kubelet-k8s-io-v1-AuthConfig}

نمایش داده شده در:

  • CredentialProviderResponse

AuthConfig شامل اطلاعات احراز هویت برای یک رجیستری کانتینر است. در حال حاضر تنها احراز هویت مبتنی بر نام کاربری/گذرواژه پشتیبانی می‌شود، اما ممکن است سازوکارهای احراز هویت بیشتری در آینده اضافه شوند.

FieldDescription
username [Required]
string

username نام کاربری است که برای احراز هویت در رجیستری کانتینر استفاده می‌شود. نام کاربری خالی نیز معتبر است.
password [Required]
string

password گذرواژه‌ای است که برای احراز هویت در رجیستری کانتینر استفاده می‌شود. گذرواژه‌ی خالی نیز معتبر است.
