راهنمای مهاجرت از APIهای منسوخ‌شده

API کوبرنتیز به‌مرور تکامل می‌یابد و APIها به‌صورت دوره‌ای بازسازمان‌دهی یا ارتقا داده می‌شوند. با تکامل APIها، API قدیمی منسوخ (deprecated) و در نهایت حذف می‌شود. این صفحه اطلاعاتی را در بر دارد که هنگام مهاجرت از نسخه‌های منسوخ‌شدهٔ API به نسخه‌های جدیدتر و پایدارتر به آن‌ها نیاز دارید.

فهرست APIهای حذف‌شده به تفکیک نسخهٔ انتشار

نسخهٔ v1.32

در نسخهٔ v1.32، ارائهٔ نسخه‌های منسوخ‌شدهٔ زیر از API متوقف شد:

منابع کنترل جریان (Flow control) {#flowcontrol-resources-v132}

نسخهٔ API flowcontrol.apiserver.k8s.io/v1beta3 برای FlowSchema و PriorityLevelConfiguration از v1.32 به بعد دیگر ارائه نمی‌شود.

  • مانیفست‌ها و کلاینت‌های API را به نسخهٔ API flowcontrol.apiserver.k8s.io/v1 منتقل کنید که از v1.29 در دسترس است.
  • همهٔ آبجکت‌های ذخیره‌شدهٔ موجود از طریق API جدید در دسترس هستند.
  • تغییرات قابل توجه در flowcontrol.apiserver.k8s.io/v1:
    • فیلد spec.limited.nominalConcurrencyShares در PriorityLevelConfiguration فقط زمانی مقدار پیش‌فرض 30 را می‌گیرد که مقداری برای آن تعیین نشده باشد، و مقدار صریح 0 به 30 تغییر نمی‌کند.

منبع Event {#event-v125}

  • همهٔ آبجکت‌های ذخیره‌شدهٔ موجود از طریق API جدید در دسترس هستند.
  • تغییرات قابل توجه در events.k8s.io/v1:
    • مقدار فیلد type به Normal و Warning محدود است.
    • نام فیلد involvedObject به regarding تغییر کرده است.
    • هنگام ایجاد Eventهای جدید events.k8s.io/v1، فیلدهای action، reason، reportingController و reportingInstance الزامی هستند.
    • به جای فیلد منسوخ‌شدهٔ firstTimestamp از eventTime استفاده کنید (نام آن فیلد به deprecatedFirstTimestamp تغییر کرده است و در Eventهای جدید events.k8s.io/v1 مجاز نیست).
    • به جای فیلد منسوخ‌شدهٔ lastTimestamp از series.lastObservedTime استفاده کنید (نام آن فیلد به deprecatedLastTimestamp تغییر کرده است و در Eventهای جدید events.k8s.io/v1 مجاز نیست).
    • به جای فیلد منسوخ‌شدهٔ count از series.count استفاده کنید (نام آن فیلد به deprecatedCount تغییر کرده است و در Eventهای جدید events.k8s.io/v1 مجاز نیست).
    • به جای فیلد منسوخ‌شدهٔ source.component از reportingController استفاده کنید (نام آن فیلد به deprecatedSource.component تغییر کرده است و در Eventهای جدید events.k8s.io/v1 مجاز نیست).
    • به جای فیلد منسوخ‌شدهٔ source.host از reportingInstance استفاده کنید (نام آن فیلد به deprecatedSource.host تغییر کرده است و در Eventهای جدید events.k8s.io/v1 مجاز نیست).

منبع PodDisruptionBudget {#poddisruptionbudget-v125}

  • همهٔ آبجکت‌های ذخیره‌شدهٔ موجود از طریق API جدید در دسترس هستند.
  • تغییرات قابل توجه در policy/v1:
    • اگر در یک PodDisruptionBudget نسخهٔ policy/v1 مقدار spec.selector خالی ({}) نوشته شود، همهٔ پادهای آن فضای نام انتخاب می‌شوند (در policy/v1beta1، مقدار خالی spec.selector هیچ پادی را انتخاب نمی‌کرد). اگر spec.selector تنظیم نشده باشد، در هیچ‌یک از دو نسخهٔ API هیچ پادی انتخاب نمی‌شود.

منبع PodSecurityPolicy {#psp-v125}

نسخهٔ API policy/v1beta1 برای PodSecurityPolicy از v1.25 به بعد دیگر ارائه نمی‌شود و کنترل‌کنندهٔ پذیرش (admission controller) PodSecurityPolicy نیز حذف خواهد شد.

به Pod Security Admission یا یک وب‌هوک پذیرش شخص ثالث مهاجرت کنید. برای راهنمای مهاجرت، به مهاجرت از PodSecurityPolicy به کنترل‌کنندهٔ پذیرش داخلی PodSecurity مراجعه کنید. برای اطلاعات بیشتر دربارهٔ این منسوخ‌شدن، به منسوخ‌شدن PodSecurityPolicy: گذشته، حال و آینده مراجعه کنید.

نسخهٔ v1.22

منابع وب‌هوک {#webhook-resources-v122}

نسخهٔ API admissionregistration.k8s.io/v1beta1 برای MutatingWebhookConfiguration و ValidatingWebhookConfiguration از v1.22 به بعد دیگر ارائه نمی‌شود.

  • مانیفست‌ها و کلاینت‌های API را به نسخهٔ API admissionregistration.k8s.io/v1 منتقل کنید که از v1.16 در دسترس است.
  • همهٔ آبجکت‌های ذخیره‌شدهٔ موجود از طریق APIهای جدید در دسترس هستند.
  • تغییرات قابل توجه:
    • مقدار پیش‌فرض webhooks[*].failurePolicy در v1 از Ignore به Fail تغییر کرده است.
    • مقدار پیش‌فرض webhooks[*].matchPolicy در v1 از Exact به Equivalent تغییر کرده است.
    • مقدار پیش‌فرض webhooks[*].timeoutSeconds در v1 از 30s به 10s تغییر کرده است.
    • مقدار پیش‌فرض webhooks[*].sideEffects حذف شده و این فیلد الزامی شده است؛ همچنین در v1 فقط مقادیر None و NoneOnDryRun مجاز هستند.
    • مقدار پیش‌فرض webhooks[*].admissionReviewVersions حذف شده و این فیلد در v1 الزامی شده است (نسخه‌های پشتیبانی‌شده برای AdmissionReview عبارت‌اند از v1 و v1beta1).
    • در آبجکت‌هایی که از طریق admissionregistration.k8s.io/v1 ایجاد می‌شوند، مقدار webhooks[*].name باید در فهرست یکتا باشد.

منبع CustomResourceDefinition {#customresourcedefinition-v122}

نسخهٔ API apiextensions.k8s.io/v1beta1 برای CustomResourceDefinition از v1.22 به بعد دیگر ارائه نمی‌شود.

  • مانیفست‌ها و کلاینت‌های API را به نسخهٔ API apiextensions.k8s.io/v1 منتقل کنید که از v1.16 در دسترس است.
  • همهٔ آبجکت‌های ذخیره‌شدهٔ موجود از طریق API جدید در دسترس هستند.
  • تغییرات قابل توجه:
    • فیلد spec.scope دیگر به‌طور پیش‌فرض مقدار Namespaced نمی‌گیرد و باید به‌صراحت مشخص شود.
    • فیلد spec.version در v1 حذف شده است؛ به جای آن از spec.versions استفاده کنید.
    • فیلد spec.validation در v1 حذف شده است؛ به جای آن از spec.versions[*].schema استفاده کنید.
    • فیلد spec.subresources در v1 حذف شده است؛ به جای آن از spec.versions[*].subresources استفاده کنید.
    • فیلد spec.additionalPrinterColumns در v1 حذف شده است؛ به جای آن از spec.versions[*].additionalPrinterColumns استفاده کنید.
    • فیلد spec.conversion.webhookClientConfig در v1 به spec.conversion.webhook.clientConfig منتقل شده است.
    • فیلد spec.conversion.conversionReviewVersions در v1 به spec.conversion.webhook.conversionReviewVersions منتقل شده است.
    • هنگام ایجاد آبجکت‌های CustomResourceDefinition نسخهٔ v1، فیلد spec.versions[*].schema.openAPIV3Schema اکنون الزامی است و باید یک شِمای ساختاریافته باشد.
    • هنگام ایجاد آبجکت‌های CustomResourceDefinition نسخهٔ v1، استفاده از spec.preserveUnknownFields: true مجاز نیست؛ این تنظیم باید درون تعریف‌های شِما به‌صورت x-kubernetes-preserve-unknown-fields: true مشخص شود.
    • در آیتم‌های additionalPrinterColumns، نام فیلد JSONPath در v1 به jsonPath تغییر کرده است (رفع مشکل #66531).

      • فیلد status.conditions[*].status اکنون الزامی است.
      • مقدار status.certificate باید با کدگذاری PEM باشد و فقط بلوک‌های CERTIFICATE را در بر داشته باشد.

    • نام فیلدهای رشته‌ای servicePort در backend به service.port.name تغییر کرده است.
    • فیلد pathType اکنون برای هر مسیر مشخص‌شده الزامی است. گزینه‌های آن عبارت‌اند از Prefix، Exact و ImplementationSpecific. برای تطابق با رفتار تعریف‌نشدهٔ v1beta1، از ImplementationSpecific استفاده کنید.

اقدامات لازم

آزمایش با غیرفعال‌کردن APIهای منسوخ‌شده

برای شبیه‌سازی حذف‌های آینده، می‌توانید سرور API را با غیرفعال‌کردن نسخه‌های مشخصی از API راه‌اندازی کنید و کلاسترهای خود را آزمایش کنید. فلگ زیر را به آرگومان‌های راه‌اندازی سرور API اضافه کنید:

--runtime-config=<group>/<version>=false

برای مثال:

--runtime-config=admissionregistration.k8s.io/v1beta1=false,apiextensions.k8s.io/v1beta1,...

یافتن موارد استفاده از APIهای منسوخ‌شده

برای یافتن موارد استفاده از APIهای منسوخ‌شده، از هشدارهای کلاینت، متریک‌ها و اطلاعات ممیزی موجود در نسخهٔ 1.19 به بعد استفاده کنید.

مهاجرت به APIهای منسوخ‌نشده

  • یکپارچه‌سازی‌ها و کنترل‌کننده‌های سفارشی را به‌روزرسانی کنید تا APIهای منسوخ‌نشده را فراخوانی کنند.

  • فایل‌های YAML را طوری تغییر دهید که به APIهای منسوخ‌نشده ارجاع دهند.

    برای تبدیل خودکار یک آبجکت موجود می‌توانید از فرمان kubectl convert استفاده کنید:

    kubectl convert -f <file> --output-version <group>/<version>.

    برای نمونه، برای تبدیل یک Deployment قدیمی به apps/v1 می‌توانید این فرمان را اجرا کنید:

    kubectl convert -f ./my-deployment.yaml --output-version apps/v1

    ممکن است این تبدیل از مقادیر پیش‌فرضِ نامطلوب استفاده کند. برای آشنایی بیشتر با هر منبع، مرجع API کوبرنتیز را ببینید.

توجه:

ابزار kubectl convert به‌طور پیش‌فرض نصب نمی‌شود، هرچند زمانی بخشی از خودِ kubectl بود. برای جزئیات بیشتر می‌توانید مسئلهٔ منسوخ‌شدن و حذف این زیرفرمان داخلی را بخوانید.

برای آشنایی با نحوهٔ راه‌اندازی kubectl convert روی رایانهٔ خود، به صفحهٔ مربوط به سیستم‌عامل خود مراجعه کنید: Linux، macOS یا Windows.
