مثال: استقرار کاساندرا با StatefulSet

این آموزش نشان می‌دهد که چگونه Apache Cassandra را روی کوبرنتیز اجرا کنید. کاساندرا یک پایگاه داده است و برای تضمین ماندگاری داده‌ها (وضعیت برنامه) به ذخیره‌سازی پایدار نیاز دارد. در این مثال، یک ارائه‌دهندهٔ seed سفارشی برای کاساندرا به پایگاه داده امکان می‌دهد نمونه‌های جدید کاساندرا را هنگام پیوستن به کلاستر کاساندرا شناسایی کند.

آبجکت‌های StatefulSet استقرار برنامه‌های دارای وضعیت (stateful) را در کلاستر کوبرنتیز آسان‌تر می‌کنند. برای آشنایی بیشتر با قابلیت‌هایی که در این آموزش استفاده می‌شوند، صفحهٔ StatefulSet را ببینید.

Note

کاساندرا و کوبرنتیز هر دو اصطلاح نود را برای اشاره به یکی از اعضای کلاستر به کار می‌برند. در این آموزش، Podهایی که به StatefulSet تعلق دارند نودهای کاساندرا هستند و عضو کلاستر کاساندرا (که حلقه یا ring نامیده می‌شود) به شمار می‌روند. وقتی این Podها در کلاستر کوبرنتیز شما اجرا می‌شوند، control plane کوبرنتیز آن‌ها را روی نودهای کوبرنتیز زمان‌بندی می‌کند.

هر نود کاساندرا هنگام راه‌اندازی از یک فهرست seed برای آغاز فرایند شناسایی سایر نودهای حلقه استفاده می‌کند. این آموزش یک ارائه‌دهندهٔ seed سفارشی برای کاساندرا مستقر می‌کند که به پایگاه داده امکان می‌دهد Podهای جدید کاساندرا را به محض ظاهر شدن در کلاستر کوبرنتیز شما شناسایی کند.

اهداف

  • یک Service از نوع headless برای کاساندرا ایجاد و اعتبارسنجی کنید.
  • با استفاده از یک StatefulSet، حلقهٔ کاساندرا را ایجاد کنید.
  • آبجکت StatefulSet را اعتبارسنجی کنید.
  • آبجکت StatefulSet را تغییر دهید.
  • آبجکت StatefulSet و Podهای آن را حذف کنید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

برای انجام این آموزش، باید از پیش با مفاهیم پایهٔ Podها، Serviceها و StatefulSetها آشنا باشید.

دستورالعمل‌های تکمیلی راه‌اندازی Minikube

Caution

ابزار Minikube به‌طور پیش‌فرض از ۲۰۴۸ مگابایت حافظه و ۲ پردازنده استفاده می‌کند. اجرای Minikube با پیکربندی پیش‌فرض منابع، در طول این آموزش به خطاهای کمبود منابع منجر می‌شود. برای جلوگیری از این خطاها، Minikube را با تنظیمات زیر راه‌اندازی کنید:

minikube start --memory 5120 --cpus=4

ایجاد یک Service از نوع headless برای کاساندرا {#creating-a-cassandra-headless-service}

در کوبرنتیز، یک Service مجموعه‌ای از Podها را توصیف می‌کند که وظیفهٔ یکسانی انجام می‌دهند.

از Service زیر برای جست‌وجوهای DNS میان Podهای کاساندرا و کلاینت‌های درون کلاستر شما استفاده می‌شود:

application/cassandra/cassandra-service.yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    app: cassandra
  name: cassandra
spec:
  clusterIP: None
  ports:
  - port: 9042
  selector:
    app: cassandra

با استفاده از فایل cassandra-service.yaml، یک Service ایجاد کنید تا همهٔ اعضای StatefulSet کاساندرا را دنبال کند:

kubectl apply -f https://k8s.io/examples/application/cassandra/cassandra-service.yaml

اعتبارسنجی (اختیاری) {#validating}

اطلاعات Service کاساندرا را دریافت کنید.

kubectl get svc cassandra

پاسخ به این صورت است:

NAME        TYPE        CLUSTER-IP   EXTERNAL-IP   PORT(S)    AGE
cassandra   ClusterIP   None         <none>        9042/TCP   45s

اگر Serviceای با نام cassandra نمی‌بینید، یعنی ایجاد آن ناموفق بوده است. برای کمک به عیب‌یابی مشکلات رایج، صفحهٔ اشکال‌زدایی Serviceها را مطالعه کنید.

استفاده از StatefulSet برای ایجاد حلقهٔ کاساندرا

مانیفست StatefulSet که در ادامه آمده است، یک حلقهٔ کاساندرا متشکل از سه Pod ایجاد می‌کند.

Note

این مثال از provisioner پیش‌فرض Minikube استفاده می‌کند. لطفاً StatefulSet زیر را متناسب با محیط ابری‌ای که با آن کار می‌کنید به‌روزرسانی کنید.

application/cassandra/cassandra-statefulset.yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: cassandra
  labels:
    app: cassandra
spec:
  serviceName: cassandra
  replicas: 3
  selector:
    matchLabels:
      app: cassandra
  template:
    metadata:
      labels:
        app: cassandra
    spec:
      terminationGracePeriodSeconds: 500
      containers:
      - name: cassandra
        image: gcr.io/google-samples/cassandra:v13
        imagePullPolicy: Always
        ports:
        - containerPort: 7000
          name: intra-node
        - containerPort: 7001
          name: tls-intra-node
        - containerPort: 7199
          name: jmx
        - containerPort: 9042
          name: cql
        resources:
          limits:
            cpu: "500m"
            memory: 1Gi
          requests:
            cpu: "500m"
            memory: 1Gi
        securityContext:
          capabilities:
            add:
              - IPC_LOCK
        lifecycle:
          preStop:
            exec:
              command: 
              - /bin/sh
              - -c
              - nodetool drain
        env:
          - name: MAX_HEAP_SIZE
            value: 512M
          - name: HEAP_NEWSIZE
            value: 100M
          - name: CASSANDRA_SEEDS
            value: "cassandra-0.cassandra.default.svc.cluster.local"
          - name: CASSANDRA_CLUSTER_NAME
            value: "K8Demo"
          - name: CASSANDRA_DC
            value: "DC1-K8Demo"
          - name: CASSANDRA_RACK
            value: "Rack1-K8Demo"
          - name: POD_IP
            valueFrom:
              fieldRef:
                fieldPath: status.podIP
        readinessProbe:
          exec:
            command:
            - /bin/bash
            - -c
            - /ready-probe.sh
          initialDelaySeconds: 15
          timeoutSeconds: 5
        # These volume mounts are persistent. They are like inline claims,
        # but not exactly because the names need to match exactly one of
        # the stateful pod volumes.
        volumeMounts:
        - name: cassandra-data
          mountPath: /cassandra_data
  # These are converted to volume claims by the controller
  # and mounted at the paths mentioned above.
  # do not use these in production until ssd GCEPersistentDisk or other ssd pd
  volumeClaimTemplates:
  - metadata:
      name: cassandra-data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      storageClassName: fast
      resources:
        requests:
          storage: 1Gi
---
kind: StorageClass
apiVersion: storage.k8s.io/v1
metadata:
  name: fast
provisioner: k8s.io/minikube-hostpath
parameters:
  type: pd-ssd

با استفاده از فایل cassandra-statefulset.yaml، آبجکت StatefulSet کاساندرا را ایجاد کنید:

# Use this if you are able to apply cassandra-statefulset.yaml unmodified
kubectl apply -f https://k8s.io/examples/application/cassandra/cassandra-statefulset.yaml

اگر لازم است فایل cassandra-statefulset.yaml را متناسب با کلاستر خود تغییر دهید، فایل https://k8s.io/examples/application/cassandra/cassandra-statefulset.yaml را دانلود کنید و سپس مانیفست را از پوشه‌ای که نسخهٔ تغییریافته را در آن ذخیره کرده‌اید اعمال کنید:

# Use this if you needed to modify cassandra-statefulset.yaml locally
kubectl apply -f cassandra-statefulset.yaml

اعتبارسنجی StatefulSet کاساندرا

  1. اطلاعات StatefulSet کاساندرا را دریافت کنید:

    kubectl get statefulset cassandra

    پاسخ باید مشابه زیر باشد:

    NAME        DESIRED   CURRENT   AGE
cassandra   3         0         13s

    منبع StatefulSet پادها را به‌ترتیب و یکی پس از دیگری مستقر می‌کند.

  2. برای مشاهدهٔ وضعیت ایجاد ترتیبی Podها، فهرست آن‌ها را دریافت کنید:

    kubectl get pods -l="app=cassandra"

    پاسخ باید مشابه زیر باشد:

    NAME          READY     STATUS              RESTARTS   AGE
cassandra-0   1/1       Running             0          1m
cassandra-1   0/1       ContainerCreating   0          8s

    استقرار هر سه Pod ممکن است چند دقیقه طول بکشد. پس از استقرار آن‌ها، همین فرمان خروجی‌ای مشابه زیر برمی‌گرداند:

    NAME          READY     STATUS    RESTARTS   AGE
cassandra-0   1/1       Running   0          10m
cassandra-1   1/1       Running   0          9m
cassandra-2   1/1       Running   0          8m

  3. برای نمایش وضعیت حلقه، ابزار nodetool کاساندرا را درون نخستین Pod اجرا کنید.

    kubectl exec -it cassandra-0 -- nodetool status

    پاسخ باید تقریباً به این شکل باشد:

تغییر StatefulSet کاساندرا

برای تغییر اندازهٔ StatefulSet کاساندرا از kubectl edit استفاده کنید.

  1. فرمان زیر را اجرا کنید:

    kubectl edit statefulset cassandra

    این فرمان یک ویرایشگر را در ترمینال شما باز می‌کند. خطی که باید تغییر دهید فیلد replicas است. نمونهٔ زیر بخشی از فایل StatefulSet است:

    # Please edit the object below. Lines beginning with a '#' will be ignored,
# and an empty file will abort the edit. If an error occurs while saving this file will be
# reopened with the relevant failures.
#
apiVersion: apps/v1
kind: StatefulSet
metadata:
  creationTimestamp: 2016-08-13T18:40:58Z
  generation: 1
  labels:
  app: cassandra
  name: cassandra
  namespace: default
  resourceVersion: "323"
  uid: 7a219483-6185-11e6-a910-42010a8a0fc0
spec:
  replicas: 3

  2. تعداد رپلیکاها را به ۴ تغییر دهید و سپس مانیفست را ذخیره کنید.

    اکنون StatefulSet مقیاس‌پذیری می‌کند تا با ۴ Pod اجرا شود.

  3. برای اطمینان از اعمال تغییر، اطلاعات StatefulSet کاساندرا را دریافت کنید:

    kubectl get statefulset cassandra

    پاسخ باید مشابه زیر باشد:

    NAME        DESIRED   CURRENT   AGE
cassandra   4         4         36m

پاکسازی

حذف یک StatefulSet یا کاهش مقیاس آن، حجم‌های (volume) مرتبط با آن را حذف نمی‌کند. این تنظیم برای حفظ امنیت شماست، زیرا داده‌های شما ارزشمندتر از آن هستند که همهٔ منابع مرتبط با StatefulSet به‌طور خودکار پاک شوند.

Warning

بسته به کلاس ذخیره‌سازی و سیاست بازپس‌گیری (reclaim policy)، حذف PersistentVolumeClaimها ممکن است باعث شود حجم‌های مرتبط نیز حذف شوند. هرگز فرض نکنید که پس از حذف درخواست‌های حجم، همچنان به داده‌های آن‌ها دسترسی خواهید داشت.

  1. برای حذف همهٔ اجزای StatefulSet کاساندرا، فرمان‌های زیر را (که در قالب یک فرمان واحد به هم زنجیر شده‌اند) اجرا کنید:

    grace=$(kubectl get pod cassandra-0 -o=jsonpath='{.spec.terminationGracePeriodSeconds}') \
  && kubectl delete statefulset -l app=cassandra \
  && echo "Sleeping ${grace} seconds" 1>&2 \
  && sleep $grace \
  && kubectl delete persistentvolumeclaim -l app=cassandra

  2. برای حذف Serviceای که برای کاساندرا راه‌اندازی کرده‌اید، فرمان زیر را اجرا کنید:

    kubectl delete service -l app=cassandra

متغیرهای محیطی کانتینر کاساندرا

پادهای این آموزش از ایمیج gcr.io/google-samples/cassandra:v13 موجود در رجیستری کانتینر گوگل استفاده می‌کنند. این ایمیج داکر بر پایهٔ debian-base ساخته شده و OpenJDK 8 را در خود دارد.

این ایمیج شامل یک نصب استاندارد کاساندرا از مخزن Debian بنیاد Apache است. با استفاده از متغیرهای محیطی می‌توانید مقادیری را که در فایل cassandra.yaml درج می‌شوند تغییر دهید.

متغیر محیطی مقدار پیش‌فرض
CASSANDRA_CLUSTER_NAME 'Test Cluster'
CASSANDRA_NUM_TOKENS 32
CASSANDRA_RPC_ADDRESS 0.0.0.0

گام‌های بعدی

  • با نحوهٔ تغییر مقیاس یک StatefulSet آشنا شوید.
  • دربارهٔ KubernetesSeedProvider بیشتر بیاموزید.
  • پیکربندی‌های سفارشی بیشتری برای ارائه‌دهندهٔ seed را ببینید.
