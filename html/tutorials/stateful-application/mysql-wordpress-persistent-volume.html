مثال: استقرار WordPress و MySQL با حجم‌های پایدار

این آموزش نشان می‌دهد که چگونه یک سایت WordPress و یک پایگاه داده MySQL را با استفاده از Minikube مستقر کنید. هر دو برنامه برای ذخیره داده‌ها از PersistentVolume و PersistentVolumeClaim استفاده می‌کنند.

هر PersistentVolume (PV) بخشی از فضای ذخیره‌سازی در کلاستر است که یا مدیر کلاستر آن را به‌صورت دستی تأمین کرده است، یا کوبرنتیز آن را با استفاده از یک StorageClass به‌صورت پویا تأمین می‌کند. هر PersistentVolumeClaim (PVC) درخواستی از سوی کاربر برای فضای ذخیره‌سازی است که یک PV می‌تواند به آن پاسخ دهد. چرخه عمر PersistentVolumeها و PersistentVolumeClaimها مستقل از چرخه عمر Podها است و داده‌ها هنگام راه‌اندازی مجدد، زمان‌بندی مجدد و حتی حذف Podها حفظ می‌شوند.

Warning

این استقرار برای محیط‌های عملیاتی (production) مناسب نیست، زیرا از Podهای تک‌نمونه‌ای WordPress و MySQL استفاده می‌کند. برای استقرار WordPress در محیط عملیاتی، استفاده از چارت Helm وردپرس را در نظر بگیرید.

Note

فایل‌های ارائه‌شده در این آموزش از APIهای GA مربوط به Deployment استفاده می‌کنند و مختص کوبرنتیز نسخه 1.9 و بالاتر هستند. اگر می‌خواهید این آموزش را با نسخه‌ای قدیمی‌تر از کوبرنتیز به کار ببرید، نسخه API را متناسب با آن به‌روزرسانی کنید یا به نسخه‌های قدیمی‌تر این آموزش مراجعه کنید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

مثالی که در این صفحه نشان داده شده است با kubectl نسخه 1.27 و بالاتر کار می‌کند.

ایجاد PersistentVolumeClaimها و PersistentVolumeها

هر یک از MySQL و WordPress برای ذخیره داده‌ها به یک PersistentVolume نیاز دارند. PersistentVolumeClaimهای آن‌ها در مرحله استقرار ایجاد خواهند شد.

در بسیاری از محیط‌های کلاستر، یک StorageClass پیش‌فرض نصب شده است. اگر در PersistentVolumeClaim هیچ StorageClassی مشخص نشده باشد، از StorageClass پیش‌فرض کلاستر استفاده می‌شود.

هنگامی که یک PersistentVolumeClaim ایجاد می‌شود، یک PersistentVolume بر اساس پیکربندی StorageClass به‌صورت پویا تأمین می‌شود.

Warning

در کلاسترهای محلی، StorageClass پیش‌فرض از تأمین‌کننده hostPath استفاده می‌کند. حجم‌های hostPath فقط برای توسعه و آزمایش مناسب هستند. در حجم‌های hostPath، داده‌های شما در مسیر /tmp روی نودی قرار می‌گیرند که Pod روی آن زمان‌بندی شده است و بین نودها جابه‌جا نمی‌شوند. اگر Pod از کار بیفتد و روی نود دیگری در کلاستر زمان‌بندی شود، یا نود راه‌اندازی مجدد شود، داده‌ها از دست می‌روند.

Note

اگر کلاستری راه‌اندازی می‌کنید که باید از تأمین‌کننده hostPath استفاده کند، باید فلگ --enable-hostpath-provisioner را در مؤلفه controller-manager تنظیم کنید.

Note

اگر یک کلاستر کوبرنتیز دارید که روی Google Kubernetes Engine اجرا می‌شود، این راهنما را دنبال کنید.

ایجاد فایل kustomization.yaml

افزودن یک مولد Secret

هر Secret آبجکتی است که بخشی از داده‌های حساس، مانند گذرواژه یا کلید، را ذخیره می‌کند. از نسخه 1.14 به بعد، kubectl از مدیریت آبجکت‌های کوبرنتیز با استفاده از فایل kustomization پشتیبانی می‌کند. می‌توانید با استفاده از مولدها در kustomization.yaml یک Secret ایجاد کنید.

با دستور زیر، یک مولد Secret به kustomization.yaml اضافه کنید. لازم است YOUR_PASSWORD را با گذرواژه‌ای که می‌خواهید استفاده کنید جایگزین کنید.

cat <<EOF >./kustomization.yaml
secretGenerator:
- name: mysql-pass
  literals:
  - password=YOUR_PASSWORD
EOF

افزودن پیکربندی‌های منابع برای MySQL و WordPress

مانیفست زیر یک Deployment تک‌نمونه‌ای از MySQL را توصیف می‌کند. کانتینر MySQL، PersistentVolume را در مسیر /var/lib/mysql متصل (mount) می‌کند. متغیر محیطی MYSQL_ROOT_PASSWORD گذرواژه پایگاه داده را از Secret تنظیم می‌کند.

application/wordpress/mysql-deployment.yaml
apiVersion: v1
kind: Service
metadata:
  name: wordpress-mysql
  labels:
    app: wordpress
spec:
  ports:
    - port: 3306
  selector:
    app: wordpress
    tier: mysql
  clusterIP: None
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pv-claim
  labels:
    app: wordpress
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wordpress-mysql
  labels:
    app: wordpress
spec:
  selector:
    matchLabels:
      app: wordpress
      tier: mysql
  strategy:
    type: Recreate
  template:
    metadata:
      labels:
        app: wordpress
        tier: mysql
    spec:
      containers:
      - image: mysql:8.0
        name: mysql
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-pass
              key: password
        - name: MYSQL_DATABASE
          value: wordpress
        - name: MYSQL_USER
          value: wordpress
        - name: MYSQL_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-pass
              key: password
        ports:
        - containerPort: 3306
          name: mysql
        volumeMounts:
        - name: mysql-persistent-storage
          mountPath: /var/lib/mysql
      volumes:
      - name: mysql-persistent-storage
        persistentVolumeClaim:
          claimName: mysql-pv-claim

مانیفست زیر یک Deployment تک‌نمونه‌ای از WordPress را توصیف می‌کند. کانتینر WordPress، PersistentVolume را برای فایل‌های داده وب‌سایت در مسیر /var/www/html متصل می‌کند. متغیر محیطی WORDPRESS_DB_HOST نام Service مربوط به MySQL را که در بالا تعریف شد تنظیم می‌کند و WordPress از طریق این Service به پایگاه داده دسترسی خواهد داشت. متغیر محیطی WORDPRESS_DB_PASSWORD گذرواژه پایگاه داده را از Secretی که kustomize تولید کرده است تنظیم می‌کند.

application/wordpress/wordpress-deployment.yaml
apiVersion: v1
kind: Service
metadata:
  name: wordpress
  labels:
    app: wordpress
spec:
  ports:
    - port: 80
  selector:
    app: wordpress
    tier: frontend
  type: LoadBalancer
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: wp-pv-claim
  labels:
    app: wordpress
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wordpress
  labels:
    app: wordpress
spec:
  selector:
    matchLabels:
      app: wordpress
      tier: frontend
  strategy:
    type: Recreate
  template:
    metadata:
      labels:
        app: wordpress
        tier: frontend
    spec:
      containers:
      - image: wordpress:6.2.1-apache
        name: wordpress
        env:
        - name: WORDPRESS_DB_HOST
          value: wordpress-mysql
        - name: WORDPRESS_DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-pass
              key: password
        - name: WORDPRESS_DB_USER
          value: wordpress
        ports:
        - containerPort: 80
          name: wordpress
        volumeMounts:
        - name: wordpress-persistent-storage
          mountPath: /var/www/html
      volumes:
      - name: wordpress-persistent-storage
        persistentVolumeClaim:
          claimName: wp-pv-claim

  1. فایل پیکربندی استقرار MySQL را دانلود کنید.

    curl -LO https://k8s.io/examples/application/wordpress/mysql-deployment.yaml

  2. فایل پیکربندی WordPress را دانلود کنید.

    curl -LO https://k8s.io/examples/application/wordpress/wordpress-deployment.yaml

  3. آن‌ها را به فایل kustomization.yaml اضافه کنید.

    cat <<EOF >>./kustomization.yaml
resources:
  - mysql-deployment.yaml
  - wordpress-deployment.yaml
EOF

اعمال و بررسی

فایل kustomization.yaml همه منابع لازم برای استقرار یک سایت WordPress و یک پایگاه داده MySQL را در بر دارد. می‌توانید پوشه را با دستور زیر اعمال کنید:

kubectl apply -k ./

اکنون می‌توانید بررسی کنید که همه آبجکت‌ها وجود دارند.

  1. با اجرای دستور زیر بررسی کنید که Secret وجود دارد:

    kubectl get secrets

    خروجی باید مشابه زیر باشد:

    NAME                    TYPE                                  DATA   AGE
mysql-pass-c57bb4t7mf   Opaque                                1      9s

  2. بررسی کنید که یک PersistentVolume به‌صورت پویا تأمین شده است.

    kubectl get pvc
Note

ممکن است تأمین و اتصال (bind) PVها تا چند دقیقه طول بکشد.

خروجی باید مشابه زیر باشد:

NAME             STATUS    VOLUME                                     CAPACITY   ACCESS MODES   STORAGECLASS       AGE
mysql-pv-claim   Bound     pvc-8cbd7b2e-4044-11e9-b2bb-42010a800002   20Gi       RWO            standard           77s
wp-pv-claim      Bound     pvc-8cd0df54-4044-11e9-b2bb-42010a800002   20Gi       RWO            standard           77s

  1. با اجرای دستور زیر بررسی کنید که Pod در حال اجرا است:

    kubectl get pods
Note

ممکن است تا چند دقیقه طول بکشد تا وضعیت Pod به RUNNING تغییر کند.

خروجی باید مشابه زیر باشد:

NAME                               READY     STATUS    RESTARTS   AGE
wordpress-mysql-1894417608-x5dzt   1/1       Running   0          40s

  1. با اجرای دستور زیر بررسی کنید که Service در حال اجرا است:

    kubectl get services wordpress

    خروجی باید مشابه زیر باشد:

    NAME        TYPE            CLUSTER-IP   EXTERNAL-IP   PORT(S)        AGE
wordpress   LoadBalancer    10.0.0.89    <pending>     80:32406/TCP   4m
Note

در Minikube، Serviceها فقط از طریق NodePort در دسترس قرار می‌گیرند. مقدار EXTERNAL-IP همیشه در وضعیت pending است.

  1. برای دریافت نشانی IP مربوط به Service وردپرس، دستور زیر را اجرا کنید:

    minikube service wordpress --url

    خروجی باید مشابه زیر باشد:

    http://1.2.3.4:32406

  2. نشانی IP را کپی کنید و برای مشاهده سایت خود، صفحه را در مرورگر باز کنید.

    باید صفحه راه‌اندازی WordPress را مشابه تصویر زیر ببینید.

Warning

نصب WordPress را در همین صفحه رها نکنید. اگر کاربر دیگری آن را پیدا کند، می‌تواند روی نمونه شما یک وب‌سایت راه‌اندازی کند و از آن برای ارائه محتوای مخرب استفاده کند.

یا WordPress را با ایجاد نام کاربری و گذرواژه نصب کنید، یا نمونه خود را حذف کنید.

پاکسازی

  1. برای حذف Secret، Deploymentها، Serviceها و PersistentVolumeClaimهای خود، دستور زیر را اجرا کنید:

    kubectl delete -k ./
