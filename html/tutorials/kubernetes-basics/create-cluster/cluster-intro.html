استفاده از Minikube برای ایجاد یک کلاستر

اهداف

  • با مفهوم کلاستر کوبرنتیز آشنا شوید.
  • با Minikube آشنا شوید.
  • یک کلاستر کوبرنتیز را روی رایانهٔ خود راه‌اندازی کنید.

پیش از شروع

در این آموزش فرض بر این است که minikube را از قبل نصب کرده‌اید. برای دستورالعمل‌های نصب، صفحهٔ minikube start را ببینید.

توجه:

فقط دستورالعمل‌های مرحلهٔ ۱: نصب را اجرا کنید. بقیهٔ مراحل در همین آموزش پوشش داده می‌شوند.

همچنین باید kubectl را نصب کنید. برای دستورالعمل‌های نصب، صفحهٔ نصب ابزارها را ببینید.

دستورهای پوسته (shell) در این آموزش از نحو پوستهٔ POSIX استفاده می‌کنند که پوسته‌های پیش‌فرض بیشتر سیستم‌های Linux و macOS (برای مثال bash، zsh یا sh) از آن پشتیبانی می‌کنند. کاربران Windows برای اجرای دستورها به همان شکلی که نوشته شده‌اند، باید از یک پوستهٔ سازگار با POSIX مانند Windows Subsystem for Linux (WSL) یا Git Bash استفاده کنند. دستورهایی که از export، $() و ساختارهای مشابه استفاده می‌کنند، با PowerShell یا Command Prompt ویندوز سازگار نیستند.

کلاسترهای کوبرنتیز

کوبرنتیز یک پلتفرم متن‌باز و مناسب محیط عملیاتی (production) است که جای‌گذاری (زمان‌بندی) و اجرای کانتینرهای برنامه را درون کلاسترهای رایانه‌ای و در سراسر آن‌ها هماهنگ (orchestrate) می‌کند.

کوبرنتیز یک کلاستر با دسترس‌پذیری بالا از رایانه‌هایی را هماهنگ می‌کند که به هم متصل‌اند تا به‌صورت یک واحد واحد کار کنند. انتزاع‌های کوبرنتیز به شما امکان می‌دهند برنامه‌های کانتینری‌شده را بدون وابسته‌کردن آن‌ها به ماشین‌های مشخص، روی یک کلاستر مستقر کنید. برای بهره‌گیری از این مدل جدید استقرار، برنامه‌ها باید به گونه‌ای بسته‌بندی شوند که از میزبان‌های مشخص جدا باشند؛ یعنی باید کانتینری شوند. برنامه‌های کانتینری‌شده نسبت به مدل‌های استقرار گذشته انعطاف‌پذیرتر و دسترس‌پذیرترند؛ در آن مدل‌ها برنامه‌ها مستقیماً روی ماشین‌های مشخص و به‌صورت بسته‌هایی نصب می‌شدند که عمیقاً با میزبان یکپارچه بودند. کوبرنتیز توزیع و زمان‌بندی کانتینرهای برنامه را در سراسر کلاستر به شکلی کارآمدتر خودکار می‌کند. کوبرنتیز پلتفرمی متن‌باز و آمادهٔ استفاده در محیط عملیاتی است.

هر کلاستر کوبرنتیز از دو نوع منبع تشکیل می‌شود:

  • Control Plane کلاستر را هماهنگ می‌کند.
  • نودها کارگرهایی هستند که برنامه‌ها را اجرا می‌کنند.

نمودار کلاستر

مسئولیت مدیریت کلاستر بر عهدهٔ Control Plane است. این بخش همهٔ فعالیت‌های کلاستر شما، مانند زمان‌بندی برنامه‌ها، حفظ وضعیت مطلوب برنامه‌ها، مقیاس‌دهی برنامه‌ها و انتشار به‌روزرسانی‌های جدید را هماهنگ می‌کند.

هر Control Plane کلاستر و نودهایی را مدیریت می‌کند که میزبان برنامه‌های در حال اجرا هستند.

نود یک ماشین مجازی (VM) یا رایانهٔ فیزیکی است که در کلاستر کوبرنتیز نقش ماشین کارگر را دارد. هر نود یک Kubelet دارد؛ این عامل (agent) نود را مدیریت می‌کند و با control plane کوبرنتیز ارتباط برقرار می‌کند. همچنین نود باید ابزارهایی برای انجام عملیات کانتینری، مانند containerd یا cri o، داشته باشد. یکی از مدل‌های رایج و پشتیبانی‌شدهٔ استقرار این است که مؤلفه‌های control plane کوبرنتیز روی نودهای control plane اختصاصی اجرا شوند.

هنگامی که برنامه‌ها را روی کوبرنتیز مستقر می‌کنید، به control plane اعلام می‌کنید که کانتینرهای برنامه را راه‌اندازی کند. سپس control plane کانتینرها را برای اجرا روی نودهای کلاستر زمان‌بندی می‌کند. مؤلفه‌های سطح نود، مانند kubelet، از طریق API کوبرنتیز با control plane ارتباط برقرار می‌کنند؛ این API را control plane در دسترس قرار می‌دهد. کاربران نهایی نیز می‌توانند مستقیماً از API کوبرنتیز برای تعامل با کلاستر استفاده کنند.

کلاستر کوبرنتیز را می‌توان روی ماشین‌های فیزیکی یا مجازی مستقر کرد. برای شروع توسعه با کوبرنتیز می‌توانید از Minikube استفاده کنید. Minikube یک پیاده‌سازی سبک از کوبرنتیز است که یک ماشین مجازی روی ماشین محلی شما ایجاد می‌کند و یک کلاستر ساده با تنها یک نود را مستقر می‌کند. این ابزار برای سیستم‌های Linux، macOS و Windows در دسترس است. رابط خط فرمان (CLI) آن عملیات پایه‌ای راه‌اندازی برای کار با کلاستر، از جمله شروع، توقف، بررسی وضعیت و حذف، را فراهم می‌کند.

ایجاد یک کلاستر minikube

برای راه‌اندازی یک کلاستر minikube:

minikube start

برای بررسی وضعیت کلاستر:

minikube status

برای راهنمای کامل، شامل استقرار نخستین برنامه و بررسی داشبورد کوبرنتیز، آموزش Hello Minikube را ببینید.

گام‌های بعدی

  • آموزش استقرار یک برنامه.
  • دربارهٔ معماری کلاستر بیشتر بیاموزید.
