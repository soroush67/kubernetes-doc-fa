سلام Minikube

این آموزش نشان می‌دهد که چگونه یک برنامهٔ نمونه را با استفاده از minikube روی کوبرنتیز اجرا کنید. در این آموزش یک ایمیج کانتینر در اختیار شما قرار می‌گیرد که با استفاده از NGINX همهٔ درخواست‌ها را عیناً بازمی‌گرداند.

اهداف

  • استقرار یک برنامهٔ نمونه روی minikube.
  • اجرای برنامه.
  • مشاهدهٔ لاگ‌های برنامه.

پیش از شروع

در این آموزش فرض بر این است که minikube را از قبل راه‌اندازی کرده‌اید. برای دستورالعمل‌های نصب، گام ۱ را در شروع کار با minikube ببینید.

Note

فقط دستورالعمل‌های گام ۱، نصب را اجرا کنید. باقی مراحل در همین صفحه پوشش داده شده است.

همچنین باید kubectl را نصب کنید. برای دستورالعمل‌های نصب، نصب ابزارها را ببینید.

ایجاد یک کلاستر minikube

minikube start
Note

دستور minikube start یک کلاستر تک‌نودی ایجاد می‌کند. این نود هم نقش control plane و هم نقش نود کارگر (worker) را بر عهده دارد. این وضعیت با بسیاری از کلاسترهای عملیاتی (production) کوبرنتیز متفاوت است؛ در آن کلاسترها نودهای control plane معمولاً با استفاده از taintها از نودهای کارگر جدا می‌شوند یا اصلاً برای کاربر قابل مشاهده نیستند.

بررسی وضعیت کلاستر minikube

وضعیت کلاستر minikube را بررسی کنید تا مطمئن شوید همهٔ مؤلفه‌ها در حال اجرا هستند.

minikube status

خروجی دستور بالا باید همهٔ مؤلفه‌ها را در وضعیت Running یا Configured نشان دهد، مانند نمونه خروجی زیر:

minikube
type: Control Plane
host: Running
kubelet: Running
apiserver: Running
kubeconfig: Configured

باز کردن داشبورد

داشبورد کوبرنتیز را باز کنید. این کار را به دو روش می‌توانید انجام دهید:

اجرای مرورگر

یک ترمینال جدید باز کنید و دستور زیر را اجرا کنید:

# Start a new terminal, and leave this running.
minikube dashboard

اکنون به ترمینالی برگردید که دستور minikube start را در آن اجرا کردید.

Note

دستور dashboard افزونهٔ داشبورد را فعال می‌کند و پراکسی را در مرورگر وب پیش‌فرض باز می‌کند. در داشبورد می‌توانید منابع کوبرنتیز مانند Deployment و Service ایجاد کنید.

برای اینکه بدانید چگونه می‌توان از باز شدن مستقیم مرورگر از طریق ترمینال جلوگیری کرد و یک URL برای داشبورد وب به دست آورد، زبانهٔ «کپی و جای‌گذاری URL» را ببینید.

داشبورد به‌طور پیش‌فرض فقط از داخل شبکهٔ مجازی داخلی کوبرنتیز در دسترس است. دستور dashboard یک پراکسی موقت ایجاد می‌کند تا داشبورد از بیرون شبکهٔ مجازی کوبرنتیز نیز در دسترس باشد.

برای متوقف کردن پراکسی، با زدن Ctrl+C از فرایند خارج شوید. پس از خروج دستور، داشبورد همچنان در کلاستر کوبرنتیز در حال اجرا باقی می‌ماند. می‌توانید دستور dashboard را دوباره اجرا کنید تا پراکسی دیگری برای دسترسی به داشبورد ایجاد شود.

کپی و جای‌گذاری URL

اگر نمی‌خواهید minikube مرورگر وب را برایتان باز کند، زیرفرمان dashboard را همراه با فلگ --url اجرا کنید. در این حالت، minikube یک URL در خروجی نمایش می‌دهد که می‌توانید آن را در مرورگر دلخواه خود باز کنید.

یک ترمینال جدید باز کنید و دستور زیر را اجرا کنید:

# Start a new terminal, and leave this running.
minikube dashboard --url

اکنون می‌توانید از این URL استفاده کنید و به ترمینالی برگردید که دستور minikube start را در آن اجرا کردید.

ایجاد یک Deployment

هر Pod در کوبرنتیز گروهی از یک یا چند کانتینر است که برای اهداف مدیریتی و شبکه‌ای به هم پیوند خورده‌اند. Pod این آموزش فقط یک کانتینر دارد. هر Deployment در کوبرنتیز سلامت Pod شما را بررسی می‌کند و در صورت خاتمه یافتن کانتینر Pod، آن را دوباره راه‌اندازی می‌کند. استفاده از Deploymentها روش توصیه‌شده برای مدیریت ایجاد و مقیاس‌دهی Podها است.

  1. با استفاده از دستور kubectl create یک Deployment ایجاد کنید که یک Pod را مدیریت می‌کند. این Pod یک کانتینر را بر پایهٔ ایمیج Docker ارائه‌شده اجرا می‌کند.

    # Run a test container image that includes a webserver
kubectl create deployment hello-node --image=registry.k8s.io/e2e-test-images/agnhost:2.53 -- /agnhost netexec --http-port=8080

  2. Deployment را مشاهده کنید:

    kubectl get deployments

    خروجی مشابه زیر است:

    NAME         READY   UP-TO-DATE   AVAILABLE   AGE
hello-node   1/1     1            1           1m

    (ممکن است مدتی طول بکشد تا Pod در دسترس قرار گیرد. اگر مقدار «0/1» را می‌بینید، چند ثانیه بعد دوباره امتحان کنید.)

  3. Pod را مشاهده کنید:

    kubectl get pods

    خروجی مشابه زیر است:

    NAME                          READY     STATUS    RESTARTS   AGE
hello-node-5f76cf6ccf-br9b5   1/1       Running   0          1m

  4. رویدادهای کلاستر را مشاهده کنید:

    kubectl get events

  5. پیکربندی kubectl را مشاهده کنید:

    kubectl config view

  6. لاگ‌های برنامهٔ یک کانتینر را در یک Pod مشاهده کنید (نام Pod را با نامی که از kubectl get pods به دست آوردید جایگزین کنید).

Note

در دستور kubectl logs، عبارت hello-node-5f76cf6ccf-br9b5 را با نام Pod در خروجی دستور kubectl get pods جایگزین کنید.

kubectl logs hello-node-5f76cf6ccf-br9b5

خروجی مشابه زیر است:

I0911 09:19:26.677397       1 log.go:195] Started HTTP server on port 8080
I0911 09:19:26.677586       1 log.go:195] Started UDP server on port  8081
Note

برای اطلاعات بیشتر دربارهٔ دستورهای kubectl، مروری بر kubectl را ببینید.

ایجاد یک Service

به‌طور پیش‌فرض، Pod فقط از طریق نشانی IP داخلی خود و از درون کلاستر کوبرنتیز در دسترس است. برای اینکه کانتینر hello-node از بیرون شبکهٔ مجازی کوبرنتیز در دسترس باشد، باید Pod را در قالب یک Service کوبرنتیز در معرض دسترسی قرار دهید.

Warning

کانتینر agnhost یک endpoint با مسیر /shell دارد که برای اشکال‌زدایی مفید است، اما قرار دادن آن در معرض اینترنت عمومی خطرناک است. این کانتینر را روی کلاستری که به اینترنت دسترسی دارد یا روی کلاستر عملیاتی اجرا نکنید.

  1. با استفاده از دستور kubectl expose، Pod را در معرض اینترنت عمومی قرار دهید:

    kubectl expose deployment hello-node --type=LoadBalancer --port=8080

    فلگ --type=LoadBalancer نشان می‌دهد که می‌خواهید Service خود را بیرون از کلاستر در دسترس قرار دهید.

    کد برنامه در ایمیج آزمایشی فقط به پورت TCP شمارهٔ 8080 گوش می‌دهد. اگر با kubectl expose پورت دیگری را در معرض دسترسی قرار دهید، کلاینت‌ها نمی‌توانند به آن پورت متصل شوند.

  2. Service ایجادشده را مشاهده کنید:

    kubectl get services

    خروجی مشابه زیر است:

    NAME         TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)          AGE
hello-node   LoadBalancer   10.108.144.78   <pending>     8080:30369/TCP   21s
kubernetes   ClusterIP      10.96.0.1       <none>        443/TCP          23m

    در ارائه‌دهندگان ابری که از متعادل‌کننده‌های بار (load balancer) پشتیبانی می‌کنند، یک نشانی IP خارجی برای دسترسی به Service تخصیص داده می‌شود. در minikube، نوع LoadBalancer باعث می‌شود Service از طریق دستور minikube service در دسترس باشد.

  3. دستور زیر را اجرا کنید:

    minikube service hello-node

    با این دستور، یک پنجرهٔ مرورگر باز می‌شود که برنامهٔ شما را ارائه می‌دهد و پاسخ برنامه را نشان می‌دهد.

فعال کردن افزونه‌ها

ابزار minikube شامل مجموعه‌ای از افزونه‌های داخلی است که می‌توان آن‌ها را در محیط محلی کوبرنتیز فعال، غیرفعال و باز کرد.

  1. افزونه‌هایی را که در حال حاضر پشتیبانی می‌شوند فهرست کنید:

    minikube addons list

    خروجی مشابه زیر است:

    addon-manager: enabled
dashboard: enabled
default-storageclass: enabled
efk: disabled

gvisor: disabled
helm-tiller: disabled
ingress: disabled

metrics-server: disabled
nvidia-driver-installer: disabled
nvidia-gpu-device-plugin: disabled
registry: disabled
registry-creds: disabled
storage-provisioner: enabled
storage-provisioner-gluster: disabled

  2. یک افزونه، برای مثال metrics-server، را فعال کنید:

    minikube addons enable metrics-server

    خروجی مشابه زیر است:

    The 'metrics-server' addon is enabled

  3. Pod و Serviceای را که با نصب این افزونه ایجاد شده‌اند مشاهده کنید:

    kubectl get pod,svc -n kube-system

    خروجی مشابه زیر است:

    kubectl top pods

    خروجی مشابه زیر است:

    error: Metrics API not available

  5. افزونهٔ metrics-server را غیرفعال کنید:

    minikube addons disable metrics-server

    خروجی مشابه زیر است:

    metrics-server was successfully disabled

پاک‌سازی

اکنون می‌توانید منابعی را که در کلاستر خود ایجاد کرده‌اید پاک کنید:

kubectl delete service hello-node
kubectl delete deployment hello-node

کلاستر Minikube را متوقف کنید:

minikube stop

در صورت تمایل، ماشین مجازی Minikube را حذف کنید:

# Optional
minikube delete

اگر می‌خواهید برای یادگیری بیشتر دربارهٔ کوبرنتیز دوباره از minikube استفاده کنید، نیازی به حذف آن ندارید.

جمع‌بندی

در این صفحه، جنبه‌های اصلی راه‌اندازی و اجرای یک کلاستر minikube پوشش داده شد. اکنون آماده‌اید که برنامه‌ها را مستقر کنید.

گام‌های بعدی

  • آموزش استقرار نخستین برنامهٔ خود روی کوبرنتیز با kubectl.
  • دربارهٔ آبجکت‌های Deployment بیشتر بیاموزید.
  • دربارهٔ استقرار برنامه‌ها بیشتر بیاموزید.
  • دربارهٔ آبجکت‌های Service بیشتر بیاموزید.
