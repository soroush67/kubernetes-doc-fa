پیکربندی سهمیه‌های حافظه و CPU برای یک فضای نام

محدودیت‌های کلی منابع حافظه و CPU را برای یک فضای نام تعریف کنید.

این صفحه نشان می‌دهد که چگونه برای مجموع حافظه و CPU قابل استفاده توسط همهٔ Podهای در حال اجرا در یک فضای نام سهمیه (quota) تعیین کنید. سهمیه‌ها را در یک آبجکت ResourceQuota مشخص می‌کنید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

باید دسترسی ایجاد فضای نام در کلاستر خود را داشته باشید.

هر نود در کلاستر شما باید دست‌کم ۱ GiB حافظه داشته باشد.

ایجاد یک فضای نام

یک فضای نام ایجاد کنید تا منابعی که در این تمرین می‌سازید از بقیهٔ کلاستر شما جدا بمانند.

kubectl create namespace quota-mem-cpu-example

ایجاد یک ResourceQuota

در ادامه مانیفست یک ResourceQuota نمونه آمده است:

admin/resource/quota-mem-cpu.yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: mem-cpu-demo
spec:
  hard:
    requests.cpu: "1"
    requests.memory: 1Gi
    limits.cpu: "2"
    limits.memory: 2Gi

ResourceQuota را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/admin/resource/quota-mem-cpu.yaml --namespace=quota-mem-cpu-example

اطلاعات دقیق ResourceQuota را مشاهده کنید:

kubectl get resourcequota mem-cpu-demo --namespace=quota-mem-cpu-example --output=yaml

این ResourceQuota الزامات زیر را بر فضای نام quota-mem-cpu-example اعمال می‌کند:

  • برای هر Pod در این فضای نام، هر کانتینر باید درخواست حافظه، حد حافظه، درخواست CPU و حد CPU داشته باشد.
  • مجموع درخواست‌های حافظهٔ همهٔ Podهای آن فضای نام نباید از ۱ GiB بیشتر شود.
  • مجموع حدهای حافظهٔ همهٔ Podهای آن فضای نام نباید از ۲ GiB بیشتر شود.
  • مجموع درخواست‌های CPU همهٔ Podهای آن فضای نام نباید از ۱ CPU بیشتر شود.
  • مجموع حدهای CPU همهٔ Podهای آن فضای نام نباید از ۲ CPU بیشتر شود.

برای آشنایی با منظور کوبرنتیز از «۱ CPU»، بخش معنای CPU را ببینید.

ایجاد یک Pod

در ادامه مانیفست یک Pod نمونه آمده است:

admin/resource/quota-mem-cpu-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: quota-mem-cpu-demo
spec:
  containers:
  - name: quota-mem-cpu-demo-ctr
    image: nginx
    resources:
      limits:
        memory: "800Mi"
        cpu: "800m"
      requests:
        memory: "600Mi"
        cpu: "400m"

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/admin/resource/quota-mem-cpu-pod.yaml --namespace=quota-mem-cpu-example

بررسی کنید که Pod در حال اجرا باشد و تنها کانتینر آن سالم باشد:

kubectl get pod quota-mem-cpu-demo --namespace=quota-mem-cpu-example

بار دیگر اطلاعات دقیق ResourceQuota را مشاهده کنید:

kubectl get resourcequota mem-cpu-demo --namespace=quota-mem-cpu-example --output=yaml

خروجی، سهمیه را همراه با میزان مصرف‌شده از آن نشان می‌دهد. می‌بینید که درخواست‌ها و حدهای حافظه و CPU مربوط به Pod شما از سهمیه فراتر نمی‌روند.

status:
  hard:
    limits.cpu: "2"
    limits.memory: 2Gi
    requests.cpu: "1"
    requests.memory: 1Gi
  used:
    limits.cpu: 800m
    limits.memory: 800Mi
    requests.cpu: 400m
    requests.memory: 600Mi

اگر ابزار jq را در اختیار دارید، می‌توانید فقط مقادیر used را (با استفاده از JSONPath) پرس‌وجو کنید و خروجی را به شکلی خوانا نمایش دهید. برای مثال:

kubectl get resourcequota mem-cpu-demo --namespace=quota-mem-cpu-example -o jsonpath='{ .status.used }' | jq .

تلاش برای ایجاد Pod دوم

در ادامه مانیفست Pod دوم آمده است:

admin/resource/quota-mem-cpu-pod-2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: quota-mem-cpu-demo-2
spec:
  containers:
  - name: quota-mem-cpu-demo-2-ctr
    image: redis
    resources:
      limits:
        memory: "1Gi"
        cpu: "800m"
      requests:
        memory: "700Mi"
        cpu: "400m"

در این مانیفست می‌بینید که Pod درخواست حافظه‌ای برابر با ۷۰۰ MiB دارد. توجه کنید که مجموع درخواست حافظهٔ مصرف‌شده و این درخواست حافظهٔ جدید از سهمیهٔ درخواست حافظه بیشتر است: 600 MiB + 700 MiB > 1 GiB.

برای ایجاد Pod تلاش کنید:

kubectl apply -f https://k8s.io/examples/admin/resource/quota-mem-cpu-pod-2.yaml --namespace=quota-mem-cpu-example

Pod دوم ایجاد نمی‌شود. خروجی نشان می‌دهد که ایجاد Pod دوم باعث می‌شد مجموع درخواست‌های حافظه از سهمیهٔ درخواست حافظه فراتر رود.

Error from server (Forbidden): error when creating "examples/admin/resource/quota-mem-cpu-pod-2.yaml":
pods "quota-mem-cpu-demo-2" is forbidden: exceeded quota: mem-cpu-demo,
requested: requests.memory=700Mi,used: requests.memory=600Mi, limited: requests.memory=1Gi

بحث

همان‌طور که در این تمرین دیدید، می‌توانید با یک ResourceQuota مجموع درخواست‌های حافظهٔ همهٔ Podهای در حال اجرا در یک فضای نام را محدود کنید. همچنین می‌توانید مجموع حدهای حافظه، درخواست‌های CPU و حدهای CPU را نیز محدود کنید.

ممکن است به‌جای مدیریت مجموع مصرف منابع در یک فضای نام، بخواهید تک‌تک Podها یا کانتینرهای درون آن‌ها را محدود کنید. برای چنین محدودسازی‌ای از یک LimitRange استفاده کنید.

توجه:

هنگام استفاده از تغییر اندازهٔ درجای Pod، اعمال ResourceQuota روی مقادیر تغییریافته انجام می‌شود. اگر تغییر اندازه باعث شود فضای نام از حدهای سهمیهٔ خود فراتر رود، تغییر اندازه رد می‌شود و منابع Pod بدون تغییر باقی می‌مانند.

پاک‌سازی

فضای نام خود را حذف کنید:

kubectl delete namespace quota-mem-cpu-example

گام‌های بعدی

برای مدیران کلاستر

  • پیکربندی درخواست‌ها و حدهای پیش‌فرض حافظه برای یک فضای نام

  • پیکربندی درخواست‌ها و حدهای پیش‌فرض CPU برای یک فضای نام

  • پیکربندی محدودیت‌های کمینه و بیشینهٔ حافظه برای یک فضای نام

  • پیکربندی محدودیت‌های کمینه و بیشینهٔ CPU برای یک فضای نام

  • پیکربندی سهمیهٔ Pod برای یک فضای نام

  • پیکربندی سهمیه برای آبجکت‌های API

برای توسعه‌دهندگان برنامه

  • تخصیص منابع حافظه به کانتینرها و Podها

  • تخصیص منابع CPU به کانتینرها و Podها

  • تخصیص منابع CPU و حافظه در سطح Pod

  • پیکربندی کیفیت سرویس برای Podها
