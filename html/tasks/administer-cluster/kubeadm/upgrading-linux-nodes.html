ارتقای نودهای لینوکسی

این صفحه نحوهٔ ارتقای نودهای کارگر (Worker Nodes) لینوکسیِ ایجادشده با kubeadm را توضیح می‌دهد.

پیش از شروع

باید به همه نودها دسترسی shell داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند.

  • با فرایند ارتقای بقیهٔ کلاستر kubeadm خود آشنا شوید. لازم است پیش از ارتقای نودهای کارگر لینوکسی، نودهای control plane را ارتقا دهید.

تغییر مخزن بسته‌ها

اگر از مخازن بستهٔ متعلق به جامعه (pkgs.k8s.io) استفاده می‌کنید، باید مخزن بستهٔ مربوط به نسخهٔ فرعی (minor) موردنظر کوبرنتیز را فعال کنید. این کار در سند تغییر مخزن بستهٔ کوبرنتیز توضیح داده شده است.

ارتقای نودهای کارگر

ارتقای kubeadm و kubectl

ابزارهای kubeadm و kubectl را ارتقا دهید:

توجه:

طبق سیاست اختلاف نسخه، نسخهٔ kubectl باید حداکثر یک نسخهٔ فرعی با kube-apiserver فاصله داشته باشد. اگر پیش از ارتقای نودهای کارگر، control plane را چند نسخهٔ فرعی ارتقا می‌دهید، ممکن است kubectl محلیِ نود از محدودهٔ اختلاف مجاز خارج شود. ارتقای هم‌زمان kubectl و kubeadm در این مرحله تضمین می‌کند که kubectl در تمام طول فرایند ارتقای نود در محدودهٔ نسخه‌های پشتیبانی‌شده باقی بماند.

Ubuntu، Debian یا HypriotOS
# replace x in 1.37.x-* with the latest patch version
sudo apt-mark unhold kubeadm kubectl && \
sudo apt-get update && sudo apt-get install -y kubeadm='1.37.x-*' kubectl='1.37.x-*' && \
sudo apt-mark hold kubeadm kubectl
CentOS، RHEL یا Fedora

برای سیستم‌های دارای DNF4 (Fedora < 41، RHEL/Centos < 10):

# replace x in 1.37.x-* with the latest patch version
sudo dnf install -y kubeadm-'1.37.x-*' kubectl-'1.37.x-*' --disableexcludes=kubernetes

برای سیستم‌های دارای DNF5:

# replace x in 1.37.x-* with the latest patch version
sudo dnf install -y kubeadm-'1.37.x-*' kubectl-'1.37.x-*' --setopt=disable_excludes=kubernetes

اجرای «kubeadm upgrade»

در نودهای کارگر، این دستور پیکربندی محلی kubelet را ارتقا می‌دهد:

sudo kubeadm upgrade node

تخلیهٔ نود

نود را با علامت‌گذاری به‌عنوان غیرقابل‌زمان‌بندی و بیرون‌راندن بارهای کاری، برای نگهداری آماده کنید:

# execute this command on a control plane node
# replace <node-to-drain> with the name of your node you are draining
kubectl drain <node-to-drain> --ignore-daemonsets

ارتقای kubelet

  1. ابزار kubelet را ارتقا دهید:
Ubuntu، Debian یا HypriotOS
# replace x in 1.37.x-* with the latest patch version
sudo apt-mark unhold kubelet && \
sudo apt-get update && sudo apt-get install -y kubelet='1.37.x-*' && \
sudo apt-mark hold kubelet
CentOS، RHEL یا Fedora

برای سیستم‌های دارای DNF4 (Fedora < 41، RHEL/CentOS < 10):

# replace x in 1.37.x-* with the latest patch version
sudo dnf install -y kubelet-'1.37.x-*' --disableexcludes=kubernetes

برای سیستم‌های دارای DNF5:

# replace x in 1.37.x-* with the latest patch version
sudo dnf install -y kubelet-'1.37.x-*' --setopt=disable_excludes=kubernetes

  1. ابزار kubelet را مجدداً راه‌اندازی کنید:

    sudo systemctl daemon-reload
sudo systemctl restart kubelet

خارج‌کردن نود از حالت cordon

نود را با علامت‌گذاری به‌عنوان قابل‌زمان‌بندی، دوباره به چرخهٔ کار برگردانید:

# execute this command on a control plane node
# replace <node-to-uncordon> with the name of your node
kubectl uncordon <node-to-uncordon>
