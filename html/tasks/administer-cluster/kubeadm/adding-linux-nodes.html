افزودن نودهای کارگر لینوکسی

این صفحه نحوهٔ افزودن نودهای کارگر (worker node) لینوکسی به یک کلاستر kubeadm را توضیح می‌دهد.

پیش از شروع

  • روی هر نود کارگری که به کلاستر می‌پیوندد، اجزای لازم مطابق راهنمای نصب kubeadm نصب شده باشد؛ از جمله kubeadm، kubelet و یک محیط اجرای کانتینر.
  • یک کلاستر kubeadm در حال اجرا که با kubeadm init و طبق مراحل سند ایجاد کلاستر با kubeadm ایجاد شده باشد.
  • به دسترسی کاربر ارشد (superuser) روی نود نیاز دارید.

افزودن نودهای کارگر لینوکسی

برای افزودن نودهای کارگر لینوکسی جدید به کلاستر، کارهای زیر را برای هر ماشین انجام دهید:

  1. با استفاده از SSH یا روشی دیگر به ماشین متصل شوید.
  2. دستوری را که kubeadm init در خروجی خود نمایش داده است اجرا کنید. برای مثال:
sudo kubeadm join --token <token> <control-plane-host>:<control-plane-port> --discovery-token-ca-cert-hash sha256:<hash>

اطلاعات تکمیلی دربارهٔ kubeadm join

توجه:

برای تعیین یک زوج IPv6 به‌جای <control-plane-host>:<control-plane-port>، نشانی IPv6 باید داخل کروشه قرار گیرد؛ برای مثال: [2001:db8::101]:2073.

اگر توکن را در اختیار ندارید، می‌توانید آن را با اجرای دستور زیر روی نود control plane به دست آورید:

# Run this on a control plane node
sudo kubeadm token list

خروجی مشابه زیر است:

TOKEN                    TTL  EXPIRES              USAGES           DESCRIPTION            EXTRA GROUPS
8ewj1p.9r9hcjoqgajrj4gi  23h  2018-06-12T02:51:28Z authentication,  The default bootstrap  system:
                                                   signing          token generated by     bootstrappers:
                                                                    'kubeadm init'.        kubeadm:
                                                                                           default-node-token

توکن‌های پیوستن نود به‌طور پیش‌فرض پس از ۲۴ ساعت منقضی می‌شوند. اگر پس از منقضی شدن توکن فعلی نودی را به کلاستر اضافه می‌کنید، می‌توانید با اجرای دستور زیر روی نود control plane یک توکن جدید ایجاد کنید:

# Run this on a control plane node
sudo kubeadm token create

خروجی مشابه زیر است:

5didvk.d09sbcov8ph2amjw

برای چاپ دستور kubeadm join و هم‌زمان تولید یک توکن جدید، می‌توانید از دستور زیر استفاده کنید:

sudo kubeadm token create --print-join-command

اگر مقدار --discovery-token-ca-cert-hash را ندارید، می‌توانید آن را با اجرای دستورهای زیر روی نود control plane به دست آورید:

# Run this on a control plane node
sudo cat /etc/kubernetes/pki/ca.crt | openssl x509 -pubkey  | openssl rsa -pubin -outform der 2>/dev/null | \
   openssl dgst -sha256 -hex | sed 's/^.* //'

خروجی مشابه زیر است:

8cb2de97839780a412b93877f8507ad6c94f73add17d5d7058e91741c9d5ec78

خروجی دستور kubeadm join باید تقریباً به این شکل باشد:

[preflight] Running pre-flight checks

... (log output of join workflow) ...

Node join complete:
* Certificate signing request sent to control-plane and response
  received.
* Kubelet informed of new secure connection details.

Run 'kubectl get nodes' on control-plane to see this machine join.

چند ثانیه بعد، باید این نود را در خروجی kubectl get nodes ببینید (برای مثال، kubectl را روی یک نود control plane اجرا کنید).

توجه:

از آنجا که نودهای کلاستر معمولاً به‌ترتیب راه‌اندازی می‌شوند، احتمالاً همهٔ Podهای CoreDNS روی نخستین نود control plane اجرا می‌شوند. برای دستیابی به دسترس‌پذیری بالاتر، پس از پیوستن دست‌کم یک نود جدید، Podهای CoreDNS را با دستور kubectl -n kube-system rollout restart deployment coredns دوباره توزیع کنید.

گام‌های بعدی

  • ببینید چگونه می‌توان نودهای کارگر ویندوزی را اضافه کرد.
