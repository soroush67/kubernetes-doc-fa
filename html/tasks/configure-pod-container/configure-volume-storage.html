پیکربندی یک Pod برای استفاده از حجم (Volume) به‌منظور ذخیره‌سازی

این صفحه نشان می‌دهد که چگونه یک Pod را پیکربندی کنید تا برای ذخیره‌سازی از یک حجم (Volume) استفاده کند.

سیستم فایل هر کانتینر فقط تا زمانی وجود دارد که خود کانتینر وجود داشته باشد. بنابراین وقتی یک کانتینر خاتمه می‌یابد و دوباره راه‌اندازی می‌شود، تغییرات سیستم فایل از بین می‌روند. برای ذخیره‌سازی پایدارتری که مستقل از کانتینر باشد، می‌توانید از یک حجم استفاده کنید. این موضوع به‌ویژه برای برنامه‌های حالت‌مند (stateful)، مانند مخازن کلید-مقدار (مثلاً Redis) و پایگاه‌های داده، اهمیت دارد.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

پیکربندی یک حجم برای Pod

در این تمرین، یک Pod می‌سازید که یک کانتینر را اجرا می‌کند. این Pod یک حجم از نوع emptyDir دارد که در تمام طول عمر Pod باقی می‌ماند، حتی اگر کانتینر خاتمه یابد و دوباره راه‌اندازی شود. فایل پیکربندی Pod در ادامه آمده است:

pods/storage/redis.yaml
apiVersion: v1
kind: Pod
metadata:
  name: redis
spec:
  containers:
  - name: redis
    image: redis
    volumeMounts:
    - name: redis-storage
      mountPath: /data/redis
  volumes:
  - name: redis-storage
    emptyDir: {}

  1. Pod را ایجاد کنید:

    kubectl apply -f https://k8s.io/examples/pods/storage/redis.yaml

  2. بررسی کنید که کانتینر Pod در حال اجرا باشد و سپس تغییرات Pod را زیر نظر بگیرید:

    kubectl get pod redis --watch

    خروجی به این شکل است:

    NAME      READY     STATUS    RESTARTS   AGE
redis     1/1       Running   0          13s

  3. در یک ترمینال دیگر، یک پوسته (shell) در کانتینر در حال اجرا باز کنید:

    kubectl exec -it redis -- /bin/bash

  4. در پوسته، به مسیر /data/redis بروید و سپس یک فایل ایجاد کنید:

    root@redis:/data# cd /data/redis/
root@redis:/data/redis# echo Hello > test-file

  5. در پوسته، فرایندهای در حال اجرا را فهرست کنید:

    root@redis:/data/redis# apt-get update
root@redis:/data/redis# apt-get install procps
root@redis:/data/redis# ps aux

    خروجی مشابه این است:

    USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
redis        1  0.1  0.1  33308  3828 ?        Ssl  00:46   0:00 redis-server *:6379
root        12  0.0  0.0  20228  3020 ?        Ss   00:47   0:00 /bin/bash
root        15  0.0  0.0  17500  2072 ?        R+   00:48   0:00 ps aux

  6. در پوسته، فرایند Redis را متوقف (kill) کنید:

    root@redis:/data/redis# kill <pid>

    که در آن <pid> شناسه فرایند (PID) مربوط به Redis است.

  7. در ترمینال اصلی، تغییرات Pod مربوط به Redis را زیر نظر بگیرید. پس از مدتی، چیزی شبیه به این خواهید دید:

    NAME      READY     STATUS     RESTARTS   AGE
redis     1/1       Running    0          13s
redis     0/1       Completed  0         6m
redis     1/1       Running    1         6m

در این مرحله، کانتینر خاتمه یافته و دوباره راه‌اندازی شده است. علت این است که مقدار restartPolicy در Pod مربوط به Redis برابر با Always است.

  1. یک پوسته در کانتینرِ دوباره راه‌اندازی‌شده باز کنید:

    kubectl exec -it redis -- /bin/bash

  2. در پوسته، به مسیر /data/redis بروید و بررسی کنید که فایل test-file هنوز آنجا باشد.

    root@redis:/data/redis# cd /data/redis/
root@redis:/data/redis# ls
test-file

  3. Pod‌ای را که برای این تمرین ایجاد کرده‌اید حذف کنید:

    kubectl delete pod redis

گام‌های بعدی

  • مرجع Volume را ببینید.

  • مرجع Pod را ببینید.

  • کوبرنتیز علاوه بر ذخیره‌سازی روی دیسک محلی که emptyDir فراهم می‌کند، از راهکارهای متنوع ذخیره‌سازی متصل به شبکه نیز پشتیبانی می‌کند؛ از جمله PD در GCE و EBS در EC2. این راهکارها برای داده‌های حیاتی ترجیح داده می‌شوند و جزئیاتی مانند متصل‌کردن (mount) و جداکردن (unmount) دستگاه‌ها روی نودها را خودشان مدیریت می‌کنند. برای جزئیات بیشتر، حجم‌ها را ببینید.
