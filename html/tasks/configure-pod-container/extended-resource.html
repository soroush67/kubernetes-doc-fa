تخصیص منابع توسعه‌یافته به یک کانتینر

وضعیت ویژگی: Kubernetes [stable] (پایدار)

این صفحه نشان می‌دهد که چگونه می‌توانید منابع توسعه‌یافته (extended resources) را به یک کانتینر تخصیص دهید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

پیش از انجام این تمرین، تمرین اعلام منابع توسعه‌یافته برای یک نود را انجام دهید. با انجام آن تمرین، یکی از نودهای شما طوری پیکربندی می‌شود که یک منبع dongle را اعلام کند.

تخصیص یک منبع توسعه‌یافته به یک Pod

برای درخواست یک منبع توسعه‌یافته، فیلد resources.requests.<resource_name> را در مانیفست کانتینر قرار دهید. *.kubernetes.io/. نام‌های معتبر منابع توسعه‌یافته به شکل example.com/foo هستند که در آن به جای example.com دامنهٔ سازمان شما و به جای foo یک نام توصیفی برای منبع قرار می‌گیرد.

فایل پیکربندی یک Pod که یک کانتینر دارد در ادامه آمده است:

pods/resource/extended-resource-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: extended-resource-demo
spec:
  containers:
  - name: extended-resource-demo-ctr
    image: nginx
    resources:
      requests:
        example.com/dongle: 3
      limits:
        example.com/dongle: 3

در این فایل پیکربندی می‌بینید که کانتینر ۳ dongle درخواست می‌کند.

یک Pod ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/resource/extended-resource-pod.yaml

بررسی کنید که Pod در حال اجرا باشد:

kubectl get pod extended-resource-demo

جزئیات Pod را مشاهده کنید:

kubectl describe pod extended-resource-demo

خروجی، درخواست‌های dongle را نشان می‌دهد:

Limits:
  example.com/dongle: 3
Requests:
  example.com/dongle: 3

تلاش برای ایجاد Pod دوم

فایل پیکربندی یک Pod که یک کانتینر دارد در ادامه آمده است. این کانتینر دو dongle درخواست می‌کند.

pods/resource/extended-resource-pod-2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: extended-resource-demo-2
spec:
  containers:
  - name: extended-resource-demo-2-ctr
    image: nginx
    resources:
      requests:
        example.com/dongle: 2
      limits:
        example.com/dongle: 2

کوبرنتیز نمی‌تواند درخواست دو dongle را برآورده کند، زیرا Pod اول سه dongle از چهار dongle موجود را استفاده کرده است.

برای ایجاد Pod تلاش کنید:

kubectl apply -f https://k8s.io/examples/pods/resource/extended-resource-pod-2.yaml

جزئیات Pod را مشاهده کنید:

kubectl describe pod extended-resource-demo-2

خروجی نشان می‌دهد که Pod زمان‌بندی نمی‌شود، زیرا هیچ نودی وجود ندارد که ۲ dongle در دسترس داشته باشد:

Conditions:
  Type    Status
  PodScheduled  False
...
Events:
  ...
  ... Warning   FailedScheduling  pod (extended-resource-demo-2) failed to fit in any node
fit failure summary on nodes : Insufficient example.com/dongle (1)

وضعیت Pod را مشاهده کنید:

kubectl get pod extended-resource-demo-2

خروجی نشان می‌دهد که Pod ایجاد شده، اما برای اجرا روی هیچ نودی زمان‌بندی نشده است. وضعیت آن Pending است:

NAME                       READY     STATUS    RESTARTS   AGE
extended-resource-demo-2   0/1       Pending   0          6m

پاک‌سازی

Podهایی را که برای این تمرین ایجاد کرده‌اید حذف کنید:

kubectl delete pod extended-resource-demo
kubectl delete pod extended-resource-demo-2

منابع توسعه‌یافته مبتنی بر DRA

وضعیت ویژگی: Kubernetes [] ()

تمرین بالا از یک منبع توسعه‌یافته استفاده می‌کند که یک نود آن را اعلام می‌کند. منابع توسعه‌یافته را می‌توان با تخصیص پویای منابع (DRA) نیز فراهم کرد: در این حالت، یک DeviceClass مقدار extendedResourceName را تعیین می‌کند و زمان‌بند درخواست‌های منطبق برای منابع توسعه‌یافته را به جای ظرفیت اعلام‌شده توسط نود، با دستگاه‌های DRA برآورده می‌کند.

یک Pod در هر دو حالت منبع را به یک شکل درخواست می‌کند، یعنی از طریق resources.requests.<resource_name>؛ بنابراین بار کاری نیازی ندارد بداند که این منبع را یک افزونهٔ دستگاه (device plugin) فراهم می‌کند یا DRA. حتی ممکن است یک نام منبع واحد روی برخی نودها با افزونهٔ دستگاه و روی نودهای دیگر با DRA فراهم شود.

برای راه‌اندازی DeviceClass و دیدن نمونه‌ها، به تخصیص منابع توسعه‌یافته با DRA مراجعه کنید.

گام‌های بعدی

برای توسعه‌دهندگان برنامه

  • تخصیص منابع حافظه به کانتینرها و Podها
  • تخصیص منابع CPU به کانتینرها و Podها

برای مدیران کلاستر

  • اعلام منابع توسعه‌یافته برای یک نود
