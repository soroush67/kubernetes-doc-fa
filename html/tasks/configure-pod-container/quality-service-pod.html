پیکربندی کیفیت سرویس برای Podها

این صفحه نشان می‌دهد که چگونه Podها را طوری پیکربندی کنید که کلاس‌های کیفیت سرویس (QoS) مشخصی به آن‌ها اختصاص یابد. کوبرنتیز از کلاس‌های QoS برای تصمیم‌گیری دربارهٔ بیرون‌راندن (evict) Podها در زمانی استفاده می‌کند که مصرف منابع نود از حد مجاز فراتر رود.

کوبرنتیز هنگام ایجاد یک Pod، یکی از کلاس‌های QoS زیر را به آن اختصاص می‌دهد:

  • Guaranteed
  • Burstable
  • BestEffort
توجه:

کوبرنتیز کلاس QoS را هنگام ایجاد Pod اختصاص می‌دهد و این کلاس در تمام طول عمر Pod بدون تغییر باقی می‌ماند. اگر بخواهید منابع Pod را تغییر اندازه دهید و مقادیر جدید به کلاس QoS متفاوتی منجر شوند، control plane درخواست شما را با یک پیام خطا رد می‌کند.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

همچنین باید بتوانید فضاهای نام (namespace) را ایجاد و حذف کنید.

ایجاد یک فضای نام

یک فضای نام ایجاد کنید تا منابعی که در این تمرین می‌سازید از بقیهٔ کلاستر شما جدا بمانند.

kubectl create namespace qos-example

ایجاد یک Pod با کلاس QoS از نوع Guaranteed

برای اینکه کلاس QoS یک Pod از نوع Guaranteed باشد:

  • هر کانتینر در Pod باید یک حد (limit) حافظه و یک درخواست (request) حافظه داشته باشد.
  • برای هر کانتینر در Pod، حد حافظه باید با درخواست حافظه برابر باشد.
  • هر کانتینر در Pod باید یک حد CPU و یک درخواست CPU داشته باشد.
  • برای هر کانتینر در Pod، حد CPU باید با درخواست CPU برابر باشد.

این محدودیت‌ها به‌طور یکسان برای کانتینرهای init و کانتینرهای برنامه اعمال می‌شوند. کانتینرهای موقت نمی‌توانند منابع تعریف کنند، بنابراین این محدودیت‌ها شامل آن‌ها نمی‌شود.

در ادامه مانیفست یک Pod با یک کانتینر آمده است. این کانتینر یک حد حافظه و یک درخواست حافظه دارد که هر دو برابر با 200 MiB هستند. همچنین یک حد CPU و یک درخواست CPU دارد که هر دو برابر با 700 میلی‌CPU هستند:

pods/qos/qos-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: qos-demo
  namespace: qos-example
spec:
  containers:
  - name: qos-demo-ctr
    image: nginx
    resources:
      limits:
        memory: "200Mi"
        cpu: "700m"
      requests:
        memory: "200Mi"
        cpu: "700m"

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/qos/qos-pod.yaml --namespace=qos-example

اطلاعات تفصیلی Pod را مشاهده کنید:

kubectl get pod qos-demo --namespace=qos-example --output=yaml

خروجی نشان می‌دهد که کوبرنتیز کلاس QoS از نوع Guaranteed را به Pod داده است. خروجی همچنین تأیید می‌کند که درخواست حافظهٔ کانتینر Pod با حد حافظهٔ آن و درخواست CPU آن با حد CPU آن برابر است.

spec:
  containers:
    ...
    resources:
      limits:
        cpu: 700m
        memory: 200Mi
      requests:
        cpu: 700m
        memory: 200Mi
    ...
status:
  qosClass: Guaranteed
توجه:

اگر یک کانتینر حد حافظهٔ خود را مشخص کند اما درخواست حافظه را مشخص نکند، کوبرنتیز به‌طور خودکار یک درخواست حافظه برابر با آن حد اختصاص می‌دهد. به همین ترتیب، اگر یک کانتینر حد CPU خود را مشخص کند اما درخواست CPU را مشخص نکند، کوبرنتیز به‌طور خودکار یک درخواست CPU برابر با آن حد اختصاص می‌دهد.

پاک‌سازی {#clean-up-guaranteed}

Pod خود را حذف کنید:

kubectl delete pod qos-demo --namespace=qos-example

ایجاد یک Pod با کلاس QoS از نوع Burstable

کلاس QoS یک Pod در صورتی Burstable است که:

  • آن Pod معیارهای کلاس QoS از نوع Guaranteed را نداشته باشد.
  • دست‌کم یکی از کانتینرهای Pod درخواست یا حد حافظه یا CPU داشته باشد.

در ادامه مانیفست یک Pod با یک کانتینر آمده است. این کانتینر حد حافظهٔ 200 MiB و درخواست حافظهٔ 100 MiB دارد.

pods/qos/qos-pod-2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: qos-demo-2
  namespace: qos-example
spec:
  containers:
  - name: qos-demo-2-ctr
    image: nginx
    resources:
      limits:
        memory: "200Mi"
      requests:
        memory: "100Mi"

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/qos/qos-pod-2.yaml --namespace=qos-example

اطلاعات تفصیلی Pod را مشاهده کنید:

kubectl get pod qos-demo-2 --namespace=qos-example --output=yaml

خروجی نشان می‌دهد که کوبرنتیز کلاس QoS از نوع Burstable را به Pod داده است:

spec:
  containers:
  - image: nginx
    imagePullPolicy: Always
    name: qos-demo-2-ctr
    resources:
      limits:
        memory: 200Mi
      requests:
        memory: 100Mi
  ...
status:
  qosClass: Burstable

پاک‌سازی {#clean-up-burstable}

Pod خود را حذف کنید:

kubectl delete pod qos-demo-2 --namespace=qos-example

ایجاد یک Pod با کلاس QoS از نوع BestEffort

برای اینکه کلاس QoS یک Pod از نوع BestEffort باشد، کانتینرهای آن Pod نباید هیچ حد یا درخواست حافظه یا CPU داشته باشند.

در ادامه مانیفست یک Pod با یک کانتینر آمده است. این کانتینر هیچ حد یا درخواست حافظه یا CPU ندارد:

pods/qos/qos-pod-3.yaml
apiVersion: v1
kind: Pod
metadata:
  name: qos-demo-3
  namespace: qos-example
spec:
  containers:
  - name: qos-demo-3-ctr
    image: nginx

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/qos/qos-pod-3.yaml --namespace=qos-example

اطلاعات تفصیلی Pod را مشاهده کنید:

kubectl get pod qos-demo-3 --namespace=qos-example --output=yaml

خروجی نشان می‌دهد که کوبرنتیز کلاس QoS از نوع BestEffort را به Pod داده است:

spec:
  containers:
    ...
    resources: {}
  ...
status:
  qosClass: BestEffort

پاک‌سازی {#clean-up-besteffort}

Pod خود را حذف کنید:

kubectl delete pod qos-demo-3 --namespace=qos-example

ایجاد یک Pod با دو کانتینر

در ادامه مانیفست یک Pod با دو کانتینر آمده است. یکی از کانتینرها درخواست حافظهٔ 200 MiB را مشخص می‌کند و کانتینر دیگر هیچ درخواست یا حدی مشخص نمی‌کند.

pods/qos/qos-pod-4.yaml
apiVersion: v1
kind: Pod
metadata:
  name: qos-demo-4
  namespace: qos-example
spec:
  containers:

  - name: qos-demo-4-ctr-1
    image: nginx
    resources:
      requests:
        memory: "200Mi"

  - name: qos-demo-4-ctr-2
    image: redis

توجه کنید که این Pod معیارهای کلاس QoS از نوع Burstable را دارد؛ یعنی معیارهای کلاس QoS از نوع Guaranteed را ندارد و یکی از کانتینرهایش درخواست حافظه دارد.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/qos/qos-pod-4.yaml --namespace=qos-example

اطلاعات تفصیلی Pod را مشاهده کنید:

kubectl get pod qos-demo-4 --namespace=qos-example --output=yaml

خروجی نشان می‌دهد که کوبرنتیز کلاس QoS از نوع Burstable را به Pod داده است:

spec:
  containers:
    ...
    name: qos-demo-4-ctr-1
    resources:
      requests:
        memory: 200Mi
    ...
    name: qos-demo-4-ctr-2
    resources: {}
    ...
status:
  qosClass: Burstable

دریافت کلاس QoS یک Pod

به‌جای مشاهدهٔ همهٔ فیلدها، می‌توانید فقط فیلد مورد نیاز خود را ببینید:

kubectl --namespace=qos-example get pod qos-demo-4 -o jsonpath='{ .status.qosClass}{"\n"}'

گام‌های بعدی

برای توسعه‌دهندگان برنامه

  • اختصاص منابع حافظه به کانتینرها و Podها

  • اختصاص منابع CPU به کانتینرها و Podها

برای مدیران کلاستر

  • پیکربندی درخواست‌ها و حدهای پیش‌فرض حافظه برای یک فضای نام

  • پیکربندی درخواست‌ها و حدهای پیش‌فرض CPU برای یک فضای نام

  • پیکربندی محدودیت‌های کمینه و بیشینهٔ حافظه برای یک فضای نام

  • پیکربندی محدودیت‌های کمینه و بیشینهٔ CPU برای یک فضای نام

  • پیکربندی سهمیه‌های حافظه و CPU برای یک فضای نام

  • پیکربندی سهمیهٔ Pod برای یک فضای نام

  • پیکربندی سهمیه‌ها برای آبجکت‌های API

  • کنترل سیاست‌های مدیریت توپولوژی روی یک نود
