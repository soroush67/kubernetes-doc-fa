پردازش موازی ریزدانه با استفاده از صف کار

در این مثال، یک Job کوبرنتیز اجرا می‌کنید که چندین وظیفهٔ موازی را در قالب فرایندهای کارگر (worker) اجرا می‌کند و هر کدام از این فرایندها در یک Pod جداگانه اجرا می‌شود.

در این مثال، هر Pod پس از ایجاد شدن، یک واحد کار را از صف وظایف برمی‌دارد، آن را پردازش می‌کند و این کار را تا رسیدن به انتهای صف تکرار می‌کند.

مراحل این مثال به‌طور خلاصه به شرح زیر است:

  1. یک سرویس ذخیره‌سازی برای نگهداری صف کار راه‌اندازی کنید. در این مثال، برای ذخیرهٔ آیتم‌های کار از Redis استفاده می‌کنید. در مثال قبلی از RabbitMQ استفاده کردید. در این مثال از Redis و یک کتابخانهٔ کلاینت سفارشی برای صف کار استفاده می‌کنید، زیرا AMQP روش مناسبی در اختیار کلاینت‌ها قرار نمی‌دهد تا خالی شدن یک صف کار با طول محدود را تشخیص دهند. در عمل، یک مخزن ذخیره‌سازی مانند Redis را یک بار راه‌اندازی می‌کنید و از آن برای صف‌های کار Jobهای متعدد و کاربردهای دیگر دوباره استفاده می‌کنید.
  2. یک صف ایجاد کنید و آن را با پیام‌ها پر کنید. هر پیام نمایانگر یک وظیفه برای انجام است. در این مثال، هر پیام یک عدد صحیح است که یک محاسبهٔ طولانی روی آن انجام می‌دهیم.
  3. یک Job راه‌اندازی کنید که وظایف موجود در صف را پردازش کند. این Job چندین Pod را راه‌اندازی می‌کند. هر Pod یک وظیفه را از صف پیام برمی‌دارد، آن را پردازش می‌کند و این کار را تا رسیدن به انتهای صف تکرار می‌کند.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

به یک رجیستری ایمیج کانتینر نیاز دارید که بتوانید ایمیج‌ها را برای اجرا در کلاستر خود در آن بارگذاری کنید. این مثال از Docker Hub استفاده می‌کند، اما می‌توانید آن را برای یک رجیستری ایمیج کانتینر دیگر نیز تطبیق دهید.

همچنین فرض این مثال بر آن است که Docker را به‌صورت محلی نصب کرده‌اید. از Docker برای ساخت ایمیج‌های کانتینر استفاده می‌کنید.

با استفادهٔ پایه و غیرموازی از Job آشنا باشید.

راه‌اندازی Redis

در این مثال، برای سادگی، تنها یک نمونه از Redis را راه‌اندازی می‌کنید. برای مشاهدهٔ نمونه‌ای از استقرار Redis به‌صورت مقیاس‌پذیر و با افزونگی، به مثال Redis مراجعه کنید.

همچنین می‌توانید فایل‌های زیر را مستقیماً دانلود کنید:

  • redis-pod.yaml
  • redis-service.yaml
  • Dockerfile
  • job.yaml
  • rediswq.py
  • worker.py

برای راه‌اندازی یک نمونهٔ واحد از Redis، باید Pod و Service مربوط به redis را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/application/job/redis/redis-pod.yaml
kubectl apply -f https://k8s.io/examples/application/job/redis/redis-service.yaml

ایجاد یک ایمیج کانتینر {#create-an-image}

اکنون آماده‌اید ایمیجی بسازید که کارهای موجود در آن صف را پردازش کند.

برای خواندن پیام‌ها از صف پیام، از یک برنامهٔ کارگر پایتون همراه با یک کلاینت Redis استفاده خواهید کرد.

یک کتابخانهٔ کلاینت ساده برای صف کار Redis با نام rediswq.py (دانلود) در اختیار شما قرار گرفته است.

برنامهٔ «کارگر» در هر Pod از این Job، برای دریافت کار از کتابخانهٔ کلاینت صف کار استفاده می‌کند. کد آن در ادامه آمده است:

application/job/redis/worker.py
#!/usr/bin/env python

import time
import rediswq

host="redis"
# Uncomment next two lines if you do not have CoreDNS working.
# import os
# host = os.getenv("REDIS_SERVICE_HOST")

q = rediswq.RedisWQ(name="job2", host=host)
print("Worker with sessionID: " +  q.sessionID())
print("Initial queue state: empty=" + str(q.empty()))
while not q.empty():
  item = q.lease(lease_secs=10, block=True, timeout=2) 
  if item is not None:
    itemstr = item.decode("utf-8")
    print("Working on " + itemstr)
    time.sleep(10) # Put your actual work here instead of sleep.
    q.complete(item)
  else:
    print("Waiting for work")
print("Queue empty, exiting")

همچنین می‌توانید فایل‌های worker.py، rediswq.py و Dockerfile را دانلود کنید و سپس ایمیج کانتینر را بسازید. در ادامه نمونه‌ای از ساخت ایمیج با Docker آمده است:

docker build -t job-wq-2 .

ارسال (push) ایمیج

برای Docker Hub، ایمیج برنامهٔ خود را با نام کاربری‌تان برچسب‌گذاری (tag) کنید و با دستورهای زیر آن را به Hub ارسال کنید. به‌جای <username> نام کاربری Hub خود را قرار دهید.

docker tag job-wq-2 <username>/job-wq-2
docker push <username>/job-wq-2

باید ایمیج را به یک مخزن عمومی ارسال کنید یا کلاستر خود را طوری پیکربندی کنید که به مخزن خصوصی شما دسترسی داشته باشد.

تعریف یک Job

مانیفست Jobی که ایجاد خواهید کرد در ادامه آمده است:

application/job/redis/job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: job-wq-2
spec:
  parallelism: 2
  template:
    metadata:
      name: job-wq-2
    spec:
      containers:
      - name: c
        image: gcr.io/myproject/job-wq-2
      restartPolicy: OnFailure
توجه:

حتماً مانیفست را ویرایش کنید و gcr.io/myproject را به مسیر خودتان تغییر دهید.

در این مثال، هر Pod چندین آیتم از صف را پردازش می‌کند و هنگامی که آیتم دیگری باقی نماند، خارج می‌شود. از آنجا که خود کارگرها خالی شدن صف کار را تشخیص می‌دهند و کنترل‌کنندهٔ Job از صف کار اطلاعی ندارد، این کنترل‌کننده برای اطلاع از پایان کار به اعلام کارگرها متکی است. کارگرها با خروج موفقیت‌آمیز، خالی بودن صف را اعلام می‌کنند. بنابراین به محض اینکه هر یک از کارگرها با موفقیت خارج شود، کنترل‌کننده متوجه می‌شود که کار به پایان رسیده است و Podها به‌زودی خارج خواهند شد. از این رو، باید تعداد تکمیل (completion count) را برای Job تنظیم‌نشده باقی بگذارید. کنترل‌کنندهٔ Job منتظر می‌ماند تا Podهای دیگر نیز کار خود را به پایان برسانند.

راهکارهای جایگزین

اگر اجرای یک سرویس صف یا تغییر کانتینرها برای استفاده از صف کار برایتان دشوار است، می‌توانید یکی از دیگر الگوهای Job را در نظر بگیرید.

اگر جریان پیوسته‌ای از کارهای پردازشی پس‌زمینه برای اجرا دارید، بهتر است کارگرهای پس‌زمینهٔ خود را به‌جای Job با یک ReplicaSet اجرا کنید و استفاده از یک کتابخانهٔ پردازش پس‌زمینه مانند https://github.com/resque/resque را نیز در نظر بگیرید.
