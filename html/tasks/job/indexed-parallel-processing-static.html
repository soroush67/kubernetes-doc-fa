Job نمایه‌دار برای پردازش موازی با تخصیص ایستای کار

وضعیت ویژگی: Kubernetes v1.24 [stable] (پایدار)

در این مثال، یک Job کوبرنتیز اجرا می‌کنید که از چند فرایند کارگر (worker) موازی استفاده می‌کند. هر کارگر کانتینر جداگانه‌ای است که در Pod مخصوص به خود اجرا می‌شود. هر Pod یک شماره‌ی نمایه (index number) دارد که control plane به‌طور خودکار آن را تعیین می‌کند؛ به این ترتیب، هر Pod می‌تواند تشخیص دهد که روی کدام بخش از کل کار باید کار کند.

نمایه‌ی هر پاد در حاشیه‌نویسی batch.kubernetes.io/job-completion-index و به‌صورت رشته‌ای که مقدار دهدهی آن را نشان می‌دهد، در دسترس است. برای اینکه فرایند کانتینری‌شده‌ی کار بتواند این نمایه را دریافت کند، می‌توانید مقدار این حاشیه‌نویسی را با سازوکار downward API منتشر کنید. برای سهولت کار، control plane به‌طور خودکار downward API را طوری تنظیم می‌کند که نمایه را در متغیر محیطی JOB_COMPLETION_INDEX در اختیار قرار دهد.

در ادامه، مروری بر مراحل این مثال آمده است:

  1. تعریف یک مانیفست Job با استفاده از تکمیل نمایه‌دار. با downward API می‌توانید حاشیه‌نویسی نمایه‌ی پاد را به‌صورت متغیر محیطی یا فایل به کانتینر منتقل کنید.
  2. راه‌اندازی یک Job از نوع Indexed بر اساس آن مانیفست.

پیش از شروع

باید از قبل با استفاده‌ی پایه و غیرموازی از Job آشنا باشید.

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

انتخاب یک رویکرد

برای دسترسی به آیتم کاری از درون برنامه‌ی کارگر، چند گزینه دارید:

  1. متغیر محیطی JOB_COMPLETION_INDEX را بخوانید. کنترل‌کننده‌ی Job این متغیر را به‌طور خودکار به حاشیه‌نویسی حاوی نمایه‌ی تکمیل پیوند می‌دهد.
  2. فایلی را بخوانید که نمایه‌ی تکمیل را در خود دارد.
  3. اگر نتوانید برنامه را تغییر دهید، می‌توانید آن را درون اسکریپتی قرار دهید که نمایه را با یکی از روش‌های بالا می‌خواند و آن را به ورودی‌ای تبدیل می‌کند که برنامه بتواند از آن استفاده کند.

در این مثال، فرض کنید گزینه‌ی ۳ را انتخاب کرده‌اید و می‌خواهید ابزار rev را اجرا کنید. این برنامه یک فایل را به‌عنوان آرگومان می‌پذیرد و محتوای آن را به‌صورت وارونه چاپ می‌کند.

rev data.txt

از ابزار rev موجود در ایمیج کانتینر busybox استفاده خواهید کرد.

از آنجا که این فقط یک مثال است، هر Pod تنها بخش بسیار کوچکی از کار را انجام می‌دهد (وارونه کردن یک رشته‌ی کوتاه). در یک بار کاری واقعی، ممکن است برای نمونه Jobی بسازید که وظیفه‌ی تولید ۶۰ ثانیه ویدئو بر اساس داده‌های صحنه را نمایندگی می‌کند. هر آیتم کاری در Job رندر ویدئو، رندر کردن یک فریم مشخص از آن کلیپ ویدئویی است. تکمیل نمایه‌دار به این معناست که هر Pod در Job، با شمارش فریم‌ها از ابتدای کلیپ، می‌داند کدام فریم را باید رندر و منتشر کند.

تعریف یک Job نمایه‌دار

در ادامه، نمونه‌ای از مانیفست Job آمده است که از حالت تکمیل Indexed استفاده می‌کند:

application/job/indexed-job.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: 'indexed-job'
spec:
  completions: 5
  parallelism: 3
  completionMode: Indexed
  template:
    spec:
      restartPolicy: Never
      initContainers:
      - name: 'input'
        image: 'docker.io/library/bash'
        command:
        - "bash"
        - "-c"
        - |
          items=(foo bar baz qux xyz)
          echo ${items[$JOB_COMPLETION_INDEX]} > /input/data.txt
        volumeMounts:
        - mountPath: /input
          name: input
      containers:
      - name: 'worker'
        image: 'docker.io/library/busybox'
        command:
        - "rev"
        - "/input/data.txt"
        volumeMounts:
        - mountPath: /input
          name: input
      volumes:
      - name: input
        emptyDir: {}

در مثال بالا، از متغیر محیطی داخلی JOB_COMPLETION_INDEX استفاده می‌کنید که کنترل‌کننده‌ی Job آن را برای همه‌ی کانتینرها تنظیم می‌کند. یک کانتینر init نمایه را به یک مقدار ایستا نگاشت می‌کند و آن را در فایلی می‌نویسد که از طریق یک حجم (volume) از نوع emptyDir با کانتینرِ اجراکننده‌ی کارگر به اشتراک گذاشته می‌شود. در صورت تمایل، می‌توانید متغیر محیطی دلخواه خود را از طریق downward API تعریف کنید تا نمایه را در اختیار کانتینرها قرار دهید. همچنین می‌توانید فهرستی از مقادیر را از یک ConfigMap به‌صورت متغیر محیطی یا فایل بارگذاری کنید.

به‌عنوان راه دیگر، می‌توانید مستقیماً با downward API مقدار حاشیه‌نویسی را به‌صورت یک فایل حجم منتقل کنید؛ مانند مثال زیر:

application/job/indexed-job-vol.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: 'indexed-job'
spec:
  completions: 5
  parallelism: 3
  completionMode: Indexed
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: 'worker'
        image: 'docker.io/library/busybox'
        command:
        - "rev"
        - "/input/data.txt"
        volumeMounts:
        - mountPath: /input
          name: input
      volumes:
      - name: input
        downwardAPI:
          items:
          - path: "data.txt"
            fieldRef:
              fieldPath: metadata.annotations['batch.kubernetes.io/job-completion-index']

اجرای Job

اکنون Job را اجرا کنید:

# This uses the first approach (relying on $JOB_COMPLETION_INDEX)
kubectl apply -f https://kubernetes.io/examples/application/job/indexed-job.yaml

هنگامی که این Job را ایجاد می‌کنید، control plane مجموعه‌ای از Podها را می‌سازد؛ یکی برای هر نمایه‌ای که مشخص کرده‌اید. مقدار .spec.parallelism تعیین می‌کند که چند Pod می‌توانند هم‌زمان اجرا شوند، در حالی که .spec.completions تعیین می‌کند Job در مجموع چند Pod ایجاد کند.

از آنجا که .spec.parallelism کمتر از .spec.completions است، control plane پیش از راه‌اندازی Podهای بیشتر، منتظر می‌ماند تا برخی از نخستین Podها کامل شوند.

می‌توانید با تعیین یک مهلت زمانی، منتظر بمانید تا Job با موفقیت به پایان برسد:

# The check for condition name is case insensitive
kubectl wait --for=condition=complete --timeout=300s job/indexed-job

اکنون Job را توصیف کنید و بررسی کنید که با موفقیت انجام شده باشد.

kubectl describe jobs/indexed-job
