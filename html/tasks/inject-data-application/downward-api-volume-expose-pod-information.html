افشای اطلاعات Pod برای کانتینرها از طریق فایل‌ها

این صفحه نشان می‌دهد که یک Pod چگونه می‌تواند با استفاده از یک حجم downwardAPI اطلاعاتی دربارهٔ خودش را در اختیار کانتینرهایی قرار دهد که در آن Pod اجرا می‌شوند. یک حجم downwardAPI می‌تواند فیلدهای Pod و فیلدهای کانتینر را در دسترس قرار دهد.

در کوبرنتیز، دو روش برای در دسترس قرار دادن فیلدهای Pod و کانتینر برای یک کانتینر در حال اجرا وجود دارد:

  • متغیرهای محیطی
  • فایل‌های حجم (volume)، همان‌طور که در این تمرین توضیح داده می‌شود

به این دو روش برای در دسترس قرار دادن فیلدهای Pod و کانتینر، روی هم رفته downward API گفته می‌شود.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

ذخیرهٔ فیلدهای Pod

در این بخش از تمرین، یک Pod با یک کانتینر ایجاد می‌کنید و فیلدهای سطح Pod را به‌صورت فایل در کانتینر در حال اجرا قرار می‌دهید (project می‌کنید). مانیفست این Pod در ادامه آمده است:

pods/inject/dapi-volume.yaml
apiVersion: v1
kind: Pod
metadata:
  name: kubernetes-downwardapi-volume-example
  labels:
    zone: us-est-coast
    cluster: test-cluster1
    rack: rack-22
  annotations:
    build: two
    builder: john-doe
spec:
  containers:
    - name: client-container
      image: registry.k8s.io/busybox:1.27.2
      command: ["sh", "-c"]
      args:
      - while true; do
          if [[ -e /etc/podinfo/labels ]]; then
            echo -en '\n\n'; cat /etc/podinfo/labels; fi;
          if [[ -e /etc/podinfo/annotations ]]; then
            echo -en '\n\n'; cat /etc/podinfo/annotations; fi;
          sleep 5;
        done;
      volumeMounts:
        - name: podinfo
          mountPath: /etc/podinfo
  volumes:
    - name: podinfo
      downwardAPI:
        items:
          - path: "labels"
            fieldRef:
              fieldPath: metadata.labels
          - path: "annotations"
            fieldRef:
              fieldPath: metadata.annotations

در این مانیفست می‌بینید که Pod یک حجم downwardAPI دارد و کانتینر این حجم را در مسیر /etc/podinfo سوار (mount) می‌کند.

به آرایهٔ items در زیر downwardAPI نگاه کنید. هر عنصر این آرایه یک حجم downwardAPI را تعریف می‌کند. عنصر اول مشخص می‌کند که مقدار فیلد metadata.labels مربوط به Pod باید در فایلی به نام labels ذخیره شود. عنصر دوم مشخص می‌کند که مقدار فیلد annotations مربوط به Pod باید در فایلی به نام annotations ذخیره شود.

توجه:

فیلدهای این مثال، فیلدهای Pod هستند و فیلدهای کانتینرِ درون Pod نیستند.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/inject/dapi-volume.yaml

بررسی کنید که کانتینر درون Pod در حال اجرا باشد:

kubectl get pods

لاگ‌های کانتینر را مشاهده کنید:

kubectl logs kubernetes-downwardapi-volume-example

خروجی، محتوای فایل labels و فایل annotations را نشان می‌دهد:

cluster="test-cluster1"
rack="rack-22"
zone="us-est-coast"

build="two"
builder="john-doe"

یک پوسته (shell) در کانتینری که در Pod شما اجرا می‌شود باز کنید:

kubectl exec -it kubernetes-downwardapi-volume-example -- sh

در پوستهٔ خود، فایل labels را مشاهده کنید:

/# cat /etc/podinfo/labels

خروجی نشان می‌دهد که همهٔ برچسب‌های Pod در فایل labels نوشته شده‌اند:

cluster="test-cluster1"
rack="rack-22"
zone="us-est-coast"

به همین ترتیب، فایل annotations را مشاهده کنید:

/# cat /etc/podinfo/annotations

فایل‌های موجود در دایرکتوری /etc/podinfo را مشاهده کنید:

/# ls -laR /etc/podinfo

در خروجی می‌بینید که فایل‌های labels و annotations در یک زیردایرکتوری موقت قرار دارند که در این مثال ..2982_06_02_21_47_53.299460680 است. در دایرکتوری /etc/podinfo، مسیر ..data یک پیوند نمادین (symbolic link) به این زیردایرکتوری موقت است. همچنین در دایرکتوری /etc/podinfo، فایل‌های labels و annotations پیوند نمادین هستند.

drwxr-xr-x  ... Feb 6 21:47 ..2982_06_02_21_47_53.299460680
lrwxrwxrwx  ... Feb 6 21:47 ..data -> ..2982_06_02_21_47_53.299460680
lrwxrwxrwx  ... Feb 6 21:47 annotations -> ..data/annotations
lrwxrwxrwx  ... Feb 6 21:47 labels -> ..data/labels

/etc/..2982_06_02_21_47_53.299460680:
total 8
-rw-r--r--  ... Feb  6 21:47 annotations
-rw-r--r--  ... Feb  6 21:47 labels

استفاده از پیوندهای نمادین، به‌روزرسانی پویا و اتمی فراداده‌ها را ممکن می‌کند؛ به‌روزرسانی‌ها در یک دایرکتوری موقت جدید نوشته می‌شوند و پیوند نمادین ..data با استفاده از rename(2) به‌صورت اتمی به‌روزرسانی می‌شود.

توجه:

کانتینری که از Downward API به‌صورت سوارکردن حجم با subPath استفاده می‌کند، به‌روزرسانی‌های Downward API را دریافت نخواهد کرد.

از پوسته خارج شوید:

/# exit

ذخیرهٔ فیلدهای کانتینر

در تمرین قبل، فیلدهای سطح Pod را با استفاده از downward API در دسترس قرار دادید. در تمرین بعدی، فیلدهایی را منتقل می‌کنید که بخشی از تعریف Pod هستند، اما به‌جای کل Pod، از کانتینر مشخصی گرفته می‌شوند. مانیفست Pod زیر نیز تنها یک کانتینر دارد:

pods/inject/dapi-volume-resources.yaml
apiVersion: v1
kind: Pod
metadata:
  name: kubernetes-downwardapi-volume-example-2
spec:
  containers:
    - name: client-container
      image: registry.k8s.io/busybox:1.27.2
      command: ["sh", "-c"]
      args:
      - while true; do
          echo -en '\n';
          if [[ -e /etc/podinfo/cpu_limit ]]; then
            echo -en '\n'; cat /etc/podinfo/cpu_limit; fi;
          if [[ -e /etc/podinfo/cpu_request ]]; then
            echo -en '\n'; cat /etc/podinfo/cpu_request; fi;
          if [[ -e /etc/podinfo/mem_limit ]]; then
            echo -en '\n'; cat /etc/podinfo/mem_limit; fi;
          if [[ -e /etc/podinfo/mem_request ]]; then
            echo -en '\n'; cat /etc/podinfo/mem_request; fi;
          sleep 5;
        done;
      resources:
        requests:
          memory: "32Mi"
          cpu: "125m"
        limits:
          memory: "64Mi"
          cpu: "250m"
      volumeMounts:
        - name: podinfo
          mountPath: /etc/podinfo
  volumes:
    - name: podinfo
      downwardAPI:
        items:
          - path: "cpu_limit"
            resourceFieldRef:
              containerName: client-container
              resource: limits.cpu
              divisor: 1m
          - path: "cpu_request"
            resourceFieldRef:
              containerName: client-container
              resource: requests.cpu
              divisor: 1m
          - path: "mem_limit"
            resourceFieldRef:
              containerName: client-container
              resource: limits.memory
              divisor: 1Mi
          - path: "mem_request"
            resourceFieldRef:
              containerName: client-container
              resource: requests.memory
              divisor: 1Mi

در این مانیفست می‌بینید که Pod یک حجم downwardAPI دارد و تنها کانتینر آن Pod، این حجم را در مسیر /etc/podinfo سوار می‌کند.

به آرایهٔ items در زیر downwardAPI نگاه کنید. هر عنصر این آرایه یک فایل را در حجم downward API تعریف می‌کند.

عنصر اول مشخص می‌کند که در کانتینری به نام client-container، مقدار فیلد limits.cpu با قالبی که 1m تعیین می‌کند، باید به‌صورت فایلی به نام cpu_limit منتشر شود. فیلد divisor اختیاری است و مقدار پیش‌فرض آن 1 است. مقسوم‌علیه ۱ برای منابع cpu به معنای هسته و برای منابع memory به معنای بایت است.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/inject/dapi-volume-resources.yaml

یک پوسته در کانتینری که در Pod شما اجرا می‌شود باز کنید:

kubectl exec -it kubernetes-downwardapi-volume-example-2 -- sh

در پوستهٔ خود، فایل cpu_limit را مشاهده کنید:

# Run this in a shell inside the container
cat /etc/podinfo/cpu_limit

با دستورهای مشابه می‌توانید فایل‌های cpu_request، mem_limit و mem_request را مشاهده کنید.

نگاشت کلیدها به مسیرهای مشخص و تعیین مجوزهای فایل

می‌توانید کلیدها را به مسیرهای مشخص نگاشت (project) کنید و برای هر فایل مجوزهای مشخصی تعیین کنید. برای اطلاعات بیشتر، Secretها را ببینید.

گام‌های بعدی

  • تعریف API مربوط به spec در Pod را بخوانید. این تعریف شامل تعریف Container (بخشی از Pod) نیز هست.
  • فهرست فیلدهای موجود را که می‌توانید با downward API در دسترس قرار دهید، بخوانید.

دربارهٔ حجم‌ها در مرجع API قدیمی بخوانید:

  • تعریف API مربوط به Volume را بررسی کنید که یک حجم عمومی را در Pod تعریف می‌کند تا کانتینرها به آن دسترسی داشته باشند.
  • تعریف API مربوط به DownwardAPIVolumeSource را بررسی کنید که حجمی حاوی اطلاعات Downward API را تعریف می‌کند.
  • تعریف API مربوط به DownwardAPIVolumeFile را بررسی کنید که شامل ارجاع‌هایی به فیلدهای آبجکت یا منبع برای پر کردن یک فایل در حجم Downward API است.
  • تعریف API مربوط به ResourceFieldSelector را بررسی کنید که منابع کانتینر و قالب خروجی آن‌ها را مشخص می‌کند.
