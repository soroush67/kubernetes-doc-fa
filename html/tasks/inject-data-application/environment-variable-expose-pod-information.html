نمایش اطلاعات Pod به کانتینرها از طریق متغیرهای محیطی

این صفحه نشان می‌دهد که یک Pod چگونه می‌تواند با استفاده از downward API و از طریق متغیرهای محیطی، اطلاعاتی دربارهٔ خودش را در اختیار کانتینرهایی بگذارد که در آن Pod اجرا می‌شوند. با متغیرهای محیطی می‌توانید فیلدهای Pod، فیلدهای کانتینر یا هر دو را در دسترس قرار دهید.

در کوبرنتیز، دو روش برای در دسترس قرار دادن فیلدهای Pod و کانتینر برای یک کانتینر در حال اجرا وجود دارد:

  • متغیرهای محیطی، همان‌طور که در این تمرین توضیح داده شده است
  • فایل‌های حجم (volume)

این دو روش برای در دسترس قرار دادن فیلدهای Pod و کانتینر، روی هم downward API نامیده می‌شوند.

از آنجا که Serviceها اصلی‌ترین راه ارتباط میان برنامه‌های کانتینری‌شده‌ای هستند که کوبرنتیز آن‌ها را مدیریت می‌کند، بهتر است بتوان آن‌ها را در زمان اجرا کشف کرد.

دربارهٔ دسترسی به Serviceها اینجا بیشتر بخوانید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

استفاده از فیلدهای Pod به‌عنوان مقدار متغیرهای محیطی

در این بخش از تمرین، یک Pod با یک کانتینر ایجاد می‌کنید و فیلدهای سطح Pod را به‌صورت متغیرهای محیطی در کانتینر در حال اجرا قرار می‌دهید.

pods/inject/dapi-envars-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: dapi-envars-fieldref
spec:
  containers:
    - name: test-container
      image: registry.k8s.io/busybox:1.27.2
      command: [ "sh", "-c"]
      args:
      - while true; do
          echo -en '\n';
          printenv MY_NODE_NAME MY_POD_NAME MY_POD_NAMESPACE;
          printenv MY_POD_IP MY_POD_SERVICE_ACCOUNT;
          sleep 10;
        done;
      env:
        - name: MY_NODE_NAME
          valueFrom:
            fieldRef:
              fieldPath: spec.nodeName
        - name: MY_POD_NAME
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: MY_POD_NAMESPACE
          valueFrom:
            fieldRef:
              fieldPath: metadata.namespace
        - name: MY_POD_IP
          valueFrom:
            fieldRef:
              fieldPath: status.podIP
        - name: MY_POD_SERVICE_ACCOUNT
          valueFrom:
            fieldRef:
              fieldPath: spec.serviceAccountName
  restartPolicy: Never

در این مانیفست، پنج متغیر محیطی را می‌بینید. فیلد env آرایه‌ای از تعریف‌های متغیرهای محیطی است. نخستین عنصر این آرایه مشخص می‌کند که متغیر محیطی MY_NODE_NAME مقدار خود را از فیلد spec.nodeName در Pod می‌گیرد. به همین ترتیب، سایر متغیرهای محیطی نیز نام‌های خود را از فیلدهای Pod می‌گیرند.

توجه:

فیلدهای این مثال، فیلدهای Pod هستند و فیلدهای کانتینرِ درون Pod به شمار نمی‌آیند.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/inject/dapi-envars-pod.yaml

بررسی کنید که کانتینر درون Pod در حال اجرا باشد:

# If the new Pod isn't yet healthy, rerun this command a few times.
kubectl get pods

لاگ‌های کانتینر را مشاهده کنید:

kubectl logs dapi-envars-fieldref

خروجی، مقادیر متغیرهای محیطی انتخاب‌شده را نشان می‌دهد:

minikube
dapi-envars-fieldref
default
172.17.0.4
default

برای اینکه ببینید چرا این مقادیر در لاگ آمده‌اند، به فیلدهای command و args در فایل پیکربندی نگاه کنید. هنگامی که کانتینر شروع به کار می‌کند، مقادیر پنج متغیر محیطی را در stdout می‌نویسد و این کار را هر ده ثانیه یک‌بار تکرار می‌کند.

سپس، یک شل در کانتینری که در Pod شما اجرا می‌شود باز کنید:

kubectl exec -it dapi-envars-fieldref -- sh

در شل خود، متغیرهای محیطی را مشاهده کنید:

# Run this in a shell inside the container
printenv

خروجی نشان می‌دهد که مقادیر فیلدهای Pod به برخی از متغیرهای محیطی اختصاص داده شده است:

MY_POD_SERVICE_ACCOUNT=default
...
MY_POD_NAMESPACE=default
MY_POD_IP=172.17.0.4
...
MY_NODE_NAME=minikube
...
MY_POD_NAME=dapi-envars-fieldref

استفاده از فیلدهای کانتینر به‌عنوان مقدار متغیرهای محیطی

در تمرین قبل، از اطلاعات فیلدهای سطح Pod به‌عنوان مقدار متغیرهای محیطی استفاده کردید. در تمرین بعدی، فیلدهایی را منتقل می‌کنید که بخشی از تعریف Pod هستند، اما به‌جای کل Pod، از یک کانتینر مشخص گرفته می‌شوند.

در ادامه، مانیفست Pod دیگری آمده است که این بار نیز تنها یک کانتینر دارد:

pods/inject/dapi-envars-container.yaml
apiVersion: v1
kind: Pod
metadata:
  name: dapi-envars-resourcefieldref
spec:
  containers:
    - name: test-container
      image: registry.k8s.io/busybox:1.27.2
      command: [ "sh", "-c"]
      args:
      - while true; do
          echo -en '\n';
          printenv MY_CPU_REQUEST MY_CPU_LIMIT;
          printenv MY_MEM_REQUEST MY_MEM_LIMIT;
          sleep 10;
        done;
      resources:
        requests:
          memory: "32Mi"
          cpu: "125m"
        limits:
          memory: "64Mi"
          cpu: "250m"
      env:
        - name: MY_CPU_REQUEST
          valueFrom:
            resourceFieldRef:
              containerName: test-container
              resource: requests.cpu
        - name: MY_CPU_LIMIT
          valueFrom:
            resourceFieldRef:
              containerName: test-container
              resource: limits.cpu
        - name: MY_MEM_REQUEST
          valueFrom:
            resourceFieldRef:
              containerName: test-container
              resource: requests.memory
        - name: MY_MEM_LIMIT
          valueFrom:
            resourceFieldRef:
              containerName: test-container
              resource: limits.memory
  restartPolicy: Never

در این مانیفست، چهار متغیر محیطی را می‌بینید. فیلد env آرایه‌ای از تعریف‌های متغیرهای محیطی است. نخستین عنصر این آرایه مشخص می‌کند که متغیر محیطی MY_CPU_REQUEST مقدار خود را از فیلد requests.cpu در کانتینری به نام test-container می‌گیرد. به همین ترتیب، سایر متغیرهای محیطی نیز مقادیر خود را از فیلدهایی می‌گیرند که مختص همین کانتینر هستند.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/inject/dapi-envars-container.yaml

بررسی کنید که کانتینر درون Pod در حال اجرا باشد:

# If the new Pod isn't yet healthy, rerun this command a few times.
kubectl get pods

لاگ‌های کانتینر را مشاهده کنید:

kubectl logs dapi-envars-resourcefieldref

خروجی، مقادیر متغیرهای محیطی انتخاب‌شده را نشان می‌دهد:

گام‌های بعدی

  • تعریف متغیرهای محیطی برای یک کانتینر را بخوانید.
  • تعریف API مربوط به spec در Pod را بخوانید. این تعریف شامل تعریف Container (بخشی از Pod) نیز هست.
  • فهرست فیلدهای موجود را که می‌توانید با downward API در دسترس قرار دهید، بخوانید.

دربارهٔ Podها، کانتینرها و متغیرهای محیطی در مرجع قدیمی API بخوانید:

  • PodSpec
  • Container
  • EnvVar
  • EnvVarSource
  • ObjectFieldSelector
  • ResourceFieldSelector
