تعریف مقادیر متغیرهای محیطی با استفاده از یک Init Container

وضعیت ویژگی: Kubernetes [] ()

این صفحه نشان می‌دهد که چگونه می‌توان متغیرهای محیطی کانتینرهای یک Pod را از طریق فایل پیکربندی کرد.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

این طراحی چگونه کار می‌کند

در این تمرین، یک Pod ایجاد می‌کنید که متغیرهای محیطی را از فایل‌ها می‌خواند و این مقادیر را در کانتینر در حال اجرا قرار می‌دهد.

pods/inject/envars-file-container.yaml
apiVersion: v1
kind: Pod
metadata:
  name: envfile-test-pod
spec:
  initContainers:
    - name: setup-envfile
      image:  nginx
      command: ['sh', '-c', "echo \"DB_ADDRESS=\'address\'\nREST_ENDPOINT=\'endpoint\'\" > /data/config.env"]
      volumeMounts:
        - name: config
          mountPath: /data
  containers:
    - name: use-envfile
      image: nginx
      command: [ "/bin/sh", "-c", "env" ]
      env:
        - name: DB_ADDRESS
          valueFrom:
            fileKeyRef:
              path: config.env
              volumeName: config
              key: DB_ADDRESS
              optional: false
  restartPolicy: Never
  volumes:
    - name: config
      emptyDir: {}

همان‌طور که در این مانیفست می‌بینید، initContainer یک حجم (volume) از نوع emptyDir را مونت می‌کند و متغیرهای محیطی را در فایلی درون آن می‌نویسد. کانتینرهای عادی نیز بدون نیاز به مونت کردن این حجم، از طریق فیلد fileKeyRef هم به فایل و هم به کلید متغیر محیطی ارجاع می‌دهند. هنگامی که فیلد optional برابر با false باشد، کلید مشخص‌شده در key درون fileKeyRef باید در فایل متغیرهای محیطی وجود داشته باشد.

این حجم فقط در کانتینری مونت می‌شود که در فایل می‌نویسد (initContainer)، و کانتینر مصرف‌کننده‌ای که از متغیر محیطی استفاده می‌کند، این حجم را مونت نخواهد داشت.

قالب فایل env از استاندارد فایل env در کوبرنتیز پیروی می‌کند.

در طول مقداردهی اولیه کانتینر، kubelet متغیرهای محیطی را از فایل‌های مشخص‌شده در حجم emptyDir بازیابی می‌کند و آن‌ها را در اختیار کانتینر قرار می‌دهد.

توجه:

همه انواع کانتینر (initContainerها، کانتینرهای عادی، کانتینرهای sidecar و کانتینرهای موقت (ephemeral)) از بارگذاری متغیرهای محیطی از فایل پشتیبانی می‌کنند.

اگرچه این متغیرهای محیطی می‌توانند اطلاعات حساس را ذخیره کنند، حجم‌های emptyDir سازوکارهای حفاظتی مشابه آبجکت‌های اختصاصی Secret را فراهم نمی‌کنند. بنابراین، در اختیار قرار دادن متغیرهای محیطی محرمانه برای کانتینرها از طریق این قابلیت، بهترین روش امنیتی محسوب نمی‌شود.

Pod را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/pods/inject/envars-file-container.yaml

بررسی کنید که کانتینر درون Pod در حال اجرا باشد:

# If the new Pod isn't yet healthy, rerun this command a few times.
kubectl get pods

لاگ‌های کانتینر را برای یافتن متغیرهای محیطی بررسی کنید:

kubectl logs envfile-test-pod -c use-envfile | grep DB_ADDRESS

خروجی، مقادیر متغیرهای محیطی انتخاب‌شده را نشان می‌دهد:

DB_ADDRESS=address

نحو فایل env {#env-file-syntax}

قالب فایل env که کوبرنتیز از آن استفاده می‌کند، زیرمجموعه‌ای به‌خوبی تعریف‌شده از معنای متغیرهای محیطی در bash سازگار با POSIX است. هر فایل env که کوبرنتیز از آن پشتیبانی می‌کند، همان متغیرهای محیطی‌ای را تولید می‌کند که در صورت تفسیر با bash سازگار با POSIX تولید می‌شوند. با این حال، bash سازگار با POSIX از برخی قالب‌های دیگر نیز پشتیبانی می‌کند که کوبرنتیز آن‌ها را نمی‌پذیرد.

مثال:

MY_VAR='my-literal-value'

قواعد

  • تعریف متغیر: از شکل VAR='value' استفاده کنید. فاصله‌های اطراف = نادیده گرفته می‌شوند؛ فاصله‌های ابتدای هر خط نادیده گرفته می‌شوند؛ خطوط خالی نیز نادیده گرفته می‌شوند.
  • مقادیر داخل نقل‌قول: مقادیر باید درون نقل‌قول تکی (') قرار گیرند.
    • محتوای درون نقل‌قول تکی عیناً حفظ می‌شود. هیچ پردازشی روی دنباله‌های گریز (escape sequence) انجام نمی‌شود، فاصله‌های سفید ادغام نمی‌شوند و هیچ نویسه‌ای تفسیر نمی‌شود.
    • خطوط جدید درون نقل‌قول تکی حفظ می‌شوند (از مقادیر چندخطی پشتیبانی می‌شود).
  • توضیحات: خطوطی که با # شروع می‌شوند، توضیح در نظر گرفته شده و نادیده گرفته می‌شوند. نویسه # درون مقداری که در نقل‌قول تکی قرار دارد، توضیح محسوب نمی‌شود.

مثال‌ها:

# comment
DB_ADDRESS='address'

MULTI='line1
line2'

قالب‌های پشتیبانی‌نشده

  • مقادیر بدون نقل‌قول ممنوع هستند:
    • VAR=value — پشتیبانی نمی‌شود.
  • مقادیر درون نقل‌قول دوتایی ممنوع هستند:
    • VAR="value" — پشتیبانی نمی‌شود.
  • چند رشته نقل‌قول‌شده مجاور هم پشتیبانی نمی‌شوند:
    • VAR='val1''val2' — پشتیبانی نمی‌شود.
  • هیچ نوعی از درون‌یابی (interpolation)، بسط (expansion) یا الحاق (concatenation) پشتیبانی نمی‌شود:
    • VAR='a'$OTHER یا VAR=${OTHER} — پشتیبانی نمی‌شود.

الزام سخت‌گیرانه به استفاده از نقل‌قول تکی تضمین می‌کند که kubelet هنگام بارگذاری متغیرهای محیطی از فایل‌ها، مقدار را عیناً و به همان شکل نوشته‌شده دریافت کند.

گام‌های بعدی

  • درباره متغیرهای محیطی بیشتر بیاموزید.
  • تعریف متغیرهای محیطی برای یک کانتینر را بخوانید.
  • در اختیار قرار دادن اطلاعات Pod برای کانتینرها از طریق متغیرهای محیطی را بخوانید.
