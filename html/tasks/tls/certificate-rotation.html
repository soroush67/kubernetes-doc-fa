پیکربندی چرخش گواهی‌ها برای kubelet

این صفحه نشان می‌دهد چگونه چرخش گواهی‌ها (certificate rotation) را برای kubelet فعال و پیکربندی کنید.

وضعیت ویژگی: Kubernetes v1.19 [stable] (پایدار)

پیش از شروع

  • به کوبرنتیز نسخهٔ 1.8.0 یا بالاتر نیاز است

مرور کلی

برنامهٔ kubelet برای احراز هویت در برابر API کوبرنتیز از گواهی‌ها استفاده می‌کند. این گواهی‌ها به‌طور پیش‌فرض با اعتبار یک‌ساله صادر می‌شوند تا نیازی به تمدید مکرر آن‌ها نباشد.

کوبرنتیز قابلیت چرخش گواهی kubelet را در خود دارد. با نزدیک شدن زمان انقضای گواهی فعلی، این قابلیت به‌طور خودکار یک کلید جدید تولید می‌کند و گواهی جدیدی از API کوبرنتیز درخواست می‌کند. پس از آماده شدن گواهی جدید، از آن برای احراز هویت اتصال‌ها به API کوبرنتیز استفاده می‌شود.

فعال‌سازی چرخش گواهی کلاینت

فرایند kubelet آرگومان --rotate-certificates را می‌پذیرد. این آرگومان تعیین می‌کند که آیا kubelet با نزدیک شدن زمان انقضای گواهیِ در حال استفاده، به‌طور خودکار گواهی جدیدی درخواست کند یا نه.

فرایند kube-controller-manager آرگومان --cluster-signing-duration را می‌پذیرد (در نسخه‌های پیش از 1.19 با نام --experimental-cluster-signing-duration). این آرگومان مدت اعتبار گواهی‌های صادرشده را تعیین می‌کند.

درک پیکربندی چرخش گواهی

هنگامی که kubelet راه‌اندازی می‌شود، اگر برای راه‌اندازی اولیه (bootstrap) پیکربندی شده باشد (با استفاده از فلگ --bootstrap-kubeconfig)، با گواهی اولیهٔ خود به API کوبرنتیز متصل می‌شود و یک درخواست امضای گواهی (certificate signing request) صادر می‌کند. وضعیت درخواست‌های امضای گواهی را می‌توانید با دستور زیر مشاهده کنید:

kubectl get csr

در ابتدا، وضعیت درخواست امضای گواهیِ kubelet روی یک نود Pending است. اگر این درخواست معیارهای مشخصی را برآورده کند، controller manager آن را به‌طور خودکار تأیید می‌کند و وضعیت آن به Approved تغییر می‌یابد. سپس controller manager گواهی‌ای را امضا می‌کند که برای مدت تعیین‌شده در پارامتر --cluster-signing-duration صادر می‌شود، و گواهی امضاشده به درخواست امضای گواهی پیوست می‌شود.

برنامهٔ kubelet گواهی امضاشده را از API کوبرنتیز دریافت می‌کند و آن را در مسیر تعیین‌شده با --cert-dir روی دیسک می‌نویسد. سپس kubelet برای اتصال به API کوبرنتیز از گواهی جدید استفاده می‌کند.

با نزدیک شدن زمان انقضای گواهی امضاشده، kubelet به‌طور خودکار و با استفاده از API کوبرنتیز یک درخواست امضای گواهی جدید صادر می‌کند. این کار ممکن است در هر زمانی بین ۳۰٪ تا ۱۰٪ باقی‌ماندهٔ مدت اعتبار گواهی انجام شود. باز هم controller manager درخواست گواهی را به‌طور خودکار تأیید می‌کند و یک گواهی امضاشده به درخواست امضای گواهی پیوست می‌کند. kubelet گواهی امضاشدهٔ جدید را از API کوبرنتیز دریافت می‌کند و آن را روی دیسک می‌نویسد. سپس اتصال‌های خود به API کوبرنتیز را به‌روزرسانی می‌کند تا با گواهی جدید دوباره متصل شود.
