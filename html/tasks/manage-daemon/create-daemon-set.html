ساخت یک DaemonSet پایه

این صفحه نشان می‌دهد که چگونه می‌توان یک DaemonSet پایه ساخت که روی هر نود در یک کلاستر کوبرنتیز یک Pod اجرا کند. در این صفحه یک مورد استفادهٔ ساده بررسی می‌شود: یک فایل از میزبان سوار (mount) می‌شود، محتوای آن به کمک یک کانتینر init در لاگ ثبت می‌شود و از یک کانتینر pause نیز استفاده می‌شود.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

برای نمایش رفتار DaemonSetها، به یک کلاستر کوبرنتیز با دست‌کم دو نود (یک نود control plane و یک نود کارگر) نیاز دارید.

تعریف DaemonSet

در این تمرین، یک DaemonSet پایه ساخته می‌شود که تضمین می‌کند یک نسخه از Pod روی هر نود زمان‌بندی شود. این Pod از یک کانتینر init برای خواندن محتوای /etc/machine-id از میزبان و ثبت آن در لاگ استفاده می‌کند، و کانتینر اصلی آن یک کانتینر pause است که Pod را در حال اجرا نگه می‌دارد.

application/basic-daemonset.yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: example-daemonset
spec:
  selector:
    matchLabels:
      app.kubernetes.io/name: example
  template:
    metadata:
      labels:
        app.kubernetes.io/name: example
    spec:
      containers:
      - name: pause
        image: registry.k8s.io/pause
      initContainers:
      - name: log-machine-id
        image: busybox:1.37
        command: ['sh', '-c', 'cat /etc/machine-id > /var/log/machine-id.log']
        volumeMounts:
        - name: machine-id
          mountPath: /etc/machine-id
          readOnly: true
        - name: log-dir
          mountPath: /var/log
      volumes:
      - name: machine-id
        hostPath:
          path: /etc/machine-id
          type: File
      - name: log-dir
        hostPath:
          path: /var/log

  1. یک DaemonSet بر اساس مانیفست (YAML) بسازید:

    kubectl apply -f https://k8s.io/examples/application/basic-daemonset.yaml

  2. پس از اعمال مانیفست، می‌توانید بررسی کنید که DaemonSet روی هر نود کلاستر یک Pod اجرا می‌کند:

    kubectl get pods -o wide

    خروجی، به‌ازای هر نود یک Pod فهرست می‌کند و مشابه زیر است:

    NAME                                READY   STATUS    RESTARTS   AGE    IP       NODE
example-daemonset-xxxxx             1/1     Running   0          5m     x.x.x.x  node-1
example-daemonset-yyyyy             1/1     Running   0          5m     x.x.x.x  node-2

  3. برای مشاهدهٔ محتوای فایل /etc/machine-id که در لاگ ثبت شده است، می‌توانید دایرکتوری لاگی را که از میزبان سوار شده است بررسی کنید:

    kubectl exec <pod-name> -- cat /var/log/machine-id.log

    در این دستور، <pod-name> نام یکی از Podهای شماست.

پاکسازی

برای حذف DaemonSet، این دستور را اجرا کنید:

kubectl delete --cascade=foreground --ignore-not-found --now daemonsets/example-daemonset

این مثال سادهٔ DaemonSet اجزای کلیدی مانند کانتینرهای init و حجم‌های (volume) مسیر میزبان (host path) را معرفی می‌کند که می‌توان آن‌ها را برای موارد استفادهٔ پیشرفته‌تر گسترش داد. برای جزئیات بیشتر به DaemonSet مراجعه کنید.

گام‌های بعدی

  • انجام به‌روزرسانی تدریجی (rolling update) روی یک DaemonSet را ببینید.
  • ساخت یک DaemonSet برای پذیرفتن Podهای موجود یک DaemonSet دیگر را ببینید.
