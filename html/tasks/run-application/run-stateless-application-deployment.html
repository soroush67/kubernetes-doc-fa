اجرای یک برنامهٔ بدون حالت با استفاده از Deployment

این صفحه نشان می‌دهد که چگونه می‌توان یک برنامه را با استفاده از آبجکت Deployment در کوبرنتیز اجرا کرد.

اهداف

  • یک استقرار nginx ایجاد کنید.
  • با استفاده از kubectl اطلاعات مربوط به استقرار را فهرست کنید.
  • استقرار را به‌روزرسانی کنید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

ایجاد و بررسی یک استقرار nginx

برای اجرای یک برنامه می‌توانید یک آبجکت Deployment در کوبرنتیز ایجاد کنید و مشخصات این Deployment را در یک فایل YAML بنویسید. برای نمونه، فایل YAML زیر یک Deployment را توصیف می‌کند که ایمیج Docker با نام nginx:1.14.2 را اجرا می‌کند:

application/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 2 # tells deployment to run 2 pods matching the template
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80

  1. بر اساس فایل YAML یک Deployment ایجاد کنید:

    kubectl apply -f https://k8s.io/examples/application/deployment.yaml

  2. اطلاعات مربوط به Deployment را نمایش دهید:

    kubectl describe deployment nginx-deployment

    خروجی مشابه زیر است:

  3. Podهایی را که این استقرار ایجاد کرده است فهرست کنید:

    kubectl get pods -l app=nginx

    خروجی مشابه زیر است:

    NAME                                READY     STATUS    RESTARTS   AGE
nginx-deployment-1771418926-7o5ns   1/1       Running   0          16h

  4. اطلاعات مربوط به یک Pod را نمایش دهید:

    kubectl describe pod <pod-name>

    در این دستور، <pod-name> نام یکی از Podهای شماست.

به‌روزرسانی استقرار

برای به‌روزرسانی استقرار می‌توانید یک فایل YAML جدید را اعمال کنید. فایل YAML زیر مشخص می‌کند که استقرار باید طوری به‌روزرسانی شود که از nginx 1.16.1 استفاده کند.

application/deployment-update.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 2
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.16.1 # Update the version of nginx from 1.14.2 to 1.16.1
        ports:
        - containerPort: 80

  1. فایل YAML جدید را اعمال کنید:

    kubectl apply -f https://k8s.io/examples/application/deployment-update.yaml

  2. مشاهده کنید که استقرار، Podهایی با نام‌های جدید ایجاد می‌کند و Podهای قدیمی را حذف می‌کند:

    kubectl get pods -l app=nginx

مقیاس‌دهی برنامه با افزایش تعداد رپلیکاها

با اعمال یک فایل YAML جدید می‌توانید تعداد Podهای Deployment خود را افزایش دهید. این فایل YAML مقدار replicas را برابر با ۴ قرار می‌دهد؛ یعنی Deployment باید چهار Pod داشته باشد:

application/deployment-scale.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 4 # Update the replicas from 2 to 4
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.16.1
        ports:
        - containerPort: 80

  1. فایل YAML جدید را اعمال کنید:

    kubectl apply -f https://k8s.io/examples/application/deployment-scale.yaml

  2. بررسی کنید که Deployment چهار Pod دارد:

    kubectl get pods -l app=nginx

    خروجی مشابه زیر است:

    NAME                               READY     STATUS    RESTARTS   AGE
nginx-deployment-148880595-4zdqq   1/1       Running   0          25s
nginx-deployment-148880595-6zgi1   1/1       Running   0          25s
nginx-deployment-148880595-fxcez   1/1       Running   0          2m
nginx-deployment-148880595-rwovn   1/1       Running   0          2m

برای آشنایی با روش‌های دقیق مقیاس‌دهی، از جمله کاهش مقیاس و مقیاس‌دهی تا صفر، به مقیاس‌دهی دستی یک Deployment مراجعه کنید.

حذف یک استقرار

استقرار را با استفاده از نام آن حذف کنید:

kubectl delete deployment nginx-deployment

ReplicationControllerها؛ روش قدیمی

روش ترجیحی برای ایجاد یک برنامهٔ تکثیرشده، استفاده از Deployment است که خود از ReplicaSet استفاده می‌کند. پیش از آنکه Deployment و ReplicaSet به کوبرنتیز افزوده شوند، برنامه‌های تکثیرشده با استفاده از ReplicationController پیکربندی می‌شدند.

گام‌های بعدی

  • دربارهٔ آبجکت‌های Deployment بیشتر بیاموزید.
  • با نحوهٔ به‌روزرسانی یک Deployment بدون وقفه در سرویس‌دهی آشنا شوید.
