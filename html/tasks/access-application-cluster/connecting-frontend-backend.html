اتصال فرانت‌اند به بک‌اند با استفاده از Serviceها

این تمرین نشان می‌دهد که چگونه یک میکروسرویس فرانت‌اند (frontend) و یک میکروسرویس بک‌اند (backend) بسازید. میکروسرویس بک‌اند یک سرویس ساده‌ی خوشامدگو (hello greeter) است. فرانت‌اند با استفاده از nginx و یک آبجکت service کوبرنتیز، بک‌اند را در دسترس قرار می‌دهد.

اهداف

  • یک میکروسرویس بک‌اند نمونه به نام hello را با استفاده از یک آبجکت deployment ایجاد و اجرا کنید.
  • از یک آبجکت Service برای ارسال ترافیک به رپلیکاهای متعدد میکروسرویس بک‌اند استفاده کنید.
  • یک میکروسرویس فرانت‌اند nginx را، باز هم با استفاده از یک آبجکت Deployment، ایجاد و اجرا کنید.
  • میکروسرویس فرانت‌اند را طوری پیکربندی کنید که ترافیک را به میکروسرویس بک‌اند بفرستد.
  • با استفاده از یک آبجکت Service از نوع type=LoadBalancer، میکروسرویس فرانت‌اند را در خارج از کلاستر در دسترس قرار دهید.

پیش از شروع

باید یک کلاستر کوبرنتیز داشته باشید و ابزار خط فرمان kubectl باید برای ارتباط با کلاستر شما پیکربندی شده باشد. توصیه می‌شود این آموزش را روی کلاستری اجرا کنید که دست‌کم دو نود داشته باشد که نقش میزبان control plane را ندارند. اگر هنوز کلاستری ندارید، می‌توانید با استفاده از minikube یکی بسازید یا از یکی از این محیط‌های آزمایشی کوبرنتیز استفاده کنید:

  • iximiuz Labs
  • Killercoda
  • KodeKloud

در این تمرین از Serviceهایی با متعادل‌کننده‌ی بار خارجی استفاده می‌شود که به محیطی نیاز دارند که از آن‌ها پشتیبانی کند. اگر محیط شما از این قابلیت پشتیبانی نمی‌کند، می‌توانید به‌جای آن از یک Service از نوع NodePort استفاده کنید.

ایجاد بک‌اند با استفاده از یک Deployment

بک‌اند یک میکروسرویس خوشامدگوی ساده است. فایل پیکربندی Deployment بک‌اند به این صورت است:

service/access/backend-deployment.yaml
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
spec:
  selector:
    matchLabels:
      app: hello
      tier: backend
      track: stable
  replicas: 3
  template:
    metadata:
      labels:
        app: hello
        tier: backend
        track: stable
    spec:
      containers:
        - name: hello
          image: "gcr.io/google-samples/hello-go-gke:1.0"
          ports:
            - name: http
              containerPort: 80
...

Deployment بک‌اند را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/service/access/backend-deployment.yaml

اطلاعات مربوط به Deployment بک‌اند را مشاهده کنید:

kubectl describe deployment backend

ایجاد آبجکت Service با نام hello

کلید ارسال درخواست از فرانت‌اند به بک‌اند، Service بک‌اند است. هر Service یک نشانی IP و یک رکورد نام DNS پایدار ایجاد می‌کند تا میکروسرویس بک‌اند همیشه در دسترس باشد. هر Service با استفاده از انتخابگرها، Podهایی را پیدا می‌کند که ترافیک را به آن‌ها هدایت می‌کند.

ابتدا فایل پیکربندی Service را بررسی کنید:

service/access/backend-service.yaml
---
apiVersion: v1
kind: Service
metadata:
  name: hello
spec:
  selector:
    app: hello
    tier: backend
  ports:
  - protocol: TCP
    port: 80
    targetPort: http
...

در فایل پیکربندی می‌بینید که Service با نام hello ترافیک را به Podهایی هدایت می‌کند که برچسب‌های app: hello و tier: backend را دارند.

Service بک‌اند را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/service/access/backend-service.yaml

در این مرحله، یک Deployment به نام backend دارید که سه رپلیکا از برنامه‌ی hello را اجرا می‌کند، و یک Service دارید که می‌تواند ترافیک را به آن‌ها هدایت کند. با این حال، این سرویس نه از خارج از کلاستر در دسترس است و نه نام آن در خارج از کلاستر قابل تفکیک (resolve) است.

ایجاد فرانت‌اند

اکنون که بک‌اند در حال اجراست، می‌توانید فرانت‌اندی بسازید که از خارج از کلاستر در دسترس باشد و با پراکسی کردن درخواست‌ها به بک‌اند، به آن متصل شود.

فرانت‌اند با استفاده از نام DNS اختصاص‌داده‌شده به Service بک‌اند، درخواست‌ها را به Podهای کارگر بک‌اند می‌فرستد. این نام DNS برابر با hello است که مقدار فیلد name در فایل پیکربندی examples/service/access/backend-service.yaml است.

Podهای موجود در Deployment فرانت‌اند، یک ایمیج nginx را اجرا می‌کنند که طوری پیکربندی شده است که درخواست‌ها را به Service بک‌اند hello پراکسی کند. فایل پیکربندی nginx به این صورت است:

service/access/frontend-nginx.conf
# The identifier Backend is internal to nginx, and used to name this specific upstream
upstream Backend {
    # hello is the internal DNS name used by the backend Service inside Kubernetes
    server hello;
}

server {
    listen 80;

    location / {
        # The following statement will proxy traffic to the upstream named Backend
        proxy_pass http://Backend;
    }
}

فرانت‌اند نیز مانند بک‌اند، یک Deployment و یک Service دارد. تفاوت مهمی که میان سرویس‌های بک‌اند و فرانت‌اند باید به آن توجه کرد این است که پیکربندی Service فرانت‌اند شامل type: LoadBalancer است؛ یعنی این Service از متعادل‌کننده‌ی باری استفاده می‌کند که ارائه‌دهنده‌ی ابری شما فراهم کرده است و از خارج از کلاستر در دسترس خواهد بود.

service/access/frontend-service.yaml
---
apiVersion: v1
kind: Service
metadata:
  name: frontend
spec:
  selector:
    app: hello
    tier: frontend
  ports:
  - protocol: "TCP"
    port: 80
    targetPort: 80
  type: LoadBalancer
...
service/access/frontend-deployment.yaml
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  selector:
    matchLabels:
      app: hello
      tier: frontend
      track: stable
  replicas: 1
  template:
    metadata:
      labels:
        app: hello
        tier: frontend
        track: stable
    spec:
      containers:
        - name: nginx
          image: "gcr.io/google-samples/hello-frontend:1.0"
          lifecycle:
            preStop:
              exec:
                command: ["/usr/sbin/nginx","-s","quit"]
...

Deployment و Service فرانت‌اند را ایجاد کنید:

kubectl apply -f https://k8s.io/examples/service/access/frontend-deployment.yaml
kubectl apply -f https://k8s.io/examples/service/access/frontend-service.yaml

خروجی تأیید می‌کند که هر دو منبع ایجاد شده‌اند:

deployment.apps/frontend created
service/frontend created
توجه:

پیکربندی nginx درون ایمیج کانتینر قرار داده شده است. روش بهتر برای این کار، استفاده از یک ConfigMap است تا بتوانید پیکربندی را آسان‌تر تغییر دهید.

تعامل با Service فرانت‌اند

پس از ایجاد یک Service از نوع LoadBalancer، می‌توانید با این دستور نشانی IP خارجی را پیدا کنید:

kubectl get service frontend --watch

این دستور پیکربندی Service با نام frontend را نمایش می‌دهد و تغییرات آن را زیر نظر می‌گیرد. در ابتدا، نشانی IP خارجی به‌صورت <pending> نمایش داده می‌شود:

NAME       TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)  AGE
frontend   LoadBalancer   10.51.252.116   <pending>     80/TCP   10s

اما به‌محض اینکه یک نشانی IP خارجی فراهم شود، پیکربندی به‌روزرسانی می‌شود و نشانی IP جدید را زیر سرعنوان EXTERNAL-IP نشان می‌دهد:

NAME       TYPE           CLUSTER-IP      EXTERNAL-IP        PORT(S)  AGE
frontend   LoadBalancer   10.51.252.116   XXX.XXX.XXX.XXX    80/TCP   1m

اکنون می‌توان از این نشانی IP برای تعامل با سرویس frontend از خارج از کلاستر استفاده کرد.

ارسال ترافیک از طریق فرانت‌اند

اکنون فرانت‌اند و بک‌اند به هم متصل شده‌اند. می‌توانید با اجرای دستور curl روی نشانی IP خارجی Service فرانت‌اند، به این نقطه‌ی پایانی (endpoint) درخواست بفرستید.

curl http://${EXTERNAL_IP} # replace this with the EXTERNAL-IP you saw earlier

خروجی، پیامی را نشان می‌دهد که بک‌اند تولید کرده است:

{"message":"Hello"}

پاکسازی

برای حذف Serviceها، این دستور را وارد کنید:

kubectl delete services frontend backend

برای حذف Deploymentها، ReplicaSetها و Podهایی که برنامه‌های بک‌اند و فرانت‌اند را اجرا می‌کنند، این دستور را وارد کنید:

kubectl delete deployment frontend backend

گام‌های بعدی

  • درباره‌ی Serviceها بیشتر بیاموزید.
  • درباره‌ی ConfigMapها بیشتر بیاموزید.
  • درباره‌ی DNS برای Service و Podها بیشتر بیاموزید.
