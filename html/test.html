صفحهٔ آزمون اولیهٔ مستندات

این صفحه دو هدف دارد:

  • نشان می‌دهد مستندات کوبرنتیز چگونه از Markdown استفاده می‌کند.
  • سندی برای «آزمون اولیه» (smoke test) فراهم می‌کند تا بتوان تغییرات HTML، CSS و قالب‌هایی را که بر کل مستندات اثر می‌گذارند آزمایش کرد.

عناصر درون‌خطی

عناصر درون‌خطی در میان متن یک پاراگراف، مورد فهرست، هشدار یا هر عنصر سطح بلوک دیگری ظاهر می‌شوند.

لورم ایپسوم متن ساختگی با تولید سادگی نامفهوم از صنعت چاپ و با استفاده از طراحان گرافیک است. چاپگرها و متون بلکه روزنامه و مجله در ستون و سطرآنچنان که لازم است و برای شرایط فعلی تکنولوژی مورد نیاز و کاربردهای متنوع با هدف بهبود ابزارهای کاربردی می‌باشد. کتاب‌های زیادی در شصت و سه درصد گذشته، حال و آینده شناخت فراوان جامعه و متخصصان را می‌طلبد تا با نرم‌افزارها شناخت بیشتری را برای طراحان رایانه‌ای علی‌الخصوص طراحان خلاقی و فرهنگ پیشرو در زبان فارسی ایجاد کرد.

سبک‌های متن درون‌خطی

در Markdown می‌توانید از سبک‌های متنی گوناگونی مانند موارد زیر استفاده کنید:

- **bold**
- _italic_
- ***bold italic***
- ~~strikethrough~~
- <u>underline</u>
- _<u>underline italic</u>_
- **<u>underline bold</u>**
- ***<u>underline bold italic</u>***
- `monospace text`
- **`monospace bold`**

فهرست‌ها

زبان Markdown قواعد سخت‌گیرانه‌ای برای پردازش فهرست‌ها ندارد. هنگام مهاجرت از Jekyll به Hugo، برخی از فهرست‌ها خراب شدند. برای اصلاح آن‌ها، نکات زیر را رعایت کنید:

  • مطمئن شوید که موارد زیرفهرست را ۲ فاصله تورفتگی داده‌اید.

  • برای پایان دادن به یک فهرست و آغاز فهرستی دیگر، باید میان دو فهرست، در یک خط جدید و چسبیده به حاشیهٔ چپ، یک بلوک توضیح HTML قرار دهید. در غیر این صورت، هر تعداد خط خالی هم که میان فهرست اول و دوم بگذارید، فهرست اول پایان نمی‌یابد.

فهرست‌های نشانه‌دار

می‌توانید در Markdown به این شکل یک فهرست نشانه‌دار اضافه کنید:

* This is another list item in the same list.
- You can mix `-` and `*`.
  - To make a sub-item, indent two spaces.
    - This is a sub-sub-item. Indent two more spaces.
  - Another sub-item.

بلوک‌های کد

برای ساختن بلوک کد می‌توانید آن را میان دو خط که هر کدام سه نویسهٔ بک‌تیک دارند، یکی پیش و دیگری پس از بلوک، قرار دهید. برای بلوک‌های کد فقط از بک‌تیک (حصار کد) استفاده کنید. با این روش می‌توانید زبان کد درون بلوک را مشخص کنید تا برجسته‌سازی نحوی فعال شود. این روش همچنین از روش تورفتگی پیش‌بینی‌پذیرتر است.

this is a code block created by back-ticks

روش بک‌تیک چند مزیت دارد:

  • تقریباً همیشه درست کار می‌کند.
  • هنگام مشاهدهٔ کد منبع، فشرده‌تر است.
  • می‌توانید زبان بلوک کد را برای برجسته‌سازی نحوی مشخص کنید.
  • پایان مشخصی دارد. گاهی روش تورفتگی در زبان‌هایی که فاصله‌گذاری در آن‌ها اهمیت دارد، مانند Python یا YAML، خراب می‌شود.

برای مشخص کردن زبان بلوک کد، نام زبان را بلافاصله پس از نخستین گروه بک‌تیک‌ها بنویسید:

ls -l

زبان‌های رایجی که در بلوک‌های کد مستندات کوبرنتیز به کار می‌روند عبارت‌اند از:

  • bash / shell (هر دو یکسان عمل می‌کنند)
  • go
  • json
  • yaml
  • xml
  • none (برجسته‌سازی نحوی را برای آن بلوک غیرفعال می‌کند)

بلوک‌های کد حاوی shortcodeهای Hugo

برای نمایش shortcodeهای خام Hugo، مانند نمونهٔ بالا، و جلوگیری از تفسیر آن‌ها به دست Hugo، درست پس از نویسهٔ < و پیش از نویسهٔ > از توضیح به سبک C استفاده کنید. نمونهٔ زیر این روش را نشان می‌دهد (منبع Markdown این صفحه را ببینید).



<div class="callout note"><div class="callout-title"></div>

This is a warning.

</div>

پیوندها

برای قالب‌بندی یک پیوند، متن پیوند را درون کروشه و مقصد پیوند را پس از آن درون پرانتز بنویسید.

  • [Link to Kubernetes.io](https://kubernetes.io/) یا
  • [Relative link to Kubernetes.io](/)

می‌توانید از HTML نیز استفاده کنید، اما این روش توصیه نمی‌شود. برای نمونه: <a href="https://kubernetes.io/">Link to Kubernetes.io</a>.

تصاویر

برای قالب‌بندی یک تصویر، از نحوی مشابه پیوندها استفاده کنید، اما یک نویسهٔ ! در ابتدای آن بگذارید. درون کروشه متن جایگزین (alt) تصویر قرار می‌گیرد. همیشه سعی کنید متن جایگزین بنویسید تا کاربران صفحه‌خوان‌ها نیز از تصویر بهره ببرند.

![pencil icon](/images/pencil.png)

خروجی:

برای مشخص کردن ویژگی‌های بیشتر، مانند عرض، عنوان، زیرنویس و غیره، از shortcode مربوط به figure استفاده کنید که بر برچسب HTML <img> ترجیح دارد. همچنین اگر می‌خواهید تصویر یک فراپیوند هم باشد، به‌جای قرار دادن کل figure در نحو پیوند Markdown، که در ادامه نشان داده شده است، از ویژگی link استفاده کنید.

حتی اگر از shortcode مربوط به figure استفاده نکنید، باز هم تصویر می‌تواند پیوند باشد. این بار آیکون مداد به وب‌سایت کوبرنتیز پیوند داده شده است. کروشه‌های بیرونی کل برچسب تصویر را در بر می‌گیرند و مقصد پیوند در پرانتز انتهایی قرار دارد.

جدول‌ها

در جدول‌های ساده، هر سطر در یک خط نوشته می‌شود و ستون‌ها با نویسهٔ | از هم جدا می‌شوند. سرستون با سلول‌هایی که فقط دست‌کم سه نویسهٔ - دارند از بدنهٔ جدول جدا می‌شود. برای نگهداری آسان‌تر، سعی کنید همهٔ جداکننده‌های سلول‌ها را هم‌تراز نگه دارید، حتی اگر لازم باشد فاصلهٔ اضافی بگذارید.

سلول سرستون ۱ سلول سرستون ۲
سلول بدنه ۱ سلول بدنه ۲

سرستون اختیاری است. هر متنی که با | جدا شده باشد به‌صورت جدول نمایش داده می‌شود.

جدول‌های Markdown در کار با عناصر سطح بلوک درون سلول‌ها، مانند موارد فهرست، بلوک‌های کد یا چند پاراگراف، مشکل دارند. برای جدول‌های پیچیده یا بسیار عریض، به‌جای آن از HTML استفاده کنید.

<table>
<thead>
  <tr>
    <th>Heading cell 1</th>
    <th>Heading cell 2</th>
  </tr>
</thead>
<tbody>
  <tr>
    <td>Body cell 1</td>
    <td>Body cell 2</td>
  </tr>
</tbody>
</table>
