امنیت

مفاهیمی برای ایمن نگه داشتن بار کاری cloud-native شما.

این بخش از مستندات کوبرنتیز با هدف کمک به شما برای یادگیری اجرای ایمن‌تر بارهای کاری و آشنایی با جنبه‌های اساسی ایمن نگه داشتن یک کلاستر کوبرنتیز تهیه شده است.

کوبرنتیز بر پایهٔ یک معماری cloud-native بنا شده است و از توصیه‌های CNCF دربارهٔ روش‌های خوب امنیت اطلاعات cloud-native بهره می‌گیرد.

برای آشنایی با زمینهٔ گسترده‌تر دربارهٔ نحوهٔ ایمن‌سازی کلاستر و برنامه‌هایی که روی آن اجرا می‌کنید، امنیت Cloud Native و کوبرنتیز را مطالعه کنید.

سازوکارهای امنیتی کوبرنتیز {#security-mechanisms}

کوبرنتیز شامل چندین API و کنترل امنیتی، و نیز روش‌هایی برای تعریف سیاست‌ها است که می‌توانند بخشی از نحوهٔ مدیریت امنیت اطلاعات شما را تشکیل دهند.

حفاظت از control plane

یک سازوکار امنیتی کلیدی برای هر کلاستر کوبرنتیز، کنترل دسترسی به API کوبرنتیز است.

کوبرنتیز از شما انتظار دارد که TLS را پیکربندی کرده و از آن برای فراهم کردن رمزگذاری داده‌ها در حال انتقال درون control plane، و میان control plane و کلاینت‌های آن استفاده کنید. همچنین می‌توانید رمزگذاری در حالت سکون را برای داده‌های ذخیره‌شده در control plane کوبرنتیز فعال کنید؛ این موضوع جدا از استفاده از رمزگذاری در حالت سکون برای داده‌های بارهای کاری خودتان است که آن نیز ممکن است ایدهٔ خوبی باشد.

Secretها

API مربوط به Secret حفاظت پایه‌ای را برای مقادیر پیکربندی‌ای که نیازمند محرمانگی هستند فراهم می‌کند.

حفاظت از بار کاری

استانداردهای امنیتی Pod را اعمال کنید تا اطمینان حاصل شود که پادها و کانتینرهای آن‌ها به‌درستی ایزوله شده‌اند. همچنین در صورت نیاز می‌توانید از RuntimeClassها برای تعریف ایزوله‌سازی سفارشی استفاده کنید.

سیاست‌های شبکه به شما امکان می‌دهند ترافیک شبکه را میان پادها، یا میان پادها و شبکهٔ خارج از کلاستر، کنترل کنید.

می‌توانید کنترل‌های امنیتی را از اکوسیستم گسترده‌تر مستقر کنید تا کنترل‌های پیشگیرانه یا کشف‌کننده را پیرامون پادها، کانتینرهای آن‌ها و ایمیج‌هایی که در آن‌ها اجرا می‌شوند پیاده‌سازی کنید.

کنترل پذیرش {#admission-control}

کنترل‌کننده‌های پذیرش (Admission controllers) افزونه‌هایی هستند که درخواست‌های API کوبرنتیز را رهگیری می‌کنند و می‌توانند درخواست‌ها را بر اساس فیلدهای مشخصی در درخواست اعتبارسنجی یا تغییر (mutate) دهند. طراحی سنجیدهٔ این کنترل‌کننده‌ها به جلوگیری از اختلال‌های ناخواسته هنگام تغییر APIهای کوبرنتیز در به‌روزرسانی‌های نسخه کمک می‌کند. برای ملاحظات طراحی، به روش‌های خوب برای Admission Webhook مراجعه کنید.

ممیزی

ثبت لاگ ممیزی (audit logging) در کوبرنتیز مجموعه‌ای مرتبط با امنیت و به ترتیب زمانی از رکوردها را فراهم می‌کند که توالی اقدامات انجام‌شده در یک کلاستر را مستند می‌کند. کلاستر فعالیت‌های ایجادشده توسط کاربران، توسط برنامه‌هایی که از API کوبرنتیز استفاده می‌کنند، و توسط خود control plane را ممیزی می‌کند.

سیاست‌ها

می‌توانید سیاست‌های امنیتی را با استفاده از سازوکارهای بومی کوبرنتیز تعریف کنید، مانند NetworkPolicy (کنترل اعلانی بر فیلتر کردن بسته‌های شبکه) یا ValidatingAdmissionPolicy (محدودیت‌های اعلانی بر تغییراتی که افراد می‌توانند با استفاده از API کوبرنتیز ایجاد کنند).

با این حال، می‌توانید به پیاده‌سازی‌های سیاست از اکوسیستم گسترده‌تر پیرامون کوبرنتیز نیز تکیه کنید. کوبرنتیز سازوکارهای توسعه‌پذیری را فراهم می‌کند تا آن پروژه‌های اکوسیستم بتوانند کنترل‌های سیاستی خود را بر بازبینی کد منبع، تأیید ایمیج کانتینر، کنترل‌های دسترسی API، شبکه و موارد دیگر پیاده‌سازی کنند.

برای اطلاعات بیشتر دربارهٔ سازوکارهای سیاست و کوبرنتیز، سیاست‌ها را مطالعه کنید.

گام‌های بعدی

با موضوعات مرتبط امنیتی کوبرنتیز آشنا شوید:

  • ایمن‌سازی کلاستر
  • آسیب‌پذیری‌های شناخته‌شده در کوبرنتیز (و پیوندهایی به اطلاعات بیشتر)
  • رمزگذاری داده‌ها در حال انتقال برای control plane
  • رمزگذاری داده‌ها در حالت سکون
  • کنترل دسترسی به API کوبرنتیز
  • سیاست‌های شبکه برای پادها
  • Secretها در کوبرنتیز
  • استانداردهای امنیتی Pod
  • RuntimeClassها
