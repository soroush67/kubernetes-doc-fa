Volume Populatorها و منابع داده

این سند volume populatorها و منابع داده (data sources) را در کوبرنتیز شرح می‌دهد. آشنایی با حجم‌های پایدار توصیه می‌شود.

هنگامی که یک PersistentVolumeClaim ایجاد می‌کنید، حجمی که کوبرنتیز برای آن تأمین می‌کند معمولاً خالی آغاز می‌شود. یک منبع داده به شما امکان می‌دهد به‌جای آن درخواست کنید که حجم جدید از پیش با داده‌های موجود پر شود. Volume populatorها کنترل‌کننده‌هایی هستند که این پر کردن را بر اساس منبع داده‌ای که PersistentVolumeClaim به آن ارجاع می‌دهد انجام می‌دهند.

کوبرنتیز پشتیبانی داخلی از منابع داده‌ای دارد که یک حجم موجود را شبیه‌سازی (clone) می‌کنند یا یک volume snapshot را بازیابی می‌کنند. volume populatorهای سفارشی این سازوکار را گسترش می‌دهند. منبع داده یک منبع سفارشی است، یعنی آبجکتی که نوع آن توسط یک CustomResourceDefinition تعریف شده است. یک کنترل‌کنندهٔ populator مراقب PersistentVolumeClaimهایی است که به چنین منبعی ارجاع می‌دهند و حجم جدید را از آن پر می‌کند.

Volume populatorها و منابع داده

وضعیت ویژگی: Kubernetes v1.24 [beta] (بتا)

کوبرنتیز از volume populatorهای سفارشی پشتیبانی می‌کند. برای استفاده از volume populatorهای سفارشی، باید feature gate AnyVolumeDataSource را برای kube-apiserver و kube-controller-manager فعال کنید.

Volume populatorها از فیلدی در spec مربوط به PVC به نام dataSourceRef بهره می‌برند. برخلاف فیلد dataSource که تنها می‌تواند شامل ارجاعی به یک PersistentVolumeClaim دیگر یا به یک VolumeSnapshot باشد، فیلد dataSourceRef می‌تواند شامل ارجاعی به هر آبجکتی در همان فضای نام باشد، به‌جز آبجکت‌های هسته (core) غیر از PVCها. برای کلاسترهایی که این feature gate در آن‌ها فعال است، استفاده از dataSourceRef بر dataSource ترجیح دارد.

ارجاع‌های منبع داده

فیلد dataSourceRef تقریباً همانند فیلد dataSource رفتار می‌کند. اگر یکی مشخص شود و دیگری نه، API server به هر دو فیلد مقدار یکسانی می‌دهد. هیچ‌یک از این دو فیلد پس از ایجاد قابل تغییر نیست و تلاش برای مشخص کردن مقادیر متفاوت برای این دو فیلد به خطای اعتبارسنجی منجر می‌شود. بنابراین این دو فیلد همیشه محتوای یکسانی خواهند داشت.

دو تفاوت میان فیلد dataSourceRef و فیلد dataSource وجود دارد که کاربران باید از آن‌ها آگاه باشند:

  • فیلد dataSource مقادیر نامعتبر را نادیده می‌گیرد (گویی فیلد خالی است)، در حالی که فیلد dataSourceRef هرگز مقادیر را نادیده نمی‌گیرد و در صورت استفاده از مقدار نامعتبر باعث خطا می‌شود. مقادیر نامعتبر هر آبجکت هسته (آبجکت‌های بدون apiGroup) به‌جز PVCها هستند.
  • فیلد dataSourceRef می‌تواند شامل انواع مختلفی از آبجکت‌ها باشد، در حالی که فیلد dataSource تنها PVCها و VolumeSnapshotها را مجاز می‌داند.

هنگامی که قابلیت CrossNamespaceVolumeDataSource فعال باشد، تفاوت‌های دیگری نیز وجود دارد:

  • فیلد dataSource تنها آبجکت‌های محلی را مجاز می‌داند، در حالی که فیلد dataSourceRef آبجکت‌ها را در هر فضای نامی مجاز می‌داند.
  • هنگامی که فضای نام مشخص شود، dataSource و dataSourceRef همگام‌سازی نمی‌شوند.

کاربران باید در کلاسترهایی که feature gate در آن‌ها فعال است همیشه از dataSourceRef استفاده کنند و در کلاسترهایی که فعال نیست به dataSource بازگردند. تحت هیچ شرایطی لازم نیست به هر دو فیلد نگاه کرد. مقادیر تکراری با معناشناسی اندکی متفاوت تنها برای سازگاری با نسخه‌های قبلی وجود دارند. به‌ویژه، ترکیبی از کنترل‌کننده‌های قدیمی‌تر و جدیدتر می‌توانند با یکدیگر همکاری کنند، زیرا فیلدها یکسان هستند.

استفاده از volume populatorها

Volume populatorها کنترل‌کننده‌هایی هستند که می‌توانند حجم‌های غیرخالی ایجاد کنند که محتوای آن‌ها توسط یک منبع سفارشی (Custom Resource) تعیین می‌شود. کاربران با ارجاع به یک منبع سفارشی از طریق فیلد dataSourceRef یک حجم پرشده ایجاد می‌کنند:

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: populated-pvc
spec:
  dataSourceRef:
    name: example-name
    kind: ExampleDataSource
    apiGroup: example.storage.k8s.io
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi

از آنجا که volume populatorها مؤلفه‌هایی خارجی هستند، تلاش برای ایجاد PVCی که از یکی از آن‌ها استفاده می‌کند ممکن است در صورت نصب نبودن همهٔ مؤلفه‌های درست با شکست مواجه شود. کنترل‌کننده‌های خارجی باید رویدادهایی روی PVC تولید کنند تا بازخوردی دربارهٔ وضعیت ایجاد ارائه دهند، از جمله هشدارهایی در صورتی که PVC به دلیل نبود یک مؤلفه قابل ایجاد نباشد.

می‌توانید کنترل‌کنندهٔ آلفای volume data source validator را در کلاستر خود نصب کنید. این کنترل‌کننده در صورتی که هیچ populatorی برای مدیریت آن نوع منبع داده ثبت نشده باشد، رویدادهای هشدار روی PVC تولید می‌کند. هنگامی که populator مناسبی برای یک PVC نصب شده باشد، گزارش رویدادهای مربوط به ایجاد حجم و مشکلات حین این فرایند بر عهدهٔ همان کنترل‌کنندهٔ populator است.

منابع داده میان فضاهای نام

وضعیت ویژگی: Kubernetes v1.26 [alpha] (آلفا)

کوبرنتیز از منابع داده حجم میان فضاهای نام پشتیبانی می‌کند. برای استفاده از منابع داده حجم میان فضاهای نام، باید feature gateهای AnyVolumeDataSource و CrossNamespaceVolumeDataSource را برای kube-apiserver و kube-controller-manager فعال کنید. همچنین باید feature gate CrossNamespaceVolumeDataSource را برای csi-provisioner فعال کنید.

فعال کردن feature gate CrossNamespaceVolumeDataSource به شما امکان می‌دهد یک فضای نام را در فیلد dataSourceRef مشخص کنید.

توجه:

هنگامی که برای یک منبع داده حجم فضای نام مشخص می‌کنید، کوبرنتیز پیش از پذیرش ارجاع، وجود یک ReferenceGrant را در فضای نام دیگر بررسی می‌کند. ReferenceGrant بخشی از APIهای افزونهٔ gateway.networking.k8s.io است. برای جزئیات، ReferenceGrant را در مستندات Gateway API ببینید. این بدان معناست که پیش از استفاده از این سازوکار، باید کلاستر کوبرنتیز خود را دست‌کم با ReferenceGrant از Gateway API گسترش دهید.

استفاده از یک منبع داده حجم میان فضاهای نام

وضعیت ویژگی: Kubernetes v1.26 [alpha] (آلفا)

یک ReferenceGrant ایجاد کنید تا مالک فضای نام بتواند ارجاع را بپذیرد. یک حجم پرشده را با مشخص کردن یک منبع داده حجم میان فضاهای نام از طریق فیلد dataSourceRef تعریف می‌کنید. باید از پیش یک ReferenceGrant معتبر در فضای نام مبدأ داشته باشید:

apiVersion: gateway.networking.k8s.io/v1beta1
kind: ReferenceGrant
metadata:
  name: allow-ns1-pvc
  namespace: default
spec:
  from:
  - group: ""
    kind: PersistentVolumeClaim
    namespace: ns1
  to:
  - group: snapshot.storage.k8s.io
    kind: VolumeSnapshot
    name: new-snapshot-demo

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: foo-pvc
  namespace: ns1
spec:
  storageClassName: example
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
  dataSourceRef:
    apiGroup: snapshot.storage.k8s.io
    kind: VolumeSnapshot
    name: new-snapshot-demo
    namespace: default
  volumeMode: Filesystem

گام‌های بعدی

  • دربارهٔ حجم‌های پایدار بیاموزید.
  • دربارهٔ شبیه‌سازی حجم CSI بیاموزید.
  • دربارهٔ Volume Snapshotها بیاموزید.
  • دربارهٔ feature gateهای ذکرشده در این صفحه بخوانید.
