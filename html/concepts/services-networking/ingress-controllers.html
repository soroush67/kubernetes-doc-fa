کنترل‌کننده‌های Ingress

برای آنکه یک [Ingress](/docs/concepts/services-networking/ingress/) در کلاستر شما کار کند، باید یک _کنترل‌کنندهٔ ingress_ در حال اجرا باشد. شما باید دست‌کم یک کنترل‌کنندهٔ ingress انتخاب کنید و از راه‌اندازی آن در کلاستر خود اطمینان حاصل کنید. این صفحه کنترل‌کننده‌های ingress رایجی را که می‌توانید مستقر کنید، فهرست می‌کند.

توجه:

پروژهٔ کوبرنتیز استفاده از Gateway را به‌جای Ingress توصیه می‌کند. API مربوط به Ingress منجمد شده است.

این به آن معناست که:

  • API مربوط به Ingress به‌طور عمومی در دسترس (GA) است و مشمول تضمین‌های پایداری مربوط به APIهای عمومی در دسترس است. پروژهٔ کوبرنتیز هیچ برنامه‌ای برای حذف Ingress از کوبرنتیز ندارد.
  • API مربوط به Ingress دیگر توسعه داده نمی‌شود و هیچ تغییر یا به‌روزرسانی دیگری در آن اعمال نخواهد شد.

کنترل‌کننده‌های Ingress

کوبرنتیز به‌عنوان یک پروژه، از کنترل‌کننده‌های ingress ‏AWS و GCE پشتیبانی و آن‌ها را نگهداری می‌کند.

کنترل‌کننده‌های ingress شخص ثالث

  • AKS Application Gateway Ingress Controller یک کنترل‌کنندهٔ ingress است که Azure Application Gateway را پیکربندی می‌کند.
  • Alibaba Cloud API Gateway Ingress یک کنترل‌کنندهٔ ingress است که Alibaba Cloud Native API Gateway را پیکربندی می‌کند؛ این محصول نسخهٔ تجاری Higress نیز هست.
  • کنترل‌کنندهٔ ingress ‏Apache APISIX یک کنترل‌کنندهٔ ingress مبتنی بر Apache APISIX است.
  • Avi Kubernetes Operator با استفاده از VMware NSX Advanced Load Balancer توزیع بار در لایه‌های L4 تا L7 را فراهم می‌کند.
  • BFE Ingress Controller یک کنترل‌کنندهٔ ingress مبتنی بر BFE است.
  • BunkerWeb Ingress Controller یک کنترل‌کنندهٔ ingress برای BunkerWeb است که یک WAF (دیوارهٔ آتش برنامهٔ وب) مبتنی بر nginx است.
  • Cilium Ingress Controller یک کنترل‌کنندهٔ ingress است که بر پایهٔ Cilium کار می‌کند.
  • کنترل‌کنندهٔ ingress ‏Citrix با Citrix Application Delivery Controller کار می‌کند.
  • Contour یک کنترل‌کنندهٔ ingress مبتنی بر Envoy است.
  • Emissary-Ingress API Gateway یک کنترل‌کنندهٔ ingress مبتنی بر Envoy است.
  • EnRoute یک API gateway مبتنی بر Envoy است که می‌تواند به‌عنوان کنترل‌کنندهٔ ingress اجرا شود.
  • F5 BIG-IP Container Ingress Services for Kubernetes به شما امکان می‌دهد با استفاده از یک Ingress، سرورهای مجازی F5 BIG-IP را پیکربندی کنید.
  • FortiADC Ingress Controller از منابع Ingress کوبرنتیز پشتیبانی می‌کند و به شما امکان می‌دهد آبجکت‌های FortiADC را از درون کوبرنتیز مدیریت کنید
  • Gloo یک کنترل‌کنندهٔ ingress متن‌باز مبتنی بر Envoy است که قابلیت‌های API gateway را ارائه می‌کند.
  • Higress یک API gateway مبتنی بر Envoy است که می‌تواند به‌عنوان کنترل‌کنندهٔ ingress اجرا شود.
  • HAProxy Ingress Controller for Kubernetes یک کنترل‌کنندهٔ ingress برای HAProxy است.
  • Istio Ingress یک کنترل‌کنندهٔ ingress مبتنی بر Istio است.
  • Kong Ingress Controller for Kubernetes یک کنترل‌کنندهٔ ingress است که Kong Gateway را هدایت می‌کند.
  • Kusk Gateway یک کنترل‌کنندهٔ ingress مبتنی بر OpenAPI است که بر پایهٔ Envoy ساخته شده است.
  • N42 Gateway یک کنترل‌کنندهٔ Ingress و Gateway API برای HAProxy است.
  • NGINX Ingress Controller for Kubernetes با وب‌سرور NGINX (به‌عنوان پراکسی) کار می‌کند.
  • ngrok-operator یک کنترل‌کننده برای ngrok است که از هر دو API ‏Ingress و Gateway برای افزودن دسترسی عمومی امن به Serviceهای K8s شما پشتیبانی می‌کند.
  • OCI Native Ingress Controller یک کنترل‌کنندهٔ Ingress برای Oracle Cloud Infrastructure است که به شما امکان می‌دهد OCI Load Balancer را مدیریت کنید.
  • OpenNJet Ingress Controller یک کنترل‌کنندهٔ ingress مبتنی بر OpenNJet است.
  • Pomerium Ingress Controller مبتنی بر Pomerium است که سیاست دسترسی آگاه از زمینه (context-aware) ارائه می‌کند.
  • Skipper یک مسیریاب HTTP و reverse proxy برای ترکیب سرویس‌ها، از جمله موارد استفاده‌ای مانند Ingress کوبرنتیز، است که به‌صورت یک کتابخانه برای ساخت پراکسی سفارشی شما طراحی شده است.
  • Traefik Kubernetes Ingress provider یک کنترل‌کنندهٔ ingress برای پراکسی Traefik است.
  • Tyk Operator با استفاده از منابع سفارشی، Ingress را گسترش می‌دهد تا قابلیت‌های مدیریت API را به Ingress بیاورد. Tyk Operator با Tyk Gateway متن‌باز و control plane ‏Tyk Cloud کار می‌کند.
  • Voyager یک کنترل‌کنندهٔ ingress برای HAProxy است.
  • Wallarm Ingress Controller یک کنترل‌کنندهٔ Ingress است که قابلیت‌های WAAP (WAF) و امنیت API را فراهم می‌کند.

استفاده از چند کنترل‌کنندهٔ Ingress

می‌توانید هر تعداد کنترل‌کنندهٔ ingress را با استفاده از ingress class درون یک کلاستر مستقر کنید. به .metadata.name منبع ingress class خود توجه کنید. هنگام ایجاد یک ingress، برای تعیین فیلد ingressClassName روی آبجکت Ingress خود به آن نام نیاز خواهید داشت (به مرجع IngressSpec v1 مراجعه کنید). ingressClassName جایگزین روش قدیمی‌تر حاشیه‌نویسی است.

اگر برای یک Ingress هیچ IngressClassای تعیین نکنید و کلاستر شما دقیقاً یک IngressClass داشته باشد که به‌عنوان پیش‌فرض علامت‌گذاری شده است، کوبرنتیز IngressClass پیش‌فرض کلاستر را بر Ingress اعمال می‌کند. برای علامت‌گذاری یک IngressClass به‌عنوان پیش‌فرض، حاشیه‌نویسی ingressclass.kubernetes.io/is-default-class را با مقدار رشته‌ای "true" روی آن IngressClass تنظیم می‌کنید.

در حالت ایدئال، همهٔ کنترل‌کننده‌های ingress باید این مشخصات را برآورده کنند، اما کنترل‌کننده‌های ingress مختلف اندکی متفاوت عمل می‌کنند.

توجه:

حتماً مستندات کنترل‌کنندهٔ ingress خود را مرور کنید تا از نکات احتیاطی انتخاب آن آگاه شوید.
