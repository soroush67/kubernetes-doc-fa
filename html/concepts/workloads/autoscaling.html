مقیاس‌پذیری خودکار بارهای کاری

با مقیاس‌پذیری خودکار می‌توانید بارهای کاری خود را به روش‌های گوناگون به‌طور خودکار به‌روزرسانی کنید. به این ترتیب کلاستر شما می‌تواند با انعطاف و کارایی بیشتری به تغییرات تقاضای منابع واکنش نشان دهد.

در کوبرنتیز می‌توانید یک بار کاری را بر اساس تقاضای فعلی منابع مقیاس‌دهی (scale) کنید. به این ترتیب کلاستر شما می‌تواند با انعطاف و کارایی بیشتری به تغییرات تقاضای منابع واکنش نشان دهد.

هنگام مقیاس‌دهی یک بار کاری، می‌توانید تعداد رونوشت‌هایی (replica) را که بار کاری مدیریت می‌کند افزایش یا کاهش دهید، یا منابع در دسترس رونوشت‌ها را درجا (in-place) تنظیم کنید.

به روش نخست مقیاس‌دهی افقی (horizontal scaling) و به روش دوم مقیاس‌دهی عمودی (vertical scaling) گفته می‌شود.

بسته به مورد استفاده‌تان، روش‌های دستی و خودکاری برای مقیاس‌دهی بارهای کاری وجود دارد.

مقیاس‌دهی دستی بارهای کاری

کوبرنتیز از مقیاس‌دهی دستی بارهای کاری پشتیبانی می‌کند. مقیاس‌دهی افقی را می‌توان با رابط خط فرمان kubectl انجام داد. برای مقیاس‌دهی عمودی باید تعریف منبع بار کاری خود را وصله (patch) کنید.

در ادامه نمونه‌هایی از هر دو راهبرد آمده است.

  • مقیاس‌دهی افقی: اجرای چند نمونه از برنامه
  • مقیاس‌دهی عمودی: تغییر اندازه منابع CPU و حافظه اختصاص‌یافته به کانتینرها

مقیاس‌دهی خودکار بارهای کاری

کوبرنتیز از مقیاس‌دهی خودکار بارهای کاری نیز پشتیبانی می‌کند که موضوع اصلی این صفحه است.

مفهوم مقیاس‌پذیری خودکار (Autoscaling) در کوبرنتیز به توانایی به‌روزرسانی خودکار آبجکتی اشاره دارد که مجموعه‌ای از Podها را مدیریت می‌کند (برای مثال یک Deployment).

مقیاس‌دهی افقی بارهای کاری

در کوبرنتیز می‌توانید با استفاده از HorizontalPodAutoscaler (HPA) یک بار کاری را به‌طور خودکار به‌صورت افقی مقیاس‌دهی کنید.

این قابلیت به‌صورت یک منبع API کوبرنتیز و یک کنترل‌کننده پیاده‌سازی شده است و به‌طور دوره‌ای تعداد رونوشت‌های یک بار کاری را تنظیم می‌کند تا با میزان مصرف مشاهده‌شده منابع، مانند مصرف CPU یا حافظه، مطابقت داشته باشد.

یک آموزش گام‌به‌گام برای پیکربندی HorizontalPodAutoscaler برای یک Deployment وجود دارد.

مقیاس‌دهی عمودی بارهای کاری

وضعیت ویژگی: Kubernetes v1.25 [stable] (پایدار)

می‌توانید با استفاده از VerticalPodAutoscaler (VPA) یک بار کاری را به‌طور خودکار به‌صورت عمودی مقیاس‌دهی کنید. برخلاف HPA، ابزار VPA به‌طور پیش‌فرض همراه کوبرنتیز ارائه نمی‌شود، بلکه افزونه‌ای است که ممکن است شما یا مدیر کلاستر پیش از استفاده لازم باشد آن را مستقر کنید.

پس از نصب، می‌توانید برای بارهای کاری خود CustomResourceDefinitionها (CRD) ایجاد کنید که تعیین می‌کنند منابع رونوشت‌های مدیریت‌شده چگونه و چه زمانی مقیاس‌دهی شوند.

توجه:

برای کارکرد VPA باید Metrics Server روی کلاستر شما نصب شده باشد.

مقیاس‌دهی عمودی درجای Pod

وضعیت ویژگی: Kubernetes [] ()

تا نسخه 1.37 کوبرنتیز، VPA از تغییر اندازه درجای Podها پشتیبانی نمی‌کند، اما کار روی این یکپارچه‌سازی در جریان است. برای تغییر اندازه دستی و درجای Podها، به تغییر اندازه درجای منابع کانتینر مراجعه کنید.

مقیاس‌پذیری خودکار بر اساس اندازه کلاستر

برای بارهای کاری‌ای که باید بر اساس اندازه کلاستر مقیاس‌دهی شوند (برای مثال cluster-dns یا سایر مؤلفه‌های سیستمی)، می‌توانید از Cluster Proportional Autoscaler استفاده کنید. این ابزار نیز مانند VPA بخشی از هسته کوبرنتیز نیست و به‌صورت پروژه‌ای مستقل در GitHub میزبانی می‌شود.

ابزار Cluster Proportional Autoscaler تعداد نودها و هسته‌های قابل زمان‌بندی را زیر نظر می‌گیرد و تعداد رونوشت‌های بار کاری هدف را متناسب با آن مقیاس‌دهی می‌کند.

اگر تعداد رونوشت‌ها باید ثابت بماند، می‌توانید با استفاده از Cluster Proportional Vertical Autoscaler بارهای کاری خود را متناسب با اندازه کلاستر به‌صورت عمودی مقیاس‌دهی کنید. این پروژه در حال حاضر در مرحله بتا است و در GitHub در دسترس است.

در حالی که Cluster Proportional Autoscaler تعداد رونوشت‌های یک بار کاری را مقیاس‌دهی می‌کند، Cluster Proportional Vertical Autoscaler درخواست‌های منابع یک بار کاری (برای مثال یک Deployment یا DaemonSet) را بر اساس تعداد نودها و/یا هسته‌های کلاستر تنظیم می‌کند.

مقیاس‌پذیری خودکار رویدادمحور

همچنین می‌توان بارهای کاری را بر اساس رویدادها مقیاس‌دهی کرد؛ برای مثال با استفاده از Kubernetes Event Driven Autoscaler (KEDA).

پروژه KEDA یک پروژه فارغ‌التحصیل‌شده در CNCF است که به شما امکان می‌دهد بارهای کاری خود را بر اساس تعداد رویدادهایی که باید پردازش شوند، برای مثال تعداد پیام‌های موجود در یک صف، مقیاس‌دهی کنید. طیف گسترده‌ای از آداپتورها برای منابع رویداد مختلف وجود دارد که می‌توانید از میان آن‌ها انتخاب کنید.

مقیاس‌پذیری خودکار بر اساس زمان‌بندی

راهبرد دیگر برای مقیاس‌دهی بارهای کاری، زمان‌بندی عملیات مقیاس‌دهی است؛ برای مثال برای کاهش مصرف منابع در ساعات کم‌بار.

مشابه مقیاس‌پذیری خودکار رویدادمحور، این رفتار را می‌توان با استفاده از KEDA همراه با مقیاس‌دهنده Cron آن به دست آورد. مقیاس‌دهنده Cron به شما امکان می‌دهد زمان‌بندی‌ها (و مناطق زمانی) را برای کاهش یا افزایش مقیاس بارهای کاری خود تعریف کنید.

مقیاس‌دهی زیرساخت کلاستر

اگر مقیاس‌دهی بارهای کاری برای برآوردن نیازهای شما کافی نباشد، می‌توانید خود زیرساخت کلاستر را نیز مقیاس‌دهی کنید.

مقیاس‌دهی زیرساخت کلاستر معمولاً به معنای افزودن یا حذف نودها است. برای اطلاعات بیشتر، مقیاس‌پذیری خودکار نودها را بخوانید.
