مقیاس‌گذاری خودکار بارهای کاری

با مقیاس‌گذاری خودکار (autoscaling) می‌توانید بارهای کاری خود را به یک شکل یا شکل دیگر به‌طور خودکار به‌روزرسانی کنید. این کار به کلاستر شما امکان می‌دهد با انعطاف و کارایی بیشتری به تغییرات تقاضای منابع واکنش نشان دهد.

در کوبرنتیز می‌توانید یک بار کاری را بسته به تقاضای فعلی منابع مقیاس‌گذاری کنید. این کار به کلاستر شما امکان می‌دهد با انعطاف و کارایی بیشتری به تغییرات تقاضای منابع واکنش نشان دهد.

هنگام مقیاس‌گذاری یک بار کاری، می‌توانید تعداد replicaهایی را که آن بار کاری مدیریت می‌کند افزایش یا کاهش دهید، یا منابعِ در دسترس replicaها را به‌صورت درجا (in-place) تنظیم کنید.

رویکرد اول مقیاس‌گذاری افقی و رویکرد دوم مقیاس‌گذاری عمودی نامیده می‌شود.

بسته به مورد استفاده‌تان، روش‌های دستی و خودکاری برای مقیاس‌گذاری بارهای کاری وجود دارد.

مقیاس‌گذاری دستی بارهای کاری

کوبرنتیز از مقیاس‌گذاری دستی بارهای کاری پشتیبانی می‌کند. مقیاس‌گذاری افقی را می‌توان با استفاده از CLI به نام kubectl انجام داد. برای مقیاس‌گذاری عمودی، باید تعریف منبع (resource definition) بار کاری خود را patch کنید.

برای مشاهده مثال‌هایی از هر دو راهبرد، موارد زیر را ببینید.

  • مقیاس‌گذاری افقی: اجرای چند نمونه از برنامه شما
  • مقیاس‌گذاری عمودی: تغییر اندازه منابع CPU و حافظه اختصاص‌یافته به کانتینرها

مقیاس‌گذاری خودکار بارهای کاری

کوبرنتیز همچنین از مقیاس‌گذاری خودکار بارهای کاری پشتیبانی می‌کند که محور اصلی این صفحه است.

مفهوم مقیاس‌گذاری خودکار (Autoscaling) در کوبرنتیز به توانایی به‌روزرسانی خودکار آبجکتی اشاره دارد که مجموعه‌ای از Podها را مدیریت می‌کند (برای مثال یک Deployment).

مقیاس‌گذاری افقی بارهای کاری

در کوبرنتیز می‌توانید با استفاده از HorizontalPodAutoscaler (HPA) یک بار کاری را به‌طور خودکار و افقی مقیاس‌گذاری کنید.

این قابلیت به‌صورت یک منبع API کوبرنتیز و یک کنترل‌کننده پیاده‌سازی شده است و به‌طور دوره‌ای تعداد replicaهای یک بار کاری را تنظیم می‌کند تا با میزان مصرف مشاهده‌شده منابع، مانند مصرف CPU یا حافظه، مطابقت داشته باشد.

یک آموزش گام‌به‌گام برای پیکربندی HorizontalPodAutoscaler برای یک Deployment وجود دارد.

مقیاس‌گذاری عمودی بارهای کاری

وضعیت ویژگی: Kubernetes v1.25 [stable] (پایدار)

می‌توانید با استفاده از VerticalPodAutoscaler (VPA) یک بار کاری را به‌طور خودکار و عمودی مقیاس‌گذاری کنید. برخلاف HPA، VPA به‌طور پیش‌فرض همراه کوبرنتیز نیست، بلکه یک افزونه (add-on) است که ممکن است شما یا مدیر کلاستر پیش از استفاده از آن لازم باشد آن را مستقر کنید.

پس از نصب، این افزونه به شما امکان می‌دهد برای بارهای کاری خود CustomResourceDefinitionها (CRDها) ایجاد کنید که تعیین می‌کنند منابع replicaهای مدیریت‌شده چگونه و چه زمانی مقیاس‌گذاری شوند.

توجه:

برای اینکه VPA کار کند، باید Metrics Server روی کلاستر شما نصب شده باشد.

مقیاس‌گذاری عمودی درجای Pod

وضعیت ویژگی: Kubernetes [] ()

از کوبرنتیز 1.37، VPA از تغییر اندازه درجای Podها پشتیبانی نمی‌کند، اما کار روی این یکپارچه‌سازی در حال انجام است. برای تغییر اندازه دستی Podها به‌صورت درجا، تغییر اندازه درجای منابع کانتینر را ببینید.

مقیاس‌گذاری خودکار بر اساس اندازه کلاستر

برای بارهای کاری که باید بر اساس اندازه کلاستر مقیاس‌گذاری شوند (برای مثال cluster-dns یا سایر اجزای سیستمی)، می‌توانید از Cluster Proportional Autoscaler استفاده کنید. درست مانند VPA، این ابزار بخشی از هسته کوبرنتیز نیست و به‌عنوان یک پروژه مستقل در GitHub میزبانی می‌شود.

Cluster Proportional Autoscaler تعداد نودهای قابل زمان‌بندی و هسته‌ها را زیر نظر می‌گیرد و تعداد replicaهای بار کاری هدف را بر همین اساس مقیاس‌گذاری می‌کند.

اگر تعداد replicaها باید ثابت بماند، می‌توانید بارهای کاری خود را بر اساس اندازه کلاستر به‌صورت عمودی مقیاس‌گذاری کنید؛ برای این کار از Cluster Proportional Vertical Autoscaler استفاده کنید. این پروژه در حال حاضر در مرحله بتا است و در GitHub در دسترس است.

در حالی که Cluster Proportional Autoscaler تعداد replicaهای یک بار کاری را مقیاس‌گذاری می‌کند، Cluster Proportional Vertical Autoscaler درخواست‌های منابع (resource requests) یک بار کاری (برای مثال یک Deployment یا DaemonSet) را بر اساس تعداد نودها و/یا هسته‌ها در کلاستر تنظیم می‌کند.

مقیاس‌گذاری خودکار مبتنی بر رویداد

همچنین می‌توان بارهای کاری را بر اساس رویدادها مقیاس‌گذاری کرد، برای مثال با استفاده از Kubernetes Event Driven Autoscaler (KEDA).

KEDA یک پروژه فارغ‌التحصیل‌شده (graduated) در CNCF است که به شما امکان می‌دهد بارهای کاری خود را بر اساس تعداد رویدادهایی که باید پردازش شوند، مثلاً تعداد پیام‌های موجود در یک صف، مقیاس‌گذاری کنید. طیف گسترده‌ای از آداپتورها برای منابع رویداد مختلف وجود دارد که می‌توانید از میان آن‌ها انتخاب کنید.

مقیاس‌گذاری خودکار بر اساس زمان‌بندی

راهبرد دیگر برای مقیاس‌گذاری بارهای کاری، زمان‌بندی عملیات مقیاس‌گذاری است، برای مثال به‌منظور کاهش مصرف منابع در ساعات کم‌باری.

مشابه مقیاس‌گذاری خودکار مبتنی بر رویداد، چنین رفتاری را می‌توان با استفاده از KEDA به‌همراه Cron scaler آن به دست آورد. Cron scaler به شما امکان می‌دهد زمان‌بندی‌ها (و مناطق زمانی) را برای افزایش یا کاهش مقیاس بارهای کاری خود تعریف کنید.

مقیاس‌گذاری زیرساخت کلاستر

اگر مقیاس‌گذاری بارهای کاری برای رفع نیازهای شما کافی نیست، می‌توانید خود زیرساخت کلاستر را نیز مقیاس‌گذاری کنید.

مقیاس‌گذاری زیرساخت کلاستر معمولاً به معنای افزودن یا حذف نودها است. برای اطلاعات بیشتر، مقیاس‌گذاری خودکار نود را مطالعه کنید.
