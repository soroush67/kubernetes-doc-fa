سازمان‌دهی دسترسی به کلاستر با استفاده از فایل‌های kubeconfig

از فایل‌های kubeconfig برای سازمان‌دهی اطلاعات مربوط به کلاسترها، کاربران، فضاهای نام و سازوکارهای احراز هویت استفاده کنید. ابزار خط فرمان kubectl از فایل‌های kubeconfig برای یافتن اطلاعاتی استفاده می‌کند که برای انتخاب یک کلاستر و برقراری ارتباط با سرور API آن کلاستر نیاز دارد.

توجه:

فایلی که برای پیکربندی دسترسی به کلاسترها استفاده می‌شود، فایل kubeconfig نامیده می‌شود. این روشی عمومی برای اشاره به فایل‌های پیکربندی است. به این معنا نیست که فایلی به نام kubeconfig وجود دارد.

هشدار:

تنها از فایل‌های kubeconfig از منابع مورد اعتماد استفاده کنید. استفاده از یک فایل kubeconfig که به‌طور ویژه دست‌کاری شده است می‌تواند به اجرای کد مخرب یا افشای فایل‌ها منجر شود. اگر ناچارید از یک فایل kubeconfig نامطمئن استفاده کنید، ابتدا آن را با دقت بازرسی کنید، همان‌گونه که یک اسکریپت پوسته را بازرسی می‌کنید.

به‌طور پیش‌فرض، kubectl به دنبال فایلی به نام config در دایرکتوری $HOME/.kube می‌گردد. می‌توانید با تنظیم متغیر محیطی KUBECONFIG یا با تنظیم پرچم --kubeconfig فایل‌های kubeconfig دیگری را مشخص کنید.

برای دستورالعمل‌های گام‌به‌گام دربارهٔ ایجاد و مشخص کردن فایل‌های kubeconfig، پیکربندی دسترسی به چندین کلاستر را ببینید.

پشتیبانی از چندین کلاستر، کاربر و سازوکار احراز هویت

فرض کنید چندین کلاستر دارید و کاربران و اجزای شما به شیوه‌های گوناگونی احراز هویت می‌کنند. برای نمونه:

  • یک kubelet در حال اجرا ممکن است با استفاده از گواهی‌ها احراز هویت کند.
  • یک کاربر ممکن است با استفاده از توکن‌ها احراز هویت کند.
  • مدیران ممکن است مجموعه‌هایی از گواهی‌ها داشته باشند که به کاربران منفرد ارائه می‌کنند.

با فایل‌های kubeconfig می‌توانید کلاسترها، کاربران و فضاهای نام خود را سازمان‌دهی کنید. همچنین می‌توانید contextهایی تعریف کنید تا به‌سرعت و به‌آسانی میان کلاسترها و فضاهای نام جابه‌جا شوید.

Context

عنصر context در یک فایل kubeconfig برای گروه‌بندی پارامترهای دسترسی زیر یک نام مناسب استفاده می‌شود. هر context سه پارامتر دارد: cluster، namespace و user. به‌طور پیش‌فرض، ابزار خط فرمان kubectl برای برقراری ارتباط با کلاستر از پارامترهای context جاری استفاده می‌کند.

برای انتخاب context جاری:

kubectl config use-context

متغیر محیطی KUBECONFIG

متغیر محیطی KUBECONFIG فهرستی از فایل‌های kubeconfig را نگه می‌دارد. در لینوکس و مک، اعضای این فهرست با دونقطه از هم جدا می‌شوند. در ویندوز، اعضای فهرست با نقطه‌ویرگول از هم جدا می‌شوند. وجود متغیر محیطی KUBECONFIG الزامی نیست. اگر متغیر محیطی KUBECONFIG وجود نداشته باشد، kubectl از فایل kubeconfig پیش‌فرض، یعنی $HOME/.kube/config، استفاده می‌کند.

اگر متغیر محیطی KUBECONFIG وجود داشته باشد، kubectl از پیکربندی مؤثری استفاده می‌کند که حاصل ادغام فایل‌های فهرست‌شده در متغیر محیطی KUBECONFIG است.

ادغام فایل‌های kubeconfig

برای مشاهدهٔ پیکربندی خود، این فرمان را وارد کنید:

kubectl config view

همان‌طور که پیش‌تر شرح داده شد، خروجی ممکن است از یک فایل kubeconfig منفرد باشد، یا ممکن است حاصل ادغام چندین فایل kubeconfig باشد.

قواعدی که kubectl هنگام ادغام فایل‌های kubeconfig به کار می‌برد عبارت‌اند از:

  1. اگر پرچم --kubeconfig تنظیم شده باشد، تنها از فایل مشخص‌شده استفاده کنید. ادغام نکنید. تنها یک نمونه از این پرچم مجاز است.

    در غیر این صورت، اگر متغیر محیطی KUBECONFIG تنظیم شده باشد، از آن به‌عنوان فهرستی از فایل‌هایی که باید ادغام شوند استفاده کنید. فایل‌های فهرست‌شده در متغیر محیطی KUBECONFIG را طبق این قواعد ادغام کنید:

    • نام فایل‌های خالی را نادیده بگیرید.
    • برای فایل‌هایی که محتوایشان قابل deserialize شدن نیست خطا تولید کنید.
    • نخستین فایلی که یک مقدار یا کلید نگاشت مشخص را تنظیم کند برنده است.
    • هرگز مقدار یا کلید نگاشت را تغییر ندهید. مثال: context نخستین فایلی را که current-context را تنظیم می‌کند حفظ کنید. مثال: اگر دو فایل یک red-user را مشخص کنند، تنها از مقادیر red-user فایل نخست استفاده کنید. حتی اگر فایل دوم مدخل‌های بدون تعارضی زیر red-user داشته باشد، آن‌ها را کنار بگذارید.

    برای نمونه‌ای از تنظیم متغیر محیطی KUBECONFIG، تنظیم متغیر محیطی KUBECONFIG را ببینید.

    در غیر این صورت، از فایل kubeconfig پیش‌فرض، یعنی $HOME/.kube/config، بدون ادغام استفاده کنید.

  2. context مورد استفاده را بر اساس نخستین مورد منطبق در این زنجیره تعیین کنید:

    1. در صورت وجود، از پرچم خط فرمان --context استفاده کنید.
    2. از current-context در فایل‌های kubeconfig ادغام‌شده استفاده کنید.

    در این مرحله، context خالی مجاز است.

  3. cluster و user را تعیین کنید. در این مرحله، ممکن است context وجود داشته باشد یا نداشته باشد. cluster و user را بر اساس نخستین مورد منطبق در این زنجیره تعیین کنید، که دو بار اجرا می‌شود: یک بار برای user و یک بار برای cluster:

    1. در صورت وجود، از یک پرچم خط فرمان استفاده کنید: --user یا --cluster.
    2. اگر context خالی نباشد، user یا cluster را از context بگیرید.

    در این مرحله، user و cluster می‌توانند خالی باشند.

  4. اطلاعات واقعی cluster مورد استفاده را تعیین کنید. در این مرحله، ممکن است اطلاعات cluster وجود داشته باشد یا نداشته باشد. هر بخش از اطلاعات cluster را بر اساس این زنجیره بسازید؛ نخستین مورد منطبق برنده است:

    1. در صورت وجود، از پرچم‌های خط فرمان استفاده کنید: --server، --certificate-authority، --insecure-skip-tls-verify.
    2. اگر ویژگی‌هایی از اطلاعات cluster در فایل‌های kubeconfig ادغام‌شده وجود داشته باشد، از آن‌ها استفاده کنید.
    3. اگر مکان سرور وجود نداشته باشد، با شکست مواجه شوید.

  5. اطلاعات واقعی user مورد استفاده را تعیین کنید. اطلاعات user را با همان قواعد اطلاعات cluster بسازید، با این تفاوت که برای هر user تنها یک روش احراز هویت مجاز است:

    1. در صورت وجود، از پرچم‌های خط فرمان استفاده کنید: --client-certificate، --client-key، --username، --password، --token.
    2. از فیلدهای user در فایل‌های kubeconfig ادغام‌شده استفاده کنید.
    3. اگر دو روش متعارض وجود داشته باشد، با شکست مواجه شوید.

  6. برای هر اطلاعاتی که همچنان وجود ندارد، از مقادیر پیش‌فرض استفاده کنید و در صورت لزوم اطلاعات احراز هویت را از کاربر درخواست کنید.

ارجاع به فایل‌ها

ارجاع‌های فایل و مسیر در یک فایل kubeconfig نسبت به مکان فایل kubeconfig سنجیده می‌شوند. ارجاع‌های فایل در خط فرمان نسبت به دایرکتوری کاری جاری سنجیده می‌شوند. در $HOME/.kube/config، مسیرهای نسبی به‌صورت نسبی و مسیرهای مطلق به‌صورت مطلق ذخیره می‌شوند.

پراکسی

می‌توانید kubectl را طوری پیکربندی کنید که برای هر کلاستر با استفاده از proxy-url در فایل kubeconfig خود از یک پراکسی استفاده کند، به این صورت:

apiVersion: v1
kind: Config

clusters:
- cluster:
    proxy-url: http://proxy.example.org:3128
    server: https://k8s.example.org/k8s/clusters/c-xxyyzz
  name: development

users:
- name: developer

contexts:
- context:
  name: development
