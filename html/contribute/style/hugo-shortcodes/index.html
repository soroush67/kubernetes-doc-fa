شورت‌کدهای سفارشی Hugo

این صفحه شورت‌کدهای سفارشی Hugo را توضیح می‌دهد که می‌توان از آن‌ها در مستندات Markdown کوبرنتیز استفاده کرد.

درباره شورت‌کدها بیشتر در مستندات Hugo بخوانید.

وضعیت ویژگی (Feature state) {#feature-state}

در یک صفحه Markdown (فایل .md) در این وب‌سایت می‌توانید یک شورت‌کد اضافه کنید تا نسخه و وضعیت ویژگیِ مستندشده را نمایش دهد.

نمونه نمایشی وضعیت ویژگی {#feature-state-demo}

در ادامه نمونه‌ای از قطعه کد وضعیت ویژگی آمده است که ویژگی را به‌صورت پایدار در آخرین نسخه کوبرنتیز نمایش می‌دهد.



<div class="feature-state">وضعیت ویژگی: <span class="ltr" dir="ltr">Kubernetes  [stable]</span> (پایدار)</div>

نتیجه نمایش:

وضعیت ویژگی: Kubernetes [stable] (پایدار)

مقادیر معتبر برای state عبارت‌اند از:

  • alpha
  • beta
  • deprecated
  • stable

کد وضعیت ویژگی {#feature-state-code}

نسخه کوبرنتیزِ نمایش‌داده‌شده به‌صورت پیش‌فرض همان نسخه صفحه یا وب‌سایت است. می‌توانید نسخه وضعیت ویژگی را با ارسال پارامتر for_k8s_version به شورت‌کد تغییر دهید. برای مثال:



<div class="feature-state">وضعیت ویژگی: <span class="ltr" dir="ltr">Kubernetes v1.10 [beta]</span> (بتا)</div>

نتیجه نمایش:

وضعیت ویژگی: Kubernetes v1.10 [beta] (بتا)

دریافت وضعیت ویژگی از فایل توضیحات {#feature-state-retrieval-from-description-file}

برای تعیین پویای وضعیت ویژگی، از پارامتر feature_gate_name شورت‌کد استفاده کنید. جزئیات وضعیت ویژگی از فایل توضیحات feature gate متناظر که در content/en/docs/reference/command-line-tools-reference/feature-gates/ قرار دارد استخراج می‌شود. برای مثال:



<div class="feature-state">وضعیت ویژگی: <span class="ltr" dir="ltr">Kubernetes  []</span> ()</div>

وضعیت ویژگی: Kubernetes [] ()

واژه‌نامه {#glossary}

دو شورت‌کد واژه‌نامه وجود دارد: glossary_tooltip و glossary_definition.

می‌توانید با یک شورت‌کد درج‌شونده به اصطلاحات واژه‌نامه ارجاع دهید؛ این شورت‌کد به‌صورت خودکار محتوا را به‌روزرسانی می‌کند و با پیوندهای مربوط از واژه‌نامه ما جایگزین می‌کند. وقتی نشانگر ماوس روی یک اصطلاح واژه‌نامه قرار می‌گیرد، مدخل واژه‌نامه یک راهنمای شناور (tooltip) نمایش می‌دهد. اصطلاح واژه‌نامه همچنین به‌صورت پیوند نمایش داده می‌شود.

علاوه بر درج‌هایی که tooltip دارند، می‌توانید تعریف‌های واژه‌نامه را در محتوای صفحه نیز بازاستفاده کنید.

داده خام اصطلاحات واژه‌نامه در دایرکتوری واژه‌نامه نگهداری می‌شود و برای هر اصطلاح یک فایل محتوا وجود دارد.

نمونه نمایشی واژه‌نامه {#glossary-demo}

برای مثال، درج زیر در Markdown به کلاستر همراه با یک tooltip تبدیل می‌شود:

<span class="term" title="cluster">cluster</span>

این یک تعریف کوتاه از واژه‌نامه است:

<em>(تعریف واژه‌نامه: cluster)</em>

که به این صورت نمایش داده می‌شود: (تعریف واژه‌نامه: cluster)

همچنین می‌توانید تعریف کامل را درج کنید:

<em>(تعریف واژه‌نامه: cluster)</em>

که به این صورت نمایش داده می‌شود: (تعریف واژه‌نامه: cluster)

عنوان جدول‌ها (Table captions) {#table-captions}

با افزودن عنوان به جدول می‌توانید دسترسی‌پذیری جدول‌ها را برای صفحه‌خوان‌ها بهبود دهید. برای افزودن caption به یک جدول، جدول را درون شورت‌کد table قرار دهید و عنوان را با پارامتر caption مشخص کنید.

توجه:

عنوان جدول‌ها برای صفحه‌خوان‌ها قابل مشاهده است، اما در نمایش استاندارد HTML نامرئی است.

یک مثال:


Parameter | Description | Default
:---------|:------------|:-------
`timeout` | The timeout for requests | `30s`
`logLevel` | The log level for log output | `INFO`

جدول نمایش‌داده‌شده به این شکل است:

Parameter Description Default
timeout The timeout for requests 30s
logLevel The log level for log output INFO

اگر HTML جدول را بررسی کنید، باید این المان را بلافاصله پس از المان آغازین <table> ببینید:

<caption style="display: none;">Configuration parameters</caption>

تب‌ها (Tabs) {#tabs}

در یک صفحه Markdown (فایل .md) در این وب‌سایت می‌توانید یک مجموعه تب اضافه کنید تا گونه‌های مختلف یک راه‌حل را نمایش دهد.

شورت‌کد tabs این پارامترها را می‌پذیرد:

  • name: نامی که روی تب نمایش داده می‌شود.
  • codelang: اگر محتوای داخلی را به شورت‌کد tab بدهید، می‌توانید به Hugo بگویید برای هایلایت کردن از چه زبان کدی استفاده کند.
  • include: فایلی که باید در تب درج شود. اگر تب در یک leaf bundle از Hugo قرار داشته باشد، فایل -- که می‌تواند هر نوع MIME پشتیبانی‌شده توسط Hugo باشد -- در خود bundle جست‌وجو می‌شود. در غیر این صورت، صفحه محتوایی که باید درج شود نسبت به صفحه جاری جست‌وجو می‌شود. توجه کنید که با include هیچ محتوای داخلی شورت‌کد ندارید و باید از نحو خودبسته (self-closing) استفاده کنید. برای مثال، `
Content File #1

. زبان باید با codelang` مشخص شود، در غیر این صورت زبان بر اساس نام فایل تعیین می‌شود. فایل‌های غیرمحتوایی به‌صورت پیش‌فرض هایلایت کد می‌شوند.

  • اگر محتوای داخلی شما Markdown است، باید برای احاطه کردن تب از جداکننده % استفاده کنید. برای مثال، This is **markdown**
  • می‌توانید گونه‌های ذکرشده در بالا را درون یک مجموعه تب با هم ترکیب کنید.

در ادامه نمونه‌ای از شورت‌کد tabs آمده است.

فایل‌های کد منبع {#source-code-files}

می‌توانید از شورت‌کد `` برای درج محتوای یک فایل در یک بلوک کد استفاده کنید تا کاربران بتوانند محتوای آن را دانلود یا در کلیپ‌بورد خود کپی کنند. این شورت‌کد زمانی به کار می‌رود که محتوای فایل نمونه عمومی و قابل استفاده مجدد باشد و بخواهید کاربران خودشان آن را امتحان کنند.

این شورت‌کد دو پارامتر نام‌دار می‌پذیرد: language و file. پارامتر اجباری file برای مشخص کردن مسیر فایلی که نمایش داده می‌شود استفاده می‌شود. پارامتر اختیاری language برای مشخص کردن زبان برنامه‌نویسی فایل به کار می‌رود. اگر پارامتر language ارائه نشود، شورت‌کد تلاش می‌کند زبان را بر اساس پسوند فایل حدس بزند.

برای مثال:

خروجی به این صورت است:

application/deployment-scale.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 4 # Update the replicas from 2 to 4
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.16.1
        ports:
        - containerPort: 80

هنگام افزودن یک فایل نمونه جدید، مانند یک فایل YAML، فایل را در یکی از زیردایرکتوری‌های <LANG>/examples/ ایجاد کنید، که <LANG> زبان صفحه است. در Markdown صفحه خود از شورت‌کد code استفاده کنید:

که <RELATIVE-PATH> مسیر فایل نمونه‌ای است که باید درج شود، نسبت به دایرکتوری examples. شورت‌کد زیر به یک فایل YAML در مسیر /content/en/examples/configmap/configmaps.yaml ارجاع می‌دهد.

شورت‌کد قدیمی در حال جایگزینی با است. در مستندات جدید از استفاده کنید (نه یا ``).

نشانگر محتوای شخص ثالث {#third-party-content-marker}

اجرای کوبرنتیز به نرم‌افزارهای شخص ثالث نیاز دارد. برای مثال: معمولاً باید یک سرور DNS به کلاستر خود اضافه کنید تا تفکیک نام (name resolution) کار کند.

وقتی به نرم‌افزار شخص ثالث پیوند می‌دهیم یا به‌گونه‌ای دیگر به آن اشاره می‌کنیم، از راهنمای محتوا پیروی می‌کنیم و آن موارد شخص ثالث را نیز علامت‌گذاری می‌کنیم.

استفاده از این شورت‌کدها یک سلب مسئولیت (disclaimer) به هر صفحه مستنداتی که از آن‌ها استفاده می‌کند اضافه می‌کند.

فهرست‌ها {#third-party-content-list}

برای فهرستی از چند مورد شخص ثالث، این را اضافه کنید:

درست زیر عنوان بخشی که همه موارد را در بر می‌گیرد.

موارد منفرد {#third-party-content-item}

اگر فهرستی دارید که بیشتر موارد آن به نرم‌افزارهای داخل پروژه اشاره می‌کنند (برای مثال: خود کوبرنتیز و مؤلفه جداگانه Descheduler)، باید از شکل دیگری استفاده کنید.

شورت‌کد زیر را اضافه کنید:

رشته‌های نسخه {#version-strings}

برای تولید یک رشته نسخه جهت درج در مستندات، می‌توانید از میان چند شورت‌کد نسخه انتخاب کنید. هر شورت‌کد نسخه، رشته‌ای را نمایش می‌دهد که از مقدار یک پارامتر نسخه در فایل پیکربندی وب‌سایت، یعنی hugo.toml، به دست می‌آید. دو پارامتر نسخه که بیشتر استفاده می‌شوند latest و version هستند.

v1.37

شورت‌کد v1.37 مقدار نسخه جاری مستندات کوبرنتیز را از پارامتر وب‌سایت version تولید می‌کند. شورت‌کد param نام یک پارامتر وب‌سایت را می‌پذیرد که در اینجا version است.

توجه:

در مستندات منتشرشده قبلی، مقادیر پارامترهای latest و version یکسان نیستند. پس از انتشار یک نسخه جدید، latest افزایش می‌یابد و مقدار version برای مجموعه مستندات بدون تغییر باقی می‌ماند. برای مثال، یک نسخه منتشرشده قبلی از مستندات، version را v1.19 و latest را v1.20 نمایش می‌دهد.
