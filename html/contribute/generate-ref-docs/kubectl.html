تولید مستندات مرجع برای فرمان‌های kubectl

این صفحه نحوهٔ تولید مرجع فرمان‌های kubectl را نشان می‌دهد.

توجه:

این مبحث نحوهٔ تولید مستندات مرجع برای فرمان‌های kubectl مانند kubectl apply و kubectl taint را نشان می‌دهد. این مبحث نحوهٔ تولید صفحهٔ مرجع گزینه‌های kubectl را توضیح نمی‌دهد. برای آشنایی با نحوهٔ تولید صفحهٔ مرجع گزینه‌های kubectl، به تولید صفحات مرجع برای مؤلفه‌ها و ابزارهای کوبرنتیز مراجعه کنید.

پیش از شروع

راه‌اندازی مخزن‌های محلی

یک فضای کاری محلی ایجاد کنید و GOPATH خود را تنظیم کنید:

mkdir -p $HOME/<workspace>

export GOPATH=$HOME/<workspace>

یک نسخهٔ محلی (clone) از مخزن‌های زیر تهیه کنید:

go get -u github.com/spf13/pflag
go get -u github.com/spf13/cobra
go get -u gopkg.in/yaml.v2
go get -u github.com/kubernetes-sigs/reference-docs

اگر مخزن kubernetes/website را هنوز ندارید، اکنون آن را دریافت کنید:

git clone https://github.com/<your-username>/website $GOPATH/src/github.com/<your-username>/website

یک نسخه از مخزن kubernetes/kubernetes را با نام k8s.io/kubernetes تهیه کنید:

git clone https://github.com/kubernetes/kubernetes $GOPATH/src/k8s.io/kubernetes

بستهٔ spf13 را از مسیر $GOPATH/src/k8s.io/kubernetes/vendor/github.com حذف کنید:

rm -rf $GOPATH/src/k8s.io/kubernetes/vendor/github.com/spf13

مخزن kubernetes/kubernetes کد منبع kubectl و kustomize را فراهم می‌کند.

  • پوشهٔ پایهٔ نسخهٔ محلی خود از مخزن kubernetes/kubernetes را مشخص کنید. برای مثال، اگر مخزن را با مرحلهٔ قبل دریافت کرده باشید، پوشهٔ پایهٔ شما $GOPATH/src/k8s.io/kubernetes است. در مراحل بعدی، از این پوشهٔ پایه با نام <k8s-base> یاد می‌شود.

  • پوشهٔ پایهٔ نسخهٔ محلی خود از مخزن kubernetes/website را مشخص کنید. برای مثال، اگر مخزن را با مرحلهٔ قبل دریافت کرده باشید، پوشهٔ پایهٔ شما $GOPATH/src/github.com/<your-username>/website است. در مراحل بعدی، از این پوشهٔ پایه با نام <web-base> یاد می‌شود.

  • پوشهٔ پایهٔ نسخهٔ محلی خود از مخزن kubernetes-sigs/reference-docs را مشخص کنید. برای مثال، اگر مخزن را با مرحلهٔ قبل دریافت کرده باشید، پوشهٔ پایهٔ شما $GOPATH/src/github.com/kubernetes-sigs/reference-docs است. در مراحل بعدی، از این پوشهٔ پایه با نام <rdocs-base> یاد می‌شود.

در مخزن محلی k8s.io/kubernetes، شاخهٔ موردنظر را checkout کنید و مطمئن شوید که به‌روز است. برای مثال، اگر می‌خواهید مستندات کوبرنتیز 1.37.0 را تولید کنید، می‌توانید از این فرمان‌ها استفاده کنید:

cd <k8s-base>
git checkout v1.37.0
git pull https://github.com/kubernetes/kubernetes 1.37.0

اگر نیازی به ویرایش کد منبع kubectl ندارید، دستورالعمل‌های بخش تنظیم متغیرهای ساخت را دنبال کنید.

ویرایش کد منبع kubectl

مستندات مرجع فرمان‌های kubectl به‌طور خودکار از کد منبع kubectl تولید می‌شود. اگر می‌خواهید مستندات مرجع را تغییر دهید، نخستین گام تغییر یک یا چند توضیح (comment) در کد منبع kubectl است. این تغییر را در مخزن محلی kubernetes/kubernetes خود اعمال کنید و سپس یک درخواست ادغام (pull request) به شاخهٔ master مخزن github.com/kubernetes/kubernetes ارسال کنید.

PR 56673 نمونه‌ای از یک درخواست ادغام است که یک اشتباه تایپی را در کد منبع kubectl اصلاح می‌کند.

درخواست ادغام خود را پیگیری کنید و به نظرات بازبینان پاسخ دهید. این پیگیری را تا زمانی ادامه دهید که درخواست ادغام شما در شاخهٔ هدف مخزن kubernetes/kubernetes ادغام شود.

انتقال گزینشی (cherry pick) تغییر به یک شاخهٔ انتشار

اکنون تغییر شما در شاخهٔ master قرار دارد که برای توسعهٔ انتشار بعدی کوبرنتیز استفاده می‌شود. اگر می‌خواهید تغییرتان در مستندات نسخه‌ای از کوبرنتیز که پیش‌تر منتشر شده است نیز دیده شود، باید پیشنهاد دهید که تغییرتان به‌صورت گزینشی به شاخهٔ انتشار منتقل شود.

برای مثال، فرض کنید شاخهٔ master برای توسعهٔ کوبرنتیز 1.37 استفاده می‌شود و شما می‌خواهید تغییرتان را به شاخهٔ release-1.37 منتقل کنید. برای آشنایی با نحوهٔ انجام این کار، به پیشنهاد یک انتقال گزینشی مراجعه کنید.

درخواست ادغام مربوط به انتقال گزینشی را تا زمان ادغام آن در شاخهٔ انتشار پیگیری کنید.

توجه:

برای پیشنهاد یک انتقال گزینشی، باید مجوز تعیین برچسب و نقطهٔ عطف (milestone) را در درخواست ادغام خود داشته باشید. اگر این مجوزها را ندارید، باید با فردی همکاری کنید که بتواند برچسب و نقطهٔ عطف را برای شما تعیین کند.

تنظیم متغیرهای ساخت

به <rdocs-base> بروید و در خط فرمان، متغیرهای محیطی زیر را تنظیم کنید.

  • مقدار K8S_ROOT را برابر <k8s-base> قرار دهید.
  • مقدار K8S_WEBROOT را برابر <web-base> قرار دهید.
  • مقدار K8S_RELEASE را برابر نسخه‌ای از مستندات قرار دهید که می‌خواهید بسازید. برای مثال، اگر می‌خواهید مستندات کوبرنتیز 1.37 را بسازید، مقدار K8S_RELEASE را برابر 1.37 قرار دهید.

برای مثال:

export K8S_WEBROOT=$GOPATH/src/github.com/<your-username>/website
export K8S_ROOT=$GOPATH/src/k8s.io/kubernetes
export K8S_RELEASE=1.37

ایجاد یک پوشهٔ نسخه‌دار

هدف ساخت createversiondirs یک پوشهٔ نسخه‌دار ایجاد می‌کند و فایل‌های پیکربندی مرجع kubectl را در آن کپی می‌کند. نام پوشهٔ نسخه‌دار از الگوی v<major>_<minor> پیروی می‌کند.

در پوشهٔ <rdocs-base>، هدف ساخت زیر را اجرا کنید:

cd <rdocs-base>
make createversiondirs

دریافت (checkout) یک برچسب انتشار در k8s.io/kubernetes

در مخزن محلی <k8s-base>، شاخه‌ای را checkout کنید که نسخهٔ موردنظر شما از کوبرنتیز را برای مستندسازی در خود دارد. برای مثال، اگر می‌خواهید مستندات کوبرنتیز 1.37.0 را تولید کنید، برچسب v1.37 را checkout کنید. مطمئن شوید که شاخهٔ محلی شما به‌روز است.

cd <k8s-base>
git checkout v1.37.0
git pull https://github.com/kubernetes/kubernetes v1.37.0

اجرای کد تولید مستندات

در <rdocs-base> محلی خود، هدف ساخت copycli را اجرا کنید. این فرمان با کاربر root اجرا می‌شود:

cd <rdocs-base>
make copycli

فرمان copycli پوشهٔ موقت ساخت را پاک می‌کند، فایل‌های فرمان‌های kubectl را تولید می‌کند و صفحهٔ HTML گردآوری‌شدهٔ مرجع فرمان‌های kubectl را همراه با فایل‌های جانبی آن در <web-base> کپی می‌کند.

یافتن فایل‌های تولیدشده

بررسی کنید که این دو فایل تولید شده باشند:

[ -e "<rdocs-base>/gen-kubectldocs/generators/build/index.html" ] && echo "index.html built" || echo "no index.html"
[ -e "<rdocs-base>/gen-kubectldocs/generators/build/navData.js" ] && echo "navData.js built" || echo "no navData.js"

یافتن فایل‌های کپی‌شده

بررسی کنید که همهٔ فایل‌های تولیدشده در <web-base> کپی شده باشند:

cd <web-base>
git status

خروجی باید شامل فایل‌های تغییریافتهٔ زیر باشد:

static/docs/reference/generated/kubectl/kubectl-commands.html
static/docs/reference/generated/kubectl/navData.js

خروجی ممکن است شامل این فایل‌ها نیز باشد:

static/docs/reference/generated/kubectl/scroll.js
static/docs/reference/generated/kubectl/stylesheet.css
static/docs/reference/generated/kubectl/tabvisibility.js
static/docs/reference/generated/kubectl/node_modules/bootstrap/dist/css/bootstrap.min.css
static/docs/reference/generated/kubectl/node_modules/highlight.js/styles/default.css
static/docs/reference/generated/kubectl/node_modules/jquery.scrollto/jquery.scrollTo.min.js
static/docs/reference/generated/kubectl/node_modules/jquery/dist/jquery.min.js
static/docs/reference/generated/kubectl/node_modules/font-awesome/css/font-awesome.min.css

آزمایش محلی مستندات

مستندات کوبرنتیز را در <web-base> محلی خود بسازید.

cd <web-base>
git submodule update --init --recursive --depth 1 # if not already done
make container-serve

پیش‌نمایش محلی را مشاهده کنید.

افزودن و ثبت (commit) تغییرات در kubernetes/website

برای ثبت فایل‌ها، فرمان‌های git add و git commit را اجرا کنید.

ایجاد یک درخواست ادغام

یک درخواست ادغام به مخزن kubernetes/website ایجاد کنید. درخواست ادغام خود را پیگیری کنید و در صورت نیاز به نظرات بازبینی پاسخ دهید. این پیگیری را تا زمان ادغام درخواست ادامه دهید.

چند دقیقه پس از ادغام درخواست شما، مباحث مرجع به‌روزشده در مستندات منتشرشده قابل مشاهده خواهند بود.

گام‌های بعدی

  • راهنمای سریع تولید مستندات مرجع
  • تولید مستندات مرجع برای مؤلفه‌ها و ابزارهای کوبرنتیز
  • تولید مستندات مرجع برای API کوبرنتیز
