کمک به‌عنوان همیار نگارش وبلاگ

دو وبلاگ رسمی کوبرنتیز وجود دارد و CNCF نیز وبلاگ خاص خود را دارد که می‌توانید در آن نیز درباره‌ی کوبرنتیز بنویسید. برای آشنایی با این دو وبلاگ، مشارکت در وبلاگ‌های کوبرنتیز را بخوانید.

هنگامی که افراد به‌عنوان نویسنده در هر یک از این دو وبلاگ مشارکت می‌کنند، پروژه‌ی کوبرنتیز نویسندگان را به‌عنوان همیاران نگارش (writing buddies) با هم جفت می‌کند. این صفحه توضیح می‌دهد که چگونه نقش همیار را ایفا کنید.

پیش از ادامه‌ی مطالعه‌ی این صفحه، مطمئن شوید که دست‌کم خلاصه‌ای از ارسال مقاله را خوانده‌اید.

مسئولیت‌های همیار

شما به‌عنوان همیار نگارش:

  • به تیم وبلاگ کمک می‌کنید مقالات را برای ادغام و انتشار آماده کند
  • از همیار خود پشتیبانی می‌کنید تا محتوایی تولید کند که برای ادغام مناسب باشد
  • مقاله‌ای را که همیارتان نوشته است بازبینی می‌کنید

هنگامی که تیم شما را با نویسنده‌ی دیگری جفت می‌کند، هدف این است که هر دوی شما با بازبینی پیش‌نویس مقاله‌ی یکدیگر، از هم پشتیبانی کنید. بیشتر افرادی که مقالات وبلاگ کوبرنتیز را می‌خوانند متخصص نیستند؛ محتوا باید تلاش کند برای این مخاطبان قابل‌فهم باشد، یا دست‌کم به‌شکل مناسبی از خوانندگان غیرمتخصص پشتیبانی کند.

تیم وبلاگ نیز حضور دارد تا در مسیر پیش‌نویس تا انتشار به هر دوی شما کمک کند. اعضای این تیم یا خودشان مستقیماً می‌توانند مقاله‌ی شما را برای انتشار تأیید کنند، یا می‌توانند ترتیبی دهند که این تأیید انجام شود.

پشتیبانی از تیم وبلاگ

مسئولیت اصلی شما در اینجا این است که درباره‌ی ظرفیت، در دسترس بودن و پیشرفت کار خود در بازه‌ی زمانی معقولی اطلاع‌رسانی کنید. اگر هفته‌های زیادی بگذرد و همیارتان خبری از شما نداشته باشد، کل کار زمان بیشتری خواهد برد.

ویرایش مشارکتی

(این گزینه‌ی توصیه‌شده است)

تیم وبلاگ توصیه می‌کند که نویسنده‌ی اصلی مقاله ویرایش مشارکتی را با استفاده از Google Doc یا HackMD (به انتخاب خودش) راه‌اندازی کند. سپس نویسنده‌ی اصلی آن سند را با افراد زیر به اشتراک می‌گذارد:

  • هر نویسنده‌ی همکار
  • شما (همیار نگارش او)
  • در حالت ایدئال، یک فرد تعیین‌شده از تیم وبلاگ.

سپس شما به‌عنوان همیار نگارش، متن پیش‌نویس را می‌خوانید و یا مستقیماً پیشنهادهایی ارائه می‌کنید یا بازخورد خود را به شیوه‌ی دیگری می‌دهید. نویسنده‌ی وبلاگ معمولاً به نوبه‌ی خود همیار نگارش شما نیز هست، بنابراین همان نوع بازخورد را درباره‌ی پیش‌نویس مقاله‌ی وبلاگ شما ارائه خواهد کرد.

نقش شما در اینجا پیشنهاد کوچک‌ترین مجموعه‌ی تغییراتی است که مقاله را برای انتشار مناسب می‌کند. اگر نموداری واقعاً بی‌معناست، یا نوشته واقعاً نامفهوم است، بازخورد دهید. اگر درباره‌ی واژه‌گزینی یا نشانه‌گذاری اختلاف‌نظر جزئی دارید، از آن بگذرید. اجازه دهید نویسنده(گان) مقاله به سبک خودشان بنویسند، به شرط آنکه با رهنمودهای وبلاگ همسو باشند.

پس از آماده‌شدن، نویسنده‌ی اصلی یک pull request باز می‌کند و با استفاده از Markdown مقاله را ارسال می‌کند. سپس شما یک بازبینی ارائه می‌کنید.

ویرایش با Markdown / Git

برخی نویسندگان ترجیح می‌دهند با ویرایش مشارکتی شروع کنند؛ برخی دیگر دوست دارند مستقیماً سراغ GitHub بروند.

هر مسیری را که انتخاب کنند، نقش شما ارائه‌ی بازخوردی است که به تیم وبلاگ اجازه دهد تأیید ساده‌ای بدهد و تأیید کند که مقاله می‌تواند به‌عنوان پیش‌نویس ادغام شود. برای آنچه نویسندگان باید انجام دهند، ارسال مقاله به وبلاگ‌های کوبرنتیز را ببینید.

از پیشنهادهای (suggestions) GitHub برای اشاره به هرگونه تغییر لازم استفاده کنید.

هنگامی که Markdown و سایر محتوا (مانند تصاویر) درست به نظر رسیدند، یک بازبینی رسمی ارائه می‌کنید.

بازبینی pull request

از بخش وبلاگ در صفحه‌ی بازبینی pull requestها پیروی کنید.

هنگامی که فکر می‌کنید pull request باز وبلاگ به اندازه‌ی کافی برای ادغام خوب است، نظر /lgtm را به pull request اضافه کنید.

این کار به ابزار خودکارسازی مخزن (Prow) نشان می‌دهد که محتوا «به نظر من خوب است» (looks good to me). Prow کارها را به پیش می‌برد. فرمان /lgtm به شما امکان می‌دهد نظر خود را ثبت کنید، چه به‌طور رسمی عضو پروژه‌ی کوبرنتیز باشید و چه نباشید.

شما یا نویسنده(گان) مقاله باید به تیم وبلاگ اطلاع دهید که مقاله‌ای آماده‌ی تأیید نهایی است. همان‌طور که در راهنمای ارسال توضیح داده شده است، این مقاله باید از قبل در front matter با draft: true علامت‌گذاری شده باشد.

مراحل بعدی

برای شما به‌عنوان همیار نگارش، مرحله‌ی چهارمی وجود ندارد. هنگامی که pull request برای ادغام آماده شد، تیم وبلاگ (یا برای سایت مشارکت‌کنندگان، تیم اطلاع‌رسانی مشارکت‌کنندگان) ادامه‌ی کار را بر عهده می‌گیرد. ممکن است بر اساس بازخوردها لازم باشد به مرحله‌ی قبلی بازگردید، اما معمولاً می‌توانید انتظار داشته باشید که کار شما به‌عنوان همیار به پایان رسیده است.
