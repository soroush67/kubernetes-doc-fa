اطلاع‌رسانی پس از انتشار

تیم اطلاع‌رسانی انتشار (Release Comms) کوبرنتیز (بخشی از SIG Release) مسئول اعلان‌های انتشار است که در وبلاگ اصلی پروژه منتشر می‌شوند.

پس از هر انتشار، تیم اطلاع‌رسانی انتشار برای مدتی وبلاگ اصلی را در اختیار می‌گیرد و مجموعه‌ای از مقالات تکمیلی را برای توضیح یا اعلام تغییرات مرتبط با آن انتشار منتشر می‌کند. این مقالات تکمیلی اطلاع‌رسانی پس از انتشار نامیده می‌شوند.

پیوستن به اطلاع‌رسانی پس از انتشار {#opt-in}

در طول یک چرخه‌ی انتشار، شما به‌عنوان مشارکت‌کننده می‌توانید برای یک تغییر آتی در کوبرنتیز به اطلاع‌رسانی پس از انتشار بپیوندید.

برای پیوستن، یک pull request (PR) پیش‌نویس و جانگهدار (placeholder) در k/website باز می‌کنید. در ابتدا، این PR می‌تواند یک commit خالی باشد. در توضیحات PR جانگهدار خود به issue مربوط به KEP یا سایر issueهای بهبود کوبرنتیز اشاره کنید.

هنگامی که pull request پیش‌نویس را باز می‌کنید، آن را با main به‌عنوان شاخه‌ی پایه باز می‌کنید و نه با شاخه‌ی dev-1.37. این با فرایند مربوط به تغییرات نسخه‌ی آتی و قابلیت‌های جدید متفاوت است.

همچنین باید در issue مرتبط در kubernetes/enhancements نظری همراه با پیوند به PR بگذارید تا تیم اطلاع‌رسانی انتشار که این نسخه را مدیریت می‌کند مطلع شود. نظر شما به تیم کمک می‌کند ببیند که تغییر نیاز به اعلام دارد و SIG شما به این فرایند پیوسته است.

افزون بر موارد بالا، در حالت ایدئال باید از طریق Slack (کانال #release-comms) با تیم اطلاع‌رسانی انتشار تماس بگیرید تا بدانند که این کار را انجام داده‌اید و مایل به پیوستن هستید.

آماده‌سازی محتوای مقاله {#preparation}

باید فرایند معمول ارسال مقاله را دنبال کنید تا PR جانگهدار خود را به چیزی آماده‌ی بازبینی تبدیل کنید. با این حال، برای اطلاع‌رسانی پس از انتشار، ممکن است همیار نگارش نداشته باشید؛ در عوض، تیم اطلاع‌رسانی انتشار ممکن است یکی از اعضای تیم را برای راهنمایی کار شما تعیین کند.

باید commitهای pull request خود را squash کنید؛ اگر نمی‌دانید چگونه، کاملاً اشکالی ندارد که از تیم اطلاع‌رسانی انتشار یا تیم وبلاگ کمک بخواهید.

به شرط آنکه مقاله‌ی شما در front matter به‌عنوان پیش‌نویس (draft: true) علامت‌گذاری شده باشد، PR می‌تواند در هر زمانی در طول چرخه‌ی انتشار ادغام شود.

انتشار

پیش از انتشار واقعی، تیم اطلاع‌رسانی انتشار بررسی می‌کند که چه محتوایی آماده است (اگر محتوا تا مهلت مقرر آماده نباشد و استثنایی دریافت نکرده باشید، اعلان گنجانده نخواهد شد). این تیم برنامه‌ای برای مقالاتی که منتشر خواهند شد تنظیم می‌کند و pull requestهای جدیدی باز می‌کند تا آن مقالات را از پیش‌نویس به منتشرشده تبدیل کند.

احتیاط:

همه‌ی این pull requestها برای انتشار واقعی مقالات پس از انتشار باید تا زمان انجام واقعی انتشار نگه داشته شوند (فرمان Prow با نام /hold).

تأییدکنندگان تیم وبلاگ همچنان تأیید نهایی را برای ارتقای محتوا از پیش‌نویس به پذیرفته‌شده برای انتشار ارائه می‌کنند. پیش از روز انتشار، PR (یا PRهای) انتشار این اعلان‌ها باید برچسب‌های LGTM («به نظر من خوب است») و approved را، همراه با برچسب do-not-merge/hold داشته باشند تا اطمینان حاصل شود PR زودتر از موعد ادغام نمی‌شود.

سپس تیم اطلاع‌رسانی انتشار / تیم انتشار می‌تواند به محض آنکه مخزن Git وب‌سایت پس از انتشار واقعی از حالت انجماد خارج شد، آن PR (یا مجموعه‌ی PRها) را از حالت نگه‌داشته خارج (unhold) کند.

در روزی که هر مقاله برای انتشار زمان‌بندی شده است، خودکارسازی یک ساخت وب‌سایت را آغاز می‌کند و آن مقاله قابل مشاهده می‌شود.
