مشارکت پیشرفته

این صفحه فرض می‌کند که می‌دانید چگونه در محتوای جدید مشارکت کنید و کار دیگران را بازبینی کنید، و آماده‌اید با راه‌های بیشتری برای مشارکت آشنا شوید. برای انجام برخی از این کارها باید از کلاینت خط فرمان Git و ابزارهای دیگر استفاده کنید.

پیشنهاد بهبودها

اعضای SIG Docs می‌توانند بهبودهایی را پیشنهاد کنند.

پس از آنکه مدتی در مستندات کوبرنتیز مشارکت کردید، ممکن است ایده‌هایی برای بهبود راهنمای سبک ، راهنمای محتوا، زنجیره‌ی ابزارهایی که برای ساخت مستندات استفاده می‌شود، سبک وب‌سایت، فرایندهای بازبینی و ادغام pull requestها، یا سایر جنبه‌های مستندات داشته باشید. برای حداکثر شفافیت، این نوع پیشنهادها باید در یک جلسه‌ی SIG Docs یا در فهرست پستی kubernetes-sig-docs مطرح و بررسی شوند. افزون بر این، پیش از پیشنهاد تغییرات گسترده، داشتن درکی از نحوه‌ی کار کنونی امور و دلیل تصمیم‌های گذشته می‌تواند مفید باشد. سریع‌ترین راه برای یافتن پاسخ پرسش‌هایی درباره‌ی نحوه‌ی کار کنونی مستندات، پرسیدن در کانال Slack با نام #sig-docs در kubernetes.slack.com است.

پس از آنکه بحث انجام شد و SIG درباره‌ی نتیجه‌ی مطلوب به توافق رسید، می‌توانید روی تغییرات پیشنهادی به مناسب‌ترین شیوه کار کنید. برای مثال، به‌روزرسانی راهنمای سبک یا قابلیت‌های وب‌سایت ممکن است شامل بازکردن یک pull request باشد، در حالی که تغییری مرتبط با آزمون مستندات ممکن است مستلزم همکاری با sig-testing باشد.

هماهنگی مستندات برای یک نسخه‌ی کوبرنتیز

تأییدکنندگان SIG Docs می‌توانند مستندات یک نسخه‌ی کوبرنتیز را هماهنگ کنند.

هر نسخه‌ی کوبرنتیز توسط تیمی از افراد شرکت‌کننده در گروه ذی‌نفع ویژه‌ی (SIG) sig-release هماهنگ می‌شود. سایر اعضای تیم انتشار یک نسخه‌ی مشخص شامل یک سرپرست کلی انتشار و نیز نمایندگانی از sig-testing و دیگران هستند. برای کسب اطلاعات بیشتر درباره‌ی فرایندهای انتشار کوبرنتیز، به https://github.com/kubernetes/sig-release مراجعه کنید.

نماینده‌ی SIG Docs برای یک نسخه‌ی مشخص، کارهای زیر را هماهنگ می‌کند:

  • پایش صفحه‌گسترده‌ی رهگیری قابلیت‌ها برای یافتن قابلیت‌های جدید یا تغییریافته‌ای که بر مستندات اثر دارند. اگر مستندات یک قابلیت مشخص برای انتشار آماده نباشد، ممکن است اجازه‌ی ورود آن قابلیت به نسخه داده نشود.
  • شرکت منظم در جلسات sig-release و ارائه‌ی گزارش به‌روز درباره‌ی وضعیت مستندات نسخه.
  • بازبینی و ویرایش مستندات قابلیت‌هایی که SIG مسئول پیاده‌سازی آن قابلیت پیش‌نویس کرده است.
  • ادغام pull requestهای مرتبط با انتشار و نگهداری شاخه‌ی قابلیت Git برای آن نسخه.
  • راهنمایی سایر مشارکت‌کنندگان SIG Docs که می‌خواهند انجام این نقش را در آینده بیاموزند. این کار «سایه‌روی» (shadowing) نامیده می‌شود.
  • انتشار تغییرات مستندات مرتبط با نسخه، هنگامی که مصنوعات (artifacts) انتشار منتشر می‌شوند.

هماهنگی یک نسخه معمولاً تعهدی ۳ تا ۴ ماهه است و این وظیفه میان تأییدکنندگان SIG Docs به‌صورت چرخشی انجام می‌شود.

خدمت به‌عنوان سفیر مشارکت‌کنندگان جدید

تأییدکنندگان SIG Docs می‌توانند به‌عنوان سفیر مشارکت‌کنندگان جدید خدمت کنند.

سفیران مشارکت‌کنندگان جدید به مشارکت‌کنندگان تازه‌وارد در SIG-Docs خوشامد می‌گویند، PRهایی را به مشارکت‌کنندگان جدید پیشنهاد می‌کنند و مشارکت‌کنندگان جدید را در ارسال چند PR نخستشان راهنمایی می‌کنند.

مسئولیت‌های سفیران مشارکت‌کنندگان جدید عبارت‌اند از:

  • پایش کانال Slack با نام #sig-docs برای پرسش‌های مشارکت‌کنندگان جدید.
  • همکاری با PR wranglerها برای شناسایی issueهای مناسب برای شروع برای مشارکت‌کنندگان جدید.
  • راهنمایی مشارکت‌کنندگان جدید در چند PR نخستشان به مخزن مستندات.
  • کمک به مشارکت‌کنندگان جدید برای ایجاد PRهای پیچیده‌تری که برای عضویت در کوبرنتیز به آن‌ها نیاز دارند.
  • حمایت از مشارکت‌کنندگان در مسیر عضویت در کوبرنتیز.
  • برگزاری جلسه‌ای ماهانه برای کمک و راهنمایی مشارکت‌کنندگان جدید.

سفیران کنونی مشارکت‌کنندگان جدید در هر جلسه‌ی SIG-Docs و در کانال #sig-docs کوبرنتیز اعلام می‌شوند.

حمایت از یک مشارکت‌کننده‌ی جدید

بازبینان SIG Docs می‌توانند از مشارکت‌کنندگان جدید حمایت (sponsor) کنند.

پس از آنکه یک مشارکت‌کننده‌ی جدید با موفقیت ۵ pull request اساسی به یک یا چند مخزن کوبرنتیز ارسال کرد، واجد شرایط درخواست عضویت در سازمان کوبرنتیز می‌شود. عضویت مشارکت‌کننده باید توسط دو حامی که از قبل بازبین هستند پشتیبانی شود.

مشارکت‌کنندگان جدید مستندات می‌توانند با پرسیدن در کانال #sig-docs در Slack کوبرنتیز یا در فهرست پستی SIG Docs درخواست حامی کنند. اگر به کار متقاضی اطمینان دارید، داوطلب حمایت از او می‌شوید. هنگامی که متقاضی درخواست عضویت خود را ارسال می‌کند، با یک "+1" به درخواست پاسخ دهید و جزئیاتی درباره‌ی اینکه چرا متقاضی را برای عضویت در سازمان کوبرنتیز مناسب می‌دانید بیان کنید.

خدمت به‌عنوان رئیس مشترک SIG

اعضای SIG Docs می‌توانند برای یک دوره به‌عنوان رئیس مشترک (co-chair) SIG Docs خدمت کنند.

پیش‌نیازها

یک عضو کوبرنتیز برای رئیس مشترک شدن باید شرایط زیر را داشته باشد:

  • درک جریان‌های کاری و ابزارهای SIG Docs: git، Hugo، بومی‌سازی، زیرپروژه‌ی وبلاگ
  • درک اینکه سایر SIGها و مخازن کوبرنتیز چگونه بر جریان کاری SIG Docs اثر می‌گذارند، از جمله: تیم‌ها در k/org، فرایند در k/community، افزونه‌ها در k/test-infra، و نقش SIG Architecture. افزون بر این، درک نحوه‌ی کار فرایند انتشار مستندات کوبرنتیز.
  • تأییدشدن توسط جامعه‌ی SIG Docs، یا به‌طور مستقیم یا از طریق اجماع ضمنی (lazy consensus).
  • تعهد به صرف دست‌کم ۵ ساعت در هفته (و اغلب بیشتر) برای این نقش به مدت حداقل ۶ ماه

مسئولیت‌ها

نقش رئیس مشترک نقشی خدماتی است: رؤسای مشترک ظرفیت مشارکت‌کنندگان را افزایش می‌دهند، فرایندها و سیاست‌ها را مدیریت می‌کنند، جلسات را زمان‌بندی و اداره می‌کنند، PR wranglerها را زمان‌بندی می‌کنند، در جامعه‌ی کوبرنتیز از مستندات حمایت می‌کنند، از موفقیت مستندات در چرخه‌های انتشار کوبرنتیز اطمینان حاصل می‌کنند و SIG Docs را بر اولویت‌های اثربخش متمرکز نگه می‌دارند.

مسئولیت‌ها عبارت‌اند از:

  • متمرکز نگه‌داشتن SIG Docs بر بیشینه‌کردن رضایت توسعه‌دهندگان از طریق مستندات عالی
  • الگو بودن در رعایت منشور رفتاری جامعه و پاسخ‌گو نگه‌داشتن اعضای SIG در قبال آن
  • یادگیری و تعیین بهترین شیوه‌ها برای SIG از طریق به‌روزرسانی رهنمودهای مشارکت
  • زمان‌بندی و اداره‌ی جلسات SIG: گزارش‌های هفتگی وضعیت، جلسات فصلی بازنگری/برنامه‌ریزی و سایر جلسات در صورت نیاز
  • زمان‌بندی و اداره‌ی دوره‌های فشرده‌ی مستندنویسی (doc sprints) در رویدادهای KubeCon و سایر کنفرانس‌ها
  • جذب نیرو و حمایت از SIG Docs نزد CNCF و شرکای پلاتینیوم آن، از جمله Google، Oracle، Azure، IBM و Huawei
  • حفظ روند روان فعالیت SIG

برگزاری جلسات اثربخش

برای زمان‌بندی و برگزاری جلسات اثربخش، این رهنمودها نشان می‌دهند چه کاری، چگونه و چرا باید انجام شود.

رعایت منشور رفتاری جامعه:

  • بحث‌هایی محترمانه و فراگیر با زبانی محترمانه و فراگیر داشته باشید.

تعیین دستور جلسه‌ی روشن:

  • دستور جلسه‌ای روشن از موضوعات تعیین کنید
  • دستور جلسه را از پیش منتشر کنید

برای جلسات هفتگی، یادداشت‌های هفته‌ی قبل را در بخش "Past meetings" یادداشت‌ها کپی کنید

همکاری در تهیه‌ی یادداشت‌های دقیق:

  • بحث‌های جلسه را ثبت کنید
  • واگذاری نقش یادداشت‌بردار را در نظر بگیرید

تخصیص روشن و دقیق اقدامات:

  • اقدام، فرد مسئول آن و تاریخ موردانتظار تکمیل را ثبت کنید

مدیریت جلسه در صورت نیاز:

  • اگر بحث از دستور جلسه منحرف شد، توجه شرکت‌کنندگان را دوباره به موضوع جاری معطوف کنید
  • برای سبک‌های مختلف بحث جا باز کنید، در حالی که بحث را متمرکز نگه می‌دارید و به وقت افراد احترام می‌گذارید

احترام به وقت افراد:

جلسات را به‌موقع آغاز کنید و به پایان برسانید.

استفاده‌ی اثربخش از Zoom:

  • با رهنمودهای Zoom برای کوبرنتیز آشنا شوید
  • هنگام ورود، با واردکردن کلید میزبان (host key) نقش میزبان را به دست بگیرید
