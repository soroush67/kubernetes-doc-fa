<!-- overview -->

هر کسی می‌تواند در کوبرنتیز مشارکت کند. با افزایش مشارکت‌های شما در SIG Docs، می‌توانید برای سطوح مختلف عضویت در جامعه درخواست دهید. این نقش‌ها به شما امکان می‌دهند مسئولیت بیشتری در جامعه بر عهده بگیرید. هر نقش به زمان و تعهد بیشتری نیاز دارد. این نقش‌ها عبارت‌اند از:

- همه: مشارکت‌کنندگان عادی در مستندات کوبرنتیز
- اعضا: می‌توانند ایشوها را واگذار و اولویت‌بندی کنند و روی درخواست‌های ادغام (pull request) بازبینی غیرالزام‌آور ارائه دهند
- بازبین‌ها: می‌توانند بازبینی درخواست‌های ادغام مستندات را هدایت کنند و کیفیت یک تغییر را تأیید کنند
- تأییدکنندگان: می‌توانند بازبینی مستندات را هدایت کنند و تغییرات را ادغام کنند

<!-- body -->

## همه

هر کسی که حساب GitHub داشته باشد می‌تواند در کوبرنتیز مشارکت کند. گروه SIG Docs از همهٔ مشارکت‌کنندگان تازه‌وارد استقبال می‌کند!

همه می‌توانند:

- در هر مخزن [کوبرنتیز](https://github.com/kubernetes/)، از جمله
  [`kubernetes/website`](https://github.com/kubernetes/website)، یک ایشو باز کنند
- روی یک درخواست ادغام بازخورد غیرالزام‌آور بدهند
- در یک بومی‌سازی مشارکت کنند
- پیشنهادهای بهبود را در [Slack](https://slack.k8s.io/) یا
  [فهرست پستی SIG Docs](https://groups.google.com/forum/#!forum/kubernetes-sig-docs) مطرح کنند.

پس از [امضای CLA](https://github.com/kubernetes/community/blob/main/CLA.md)، همه همچنین می‌توانند:

- برای بهبود محتوای موجود، افزودن محتوای جدید یا نوشتن یک پست وبلاگ یا مطالعهٔ موردی، درخواست ادغام باز کنند
- نمودار، دارایی‌های گرافیکی، و ویدئوها و ضبط‌های صفحه‌نمایش قابل‌جاسازی بسازند

برای اطلاعات بیشتر، [مشارکت در محتوای جدید](/docs/contribute/new-content/) را ببینید.

## اعضا

عضو کسی است که چندین درخواست ادغام به
`kubernetes/website` ارسال کرده باشد. اعضا بخشی از
[سازمان GitHub کوبرنتیز](https://github.com/kubernetes) هستند.

اعضا می‌توانند:

- همهٔ کارهای فهرست‌شده در بخش [همه](#anyone) را انجام دهند
- با کامنت `/lgtm` برچسب LGTM (به نظرم خوب است) را به یک درخواست ادغام اضافه کنند

  {{< note >}}
  استفاده از `/lgtm` فرایندهای خودکار را راه‌اندازی می‌کند. اگر می‌خواهید تأیید غیرالزام‌آور بدهید، نوشتن کامنت «LGTM» نیز کافی است!
  {{< /note >}}

- با کامنت `/hold` از ادغام یک درخواست ادغام جلوگیری کنند
- با کامنت `/assign` یک بازبین را به یک درخواست ادغام اختصاص دهند
- روی درخواست‌های ادغام بازبینی غیرالزام‌آور ارائه دهند
- با استفاده از ابزارهای خودکار، ایشوها را اولویت‌بندی و دسته‌بندی کنند
- ویژگی‌های جدید را مستند کنند

### عضو شدن

پس از ارسال دست‌کم ۵ درخواست ادغام قابل‌توجه و برآورده کردن سایر
[الزامات](https://github.com/kubernetes/community/blob/main/community-membership.md#member):

1. دو [بازبین](#reviewers) یا [تأییدکننده](#approvers) پیدا کنید تا
   [حامی](/docs/contribute/advanced#sponsor-a-new-contributor) عضویت شما شوند.

   درخواست حمایت را در [کانال #sig-docs در Slack](https://kubernetes.slack.com) یا در
   [فهرست پستی SIG Docs](https://groups.google.com/forum/#!forum/kubernetes-sig-docs) مطرح کنید.

   {{< note >}}
   به هیچ‌یک از اعضای SIG Docs به‌صورت مستقیم ایمیل یا پیام خصوصی در Slack نفرستید. باید پیش از ارسال درخواست عضویت، درخواست حمایت را مطرح کنید.
   {{< /note >}}

1. در مخزن
   [`kubernetes/org`](https://github.com/kubernetes/org/) یک ایشوی GitHub باز کنید. برای این کار از قالب ایشوی
   **Organization Membership Request** استفاده کنید.

1. حامیان خود را از ایشوی GitHub باخبر کنید. برای این کار می‌توانید:
   - نام کاربری GitHub آن‌ها را در ایشو ذکر کنید (`@<GitHub-username>`)
   - پیوند ایشو را از طریق Slack یا ایمیل برایشان بفرستید.

     حامیان با رأی `+1` درخواست شما را تأیید می‌کنند. پس از تأیید حامیان، یکی از مدیران GitHub کوبرنتیز شما را به‌عنوان عضو اضافه می‌کند.
     تبریک می‌گوییم!

     اگر درخواست عضویت شما پذیرفته نشود، بازخورد دریافت خواهید کرد.
     پس از رسیدگی به بازخوردها، دوباره درخواست دهید.

1. دعوت‌نامهٔ عضویت در سازمان GitHub کوبرنتیز را در حساب ایمیل خود بپذیرید.

   {{< note >}}
   سرویس GitHub دعوت‌نامه را به نشانی ایمیل پیش‌فرض حساب شما می‌فرستد.
   {{< /note >}}

## بازبین‌ها

بازبین‌ها مسئول بازبینی درخواست‌های ادغام باز هستند. برخلاف بازخورد اعضا، نویسندهٔ درخواست ادغام باید به بازخورد بازبین‌ها رسیدگی کند. بازبین‌ها عضو تیم GitHub
[@kubernetes/sig-docs-{language}-reviews](https://github.com/orgs/kubernetes/teams?query=sig-docs)
هستند.

بازبین‌ها می‌توانند:

- همهٔ کارهای فهرست‌شده در بخش‌های [همه](#anyone) و [اعضا](#members) را انجام دهند
- درخواست‌های ادغام را بازبینی کنند و بازخورد الزام‌آور بدهند

  {{< note >}}
  برای ارائهٔ بازخورد غیرالزام‌آور، ابتدای کامنت‌های خود عبارتی مانند «Optionally: » بیاورید.
  {{< /note >}}

- رشته‌های متنی کاربرپسند را در کد ویرایش کنند
- کامنت‌های کد را بهبود دهند

شما می‌توانید بازبین SIG Docs یا بازبین مستندات در یک حوزهٔ موضوعی مشخص باشید.

### اختصاص بازبین به درخواست‌های ادغام

ابزارهای خودکار برای همهٔ درخواست‌های ادغام بازبین تعیین می‌کنند. برای درخواست بازبینی از یک فرد مشخص، کامنت
`/assign
[@_github_handle]` را بنویسید.

اگر بازبین تعیین‌شده روی درخواست ادغام کامنتی ننوشته باشد، بازبین دیگری می‌تواند وارد عمل شود. همچنین در صورت نیاز می‌توانید بازبین‌های فنی تعیین کنید.

### استفاده از `/lgtm`

عبارت LGTM مخفف «Looks good to me» (به نظرم خوب است) است و نشان می‌دهد که یک درخواست ادغام از نظر فنی درست و آمادهٔ ادغام است. همهٔ درخواست‌های ادغام برای ادغام شدن به یک کامنت `/lgtm` از یک بازبین و یک کامنت `/approve` از یک تأییدکننده نیاز دارند.

کامنت `/lgtm` از سوی بازبین الزام‌آور است و فرایند خودکاری را راه‌اندازی می‌کند که برچسب `lgtm` را اضافه می‌کند.

### بازبین شدن

وقتی
[الزامات](https://github.com/kubernetes/community/blob/main/community-membership.md#reviewer)
را برآورده کنید، می‌توانید بازبین SIG Docs شوید. بازبین‌های سایر SIGها باید برای کسب جایگاه بازبین در SIG Docs جداگانه درخواست دهند.

برای درخواست:

1. یک درخواست ادغام باز کنید که نام کاربری GitHub شما را به یکی از بخش‌های فایل
   [OWNERS_ALIASES](https://github.com/kubernetes/website/blob/main/OWNERS_ALIASES)
   در مخزن `kubernetes/website` اضافه کند.

   {{< note >}}
   اگر مطمئن نیستید خود را در کجا اضافه کنید، خود را به `sig-docs-en-reviews` اضافه کنید.
   {{< /note >}}

1. درخواست ادغام را به یک یا چند تأییدکنندهٔ SIG Docs (نام‌های کاربری فهرست‌شده در
   `sig-docs-{language}-owners`) اختصاص دهید.

در صورت تأیید، یکی از رهبران SIG Docs شما را به تیم GitHub مناسب اضافه می‌کند. پس از افزوده شدن،
[K8s-ci-robot](https://github.com/kubernetes/test-infra/tree/master/prow#bots-home)
شما را به‌عنوان بازبین درخواست‌های ادغام جدید پیشنهاد و تعیین می‌کند.

## تأییدکنندگان

تأییدکنندگان درخواست‌های ادغام را بازبینی و برای ادغام تأیید می‌کنند. تأییدکنندگان عضو تیم‌های GitHub
[@kubernetes/sig-docs-{language}-owners](https://github.com/orgs/kubernetes/teams/?query=sig-docs)
هستند.

تأییدکنندگان می‌توانند کارهای زیر را انجام دهند:

- همهٔ کارهای فهرست‌شده در بخش‌های [همه](#anyone)، [اعضا](#members) و [بازبین‌ها](#reviewers)
- انتشار محتوای مشارکت‌کنندگان با تأیید و ادغام درخواست‌های ادغام از طریق کامنت `/approve`
- پیشنهاد بهبود برای راهنمای سبک نگارش
- پیشنهاد بهبود برای آزمون‌های مستندات
- پیشنهاد بهبود برای وب‌سایت کوبرنتیز یا سایر ابزارها

اگر درخواست ادغام از قبل `/lgtm` داشته باشد، یا تأییدکننده نیز کامنت
`/lgtm` بنویسد، درخواست ادغام به‌طور خودکار ادغام می‌شود. تأییدکنندهٔ SIG Docs فقط باید روی تغییری
`/lgtm` بگذارد که به بازبینی فنی بیشتری نیاز ندارد.


### تأیید درخواست‌های ادغام

تنها تأییدکنندگان و رهبران SIG Docs می‌توانند درخواست‌های ادغام را در مخزن وب‌سایت ادغام کنند. این اختیار مسئولیت‌هایی نیز به همراه دارد.

- تأییدکنندگان می‌توانند از دستور `/approve` استفاده کنند که درخواست‌های ادغام را در مخزن ادغام می‌کند.

  {{< warning >}}
  یک ادغام بی‌دقت می‌تواند سایت را از کار بیندازد؛ بنابراین هنگام ادغام هر چیزی، از تصمیم خود مطمئن باشید.
  {{< /warning >}}

- مطمئن شوید که تغییرات پیشنهادی با
  [راهنمای محتوای مستندات](/docs/contribute/style/content-guide/) مطابقت دارند.

  اگر پرسشی دارید یا دربارهٔ موضوعی مطمئن نیستید، بی‌درنگ درخواست بازبینی بیشتر کنید.

- پیش از `/approve` کردن یک درخواست ادغام، بررسی کنید که آزمون‌های Netlify با موفقیت انجام شده باشند.

    <img src="/images/docs/contribute/netlify-pass.png" width="75%" alt="Netlify tests must pass before approving" />

- پیش از تأیید، پیش‌نمایش صفحه در Netlify را برای درخواست ادغام ببینید تا از درست بودن همه‌چیز مطمئن شوید.

- در
  [برنامهٔ نوبتی PR Wrangler](https://github.com/kubernetes/website/wiki/PR-Wranglers)
  برای نوبت‌های هفتگی شرکت کنید. گروه SIG Docs از همهٔ تأییدکنندگان انتظار دارد در این نوبت‌دهی شرکت کنند. برای جزئیات بیشتر،
  [PR wranglers](/docs/contribute/participate/pr-wranglers/) را ببینید.

### تأییدکننده شدن

وقتی
[الزامات](https://github.com/kubernetes/community/blob/main/community-membership.md#approver)
را برآورده کنید، می‌توانید تأییدکنندهٔ SIG Docs شوید. تأییدکنندگان سایر SIGها باید برای کسب جایگاه تأییدکننده در SIG Docs جداگانه درخواست دهند.

برای درخواست:

1. یک درخواست ادغام باز کنید که شما را به یکی از بخش‌های فایل
   [OWNERS_ALIASES](https://github.com/kubernetes/website/blob/main/OWNERS_ALIASES)
   در مخزن `kubernetes/website` اضافه کند.

    {{< note >}}
    اگر مطمئن نیستید خود را در کجا اضافه کنید، خود را به `sig-docs-en-owners` اضافه کنید.
    {{< /note >}}

2. درخواست ادغام را به یک یا چند تأییدکنندهٔ فعلی SIG Docs اختصاص دهید.

در صورت تأیید، یکی از رهبران SIG Docs شما را به تیم GitHub مناسب اضافه می‌کند. پس از افزوده شدن،
