این صفحه نشان می‌دهد چگونه یک موضوع جدید برای مستندات کوبرنتیز ایجاد کنید.


## {{% heading "prerequisites" %}}

یک فورک از مخزن مستندات کوبرنتیز ایجاد کنید، همان‌طور که در
[ارسال یک PR](/docs/contribute/new-content/open-a-pr/) توضیح داده شده است.


<!-- steps -->

## انتخاب نوع صفحه

هنگامی که برای نوشتن یک موضوع جدید آماده می‌شوید، به نوع صفحه‌ای فکر کنید که بیش از همه با محتوای شما مناسبت دارد:

{{< table caption = "راهنما برای انتخاب نوع صفحه" >}}
نوع | توضیحات
:--- | :----------
Concept | صفحه مفهومی (Concept) جنبه‌ای از کوبرنتیز را توضیح می‌دهد. برای مثال، یک صفحه مفهومی ممکن است آبجکت Deployment در کوبرنتیز را شرح دهد و نقشی را که این آبجکت هنگام استقرار، مقیاس‌دهی و به‌روزرسانی یک برنامه ایفا می‌کند توضیح دهد. معمولاً صفحات مفهومی شامل توالی مراحل نیستند و در عوض پیوندهایی به تسک‌ها یا آموزش‌ها ارائه می‌کنند. برای نمونه‌ای از یک موضوع مفهومی، به <a href="/docs/concepts/architecture/nodes/">نودها</a> مراجعه کنید.
Task | صفحه تسک (Task) نشان می‌دهد چگونه یک کار مشخص را انجام دهید. هدف این است که توالی‌ای از مراحل در اختیار خوانندگان قرار گیرد که بتوانند هم‌زمان با خواندن صفحه آن‌ها را اجرا کنند. صفحه تسک می‌تواند کوتاه یا بلند باشد، به شرطی که بر یک حوزه متمرکز بماند. در صفحه تسک می‌توان توضیحات کوتاه را با مراحلِ قابل‌اجرا درآمیخت، اما اگر به توضیح مفصل نیاز دارید، باید آن را در یک موضوع مفهومی ارائه دهید. موضوعات مرتبط تسک و مفهوم باید به یکدیگر پیوند داشته باشند. برای نمونه‌ای از یک صفحه تسک کوتاه، به <a href="/docs/tasks/configure-pod-container/configure-volume-storage/">پیکربندی یک Pod برای استفاده از حجم (volume) جهت ذخیره‌سازی</a> مراجعه کنید. برای نمونه‌ای از یک صفحه تسک طولانی‌تر، به <a href="/docs/tasks/configure-pod-container/configure-liveness-readiness-probes/">پیکربندی probeهای Liveness و Readiness</a> مراجعه کنید.
Tutorial | صفحه آموزش (Tutorial) نشان می‌دهد چگونه به هدفی دست یابید که چند قابلیت کوبرنتیز را به هم پیوند می‌دهد. یک آموزش ممکن است چندین توالی از مراحل را ارائه کند که خوانندگان می‌توانند هم‌زمان با خواندن صفحه آن‌ها را اجرا کنند. یا ممکن است توضیحاتی درباره بخش‌های مرتبط کد ارائه دهد. برای مثال، یک آموزش می‌تواند مرور گام‌به‌گام یک نمونه کد را ارائه کند. آموزش می‌تواند شامل توضیحات کوتاهی درباره قابلیت‌های کوبرنتیز باشد که به هم مرتبط می‌شوند، اما برای توضیحات عمیق درباره هر قابلیت باید به موضوعات مفهومی مرتبط پیوند دهد.
{{< /table >}}

### ایجاد یک صفحه جدید

برای هر صفحه جدیدی که می‌نویسید از یک [نوع محتوا](/docs/contribute/style/page-content-types/) استفاده کنید. سایت مستندات قالب‌ها یا
[Hugo archetypeها](https://gohugo.io/content-management/archetypes/) را برای ایجاد
صفحات محتوای جدید فراهم می‌کند. برای ایجاد یک نوع جدید صفحه، دستور `hugo new` را همراه با مسیر فایلی که
می‌خواهید ایجاد کنید اجرا کنید. برای مثال:

```
hugo new docs/concepts/my-first-concept.md
```

## انتخاب عنوان و نام فایل

عنوانی انتخاب کنید که شامل کلیدواژه‌هایی باشد که می‌خواهید موتورهای جست‌وجو پیدا کنند.
نام فایلی بسازید که از کلمات عنوان شما استفاده کند و آن‌ها را با خط تیره از هم جدا کند.
برای مثال، موضوعی با عنوان
[استفاده از یک HTTP Proxy برای دسترسی به API کوبرنتیز](/docs/tasks/extend-kubernetes/http-proxy-access-api/)
نام فایل `http-proxy-access-api.md` را دارد. لازم نیست
«kubernetes» را در نام فایل بگذارید، زیرا «kubernetes» از قبل در
URL موضوع وجود دارد، برای مثال:

       /docs/tasks/extend-kubernetes/http-proxy-access-api/

## افزودن عنوان موضوع به front matter

در موضوع خود، یک فیلد `title` در
[front matter](https://gohugo.io/content-management/front-matter/) قرار دهید.
front matter همان بلوک YAML است که میان
خطوط سه‌خط‌تیره در بالای صفحه قرار دارد. نمونه‌ای از آن در ادامه آمده است:

    ---
    title: Using an HTTP Proxy to Access the Kubernetes API
    ---

## انتخاب دایرکتوری

بسته به نوع صفحه، فایل جدید خود را در یکی از زیردایرکتوری‌های زیر قرار دهید:

* /content/en/docs/tasks/
* /content/en/docs/tutorials/
* /content/en/docs/concepts/

می‌توانید فایل خود را در یک زیردایرکتوری موجود قرار دهید، یا می‌توانید یک
زیردایرکتوری جدید ایجاد کنید.

## قرار دادن موضوع در فهرست مطالب

فهرست مطالب به‌صورت پویا و با استفاده از ساختار دایرکتوری‌های
منبع مستندات ساخته می‌شود. دایرکتوری‌های سطح بالا در `/content/en/docs/`
ناوبری سطح بالا را ایجاد می‌کنند و هر زیردایرکتوری در فهرست مطالب
ورودی‌هایی دارد.

هر زیردایرکتوری یک فایل `_index.md` دارد که «صفحه اصلی» محتوای
آن زیردایرکتوری را نشان می‌دهد. فایل `_index.md` به قالب نیاز ندارد. می‌تواند
شامل محتوای کلی درباره موضوعات موجود در زیردایرکتوری باشد.

سایر فایل‌های یک دایرکتوری به‌طور پیش‌فرض به ترتیب الفبایی مرتب می‌شوند. این ترتیب تقریباً
هرگز بهترین ترتیب نیست. برای کنترل ترتیب نسبی موضوعات در یک
زیردایرکتوری، کلید front matter با نام `weight:` را روی یک عدد صحیح تنظیم کنید. معمولاً
از مضرب‌های ۱۰ استفاده می‌کنیم تا امکان افزودن موضوعات بعدی وجود داشته باشد. برای مثال، موضوعی
با وزن `10` پیش از موضوعی با وزن `20` قرار می‌گیرد.

## جاسازی کد در موضوع

اگر می‌خواهید مقداری کد در موضوع خود بگنجانید، می‌توانید کد را
با استفاده از نحو بلوک کد مارک‌داون مستقیماً در فایل خود جاسازی کنید. این روش برای
موارد زیر توصیه می‌شود (فهرست کامل نیست):

- کد، خروجی یک دستور را نشان می‌دهد، مانند
  `kubectl get deploy mydeployment -o json | jq '.status'`.
- کد به اندازه کافی عمومی نیست که کاربران آن را امتحان کنند. برای مثال، می‌توانید
  فایل YAML مربوط به ایجاد یک Pod را که به یک پیاده‌سازی مشخص از
  [FlexVolume](/docs/concepts/storage/volumes/#flexvolume) وابسته است جاسازی کنید.
- کد یک مثال ناقص است، زیرا هدف آن برجسته کردن بخشی از یک فایل بزرگ‌تر است. برای مثال، هنگام توضیح روش‌های
  سفارشی‌سازی یک [RoleBinding](/docs/reference/access-authn-authz/rbac/#role-binding-examples)،
  می‌توانید یک قطعه کد کوتاه را مستقیماً در فایل موضوع خود ارائه دهید.
- کد به دلایل دیگری برای امتحان کردن توسط کاربران در نظر گرفته نشده است. برای مثال،
  هنگام توضیح اینکه چگونه یک ویژگی جدید با استفاده از دستور
  `kubectl edit` به یک منبع افزوده می‌شود، می‌توانید یک مثال کوتاه ارائه دهید که فقط شامل
  ویژگیِ مورد نظر برای افزودن است.

## گنجاندن کد از فایل دیگر

روش دیگر برای گنجاندن کد در موضوع شما این است که یک فایل نمونه کامل و جدید
(یا گروهی از فایل‌های نمونه) ایجاد کنید و سپس از موضوع خود به آن نمونه ارجاع دهید.
از این روش برای گنجاندن فایل‌های YAML نمونه استفاده کنید، آن هم زمانی که نمونه عمومی
و قابل استفاده مجدد است و می‌خواهید خواننده خودش آن را امتحان کند.

هنگام افزودن یک فایل نمونه مستقل جدید، مانند یک فایل YAML، کد را در
یکی از زیردایرکتوری‌های `<LANG>/examples/` قرار دهید، که در آن `<LANG>` زبان
موضوع است. در فایل موضوع خود از shortcode با نام `code_sample` استفاده کنید:

```none
{{%/* code_sample file="<RELPATH>/my-example-yaml>" */%}}
```
که در آن `<RELPATH>` مسیر فایلِ مورد نظر برای گنجاندن است، نسبت به دایرکتوری
`examples`. shortcode زیر در Hugo به یک فایل YAML
واقع در `/content/en/examples/pods/storage/gce-volume.yaml` ارجاع می‌دهد.

```none
{{%/* code_sample file="pods/storage/gce-volume.yaml" */%}}
```

## نمایش نحوه ایجاد یک آبجکت API از یک فایل پیکربندی

اگر لازم است نشان دهید چگونه یک آبجکت API بر پایه یک
فایل پیکربندی ایجاد می‌شود، فایل پیکربندی را در یکی از زیردایرکتوری‌های
`<LANG>/examples` قرار دهید.

در موضوع خود، این دستور را نشان دهید:

```
kubectl create -f https://k8s.io/examples/pods/storage/gce-volume.yaml
```

{{< note >}}
هنگام افزودن فایل‌های YAML جدید به دایرکتوری `<LANG>/examples`، مطمئن شوید
فایل در `<LANG>/examples_test.go` نیز گنجانده شده است. Travis CI مربوط به وب‌سایت
هنگام ارسال PRها این آزمون را به‌طور خودکار اجرا می‌کند تا اطمینان حاصل شود همه نمونه‌ها
آزمون‌ها را با موفقیت می‌گذرانند.
{{< /note >}}

برای نمونه‌ای از موضوعی که از این تکنیک استفاده می‌کند، به
[اجرای یک برنامه Stateful تک‌نمونه‌ای](/docs/tasks/run-application/run-single-instance-stateful-application/) مراجعه کنید.

## افزودن تصاویر به یک موضوع

فایل‌های تصویر را در دایرکتوری `/images` قرار دهید. قالب
تصویر ترجیحی SVG است.
