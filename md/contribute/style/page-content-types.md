مستندات کوبرنتیز از چند نوع محتوای صفحه پیروی می‌کند:

- مفهوم
- وظیفه
- آموزش
- مرجع

چارچوب مستندسازی [Diátaxis](https://diataxis.fr/) نیز می‌تواند مرجع مفیدی برای
شیوهٔ نوشتن هر یک از این انواع محتوای صفحه باشد.

<!-- body -->

## بخش‌های محتوا

هر نوع محتوای صفحه شامل چند بخش است که با توضیحات Markdown و سرعنوان‌های HTML
تعریف می‌شوند. می‌توانید با شورت‌کد `heading` سرعنوان‌های محتوایی به صفحهٔ خود
اضافه کنید. این توضیحات و سرعنوان‌ها به حفظ ساختار انواع محتوای صفحه کمک می‌کنند.

نمونه‌هایی از توضیحات Markdown که بخش‌های محتوای صفحه را تعریف می‌کنند:

```markdown
<!-- overview -->
```

```markdown
<!-- body -->
```

برای ایجاد سرعنوان‌های رایج در صفحه‌های محتوایی، از شورت‌کد `heading` همراه با
یک رشتهٔ سرعنوان استفاده کنید.

نمونه‌هایی از رشته‌های سرعنوان:

- whatsnext
- prerequisites
- objectives
- cleanup
- synopsis
- seealso
- options

برای مثال، برای ایجاد سرعنوان `whatsnext`، شورت‌کد heading را همراه با رشتهٔ
"whatsnext" اضافه کنید:

```none
## {{%/* heading "whatsnext" */%}}
```

سرعنوان `prerequisites` را می‌توانید به این صورت تعریف کنید:

```none
## {{%/* heading "prerequisites" */%}}
```

شورت‌کد `heading` یک پارامتر رشته‌ای می‌پذیرد. این پارامتر با پیشوند یک متغیر در
فایل‌های `i18n/<lang>/<lang>.toml` مطابقت دارد. برای مثال:

`i18n/en/en.toml`:

```toml
[whatsnext_heading]
other = "What's next"
```

`i18n/ko/ko.toml`:

```toml
[whatsnext_heading]
other = "다음 내용"
```

## انواع محتوا

هر نوع محتوا به‌طور غیررسمی ساختار مورد انتظار صفحه را تعیین می‌کند. محتوای صفحه
را با بخش‌های پیشنهادی ایجاد کنید.

### مفهوم

صفحهٔ مفهوم جنبه‌ای از کوبرنتیز را توضیح می‌دهد. برای مثال، یک صفحهٔ مفهوم ممکن
است آبجکت Deployment کوبرنتیز را شرح دهد و نقش آن را به‌عنوان یک برنامه، پس از
استقرار، مقیاس‌دهی و به‌روزرسانی، توضیح دهد. صفحه‌های مفهوم معمولاً دنباله‌ای از
مراحل ندارند و در عوض پیوندهایی به وظیفه‌ها یا آموزش‌ها ارائه می‌کنند.

برای نوشتن یک صفحهٔ مفهوم جدید، یک فایل Markdown در یکی از زیرشاخه‌های پوشهٔ
`/content/en/docs/concepts` با ویژگی‌های زیر ایجاد کنید:

صفحه‌های مفهوم به سه بخش تقسیم می‌شوند:

| بخش صفحه      |
|---------------|
| overview      |
| body          |
| whatsnext     |

بخش‌های `overview` و `body` به‌صورت توضیح در صفحهٔ مفهوم قرار می‌گیرند. بخش
`whatsnext` را می‌توانید با شورت‌کد `heading` به صفحهٔ خود اضافه کنید.

هر بخش را با محتوا پر کنید و از این رهنمودها پیروی کنید:

- محتوا را با سرعنوان‌های H2 و H3 سازمان‌دهی کنید.
- در `overview`، زمینهٔ موضوع را در یک پاراگراف مشخص کنید.
- در `body`، مفهوم را توضیح دهید.
- در `whatsnext`، فهرستی گلوله‌ای از موضوعات (حداکثر ۵ مورد) برای آشنایی بیشتر با
  این مفهوم ارائه کنید.

صفحهٔ [حاشیه‌نویسی‌ها](/docs/concepts/overview/working-with-objects/annotations/) نمونهٔ منتشرشده‌ای از یک صفحهٔ مفهوم است.

### وظیفه

صفحهٔ وظیفه نشان می‌دهد که چگونه یک کار مشخص را انجام دهید؛ معمولاً با ارائهٔ
دنباله‌ای کوتاه از مراحل. صفحه‌های وظیفه توضیحات اندکی دارند، اما اغلب پیوندهایی
به موضوعات مفهومی ارائه می‌کنند که پیش‌زمینه و دانش مرتبط را فراهم می‌کنند.

برای نوشتن یک صفحهٔ وظیفهٔ جدید، یک فایل Markdown در یکی از زیرشاخه‌های پوشهٔ
`/content/en/docs/tasks` با ویژگی‌های زیر ایجاد کنید:

| بخش صفحه      |
|---------------|
| overview      |
| prerequisites |
| steps         |
| discussion    |
| whatsnext     |

بخش‌های `overview`، `steps` و `discussion` به‌صورت توضیح در صفحهٔ وظیفه قرار
می‌گیرند. بخش‌های `prerequisites` و `whatsnext` را می‌توانید با شورت‌کد `heading`
به صفحهٔ خود اضافه کنید.

محتوای هر بخش را بنویسید و از این رهنمودها پیروی کنید:

- حداقل از سرعنوان‌های H2 (با دو نویسهٔ `#` در ابتدا) استفاده کنید. عنوان خود
  بخش‌ها به‌طور خودکار توسط قالب تعیین می‌شود.
- در `overview`، با یک پاراگراف زمینهٔ کل موضوع را مشخص کنید. به‌اختصار توضیح دهید
  که چرا خواننده ممکن است بخواهد این وظیفه را انجام دهد (انگیزه یا مورد استفاده)،
  تا خواننده پیش از خواندن مراحل تشخیص دهد که آیا این صفحه به کار او می‌آید یا نه.
- در `prerequisites`، تا جای ممکن از فهرست‌های گلوله‌ای استفاده کنید. پیش‌نیازهای
  اضافی را پس از `include` بیفزایید. پیش‌نیازهای پیش‌فرض شامل یک کلاستر کوبرنتیز
  در حال اجراست.
- در `steps`، از فهرست‌های شماره‌دار استفاده کنید. تمرکز را بر خود وظیفه نگه
  دارید. اگر مرحله‌ای به پیش‌زمینهٔ قابل‌توجهی نیاز دارد، به‌جای تکرار توضیح در
  این بخش، به صفحهٔ مفهوم مرتبط پیوند دهید.
- در بخش discussion، از محتوای عادی برای بسط اطلاعاتی که در `steps` آمده است
  استفاده کنید.
- در `whatsnext`، فهرستی گلوله‌ای از حداکثر ۵ موضوع ارائه کنید که ممکن است
  خواننده بخواهد در ادامه مطالعه کند.

نمونه‌ای از یک موضوع وظیفهٔ منتشرشده، [استفاده از یک پراکسی HTTP برای دسترسی به API کوبرنتیز](/docs/tasks/extend-kubernetes/http-proxy-access-api/) است.

### آموزش

صفحهٔ آموزش نشان می‌دهد که چگونه به هدفی بزرگ‌تر از یک وظیفهٔ منفرد برسید.
صفحهٔ آموزش معمولاً چند بخش دارد که هر کدام شامل دنباله‌ای از مراحل است. برای
مثال، یک آموزش ممکن است گام‌به‌گام یک نمونه‌کد را مرور کند که ویژگی خاصی از
کوبرنتیز را نشان می‌دهد. آموزش‌ها می‌توانند توضیحات سطحی داشته باشند، اما برای
توضیحات عمیق باید به موضوعات مفهومی مرتبط پیوند دهند.

برای نوشتن یک صفحهٔ آموزش جدید، یک فایل Markdown در یکی از زیرشاخه‌های پوشهٔ
`/content/en/docs/tutorials` با ویژگی‌های زیر ایجاد کنید:

| بخش صفحه      |
|---------------|
| overview      |
| prerequisites |
| objectives    |
| lessoncontent |
| cleanup       |
| whatsnext     |

بخش‌های `overview`، `objectives` و `lessoncontent` به‌صورت توضیح در صفحهٔ آموزش
قرار می‌گیرند. بخش‌های `prerequisites`، `cleanup` و `whatsnext` را می‌توانید با
شورت‌کد `heading` به صفحهٔ خود اضافه کنید.

محتوای هر بخش را بنویسید و از این رهنمودها پیروی کنید:

- حداقل از سرعنوان‌های H2 (با دو نویسهٔ `#` در ابتدا) استفاده کنید. عنوان خود
  بخش‌ها به‌طور خودکار توسط قالب تعیین می‌شود.
- در `overview`، با یک پاراگراف زمینهٔ کل موضوع را مشخص کنید.
- در `prerequisites`، تا جای ممکن از فهرست‌های گلوله‌ای استفاده کنید. پیش‌نیازهای
  اضافی را پس از پیش‌نیازهای پیش‌فرض بیفزایید.
- در `objectives`، از فهرست‌های گلوله‌ای استفاده کنید.
- در `lessoncontent`، بسته به نیاز ترکیبی از فهرست‌های شماره‌دار و متن روایی به
  کار ببرید.
- در `cleanup`، با فهرست‌های شماره‌دار مراحل پاک‌سازی وضعیت کلاستر پس از پایان
  وظیفه را شرح دهید.
- در `whatsnext`، فهرستی گلوله‌ای از حداکثر ۵ موضوع ارائه کنید که ممکن است
  خواننده بخواهد در ادامه مطالعه کند.

نمونه‌ای از یک موضوع آموزشی منتشرشده،
[اجرای یک برنامهٔ بدون حالت با استفاده از Deployment](/docs/tasks/run-application/run-stateless-application-deployment/) است.

### مرجع

صفحهٔ مرجع یک ابزار مؤلفه، توضیحات و خروجی گزینه‌های فلگ یک ابزار مؤلفهٔ
کوبرنتیز را نشان می‌دهد. هر صفحه با اسکریپت‌هایی که از فرمان‌های ابزار مؤلفه
استفاده می‌کنند تولید می‌شود.

صفحهٔ مرجع ابزار می‌تواند چند بخش داشته باشد:

| بخش صفحه                     |
|------------------------------|
| synopsis                     |
| options                      |
| options from parent commands |
| examples                     |
| seealso                      |

نمونه‌هایی از صفحه‌های مرجع ابزار منتشرشده:

- [kubeadm init](/docs/reference/setup-tools/kubeadm/kubeadm-init/)
- [kube-apiserver](/docs/reference/command-line-tools-reference/kube-apiserver/)
- [kubectl](/docs/reference/kubectl/kubectl/)
