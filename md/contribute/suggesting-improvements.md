اگر متوجه مشکلی در مستندات کوبرنتیز شدید یا ایده‌ای برای محتوای جدید دارید، یک issue باز کنید. تنها چیزی که نیاز دارید یک [حساب کاربری GitHub](https://github.com/join) و یک مرورگر وب است.

در بیشتر موارد، کار جدید روی مستندات کوبرنتیز با یک issue در GitHub آغاز می‌شود. سپس مشارکت‌کنندگان کوبرنتیز issueها را بررسی می‌کنند، آن‌ها را دسته‌بندی می‌کنند و در صورت نیاز برچسب‌گذاری می‌کنند. پس از آن، شما یا یکی دیگر از اعضای جامعه کوبرنتیز یک pull request همراه با تغییرات لازم برای رفع آن issue باز می‌کنید.



<!-- body -->

## باز کردن یک issue {#opening-an-issue}

اگر می‌خواهید برای بهبود محتوای موجود پیشنهادی ارائه دهید یا متوجه خطایی شده‌اید، یک issue باز کنید.

1. روی پیوند **Create an issue** در نوار کناری سمت راست کلیک کنید. با این کار به یک صفحه issue در GitHub هدایت می‌شوید که برخی سرصفحه‌ها از پیش در آن پر شده‌اند.
2. مشکل یا پیشنهاد خود را برای بهبود شرح دهید. تا جای ممکن جزئیات بیشتری ارائه کنید.
3. روی **Submit new issue** کلیک کنید.

پس از ثبت، گهگاه وضعیت issue خود را بررسی کنید یا اعلان‌های GitHub را فعال کنید.
بازبینان و سایر اعضای جامعه ممکن است پیش از آنکه بتوانند برای issue شما اقدامی انجام دهند، سؤالاتی بپرسند.

## پیشنهاد محتوای جدید

اگر ایده‌ای برای محتوای جدید دارید، اما مطمئن نیستید که این محتوا باید در کجا قرار بگیرد، باز هم می‌توانید یک issue ثبت کنید. یکی از این دو روش را دنبال کنید:

- یک صفحه موجود را در بخشی که فکر می‌کنید محتوا به آن تعلق دارد انتخاب کنید و روی **Create an issue** کلیک کنید.
- به [GitHub](https://github.com/kubernetes/website/issues/new/) بروید و issue را مستقیماً ثبت کنید.

## چگونه issueهای مناسب ثبت کنیم


هنگام ثبت یک issue به نکات زیر توجه داشته باشید:

- شرح روشنی از مشکل ارائه دهید. توضیح دهید که دقیقاً چه چیزی وجود ندارد، منسوخ شده، نادرست است یا نیاز به بهبود دارد.
- تأثیر مشخصی را که این مشکل بر کاربران دارد توضیح دهید.
- دامنه هر issue را به یک واحد کاری معقول محدود کنید. مشکلاتی را که دامنه گسترده‌ای دارند به issueهای کوچکتر تقسیم کنید. برای مثال، «رفع مشکلات مستندات امنیتی» بیش از حد کلی است، اما «افزودن جزئیات به مبحث "محدودسازی دسترسی شبکه"» به اندازه کافی مشخص است و می‌توان روی آن اقدام کرد.
- issueهای موجود را جستجو کنید تا ببینید آیا مورد مرتبط یا مشابهی با issue جدید وجود دارد یا خیر.
- اگر issue جدید به issue یا pull request دیگری مرتبط است، با نشانی کامل URL آن یا با شماره issue یا pull request که با نویسه `#` شروع می‌شود به آن ارجاع دهید. برای مثال: `Introduced by #987654`.
- از [آیین‌نامه رفتار](/community/code-of-conduct/) پیروی کنید. به سایر مشارکت‌کنندگان احترام بگذارید. برای مثال، عبارت «مستندات افتضاح هستند» بازخورد مفید یا مؤدبانه‌ای نیست.
