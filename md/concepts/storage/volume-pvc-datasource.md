<!-- overview -->

این سند مفهوم شبیه‌سازی (cloning) حجم‌های CSI موجود را در کوبرنتیز شرح می‌دهد.
آشنایی با [حجم‌ها](/docs/concepts/storage/volumes) توصیه می‌شود.

<!-- body -->

## مقدمه

قابلیت شبیه‌سازی حجم {{< glossary_tooltip text="CSI" term_id="csi" >}} پشتیبانی از
مشخص کردن {{< glossary_tooltip text="PVC" term_id="persistent-volume-claim" >}}های موجود
در فیلد `dataSource` را اضافه می‌کند تا نشان دهد کاربر می‌خواهد یک {{< glossary_tooltip term_id="volume" >}} را شبیه‌سازی کند.

یک Clone به‌عنوان نسخهٔ تکراری یک Volume موجود کوبرنتیز تعریف می‌شود که می‌توان آن را
مانند هر Volume استاندارد دیگری مصرف کرد. تنها تفاوت این است که هنگام
تأمین، دستگاه backend به‌جای ایجاد یک Volume خالی «جدید»،
یک نسخهٔ تکراری دقیق از Volume مشخص‌شده ایجاد می‌کند.

پیاده‌سازی شبیه‌سازی، از دیدگاه API کوبرنتیز، امکان
مشخص کردن یک PVC موجود به‌عنوان dataSource را هنگام ایجاد PVC جدید اضافه می‌کند.
PVC مبدأ باید متصل (bound) و در دسترس (در حال استفاده نباشد) باشد.

کاربران هنگام استفاده از این قابلیت باید از موارد زیر آگاه باشند:

* پشتیبانی از شبیه‌سازی (`VolumePVCDataSource`) تنها برای درایورهای CSI در دسترس است.
* پشتیبانی از شبیه‌سازی تنها برای provisionerهای پویا در دسترس است.
* درایورهای CSI ممکن است قابلیت شبیه‌سازی حجم را پیاده‌سازی کرده باشند یا نکرده باشند.
* تنها زمانی می‌توانید یک PVC را شبیه‌سازی کنید که در همان فضای نام PVC مقصد وجود داشته باشد
  (مبدأ و مقصد باید در یک فضای نام باشند).
* شبیه‌سازی با یک Storage Class متفاوت پشتیبانی می‌شود.
  - حجم مقصد می‌تواند همان storage class مبدأ یا storage class متفاوتی داشته باشد.
  - می‌توان از storage class پیش‌فرض استفاده کرد و storageClassName را در spec حذف کرد.
* شبیه‌سازی تنها میان دو حجم با تنظیم VolumeMode یکسان قابل انجام است
  (اگر یک حجم با حالت بلوکی درخواست کنید، مبدأ نیز باید حتماً در حالت بلوکی باشد)

## تأمین

Cloneها مانند هر PVC دیگری تأمین می‌شوند، با این استثنا که یک dataSource
اضافه می‌شود که به یک PVC موجود در همان فضای نام ارجاع می‌دهد.

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
    name: clone-of-pvc-1
    namespace: myns
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: cloning
  resources:
    requests:
      storage: 5Gi
  dataSource:
    kind: PersistentVolumeClaim
    name: pvc-1
```

{{< note >}}
باید یک مقدار ظرفیت برای `spec.resources.requests.storage` مشخص کنید و
مقداری که مشخص می‌کنید باید برابر یا بزرگ‌تر از ظرفیت حجم مبدأ باشد.
{{< /note >}}

نتیجه یک PVC جدید با نام `clone-of-pvc-1` است که دقیقاً همان
محتوای مبدأ مشخص‌شده، یعنی `pvc-1`، را دارد.

## استفاده

پس از در دسترس قرار گرفتن PVC جدید، PVC شبیه‌سازی‌شده همانند سایر PVCها مصرف می‌شود.
همچنین در این مرحله انتظار می‌رود که PVC تازه ایجادشده یک آبجکت مستقل باشد.
این PVC را می‌توان به‌طور مستقل و بدون در نظر گرفتن PVC اصلی dataSource آن
مصرف، شبیه‌سازی، snapshot یا حذف کرد. این همچنین بدان معناست که مبدأ
به هیچ وجه به clone تازه ایجادشده پیوند ندارد و می‌توان آن را نیز بدون اثر گذاشتن بر
clone تازه ایجادشده تغییر داد یا حذف کرد.
