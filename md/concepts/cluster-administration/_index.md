نمای کلی مدیریت کلاستر برای هر کسی است که یک کلاستر کوبرنتیز را ایجاد یا مدیریت می‌کند.
این نمای کلی آشنایی نسبی با [مفاهیم](/docs/concepts/) اصلی کوبرنتیز را پیش‌فرض می‌گیرد.

## برنامه‌ریزی یک کلاستر

برای نمونه‌هایی از نحوهٔ برنامه‌ریزی، راه‌اندازی و پیکربندی کلاسترهای کوبرنتیز، به راهنماهای بخش [راه‌اندازی](/docs/setup/)
مراجعه کنید. راهکارهایی که در این مقاله فهرست شده‌اند *توزیع* (distro) نامیده می‌شوند.

{{< note  >}}
همهٔ توزیع‌ها به‌طور فعال نگه‌داری نمی‌شوند. توزیع‌هایی را برگزینید که با یکی از نسخه‌های اخیر
کوبرنتیز آزموده شده‌اند.
{{< /note >}}

پیش از انتخاب یک راهنما، به ملاحظات زیر توجه کنید:

- آیا می‌خواهید کوبرنتیز را روی رایانهٔ خود امتحان کنید، یا می‌خواهید یک کلاستر چندنودی با دسترس‌پذیری بالا
  بسازید؟ توزیع‌هایی را برگزینید که بیشترین تناسب را با نیازهای شما دارند.
- آیا از **یک کلاستر کوبرنتیز میزبانی‌شده**، مانند
  [Google Kubernetes Engine](https://cloud.google.com/kubernetes-engine/)، استفاده خواهید کرد یا **کلاستر خود را میزبانی می‌کنید**؟
- آیا کلاستر شما **درون‌سازمانی (on-premises)** خواهد بود یا **در ابر (IaaS)**؟ کوبرنتیز به‌طور مستقیم
  از کلاسترهای ترکیبی پشتیبانی نمی‌کند. در عوض، می‌توانید چندین کلاستر راه‌اندازی کنید.
- **اگر کوبرنتیز را به‌صورت درون‌سازمانی پیکربندی می‌کنید**، بررسی کنید کدام
  [مدل شبکه](/docs/concepts/cluster-administration/networking/) مناسب‌تر است.
- آیا کوبرنتیز را روی **سخت‌افزار «bare metal»** اجرا خواهید کرد یا روی **ماشین‌های مجازی (VM)**؟
- آیا **می‌خواهید یک کلاستر را اجرا کنید**، یا انتظار دارید **توسعهٔ فعال روی کد پروژهٔ کوبرنتیز** انجام دهید؟
  در حالت دوم، یک توزیع با توسعهٔ فعال را برگزینید. برخی توزیع‌ها تنها از انتشارهای باینری استفاده می‌کنند، اما
  تنوع گزینه‌های بیشتری ارائه می‌دهند.
- با [اجزایی](/docs/concepts/overview/components/) که برای اجرای یک کلاستر لازم است آشنا شوید.

## مدیریت یک کلاستر

* بیاموزید چگونه [نودها را مدیریت کنید](/docs/concepts/architecture/nodes/).
  * دربارهٔ [مقیاس‌دهی خودکار نود](/docs/concepts/cluster-administration/node-autoscaling/) بخوانید.

* بیاموزید چگونه [سهمیهٔ منابع](/docs/concepts/policy/resource-quotas/) را برای کلاسترهای مشترک راه‌اندازی و مدیریت کنید.

## ایمن‌سازی یک کلاستر

* [تولید گواهی‌ها](/docs/tasks/administer-cluster/certificates/) گام‌های
  تولید گواهی‌ها با استفاده از زنجیره‌ابزارهای مختلف را شرح می‌دهد.

* [محیط کانتینر کوبرنتیز](/docs/concepts/containers/container-environment/)
  محیط کانتینرهای مدیریت‌شده توسط kubelet روی یک نود کوبرنتیز را شرح می‌دهد.

* [کنترل دسترسی به API کوبرنتیز](/docs/concepts/security/controlling-access) شرح می‌دهد
  که کوبرنتیز چگونه کنترل دسترسی را برای API خود پیاده‌سازی می‌کند.

* [احراز هویت](/docs/reference/access-authn-authz/authentication/) احراز هویت در
  کوبرنتیز، از جمله گزینه‌های گوناگون احراز هویت، را توضیح می‌دهد.

* [مجوزدهی](/docs/reference/access-authn-authz/authorization/) از
  احراز هویت جداست و نحوهٔ رسیدگی به فراخوانی‌های HTTP را کنترل می‌کند.

* [استفاده از کنترل‌کننده‌های پذیرش](/docs/reference/access-authn-authz/admission-controllers/)
  افزونه‌هایی را توضیح می‌دهد که درخواست‌های ارسالی به سرور API کوبرنتیز را پس از احراز هویت
  و مجوزدهی رهگیری می‌کنند.

* [روش‌های خوب برای Admission Webhookها](/docs/concepts/cluster-administration/admission-webhooks-good-practices/)
  روش‌های خوب و ملاحظاتی را برای طراحی mutating admission
  webhookها و validating admission webhookها ارائه می‌دهد.

* [استفاده از Sysctlها در یک کلاستر کوبرنتیز](/docs/tasks/administer-cluster/sysctl-cluster/)
  برای مدیر سیستم شرح می‌دهد که چگونه از ابزار خط فرمان `sysctl` برای تنظیم پارامترهای هسته استفاده کند
.

* [ممیزی](/docs/tasks/debug/debug-cluster/audit/) شرح می‌دهد که چگونه با لاگ‌های ممیزی
  کوبرنتیز تعامل کنید.

## سرویس‌های اختیاری کلاستر

* [یکپارچه‌سازی DNS](/docs/concepts/services-networking/dns-pod-service/) شرح می‌دهد که چگونه
  یک نام DNS را مستقیماً به یک سرویس کوبرنتیز تحلیل کنید.

* [ثبت لاگ و پایش فعالیت کلاستر](/docs/concepts/cluster-administration/logging/)
  توضیح می‌دهد که ثبت لاگ در کوبرنتیز چگونه کار می‌کند و چگونه آن را پیاده‌سازی کنید.
