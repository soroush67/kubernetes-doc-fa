<!-- overview -->

در کوبرنتیز می‌توانید یک بار کاری را بر اساس تقاضای فعلی منابع _مقیاس‌دهی_ (scale) کنید.
به این ترتیب کلاستر شما می‌تواند با انعطاف و کارایی بیشتری به تغییرات تقاضای منابع واکنش نشان دهد.

هنگام مقیاس‌دهی یک بار کاری، می‌توانید تعداد رونوشت‌هایی (replica) را که بار کاری مدیریت می‌کند افزایش یا کاهش دهید، یا منابع در دسترس رونوشت‌ها را درجا (in-place) تنظیم کنید.

به روش نخست _مقیاس‌دهی افقی_ (horizontal scaling) و به روش دوم _مقیاس‌دهی عمودی_ (vertical scaling) گفته می‌شود.

بسته به مورد استفاده‌تان، روش‌های دستی و خودکاری برای مقیاس‌دهی بارهای کاری وجود دارد.

<!-- body -->

## مقیاس‌دهی دستی بارهای کاری

کوبرنتیز از _مقیاس‌دهی دستی_ بارهای کاری پشتیبانی می‌کند. مقیاس‌دهی افقی را می‌توان با رابط خط فرمان `kubectl` انجام داد.
برای مقیاس‌دهی عمودی باید تعریف منبع بار کاری خود را _وصله_ (patch) کنید.

در ادامه نمونه‌هایی از هر دو راهبرد آمده است.

- **مقیاس‌دهی افقی**: [اجرای چند نمونه از برنامه](/docs/tutorials/kubernetes-basics/scale/scale-intro/)
- **مقیاس‌دهی عمودی**: [تغییر اندازه منابع CPU و حافظه اختصاص‌یافته به کانتینرها](/docs/tasks/configure-pod-container/resize-container-resources)

## مقیاس‌دهی خودکار بارهای کاری

کوبرنتیز از _مقیاس‌دهی خودکار_ بارهای کاری نیز پشتیبانی می‌کند که موضوع اصلی این صفحه است.

مفهوم _مقیاس‌پذیری خودکار_ (Autoscaling) در کوبرنتیز به توانایی به‌روزرسانی خودکار آبجکتی اشاره دارد که مجموعه‌ای از Podها را مدیریت می‌کند (برای مثال یک
{{< glossary_tooltip text="Deployment" term_id="deployment" >}}).

### مقیاس‌دهی افقی بارهای کاری

در کوبرنتیز می‌توانید با استفاده از [HorizontalPodAutoscaler](/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/) (HPA) یک بار کاری را به‌طور خودکار به‌صورت افقی مقیاس‌دهی کنید.

این قابلیت به‌صورت یک منبع API کوبرنتیز و یک {{< glossary_tooltip text="کنترل‌کننده" term_id="controller" >}} پیاده‌سازی شده است و به‌طور دوره‌ای تعداد {{< glossary_tooltip text="رونوشت‌های" term_id="replica" >}} یک بار کاری را تنظیم می‌کند تا با میزان مصرف مشاهده‌شده منابع، مانند مصرف CPU یا حافظه، مطابقت داشته باشد.

یک [آموزش گام‌به‌گام](/docs/tasks/run-application/horizontal-pod-autoscale-walkthrough) برای پیکربندی HorizontalPodAutoscaler برای یک Deployment وجود دارد.

### مقیاس‌دهی عمودی بارهای کاری

{{< feature-state for_k8s_version="v1.25" state="stable" >}}

می‌توانید با استفاده از [VerticalPodAutoscaler](/docs/concepts/workloads/autoscaling/vertical-pod-autoscale/) (VPA) یک بار کاری را به‌طور خودکار به‌صورت عمودی مقیاس‌دهی کنید.
برخلاف HPA، ابزار VPA به‌طور پیش‌فرض همراه کوبرنتیز ارائه نمی‌شود، بلکه افزونه‌ای است که ممکن است شما یا مدیر کلاستر پیش از استفاده لازم باشد آن را مستقر کنید.

پس از نصب، می‌توانید برای بارهای کاری خود {{< glossary_tooltip text="CustomResourceDefinitionها" term_id="customresourcedefinition" >}}
(CRD) ایجاد کنید که تعیین می‌کنند منابع رونوشت‌های مدیریت‌شده _چگونه_ و _چه زمانی_ مقیاس‌دهی شوند.

{{< note >}}
برای کارکرد VPA باید [Metrics Server](https://github.com/kubernetes-sigs/metrics-server) روی کلاستر شما نصب شده باشد.
{{< /note >}}

#### مقیاس‌دهی عمودی درجای Pod

{{< feature-state feature_gate_name="InPlacePodVerticalScaling" >}}

تا نسخه {{< skew currentVersion >}} کوبرنتیز، VPA از تغییر اندازه درجای Podها پشتیبانی نمی‌کند، اما کار روی این یکپارچه‌سازی در جریان است.
برای تغییر اندازه دستی و درجای Podها، به [تغییر اندازه درجای منابع کانتینر](/docs/tasks/configure-pod-container/resize-container-resources/) مراجعه کنید.

### مقیاس‌پذیری خودکار بر اساس اندازه کلاستر

برای بارهای کاری‌ای که باید بر اساس اندازه کلاستر مقیاس‌دهی شوند (برای مثال
`cluster-dns` یا سایر مؤلفه‌های سیستمی)، می‌توانید از
[_Cluster Proportional Autoscaler_](https://github.com/kubernetes-sigs/cluster-proportional-autoscaler) استفاده کنید.
این ابزار نیز مانند VPA بخشی از هسته کوبرنتیز نیست و به‌صورت پروژه‌ای مستقل در GitHub میزبانی می‌شود.

ابزار Cluster Proportional Autoscaler تعداد {{< glossary_tooltip text="نودها" term_id="node" >}} و هسته‌های قابل زمان‌بندی را زیر نظر می‌گیرد و تعداد رونوشت‌های بار کاری هدف را متناسب با آن مقیاس‌دهی می‌کند.

اگر تعداد رونوشت‌ها باید ثابت بماند، می‌توانید با استفاده از
[_Cluster Proportional Vertical Autoscaler_](https://github.com/kubernetes-sigs/cluster-proportional-vertical-autoscaler) بارهای کاری خود را متناسب با اندازه کلاستر به‌صورت عمودی مقیاس‌دهی کنید.
این پروژه **در حال حاضر در مرحله بتا** است و در GitHub در دسترس است.

در حالی که Cluster Proportional Autoscaler تعداد رونوشت‌های یک بار کاری را مقیاس‌دهی می‌کند،
Cluster Proportional Vertical Autoscaler درخواست‌های منابع یک بار کاری (برای مثال یک Deployment یا DaemonSet) را بر اساس تعداد نودها و/یا هسته‌های کلاستر تنظیم می‌کند.

### مقیاس‌پذیری خودکار رویدادمحور

همچنین می‌توان بارهای کاری را بر اساس رویدادها مقیاس‌دهی کرد؛ برای مثال با استفاده از
[_Kubernetes Event Driven Autoscaler_ (**KEDA**)](https://keda.sh/).

پروژه KEDA یک پروژه فارغ‌التحصیل‌شده در CNCF است که به شما امکان می‌دهد بارهای کاری خود را بر اساس تعداد رویدادهایی که باید پردازش شوند، برای مثال تعداد پیام‌های موجود در یک صف، مقیاس‌دهی کنید. طیف گسترده‌ای از آداپتورها برای منابع رویداد مختلف وجود دارد که می‌توانید از میان آن‌ها انتخاب کنید.

### مقیاس‌پذیری خودکار بر اساس زمان‌بندی

راهبرد دیگر برای مقیاس‌دهی بارهای کاری، **زمان‌بندی** عملیات مقیاس‌دهی است؛ برای مثال برای کاهش مصرف منابع در ساعات کم‌بار.

مشابه مقیاس‌پذیری خودکار رویدادمحور، این رفتار را می‌توان با استفاده از KEDA همراه با
[مقیاس‌دهنده `Cron`](https://keda.sh/docs/latest/scalers/cron/) آن به دست آورد.
مقیاس‌دهنده `Cron` به شما امکان می‌دهد زمان‌بندی‌ها (و مناطق زمانی) را برای کاهش یا افزایش مقیاس بارهای کاری خود تعریف کنید.

## مقیاس‌دهی زیرساخت کلاستر

اگر مقیاس‌دهی بارهای کاری برای برآوردن نیازهای شما کافی نباشد، می‌توانید خود زیرساخت کلاستر را نیز مقیاس‌دهی کنید.

مقیاس‌دهی زیرساخت کلاستر معمولاً به معنای افزودن یا حذف {{< glossary_tooltip text="نودها" term_id="node" >}} است.
برای اطلاعات بیشتر، [مقیاس‌پذیری خودکار نودها](/docs/concepts/cluster-administration/node-autoscaling/) را بخوانید.
