CRI یک رابط افزونه‌ای (plugin) است که kubelet را قادر می‌سازد بدون نیاز به کامپایل مجدد اجزای کلاستر، از طیف گسترده‌ای از زمان‌اجراهای کانتینر استفاده کند.

برای اینکه {{< glossary_tooltip text="kubelet" term_id="kubelet" >}} بتواند {{< glossary_tooltip text="Podها" term_id="pod" >}} و کانتینرهای آن‌ها را اجرا کند، به یک
{{<glossary_tooltip text="زمان‌اجرای کانتینر" term_id="container-runtime">}}
فعال و کارآمد روی هر نود در کلاستر خود نیاز دارید.

{{< glossary_definition prepend="The Container Runtime Interface (CRI) is" term_id="cri" length="all" >}}

<!-- body -->

## API {#api}

{{< feature-state for_k8s_version="v1.23" state="stable" >}}

kubelet هنگام اتصال به زمان‌اجرای کانتینر از طریق gRPC، نقش کلاینت را ایفا می‌کند.
نقاط انتهایی (endpoint) سرویس زمان‌اجرا و سرویس ایمیج باید در زمان‌اجرای کانتینر در دسترس باشند و می‌توان آن‌ها را به‌صورت جداگانه در kubelet و با استفاده از
[فلگ خط فرمان](/docs/reference/command-line-tools-reference/kubelet/)
`--container-runtime-endpoint`
پیکربندی کرد.

در کوبرنتیز نسخهٔ v1.26 و پس از آن، kubelet الزام می‌کند که زمان‌اجرای کانتینر از API نسخهٔ `v1` در CRI پشتیبانی کند. اگر زمان‌اجرای کانتینر از API نسخهٔ `v1` پشتیبانی نکند، kubelet نود را ثبت نخواهد کرد.

## ارتقا {#upgrading}

هنگام ارتقای نسخهٔ کوبرنتیز روی یک نود، kubelet راه‌اندازی مجدد می‌شود. اگر زمان‌اجرای کانتینر از API نسخهٔ `v1` در CRI پشتیبانی نکند، kubelet در ثبت نود ناموفق خواهد بود و یک خطا گزارش می‌کند. اگر به دلیل ارتقای زمان‌اجرای کانتینر، لازم باشد اتصال gRPC دوباره برقرار شود (re-dial)، زمان‌اجرا باید از API نسخهٔ `v1` در CRI پشتیبانی کند تا اتصال با موفقیت انجام شود. ممکن است پس از پیکربندی صحیح زمان‌اجرای کانتینر، لازم باشد kubelet را راه‌اندازی مجدد کنید.

## جریان‌سازی فهرست (List streaming) {#list-streaming}

{{< feature-state feature_gate_name="CRIListStreaming" >}}

فراخوانی‌های RPC استاندارد فهرست در CRI (`ListContainers`، `ListPodSandbox`، `ListImages`) همهٔ نتایج را در یک پاسخ unary واحد برمی‌گردانند. روی نودهایی که تعداد زیادی کانتینر دارند (برای مثال، بیش از حدود ۱۰٬۰۰۰ کانتینر، با احتساب کانتینرهای در حال اجرا و متوقف‌شده)، این پاسخ‌ها می‌توانند از محدودیت پیش‌فرض اندازهٔ پیام در gRPC، یعنی ۱۶ مبی‌بایت (MiB)، فراتر روند و باعث شوند kubelet هنگام همگام‌سازی وضعیت با زمان‌اجرای کانتینر با شکست مواجه شود.

وقتی feature gate با نام `CRIListStreaming` فعال باشد، kubelet از RPCهای جریانی سمت سرور (مانند `StreamContainers`، `StreamPodSandboxes` و `StreamImages`) استفاده می‌کند که به زمان‌اجرای کانتینر اجازه می‌دهند نتایج را بین چندین پیام پاسخ تقسیم کند و بدین ترتیب از محدودیت اندازهٔ هر پیام عبور کند. این قابلیت به‌ویژه در موارد زیر مفید است:

- محیط‌هایی با نرخ بالای ایجاد و حذف کانتینر (سامانه‌های CI/CD)
- بارهای کاری پردازش دسته‌ای در مقیاس بزرگ

اگر زمان‌اجرای کانتینر از RPCهای جریانی پشتیبانی نکند، kubelet برای حفظ سازگاری با نسخه‌های قبلی، به‌طور خودکار به RPCهای استاندارد unary بازمی‌گردد.
