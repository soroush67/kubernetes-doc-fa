### شرایط چرخه عمر نود

{{< feature-state feature_gate_name="NodeLifecycleConditions" >}}

شرایط چرخه عمر نود نشان می‌دهند که آیا یک Node در حال گذراندن رویدادی از چرخه عمر خود، مانند تخلیه (drain)، نگهداری یا خاموش‌شدن آرام نود (Graceful Node Shutdown)، است یا نه. این شرایط سیگنال مشترکی فراهم می‌کنند که مدیران کلاستر، کنترل‌کننده‌ها و ابزارهای شخص ثالث می‌توانند از آن برای مدیریت چرخه عمر استفاده کنند.

شرایط شناخته‌شده زیر برای چرخه عمر در دسترس هستند:

{{< table caption = "شرایط چرخه عمر نود و معنای آن‌ها." >}}
| شرط | توضیح |
| --- | --- |
| `DrainInProgress` | این Node طبق معیارهای تخلیه‌ای که مدیر انتخاب کرده است، در حال تخلیه شدن است. |
| `Drained` | این Node به معیارهای تخلیه‌ای که مدیر انتخاب کرده، رسیده است. |
| `MaintenancePlanned` | انتظار می‌رود این Node در آینده دستخوش تغییری شود. اگر این تغییر بر بارهای کاری اثر می‌گذارد، پیش از شروع نگهداری، Node را تخلیه کنید. |
| `MaintenanceInProgress` | این Node در حال نگهداری است. نگهداری می‌تواند شامل اعمال تغییرات سخت‌افزاری یا نرم‌افزاری، رفع مشکل، خارج‌کردن از سرویس یا اشکال‌زدایی باشد. |
| `GracefulNodeShutdownInProgress` | تشخیص داده شده است که خاموش‌شدن آرام نود روی این Node در جریان است. |
{{< /table >}}

مقدار `status` هر شرط چرخه عمر معنای زیر را دارد:

* مقدار `True`: وضعیت چرخه عمری که این شرط توصیف می‌کند، در حال حاضر مشاهده می‌شود.
* مقدار `False`: وضعیت چرخه عمری که این شرط توصیف می‌کند، در حال حاضر مشاهده نمی‌شود.
* مقدار `Unknown`: نویسنده شرط نمی‌تواند تعیین کند که آیا این وضعیت چرخه عمر فعال است یا نه.

شرایط چرخه عمر مشاهداتی هستند که اطلاعات زمینه‌ای مفیدی درباره وضعیت چرخه عمر یک Node به دست می‌دهند. برای مثال، با `MaintenancePlanned` می‌توانید اعلام کنید که یک Node ممکن است در آینده وارد نگهداری شود، و با `Drained` می‌توانید نشان دهید که معیارهای تخلیه انتخاب‌شده توسط مدیر برآورده شده‌اند.

فیلد `reason` مشخص می‌کند که چرا این شرط وضعیت کنونی خود را دارد. نویسندگان شرط باید برای `reason` از مقادیر پایدار با قالب CamelCase استفاده کنند. فیلد `message` می‌تواند جزئیات بیشتری را به شکلی خوانا برای انسان ارائه دهد.

مثال زیر نشان می‌دهد که برای یک Node نگهداری برنامه‌ریزی شده است:

```yaml
status:
  conditions:
  - type: MaintenancePlanned
    status: "True"
    reason: MaintenanceWindow
    message: "Hardware maintenance is scheduled for this Node"
    lastTransitionTime: "2026-07-20T14:00:00Z"
```

#### نوشتن شرایط چرخه عمر

تنظیم و پاک‌کردن شرایط چرخه عمر روی Node بر عهده مدیر یا کنترل‌کننده‌ای است که مدیر به آن اختیار داده است.

نویسنده شرط تعیین می‌کند که یک وضعیت چرخه عمر چه زمانی فعال است. وقتی این وضعیت دیگر فعال نباشد، نویسنده شرط را روی `False` تنظیم می‌کند یا آن را حذف می‌کند.

کوبرنتیز مالکیت انحصاری نوشتن، قفل‌گذاری یا واگذاری میان عامل‌ها را تعریف نمی‌کند. نویسندگان شرط باید هماهنگی درباره مالکیت را خارج از این API انجام دهند.

{{< note >}}
کنترل‌کننده‌های اصلی بار کاری رفتار خود را بر اساس شرایط چرخه عمر تغییر نمی‌دهند. تنظیم یک شرط چرخه عمر بر رفتار اصلی Node اثری ندارد.
{{< /note >}}

همچنان باید از سازوکارهای موجود برای مدیریت چرخه عمر استفاده کرد:

* برای جلوگیری از زمان‌بندی عادی روی یک Node، از [`kubectl cordon`](/docs/reference/kubectl/generated/kubectl_cordon/) استفاده کنید یا `.spec.unschedulable` را تنظیم کنید.
* برای بیرون‌راندن ایمن Podها پیش از خارج‌کردن یک Node از سرویس، از [`kubectl drain`](/docs/tasks/administer-cluster/safely-drain-node/) استفاده کنید.
* برای کنترل زمان‌بندی Podها و سیاست بیرون‌راندن آن‌ها، از [taintها و tolerationها](/docs/concepts/scheduling-eviction/taint-and-toleration/) استفاده کنید.

#### مشاهده شرایط چرخه عمر

برای مشاهده همه شرایط یک Node، از `kubectl describe node` استفاده کنید:

```shell
kubectl describe node <node-name>
```

برای چاپ نوع و وضعیت هر شرط، از دستور زیر استفاده کنید:

```shell
kubectl get node <node-name> \
  -o jsonpath='{range .status.conditions[*]}{.type}={.status}{"\n"}{end}'
```
