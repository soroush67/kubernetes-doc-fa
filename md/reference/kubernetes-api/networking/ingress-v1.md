      <td>host نام دامنه کاملاً معتبر (fully qualified) یک میزبان شبکه است، همان‌طور که در RFC 3986 تعریف شده است. به انحراف‌های زیر نسبت به بخش «host» از URI که در RFC 3986 تعریف شده است توجه کنید: 1. نشانی‌های IP مجاز نیستند. در حال حاضر یک IngressRuleValue فقط می‌تواند برای IP موجود در Spec مربوط به Ingress والد اعمال شود. 2. جداکننده `:` رعایت نمی‌شود، زیرا پورت‌ها مجاز نیستند. در حال حاضر پورت یک Ingress به‌طور ضمنی برای http برابر :80 و برای https برابر :443 است. هر دوی این مقادیر ممکن است در آینده تغییر کنند. درخواست‌های ورودی پیش از IngressRuleValue با host مقایسه می‌شوند. اگر host مشخص نشده باشد، Ingress همه ترافیک را بر اساس IngressRuleValue مشخص‌شده مسیریابی می‌کند.  host می‌تواند «دقیق» (precise) باشد، یعنی نام دامنه یک میزبان شبکه بدون نقطه پایانی (مانند "foo.bar.com")، یا «wildcard» باشد، یعنی نام دامنه‌ای که با یک برچسب wildcard منفرد پیشوند گرفته است (مانند "*.foo.com"). نویسه wildcard یعنی '\*' باید به‌تنهایی به‌عنوان اولین برچسب DNS ظاهر شود و فقط با یک برچسب مطابقت دارد. نمی‌توان یک برچسب wildcard را به‌تنهایی داشت (مثلاً Host == "*"). درخواست‌ها با فیلد Host به روش زیر مطابقت داده می‌شوند: 1. اگر host دقیق باشد، درخواست در صورتی با این قاعده مطابقت دارد که هدر host در http با Host برابر باشد. 2. اگر host از نوع wildcard باشد، درخواست در صورتی با این قاعده مطابقت دارد که هدر host در http با پسوند قاعده wildcard (پس از حذف اولین برچسب) برابر باشد.</td>
    </tr>
