این صفحه نحوهٔ پیکربندی فضای نام کاربری (user namespace) را برای پادها نشان می‌دهد. با این کار می‌توانید کاربری را که درون کانتینر اجرا می‌شود از کاربر میزبان جدا کنید.

فرایندی که درون کانتینر با کاربر root اجرا می‌شود، می‌تواند روی میزبان با کاربر دیگری (غیر root) اجرا شود. به عبارت دیگر، این فرایند برای عملیات درون فضای نام کاربری، دسترسی‌های کامل دارد، اما برای عملیات بیرون از این فضای نام هیچ دسترسی ویژه‌ای ندارد.

با این قابلیت می‌توانید آسیبی را که یک کانتینر نفوذشده می‌تواند به میزبان یا سایر پادهای همان نود وارد کند، کاهش دهید. [چندین آسیب‌پذیری امنیتی][KEP-vulns] با سطح **HIGH** یا **CRITICAL** وجود دارد که در صورت فعال بودن فضاهای نام کاربری قابل بهره‌برداری نبودند. انتظار می‌رود فضای نام کاربری برخی از آسیب‌پذیری‌های آینده را نیز مهار کند.

اگر از فضای نام کاربری استفاده نکنید، کانتینری که با کاربر root اجرا می‌شود، در صورت گریز از کانتینر (container breakout)، روی نود دسترسی root خواهد داشت. همچنین اگر قابلیتی (capability) به کانتینر داده شده باشد، آن قابلیت‌ها روی میزبان نیز معتبر هستند. هنگام استفاده از فضاهای نام کاربری، هیچ‌یک از این موارد صدق نمی‌کند.

[KEP-vulns]: https://github.com/kubernetes/enhancements/tree/217d790720c5aef09b8bd4d6ca96284a0affe6c2/keps/sig-node/127-user-namespaces#motivation

اگر ترکیبی از نودها دارید و تنها برخی از آن‌ها از فضای نام کاربری برای Podها پشتیبانی می‌کنند، باید مطمئن شوید که Podهای دارای فضای نام کاربری روی نودهای مناسب [زمان‌بندی](/docs/concepts/scheduling-eviction/assign-pod-node/) می‌شوند.

## اجرای یک Pod که از فضای نام کاربری استفاده می‌کند {#create-pod}

برای فعال کردن فضای نام کاربری برای یک پاد، فیلد `hostUsers` در `.spec` را روی `false` تنظیم کنید. برای مثال:

{{% code_sample file="pods/user-namespaces-stateless.yaml" %}}

1. پاد را در کلاستر خود ایجاد کنید:

   ```shell
   kubectl apply -f https://k8s.io/examples/pods/user-namespaces-stateless.yaml
   ```

1. با exec وارد پاد شوید و دستور `readlink /proc/self/ns/user` را اجرا کنید:

   ```shell
   kubectl exec -ti userns -- bash
   ```

این دستور را اجرا کنید:

```shell
readlink /proc/self/ns/user
```

خروجی مشابه زیر است:

```shell
user:[4026531837]
```

همچنین این دستور را اجرا کنید:

```shell
cat /proc/self/uid_map
```

خروجی مشابه زیر است:
```shell
0  833617920      65536
```

سپس یک پوسته (shell) روی میزبان باز کنید و همین دستورها را اجرا کنید.

دستور `readlink` فضای نام کاربری‌ای را نشان می‌دهد که فرایند در آن اجرا می‌شود. خروجی این دستور هنگام اجرا روی میزبان و درون کانتینر باید متفاوت باشد.

آخرین عدد فایل `uid_map` درون کانتینر باید 65536 باشد و روی میزبان باید عدد بزرگ‌تری باشد.

اگر kubelet را درون یک فضای نام کاربری اجرا می‌کنید، باید خروجی اجرای دستور در پاد را با خروجی اجرای دستور زیر روی میزبان مقایسه کنید:

```shell
readlink /proc/$pid/ns/user
```

و به‌جای `$pid`، شناسهٔ فرایند (PID) مربوط به kubelet را قرار دهید.
