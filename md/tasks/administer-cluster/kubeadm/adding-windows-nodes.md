این صفحه نحوهٔ افزودن نودهای کارگر (worker node) ویندوزی به یک کلاستر kubeadm را توضیح می‌دهد.

## {{% heading "prerequisites" %}}

* یک نمونهٔ در حال اجرای [Windows Server 2022](https://www.microsoft.com/cloud-platform/windows-server-pricing)
(یا نسخه‌های بالاتر) با دسترسی مدیریتی.
* یک کلاستر kubeadm در حال اجرا که با `kubeadm init` و طبق مراحل
سند [ایجاد کلاستر با kubeadm](/docs/setup/production-environment/tools/kubeadm/create-cluster-kubeadm/) ایجاد شده باشد.

## افزودن نودهای کارگر ویندوزی

{{< note >}}
برای تسهیل افزودن نودهای کارگر ویندوزی به کلاستر، از اسکریپت‌های PowerShell موجود در مخزن
https://sigs.k8s.io/sig-windows-tools استفاده می‌شود.
{{< /note >}}

برای هر ماشین، کارهای زیر را انجام دهید:

1. یک نشست PowerShell روی ماشین باز کنید.
1. مطمئن شوید که با حساب Administrator یا یک کاربر دارای دسترسی ممتاز وارد شده‌اید.

سپس مراحل زیر را دنبال کنید.

### نصب containerd

{{% thirdparty-content %}}

برای نصب containerd، ابتدا دستور زیر را اجرا کنید:

  ```PowerShell
  curl.exe -LO https://raw.githubusercontent.com/kubernetes-sigs/sig-windows-tools/master/hostprocess/Install-Containerd.ps1
  ```

سپس دستور زیر را اجرا کنید، اما پیش از آن `CONTAINERD_VERSION` را با یکی از نسخه‌های اخیر
موجود در [مخزن containerd](https://github.com/containerd/containerd/releases) جایگزین کنید.
نسخه نباید پیشوند `v` داشته باشد. برای مثال، به‌جای `v1.7.22` از `1.7.22` استفاده کنید:

  ```PowerShell
  .\Install-Containerd.ps1 -ContainerDVersion CONTAINERD_VERSION
  ```

* سایر پارامترهای `Install-Containerd.ps1` مانند `netAdapterName` را در صورت نیاز تنظیم کنید.
* اگر ماشین شما از Hyper-V پشتیبانی نمی‌کند و نمی‌تواند میزبان کانتینرهای ایزوله با Hyper-V باشد،
پارامتر `skipHypervisorSupportCheck` را تنظیم کنید.
* اگر پارامترهای اختیاری `CNIBinPath` و/یا `CNIConfigPath` اسکریپت `Install-Containerd.ps1` را تغییر دهید،
باید افزونهٔ CNI ویندوزیِ نصب‌شده را نیز با مقادیر متناظر پیکربندی کنید.

### نصب kubeadm و kubelet

برای نصب kubeadm و kubelet، دستورهای زیر را اجرا کنید:

  ```PowerShell
  curl.exe -LO https://raw.githubusercontent.com/kubernetes-sigs/sig-windows-tools/master/hostprocess/PrepareNode.ps1
  .\PrepareNode.ps1 -KubernetesVersion v{{< skew currentPatchVersion >}}
  ```

* در صورت نیاز، پارامتر `KubernetesVersion` اسکریپت `PrepareNode.ps1` را تنظیم کنید.

### اجرای `kubeadm join`

دستوری را که `kubeadm init` در خروجی خود نمایش داده است اجرا کنید. برای مثال:

  ```bash
  kubeadm join --token <token> <control-plane-host>:<control-plane-port> --discovery-token-ca-cert-hash sha256:<hash>
  ```

#### اطلاعات بیشتر دربارهٔ kubeadm join

{{< note >}}
برای مشخص کردن یک زوج IPv6 برای `<control-plane-host>:<control-plane-port>`، نشانی IPv6 باید درون کروشه قرار گیرد؛ برای مثال: `[2001:db8::101]:2073`.
{{< /note >}}

اگر توکن را در اختیار ندارید، می‌توانید با اجرای دستور زیر روی نود control plane آن را به دست آورید:

```bash
# Run this on a control plane node
sudo kubeadm token list
```

خروجی مشابه زیر است:

```console
TOKEN                    TTL  EXPIRES              USAGES           DESCRIPTION            EXTRA GROUPS
8ewj1p.9r9hcjoqgajrj4gi  23h  2018-06-12T02:51:28Z authentication,  The default bootstrap  system:
                                                   signing          token generated by     bootstrappers:
                                                                    'kubeadm init'.        kubeadm:
                                                                                           default-node-token
```

به‌طور پیش‌فرض، توکن‌های پیوستن نود پس از ۲۴ ساعت منقضی می‌شوند. اگر پس از منقضی شدن توکن فعلی
می‌خواهید نودی را به کلاستر بپیوندانید، می‌توانید با اجرای دستور زیر روی نود control plane
یک توکن جدید ایجاد کنید:

```bash
# Run this on a control plane node
sudo kubeadm token create
```

خروجی مشابه زیر است:

```console
5didvk.d09sbcov8ph2amjw
```

اگر مقدار `--discovery-token-ca-cert-hash` را در اختیار ندارید، می‌توانید با اجرای
دستورهای زیر روی نود control plane آن را به دست آورید:

```bash
sudo cat /etc/kubernetes/pki/ca.crt | openssl x509 -pubkey  | openssl rsa -pubin -outform der 2>/dev/null | \
   openssl dgst -sha256 -hex | sed 's/^.* //'
```

خروجی مشابه زیر است:

```console
8cb2de97839780a412b93877f8507ad6c94f73add17d5d7058e91741c9d5ec78
```

خروجی دستور `kubeadm join` باید تقریباً به این شکل باشد:

```
[preflight] Running pre-flight checks

... (log output of join workflow) ...

Node join complete:
* Certificate signing request sent to control-plane and response
  received.
* Kubelet informed of new secure connection details.

Run 'kubectl get nodes' on control-plane to see this machine join.
```

چند ثانیه بعد، باید این نود را در خروجی `kubectl get nodes` ببینید
(برای مثال، `kubectl` را روی یک نود control plane اجرا کنید).

### پیکربندی شبکه

راه‌اندازی CNI در کلاسترهایی که ترکیبی از نودهای لینوکسی و ویندوزی دارند، به مراحلی فراتر از
اجرای `kubectl apply` روی یک فایل مانیفست نیاز دارد. افزون بر این، افزونهٔ CNI در حال اجرا روی
نودهای control plane باید برای پشتیبانی از افزونهٔ CNI در حال اجرا روی نودهای کارگر ویندوزی آماده شود.

{{% thirdparty-content %}}

در حال حاضر فقط تعداد اندکی از افزونه‌های CNI از ویندوز پشتیبانی می‌کنند. دستورالعمل‌های راه‌اندازی هر یک از آن‌ها را در ادامه می‌یابید:
* [Calico](https://docs.tigera.io/calico/latest/getting-started/kubernetes/windows-calico/)

### نصب kubectl برای ویندوز (اختیاری) {#install-kubectl}

به [نصب و راه‌اندازی kubectl در ویندوز](/docs/tasks/tools/install-kubectl-windows/) مراجعه کنید.
