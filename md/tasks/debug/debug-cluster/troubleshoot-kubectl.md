این مستند به بررسی و تشخیص مشکلات مربوط به
{{<glossary_tooltip text="kubectl" term_id="kubectl">}} می‌پردازد.
اگر در دسترسی به `kubectl` یا اتصال به کلاستر خود با مشکل روبه‌رو شده‌اید، این
مستند سناریوهای رایج و راه‌حل‌های احتمالی گوناگونی را شرح می‌دهد تا بتوانید علت
احتمالی را شناسایی و برطرف کنید.

<!-- body -->

## {{% heading "prerequisites" %}}

* باید یک کلاستر کوبرنتیز داشته باشید.
* همچنین باید `kubectl` را نصب کرده باشید؛ [ابزارهای نصب](/docs/tasks/tools/#kubectl) را ببینید.

## بررسی راه‌اندازی kubectl

مطمئن شوید که `kubectl` را به‌درستی روی ماشین محلی خود نصب و پیکربندی کرده‌اید.
نسخهٔ `kubectl` را بررسی کنید تا مطمئن شوید که به‌روز و با کلاستر شما سازگار است.

نسخهٔ kubectl را بررسی کنید:

```shell
kubectl version
```

خروجی مشابهی خواهید دید:

```console
Client Version: version.Info{Major:"1", Minor:"27", GitVersion:"v1.27.4",GitCommit:"fa3d7990104d7c1f16943a67f11b154b71f6a132", GitTreeState:"clean",BuildDate:"2023-07-19T12:20:54Z", GoVersion:"go1.20.6", Compiler:"gc", Platform:"linux/amd64"}
Kustomize Version: v5.0.1
Server Version: version.Info{Major:"1", Minor:"27", GitVersion:"v1.27.3",GitCommit:"25b4e43193bcda6c7328a6d147b1fb73a33f1598", GitTreeState:"clean",BuildDate:"2023-06-14T09:47:40Z", GoVersion:"go1.20.5", Compiler:"gc", Platform:"linux/amd64"}

```

اگر به‌جای `Server Version` پیام `Unable to connect to the server: dial tcp <server-ip>:8443: i/o timeout`
را می‌بینید، باید اتصال kubectl به کلاستر خود را عیب‌یابی کنید.

مطمئن شوید که kubectl را طبق
[مستندات رسمی نصب kubectl](/docs/tasks/tools/#kubectl) نصب کرده‌اید و
متغیر محیطی `$PATH` را به‌درستی پیکربندی کرده‌اید.

## بررسی kubeconfig

ابزار `kubectl` برای اتصال به یک کلاستر کوبرنتیز به فایل `kubeconfig` نیاز دارد.
این فایل معمولاً در مسیر `~/.kube/config` قرار دارد. مطمئن شوید که یک فایل
`kubeconfig` معتبر دارید. اگر این فایل را ندارید، می‌توانید آن را از مدیر کوبرنتیز
خود دریافت کنید یا از مسیر `/etc/kubernetes/admin.conf` در control plane کوبرنتیز
کپی کنید. اگر کلاستر کوبرنتیز خود را روی یک پلتفرم ابری مستقر کرده‌اید و فایل
`kubeconfig` خود را از دست داده‌اید، می‌توانید آن را با ابزارهای ارائه‌دهندهٔ ابری خود
دوباره تولید کنید. برای تولید دوبارهٔ فایل `kubeconfig` به مستندات ارائه‌دهندهٔ ابری
خود مراجعه کنید.

بررسی کنید که متغیر محیطی `$KUBECONFIG` به‌درستی پیکربندی شده باشد. برای تعیین
مسیر فایل `kubeconfig` می‌توانید متغیر محیطی `$KUBECONFIG` را تنظیم کنید یا
پارامتر `--kubeconfig` را همراه با kubectl به کار ببرید.

## بررسی اتصال VPN

اگر برای دسترسی به کلاستر کوبرنتیز خود از شبکهٔ خصوصی مجازی (VPN) استفاده می‌کنید،
مطمئن شوید که اتصال VPN شما فعال و پایدار است. گاهی قطع شدن VPN می‌تواند به
مشکلاتی در اتصال به کلاستر منجر شود. دوباره به VPN متصل شوید و دسترسی به کلاستر را
از نو امتحان کنید.

## احراز هویت و مجوزدهی

اگر از احراز هویت مبتنی بر توکن استفاده می‌کنید و kubectl خطایی دربارهٔ توکن احراز
هویت یا نشانی سرور احراز هویت برمی‌گرداند، بررسی کنید که توکن احراز هویت کوبرنتیز و
نشانی سرور احراز هویت به‌درستی پیکربندی شده باشند.

اگر kubectl خطایی دربارهٔ مجوزدهی برمی‌گرداند، مطمئن شوید که از اعتبارنامه‌های
کاربری معتبر استفاده می‌کنید و برای دسترسی به منبعی که درخواست کرده‌اید، مجوز
لازم را دارید.

## بررسی کانتکست‌ها

کوبرنتیز از [چندین کلاستر و کانتکست (context)](/docs/tasks/access-application-cluster/configure-access-multiple-clusters/) پشتیبانی می‌کند.
مطمئن شوید که برای تعامل با کلاستر خود از کانتکست درست استفاده می‌کنید.

کانتکست‌های موجود را فهرست کنید:

```shell
kubectl config get-contexts
```

به کانتکست مناسب تغییر دهید:

```shell
kubectl config use-context <context-name>
```

## سرور API و متعادل‌کنندهٔ بار

سرور {{<glossary_tooltip text="kube-apiserver" term_id="kube-apiserver">}} مؤلفهٔ
مرکزی یک کلاستر کوبرنتیز است. اگر سرور API یا متعادل‌کنندهٔ بار (load balancer) که
جلوی سرورهای API شما اجرا می‌شود در دسترس نباشد یا پاسخ ندهد، نمی‌توانید با کلاستر
تعامل کنید.

با دستور `ping` بررسی کنید که میزبان سرور API در دسترس باشد. اتصال شبکهٔ کلاستر و
دیوارهٔ آتش را بررسی کنید. اگر برای استقرار کلاستر از یک ارائه‌دهندهٔ ابری استفاده
می‌کنید، وضعیت بررسی سلامت سرور API کلاستر را در ارائه‌دهندهٔ ابری خود بررسی کنید.

وضعیت متعادل‌کنندهٔ بار را (در صورت استفاده) بررسی کنید تا مطمئن شوید که سالم است و
ترافیک را به سرور API هدایت می‌کند.

## مشکلات TLS
* ابزارهای اضافی موردنیاز: `base64` و `openssl` نسخهٔ 3.0 یا بالاتر.

سرور API کوبرنتیز به‌طور پیش‌فرض فقط درخواست‌های HTTPS را پاسخ می‌دهد. در این حالت
ممکن است مشکلات TLS به دلایل گوناگونی مانند انقضای گواهی یا اعتبار زنجیرهٔ اعتماد رخ دهد.

گواهی TLS را می‌توانید در فایل kubeconfig که در مسیر `~/.kube/config` قرار دارد
پیدا کنید. ویژگی `certificate-authority` گواهی CA و ویژگی `client-certificate`
گواهی کلاینت را در خود دارد.

تاریخ انقضای این گواهی‌ها را بررسی کنید:

```shell
kubectl config view --flatten --output 'jsonpath={.clusters[0].cluster.certificate-authority-data}' | base64 -d | openssl x509 -noout -dates
```

خروجی:
```console
notBefore=Feb 13 05:57:47 2024 GMT
notAfter=Feb 10 06:02:47 2034 GMT
```

```shell
kubectl config view --flatten --output 'jsonpath={.users[0].user.client-certificate-data}'| base64 -d | openssl x509 -noout -dates
```

خروجی:
```console
notBefore=Feb 13 05:57:47 2024 GMT
notAfter=Feb 12 06:02:50 2025 GMT
```

## بررسی ابزارهای کمکی kubectl

برخی از ابزارهای کمکی احراز هویت kubectl دسترسی آسانی به کلاسترهای کوبرنتیز فراهم
می‌کنند. اگر از چنین ابزارهایی استفاده کرده‌اید و با مشکلات اتصال روبه‌رو هستید،
مطمئن شوید که پیکربندی‌های لازم هنوز وجود دارند.

پیکربندی kubectl را از نظر جزئیات احراز هویت بررسی کنید:

```shell
kubectl config view
```

اگر پیش‌تر از یک ابزار کمکی (برای نمونه `kubectl-oidc-login`) استفاده کرده‌اید،
مطمئن شوید که هنوز نصب و به‌درستی پیکربندی شده باشد.
