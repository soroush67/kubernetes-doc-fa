<!-- overview -->
آبجکت‌های کوبرنتیز را می‌توان با فرمان‌های دستوری (imperative commands) که در ابزار خط فرمان `kubectl` تعبیه شده‌اند، به‌سرعت و به‌طور مستقیم ایجاد، به‌روزرسانی و حذف کرد. این سند توضیح می‌دهد که این فرمان‌ها چگونه سازمان‌دهی شده‌اند و چگونه می‌توان از آن‌ها برای مدیریت آبجکت‌های زنده استفاده کرد.

## مزایا و معایب

ابزار `kubectl` از سه نوع مدیریت آبجکت پشتیبانی می‌کند:

* فرمان‌های دستوری
* پیکربندی دستوری آبجکت
* پیکربندی اعلانی آبجکت

برای بررسی مزایا و معایب هر یک از این روش‌های مدیریت آبجکت، به [مدیریت آبجکت‌های کوبرنتیز](/docs/concepts/overview/working-with-objects/object-management/) مراجعه کنید.

## نحوهٔ ایجاد آبجکت‌ها

ابزار `kubectl` برای ایجاد برخی از رایج‌ترین انواع آبجکت، فرمان‌هایی مبتنی بر فعل در اختیار می‌گذارد. نام این فرمان‌ها طوری انتخاب شده است که برای کاربرانی که با انواع آبجکت‌های کوبرنتیز آشنا نیستند نیز قابل‌فهم باشد.

- `run`: یک Pod جدید برای اجرای یک کانتینر ایجاد می‌کند.
- `expose`: یک آبجکت Service جدید برای توزیع بار ترافیک میان Podها ایجاد می‌کند.
- `autoscale`: یک آبجکت Autoscaler جدید ایجاد می‌کند تا یک کنترل‌کننده، مانند Deployment، به‌طور خودکار و افقی مقیاس‌پذیر شود.

ابزار `kubectl` همچنین از فرمان‌های ایجادی مبتنی بر نوع آبجکت پشتیبانی می‌کند. این فرمان‌ها انواع بیشتری از آبجکت‌ها را پشتیبانی می‌کنند و هدفشان را صریح‌تر بیان می‌کنند، اما کاربر باید نوع آبجکتی را که قصد ایجادش را دارد بداند.

- `create <objecttype> [<subtype>] <instancename>`

برخی از انواع آبجکت زیرنوع‌هایی دارند که می‌توانید آن‌ها را در فرمان `create` مشخص کنید. برای مثال، آبجکت Service چند زیرنوع دارد که از جملهٔ آن‌ها ClusterIP، LoadBalancer و NodePort است. در مثال زیر یک Service با زیرنوع NodePort ایجاد می‌شود:

```shell
kubectl create service nodeport <myservicename>
```

در مثال بالا، فرمان `create service nodeport` یک زیرفرمان از فرمان `create service` نامیده می‌شود.

برای یافتن آرگومان‌ها و فلگ‌هایی که یک زیرفرمان پشتیبانی می‌کند، می‌توانید از فلگ `-h` استفاده کنید:

```shell
kubectl create service nodeport -h
```

## نحوهٔ به‌روزرسانی آبجکت‌ها

فرمان `kubectl` برای برخی از عملیات رایج به‌روزرسانی، فرمان‌هایی مبتنی بر فعل در اختیار می‌گذارد. نام این فرمان‌ها طوری انتخاب شده است که کاربرانی که با آبجکت‌های کوبرنتیز آشنا نیستند بتوانند بدون دانستن فیلدهای مشخصی که باید تنظیم شوند، به‌روزرسانی‌ها را انجام دهند:

- `scale`: یک کنترل‌کننده را با به‌روزرسانی تعداد رونوشت‌های (replica) آن به‌صورت افقی مقیاس می‌دهد تا Podهایی اضافه یا حذف شوند.
- `annotate`: یک حاشیه‌نویسی (annotation) را به یک آبجکت اضافه یا از آن حذف می‌کند.
- `label`: یک برچسب را به یک آبجکت اضافه یا از آن حذف می‌کند.

فرمان `kubectl` همچنین از فرمان‌های به‌روزرسانی مبتنی بر یکی از جنبه‌های آبجکت پشتیبانی می‌کند. تنظیم این جنبه ممکن است در انواع مختلف آبجکت، فیلدهای متفاوتی را تنظیم کند:

- `set` `<field>`: یکی از جنبه‌های یک آبجکت را تنظیم می‌کند.

{{< note >}}
در نسخهٔ 1.5 کوبرنتیز، همهٔ فرمان‌های مبتنی بر فعل یک فرمان متناظر مبتنی بر جنبه ندارند.
{{< /note >}}

ابزار `kubectl` از روش‌های دیگری نیز برای به‌روزرسانی مستقیم یک آبجکت زنده پشتیبانی می‌کند، اما استفاده از آن‌ها به درک بهتری از شِمای آبجکت‌های کوبرنتیز نیاز دارد.

- `edit`: پیکربندی خام یک آبجکت زنده را با باز کردن آن در یک ویرایشگر، به‌طور مستقیم ویرایش می‌کند.
- `patch`: فیلدهای مشخصی از یک آبجکت زنده را با استفاده از یک رشتهٔ وصله (patch string) به‌طور مستقیم تغییر می‌دهد.
برای جزئیات بیشتر دربارهٔ رشته‌های وصله، بخش patch را در
[API Conventions](https://git.k8s.io/community/contributors/devel/sig-architecture/api-conventions.md#patch-operations) ببینید.

## نحوهٔ حذف آبجکت‌ها

برای حذف یک آبجکت از کلاستر می‌توانید از فرمان `delete` استفاده کنید:

- `delete <type>/<name>`

{{< note >}}
از `kubectl delete` می‌توان هم برای فرمان‌های دستوری و هم برای پیکربندی دستوری آبجکت استفاده کرد. تفاوت در آرگومان‌هایی است که به فرمان داده می‌شود. برای استفاده از `kubectl delete` به‌عنوان یک فرمان دستوری، آبجکتی را که باید حذف شود به‌عنوان آرگومان به آن بدهید. در مثال زیر، یک آبجکت Deployment با نام nginx به فرمان داده می‌شود:
{{< /note >}}

```shell
kubectl delete deployment/nginx
```

چند فرمان برای چاپ اطلاعات دربارهٔ یک آبجکت وجود دارد:

- `get`: اطلاعات پایه‌ای دربارهٔ آبجکت‌های منطبق را چاپ می‌کند. برای دیدن فهرست گزینه‌ها از `get -h` استفاده کنید.
- `describe`: اطلاعات تفصیلی و تجمیع‌شده دربارهٔ آبجکت‌های منطبق را چاپ می‌کند.
- `logs`: خروجی‌های stdout و stderr کانتینری را که در یک Pod اجرا می‌شود چاپ می‌کند.

## استفاده از فرمان‌های `set` برای تغییر آبجکت‌ها پیش از ایجاد

برخی از فیلدهای آبجکت فلگی ندارند که بتوان آن را در فرمان `create` به کار برد. در برخی از این موارد، می‌توانید با ترکیب `set` و `create` مقدار فیلد را پیش از ایجاد آبجکت مشخص کنید. برای این کار، خروجی فرمان `create` را با لوله (pipe) به فرمان `set` می‌دهید و سپس دوباره آن را به فرمان `create` برمی‌گردانید. به مثال زیر توجه کنید:

```sh
kubectl create service clusterip my-svc --clusterip="None" -o yaml --dry-run=client | kubectl set selector --local -f - 'environment=qa' -o yaml | kubectl create -f -
```

1. فرمان `kubectl create service -o yaml --dry-run=client` پیکربندی Service را ایجاد می‌کند، اما به‌جای ارسال آن به سرور API کوبرنتیز، آن را در قالب YAML در stdout چاپ می‌کند.
1. فرمان `kubectl set selector --local -f - -o yaml` پیکربندی را از stdin می‌خواند و پیکربندی به‌روزشده را در قالب YAML در stdout می‌نویسد.
1. فرمان `kubectl create -f -` آبجکت را با استفاده از پیکربندی‌ای که از طریق stdin دریافت کرده است ایجاد می‌کند.

## استفاده از `--edit` برای تغییر آبجکت‌ها پیش از ایجاد

با `kubectl create --edit` می‌توانید پیش از ایجاد یک آبجکت، هر تغییر دلخواهی در آن اعمال کنید. به مثال زیر توجه کنید:

```sh
kubectl create service clusterip my-svc --clusterip="None" -o yaml --dry-run=client > /tmp/srv.yaml
kubectl create --edit -f /tmp/srv.yaml
```

1. فرمان `kubectl create service` پیکربندی Service را ایجاد می‌کند و آن را در `/tmp/srv.yaml` ذخیره می‌کند.
1. فرمان `kubectl create --edit` پیش از ایجاد آبجکت، فایل پیکربندی را برای ویرایش باز می‌کند.
