<!-- overview -->
می‌توان آبجکت‌های کوبرنتیز را با ابزار خط فرمان `kubectl` و یک فایل پیکربندی آبجکت که به زبان YAML یا JSON نوشته شده است، ایجاد، به‌روزرسانی و حذف کرد.
این سند توضیح می‌دهد که چگونه می‌توان آبجکت‌ها را با استفاده از فایل‌های پیکربندی تعریف و مدیریت کرد.


## {{% heading "prerequisites" %}}


ابزار [`kubectl`](/docs/tasks/tools/) را نصب کنید.

## مزایا و معایب

ابزار `kubectl` از سه نوع مدیریت آبجکت پشتیبانی می‌کند:

* فرمان‌های دستوری (imperative commands)
* پیکربندی دستوری آبجکت
* پیکربندی اعلانی (declarative) آبجکت

برای آشنایی با مزایا و معایب هر یک از انواع مدیریت آبجکت، به [مدیریت آبجکت‌های کوبرنتیز](/docs/concepts/overview/working-with-objects/object-management/) مراجعه کنید.

## نحوهٔ ایجاد آبجکت‌ها

با فرمان `kubectl create -f` می‌توانید یک آبجکت را از روی فایل پیکربندی ایجاد کنید.
برای جزئیات بیشتر به [مرجع API کوبرنتیز](/docs/reference/generated/kubernetes-api/{{< param "version" >}}/) مراجعه کنید.

* `kubectl create -f <filename|url>`

## نحوهٔ به‌روزرسانی آبجکت‌ها

{{< warning >}}
به‌روزرسانی آبجکت‌ها با فرمان `replace` همهٔ بخش‌هایی از spec را که در فایل پیکربندی مشخص نشده‌اند حذف می‌کند. بنابراین نباید از این فرمان برای آبجکت‌هایی استفاده کرد که spec آن‌ها تا حدی به‌دست کلاستر مدیریت می‌شود؛ مانند Serviceهایی از نوع `LoadBalancer` که فیلد `externalIPs` آن‌ها مستقل از فایل پیکربندی مدیریت می‌شود. برای اینکه `replace` فیلدهایی را که به‌طور مستقل مدیریت می‌شوند حذف نکند، باید این فیلدها را در فایل پیکربندی کپی کنید.
{{< /warning >}}

با فرمان `kubectl replace -f` می‌توانید یک آبجکت زنده را مطابق با فایل پیکربندی به‌روزرسانی کنید.

* `kubectl replace -f <filename|url>`

## نحوهٔ حذف آبجکت‌ها

با فرمان `kubectl delete -f` می‌توانید آبجکتی را که در یک فایل پیکربندی توصیف شده است حذف کنید.

* `kubectl delete -f <filename|url>`

{{< note >}}
اگر در فایل پیکربندی، به‌جای فیلد `name`، فیلد `generateName` در بخش `metadata` مشخص شده باشد، نمی‌توانید آبجکت را با فرمان `kubectl delete -f <filename|url>` حذف کنید.
در این حالت باید از فلگ‌های دیگری برای حذف آبجکت استفاده کنید. برای مثال:

```shell
kubectl delete <type> <name>
kubectl delete <type> -l <label>
```
{{< /note >}}

## نحوهٔ مشاهدهٔ یک آبجکت

با فرمان `kubectl get -f` می‌توانید اطلاعات آبجکتی را که در یک فایل پیکربندی توصیف شده است مشاهده کنید.

* `kubectl get -f <filename|url> -o yaml`

فلگ `-o yaml` مشخص می‌کند که پیکربندی کامل آبجکت چاپ شود.
برای دیدن فهرست گزینه‌ها از `kubectl get -h` استفاده کنید.

## محدودیت‌ها

فرمان‌های `create`، `replace` و `delete` زمانی به‌خوبی کار می‌کنند که پیکربندی هر آبجکت به‌طور کامل در فایل پیکربندی آن تعریف و ثبت شده باشد. اما اگر یک آبجکت زنده به‌روزرسانی شود و این تغییرات در فایل پیکربندی آن ادغام نشوند، دفعهٔ بعد که `replace` اجرا شود، این تغییرات از بین می‌روند. چنین وضعیتی ممکن است زمانی پیش بیاید که یک کنترل‌کننده، مانند HorizontalPodAutoscaler، مستقیماً یک آبجکت زنده را به‌روزرسانی کند. به مثال زیر توجه کنید:

1. شما یک آبجکت را از روی یک فایل پیکربندی ایجاد می‌کنید.
1. منبع دیگری با تغییر یکی از فیلدها، آبجکت را به‌روزرسانی می‌کند.
1. شما آبجکت را با استفاده از فایل پیکربندی جایگزین می‌کنید. تغییراتی که منبع دیگر در مرحلهٔ ۲ اعمال کرده بود از بین می‌روند.

اگر لازم است چند نویسنده بتوانند یک آبجکت مشترک را تغییر دهند، می‌توانید برای مدیریت آبجکت از `kubectl apply` استفاده کنید.

## ایجاد و ویرایش یک آبجکت از روی URL بدون ذخیرهٔ پیکربندی

فرض کنید نشانی URL یک فایل پیکربندی آبجکت را در اختیار دارید. با فرمان `kubectl create --edit` می‌توانید پیش از ایجاد آبجکت، پیکربندی آن را تغییر دهید. این قابلیت به‌ویژه برای آموزش‌ها و وظایفی مفید است که به فایل پیکربندی‌ای اشاره می‌کنند که خواننده ممکن است بخواهد آن را تغییر دهد.

```shell
kubectl create -f <url> --edit
```

## مهاجرت از فرمان‌های دستوری به پیکربندی دستوری آبجکت

مهاجرت از فرمان‌های دستوری به پیکربندی دستوری آبجکت شامل چند مرحلهٔ دستی است.

1. آبجکت زنده را در یک فایل پیکربندی محلی صادر کنید:

    ```shell
    kubectl get <kind>/<name> -o yaml > <kind>_<name>.yaml
    ```

1. فیلد status را به‌صورت دستی از فایل پیکربندی آبجکت حذف کنید.

1. برای مدیریت‌های بعدی آبجکت، فقط از `replace` استفاده کنید.

    ```shell
    kubectl replace -f <kind>_<name>.yaml
    ```

## تعریف انتخابگرهای کنترل‌کننده و برچسب‌های PodTemplate

{{< warning >}}
به‌شدت توصیه می‌شود انتخابگرهای (selectors) کنترل‌کننده‌ها را به‌روزرسانی نکنید.
{{< /warning >}}

رویکرد پیشنهادی این است که یک برچسب PodTemplate واحد و تغییرناپذیر تعریف کنید که فقط انتخابگر کنترل‌کننده از آن استفاده کند و هیچ معنای دیگری نداشته باشد.

نمونه‌ای از برچسب:

```yaml
selector:
  matchLabels:
      controller-selector: "apps/v1/deployment/nginx"
template:
  metadata:
    labels:
      controller-selector: "apps/v1/deployment/nginx"
```
